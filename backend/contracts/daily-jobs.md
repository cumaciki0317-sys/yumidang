# 일일 작업 등록 계약

## 2026-10-20 현행 기준과 이 문서의 적용 범위

이 문서는 현재 요구와 구현 계약을 구분한다. 아래 기술 시그니처·기존 SQL·검증 기록은 실제 구현 근거이며 새 정책 요구가 자동 구현됐다는 뜻이 아니다.

- 담당은 현재 민규=BE·AI·검색·행사·서버 운영, 종현=FE·UX/UI·앱 API/세션 소비·빌드, 유미=UT·출시/지원 책임이다. 아래 옛 종현 BE·성호 UI 배정은 당시 기록이며 현재 실행 권한으로 사용하지 않는다. 구체 파일은 현행 소유권 정책을 따른다.

- AI 탐색 동의는 첫 사용 시 받고 거절하면 일반 검색을 유지한다. 후기 요약은 가입 시 열람·내 프로필 생성/노출·작성 후기 활용을 기본 미선택인 별도 선택 세 항목으로 받는다. 전체 동의와 개별 자세히 보기를 유지하고 미동의 가입/일반 동행을 허용한다. 세 동의의 철회는 독립적이다. 현재 서버의 summary_allowed 하나·review_summary 일괄 철회가 이 세분화 요구를 구현했다고 해석하지 않는다. 테스트 계정 동의 간주는 실제 동의 증거·DB 값 변경·회원 원문 전송 승인이 아니다.

- KOPIS는 전체 공연·연극·뮤지컬·클래식·국악·대중음악·무용·대중무용·서커스/마술·복합·아동·대학로·내한·축제 14항목, 어제까지 최근7일·매일 갱신이다. basedate 누락만으로 영구 공개 보류하지 않고 공식 사이트의 실제 기간·조건·공연ID/순위/순서를 대조한 분류만 공개하는 A안을 적용한다. 요청 날짜로 기간을 확정하거나 일일순위를 합산하지 않는다. 확인 기간·시각·출처를 표시하고 실패 때 마지막 검증 기간을 유지한다. 아래 all/musical·basedate 필수 parser·not_enabled는 현재 구현/당시 검증의 기술적 한계이며 최신 제품 정책이 아니다. 일반 공연 수집·칼럼 매핑은 순위 대조와 병행한다.

- 직접 입력 행사는 해당 공고에만 저장/표시하며 공용 목록·별도 행사 상세·검수 후 공용화는 만들지 않는다. 행사명 필수, 공개 행사장 장소/주소 선택이며 개인 주소를 금지한다. 새 연결은 예정/진행 중만 허용하고 종료·공식취소·연기일정미정은 제한한다. 단순 검색 누락은 취소/비표출이 아니다. 제공기관 비표출 원천의 정보와 상세 진입만 숨기고 공고/독립 만남 장소·다른 유효 공개 원천은 유지한다. 공식 동일 개최 식별근거만 통합에 사용하고 원천ID·공고관계·필드출처·가역 이력을 보존한다. 현재 eventId UUID 저장을 직접 입력·통합·비표출 구현 완료로 표시하지 않는다.

- 서울은 키/응답의 평문 HTTP 수집을 활성화하지 않는다. 검토된 HTTPS 자동 수집 경로·실제 최신 응답 envelope·페이지 재개·진행 중 갱신 확인까지 보류한다. 홈페이지 HTTPS 성공이나 HTTP 앞에 s를 붙인 주소는 API 전송 보안 검증이 아니다. 이 보류는 다른 공급사·공통 칼럼/화면 준비의 중단을 뜻하지 않는다.

최신 기준: [정책.md](../../정책.md). 구현과 남은 조건: [서버·DB 대조 원장](../../docs/collaboration/requests/jonghyun/2026-10-20-policy-implementation-audit/server-audit.json).


## 2026-10-20 행사 UX 확정과 서버 구현 경계

기준은 [최종 행사 UX 확정](../../docs/collaboration/requests/jonghyun/2026-10-20-event-ux-approved-spec.md)이다. 사용자 명시 전체 문서 동기화 승인으로 반영하며 제품 설계 확정과 실제 코드·DB·배포 완료를 구분한다.

일일 수집으로 확인한 취소·연기·변경 일정은 연결 공고 작성자와 진행 중 동행의 확정 상대에게 앱 안 알림을 제공하고 같은 상태 변화의 중복을 방지하는 목표다. 단순 검색 누락·취소 항목 미제공을 취소로 바꾸거나 종료 동행 전체/조회자에게 전송하지 않는다. 새 푸시·외부 메시지는 도입하지 않는다.

비표출은 원천별로 적용하고 다른 유효 공개 원천은 유지한다. 명시 재표출·공개 조건과 최신 자료 확인 후 복원하며 핵심 충돌은 새 연결을 제한한다. 동일 행사 통합은 확실한 공식 개최 식별근거가 있는 경우만 허용한다. 아래 기존 수집/작업 등록이 새 통합·원천 상태 공개제어·행사 알림을 구현했다는 뜻은 아니다. 민규 후속 연결·실행 검증 대상이다.


현재 기준은 [정책.md](../../정책.md)다. 아래에서 현재 정책 목표와 기존 기술 인터페이스를 구분한다. 이번 문서 동기화는 서버 코드·SQL·설정·DB·외부 호출·배포를 변경하거나 검증하지 않았다.

## 시간·선택 운영값

행사 수집과 신규 후기 요약 작업은 매일 00:01 `Asia/Seoul`에 등록하고 분리 실행한다. UTC 전용 스케줄러는 매일 15:01 UTC(`1 15 * * *`)이며 한국에서는 다음 날 00:01이다. 한국 시간 스케줄은 `1 0 * * *`다. 실제 등록·정시 실행·복구는 별도 검증이다.

`POST /functions/v1/scheduled-jobs/daily` 본문은 `{"limit":20}`, 내부 인증은 `Authorization: Bearer INTERNAL_WORKER_SECRET`이다. 회원 JWT·anon/service-role key를 내부 secret 대신 사용하지 않는다. 비밀값은 스케줄러의 비밀 설정으로 참조하고 문서·로그·명령 원문에 넣지 않는다.

- 내부 정리 20건, 동시 실행기 1개, 점유 자동 연장 없음.
- 행사 요청 31일·100건/쪽·최대 5쪽·쪽당 15초. 초기 과거 최근 1개월, 미래 오늘부터 31일과 오래 진행 중인 행사를 갱신한다. 중단 위치를 보존해 다음 실행에 잇고 미수집 범위를 표시한다.
- 일일 요약 worker 호출 최대 1회·75초, worker 자체는 최대 10작업·60초·점유 180초다. 정상 분할을 실패로 세지 않는다.
- 실제 실패 최대 3회, 10분부터 최대 6시간 간격. 예산 부족은 실패 수를 늘리지 않고 1시간 뒤 확인한다.

## 독립 실행과 남은 연결

건별 자동 완료는 [DB 영속 예약·상주 실행기](completion-db.md)다. 후기 공개는 제출·조회 조건이며 일일 배치·모델 설정을 기다리지 않는다. 최종 동의/변경 만료·공개 정리·요약 등록의 단계 결과를 각각 기록한다. 행사 또는 요약 실패 시 실패 영역만 재시도한다. 현재 단일 호출의 단계 의존성과 중단 복구가 이 목표를 충족하는지는 후속 구현 대조가 필요하다.

공급사 KOPIS·TourAPI·서울 열린데이터는 실제 출시 연동 목표이며 자격·HTTPS·응답·범위·요금은 별도로 검증한다. KOPIS 순위 선택은 전체 공연(기본), 연극, 뮤지컬, 클래식, 국악, 대중음악, 무용, 대중무용, 서커스/마술, 복합, 아동, 대학로, 내한, 축제의 14항목이다. 표시명은 서양음악(클래식)→클래식, 한국음악(국악)→국악, 무용(서양/한국무용)→무용으로 바꾸되 원천 코드·원래 분류는 보존한다. 아동·대학로·내한·축제는 장르와 구분되는 공식 특성·지역 조건을 따른다. 집계는 어제까지 최근7일, 갱신은 매일이다. 분류마다 공식 사이트에 표시된 실제 기간·공식 분류/지역·정렬 기준과 API 공연ID·순위·순서가 일치한 Top10만 공개한다. basedate가 없어도 이 대조를 통과한 목록은 공개할 수 있으나 API 내부 집계 기간을 증명했다고 안내하지 않는다. 요청 날짜만으로 기간을 확정하거나 일간 순위를 합산한 자체 주간 순위를 만들지 않는다. 동률은 공식 표시 순서 그대로 유지하고 10개 미만이면 검증한 개수만 표시한다. 출처·실제 확인 기간·확인 시각을 표시한다. 갱신 실패 시 마지막 검증 목록의 기존 기간을 그대로 유지하고 갱신 지연을 안내하며 최신 날짜로 바꾸지 않는다. 최초 미검증·미지원 분류는 공식 사이트 링크를 제공하고 자체 순위로 채우지 않는다. 분류별 성공·실패를 독립 관리한다. 현재 API 매핑·자동 대조·저장·서버 응답 구현과 운영 검증은 별도이며 이 정책 변경만으로 연동 완료로 표시하지 않는다.

AI 설정·계정 포함량·보관 검토가 없으면 운영 호출을 시작하지 않는다. 실제 회원 원문은 공급사 회신의 교육·프로토타입 한계를 반영하고 별도 API의 구체 보관·학습·삭제·공동 사용 조건 및 회원 전송을 확인하기 전 보류한다. 선택 숫자는 실제 환경 설정·호스팅 상한·계정 한도를 확인한 후 연결하며 함수 존재를 운영 등록 성공으로 표시하지 않는다. [작업 큐](worker-jobs.md)·[요약 계약](review-summary.md)을 따른다.
