# 공고 작성·공개 데이터 계약

현재 기준은 [정책.md](../../정책.md)다. 아래에서 현재 정책 목표와 기존 기술 인터페이스를 구분한다. 이번 문서 동기화는 서버 코드·SQL·설정·DB·외부 호출·배포를 변경하거나 검증하지 않았다.

## 작성·등록

현재 무료 동행만 작성한다. 카테고리·제목·소개·장소·시작/종료 날짜와 시간은 필수이며 종료가 시작보다 늦어야 하고 자정을 넘길 수 있다. 유료 유형·금액 입력은 현재 제공하지 않는다. 모집 마감은 선택이며 생략하면 시작 시각, 입력하면 시작 시각 이하여야 한다.

장소명은 Kakao Local 검색·선택, 주소는 Kakao 우편번호 서비스, 상세 만남 지점은 별도 입력한다. 카카오 장소 사용은 로그인 제공사와 별개다. 행사 연결은 선택이며 기존 입력·일정을 자동 변경하지 않는다. 성공하면 상세로 이동하고 실패하면 입력을 유지한다. 카테고리는 지금이당·전시·축제·팝업·공연·영화·맛집·카페·쇼핑·여행·운동·산책·게임·반려동물·스터디·기타 16개다. 제목 50자·소개 2,000자·상세 만남 지점 300자로 기존 검증과 DB 제약을 맞춘다.

제목의 정확한 주소·상세 만남 지점 또는 본문의 전화번호·계좌·정확한 주소·상세 지점을 탐지하면 해당 부분을 안내하고 수정 전 등록을 막는다. 입력은 보존하고 오탐 문의를 제공한다. 공개글·프로필·후기는 등록 전 개인정보/금지 콘텐츠를 검사하며 오탐 문의를 제공한다. 탐지기의 실제 품질과 연결은 구현 검증 대상이다.

## 공개와 검색

공고 키워드는 제목·등록 장소명·등록 주소·연결된 행사명에 일치시킨다. 소개·후기·상세 만남 지점은 제외한다. 주소 검색에 일치해도 정확한 주소를 공개하지 않는다.

비로그인 공고 목록·상세의 작성자 박스는 개인정보 없는 모자이크 로그인 가드, 로그인 미확정 상대는 이름 마스킹, 양측 확정 당사자에게만 네이버 전체 이름과 정확한 주소·상세 지점을 제공한다. 일반 공개 지역은 동까지다. 취소 이후 해당 관계의 추가 공개는 종료한다.

등록일 최신순 기본·시작일 빠른순 선택, 전체 모집 상태 기본·모집 중만 보기 선택이다. 회원 나이 필터는 공고 작성자의 만 나이 19~99세 숫자 범위이며 전체에는 상한을 적용하지 않는다. 비로그인은 일정·나이 모두 전체만 사용한다. 주변·반경·거리순은 제공하지 않는다. 공고·행사 목록은 10개씩, 후기는 5개씩 가져온다. AI 후보/표시와 하루 이용 한도는 AI 계약을 따른다.

## 수정·마감·삭제와 임시저장

확정 전 수정 가능하되 핵심 조건 변경은 기존 신청자 알림·진행 중 동의 무효화·새 조건 재동의를 요구한다. 수동 모집 마감은 새 신청만 막고 기존 신청·대화는 유지한다. 삭제는 일반 목록 숨김이며 미확정 신청·동의 종료, 대화 읽기 전용 전환과 참여자 알림을 수반한다. 확정된 약속 종료 전 공고 삭제는 막고 삭제로 약속을 취소하지 않는다. 탈퇴 공고는 공개 숨김, 기존 당사자 일반 본문은 탈퇴부터 1년이며 식별정보는 제거·가림한다. 프로필·사진은 탈퇴 즉시 접근 회수와 활성 저장소 삭제다. 법적 근거·백업 실제 삭제는 별도 확인한다.

공고 임시저장은 같은 기기에만 저장하고 재진입 시 복구를 안내한다. 등록 성공·직접 삭제·로그아웃·기한 만료 때 삭제하며 삭제 후 복구하지 않는다. 최근 1개만 마지막 수정부터 7일 보관하고 교체 전 안내·복원 시 만료 시각을 표시한다. 최근 검색은 같은 기기에 최대 10개·7일 보관하며 개별/전체 삭제·로그아웃/기한 만료 시 정리한다.

## 실제 API 차이

현재 `create_service_post`의 필드와 길이·타입 제한은 [서비스 API](service-api.md), 실제 저장·권한은 [핵심 DB](core-service-db.md)에 명시한다. HTTP에서 모집 마감을 생략하면 시작 시각으로 채운다. 수정은 경로의 공고 ID와 전체 입력, 상세 조회의 `updatedAt`을 `expectedUpdatedAt`으로 보내며 오래된 입력은 충돌로 거절한다. 핵심 조건 변경은 해당 공고 잠금 아래 동의를 무효화하고 알린다. 최초 생성 재시도용 입력은 수정해 덮어쓰지 않는다.

마감·삭제는 각각 빈 본문을 받는 별도 POST 경로다. 삭제는 행·대화를 보존하는 숨김 처리이며 확정 이력의 약속 종료 전에는 거절한다. 행사 연결·행사명 검색은 아래 후속에서 연결했다. 숫자 나이·지역·최신 카테고리의 HTTP 연결은 아래 검색 입력 절을 따른다. 현재 버전의 실제 DB 통합 검증은 별도로 필요하다. 개인정보 탐지·기기 임시저장은 별도 후속이다. 확정 후 일정 변경/취소는 서비스 API의 기존 연결 계약을 따른다.

## 기존 행사 연결·최신 표시 인터페이스

생성·수정 HTTP 입력의 `eventId?: string | null`을 기존 RPC의 `p_input`에 전달한다. 생성에서 생략하면 연결 없음, 수정에서 생략하면 기존 연결 보존, `null`이면 해제, UUID면 명시 선택이다. HTTP는 생략을 `null`로 바꾸지 않는다. 새 선택은 canonical 저장소의 활성·미종료 행사만 허용하며 이미 연결한 동일 ID의 취소/종료나 최초 생성의 동일 입력 재시도는 기존 연결을 보존한다. 동일 생성 ID에 다른 행사 입력을 보내면 충돌한다.

공고에는 `source_event_id`만 저장한다. `get_service_post`는 `eventId`와 현재 canonical 자료의 `linkedEvent`를 반환하며 연결 없으면 둘 다 `null`이다. `linkedEvent`에는 행사 식별자·제목·공개 장소/주소·일정·`sourceStatus`·`state`가 포함된다. 표시를 과거 snapshot으로 고정하지 않는다. 행사 공급자 갱신은 공고의 등록 입력·동행 일정·`updatedAt`·동의 지문을 변경하지 않는다. 사용자가 연결 UUID를 교체/해제/새로 선택하면 기존 동의를 무효화하고 새 버전으로 다시 동의해야 한다. 동의 지문에는 선택 UUID만 추가하며 공급자의 최신 필드를 넣지 않는다.

연결 행사명은 기존 `search_public_posts_v2`의 검색 일치에 포함한다. 현재 공개 검색 카드는 `id,title,authorDisplayName,publicArea,startsAt,endsAt,cost,state,canApply` 9개 필드를 유지한다. 행사 정보를 카드에 추가하는 종현 decoder·AI 연결은 별도 후속이다. 공고의 비공개 실명·정확한 장소 권한은 행사 공개 정보와 독립이며 확정/취소 관계 권한을 유지한다.

행사 일정 겹침·종료 선택 차단과 현재 정책의 전체 입력 제약은 실제 코드·DB·화면에서 검증한다. 문서 정리를 외부 수집·네이버·사진·운영 연결 성공으로 보고하지 않는다.


## 최신 공개 검색 HTTP 연결 (2026-10-05)

`GET /service-api/posts`와 `GET /functions/v1/service-api/posts`는 종현의 현재 검색 코어를 호출한다. 선택 인증으로 익명은 anon 자격 증명, 회원은 Auth에서 검증한 동일 JWT를 RPC에 전달하며 서비스 키를 공개 검색에 사용하지 않는다.

- 분류는 `POST_CATEGORIES`의 16개, `region`은 `POST_REGIONS`의 정식 17개 시도 명칭을 받는다. 생략하면 전체이며 문자열 `전체`와 시도 약칭은 거절한다.
- 회원 나이는 `ageMin=19&ageMax=99`처럼 양쪽 정수로 입력한다. 19~99 범위에서 최소가 최대 이하여야 한다. `authorAge=all` 또는 나이 키 생략은 상한 없는 전체이며 숫자 키와 함께 입력할 수 없다. 구형 `20s/30s/40plus` 값은 거절한다.
- `periodStart`와 `periodEnd`는 함께 입력하고 유효한 ISO 시각·시작보다 늦은 종료를 요구한다. 비로그인은 숫자 나이와 일정 입력을 `AUTH_REQUIRED`로 거절한다. 지역·카테고리·전체 나이·정렬은 비로그인도 가능하다.
- 기본 페이지는 10개다. 명시 `limit`은 기존 코어 계약의 1~50을 유지하고 모바일은 10을 요청한다. 중복·알 수 없는 query 키, caller 주입, 반경·거리 조건은 거절한다.

RPC 입력은 `search_public_posts_v2(p_contract_version=2026-10-05,p_region,p_filters,p_cursor,p_limit)`이다. `p_filters.authorAge`는 `all` 또는 `{min,max}`이며 지역은 별도 인수다. 커서는 현재 코어 v3의 필터·권한 결합을 유지한다. 익명 카드의 `authorDisplayName`은 반드시 `null`이며 이름·정확한 주소가 섞인 DB 응답은 공개하지 않는다.

검증: 민규 검색 HTTP/런타임 테스트는 실제 HTTP 파서·Auth 조립·종현 기본 코어를 실행하되 DB 응답은 fetch 모형이다. 이 결과는 운영 DB 시그니처·마이그레이션 적용·실제 모바일 네트워크 성공을 증명하지 않는다.

## 2026-10-08 본인 공고·숨김 연결

회원 `GET /me/posts?limit=20&before={postId}` → `list_my_service_posts`는 본인 공고만 반환하며 신청 없는 공고도 포함한다. 기본 20·최대 100, `(created_at, UUID)` 내림차순이고 다음 페이지는 그보다 작은 튜플부터 조회한다. 다른 회원 또는 삭제된 커서는 404, 임의 회원 ID 입력은 거절한다. 삭제 공고를 제외하고 기존 작성자 관리 투영을 재사용한다.

개인 숨김은 DB에서 검색·목록 제한보다 먼저 적용한다. 대상 공고·행사·회원 콘텐츠·채팅 메시지의 직접 조회에도 적용하며 타인의 결과는 변경하지 않는다. 숨긴 회원의 모든 공고를 자동 숨기는 확대 정책은 추가하지 않는다. 작성자 본인 공고 관리 및 신청·확정 일정·취소·신고·안내 경로는 유지한다. 연결 행사 숨김은 공고의 `linkedEvent`를 감추며 동행 입력·일정은 보존한다.
