# 평가·공개 후기 계약

현재 기준은 [정책.md](../../정책.md)다. 아래에서 현재 정책 목표와 기존 기술 인터페이스를 구분한다. 이번 문서 동기화는 서버 코드·SQL·설정·DB·외부 호출·배포를 변경하거나 검증하지 않았다.

## 완료·작성·공개

예상 종료 후 본인 완료 확인을 마친 사람은 상대 확인 전에도 후기를 제출할 수 있으나 실제 완료 전에는 비공개다. 양쪽 확인 또는 예상 종료+24시간에 실제 완료하며 취소·노쇼는 제외하고 신고·분쟁 검토 중에는 보류한다. 지연 시 실제 성공 시각이 완료 시각이다. 작성 마감은 실제 완료부터 7일, 양쪽 제출은 실제 완료 후 즉시 공개, 한쪽 제출은 작성 기한 종료 시 공개한다. 완료 횟수는 실제 완료 즉시, 후기 당도는 상대 열람 가능 시 반영한다.

검토 중에는 작성·기한 진행·새 공개를 보류한다. 이미 공개된 후기는 접수만으로 숨기지 않고 운영자가 임시 비공개를 결정한 때 숨긴다. 정상 동행 인정 후 원래 종료+24시간이 지났으면 즉시 실제 완료한다. 첫 완료라면 그때부터 작성 7일, 이미 완료했다면 남은 기한을 재개하되 최소 24시간을 보장한다. 재개 후 양쪽 제출이면 공개하고 한쪽이면 재개·연장된 작성 기한 종료에 공개한다.

마감은 서버 접수 시각이 마감보다 빠를 때만 허용한다. 개인 확인·제출·알림 클릭으로 마감을 새로 계산하지 않는다. 상대 열람·공개 프로필·칭찬·AI 원문은 같은 공개 적격성과 각각의 관계 권한을 확인한다. 명시적 숨김을 정기 작업이 되돌리거나 기존 비공개 후보를 일괄 공개하지 않는다.

## 평가 입력과 공개 지표

좋아요·보통이에요·별로예요 중 하나와 별점 1~5가 필수이고 한마디는 선택이다. 좋아요에서만 칭찬 최대 3개를 선택한다. 공식 6종은 시간을 잘 지켜요 / 약속한 내용을 지켜요 / 소통이 원활해요 / 배려심이 있어요 / 대화가 즐거워요 / 함께하니 편안해요다. 제출 성공 후 수정·중복 제출은 금지하며 정확한 재시도는 같은 결과로 처리한다.

칭찬은 적격 공개 평가의 상위 5개와 횟수를 표시한다. 임시 숨김된 후기의 칭찬은 제외하고 유효 재공개 때 복원한다. 다른 공개 후기의 칭찬은 유지하며 복원 자체 알림은 보내지 않는다.

당도 산식은 정책 7-4절에 확정됐다. 초기 15, 반응 좋아요 +1·보통 0·별로 −2와 별점 1~2점 −2·3점 0·4~5점 +1을 합산한다. 완료 횟수·칭찬은 가산하지 않는다. 취소 제재 −2·노쇼 −3·중대 위반 −10이며 같은 사건의 운영 감점은 가장 큰 하나만, 유효 후기 기여와는 합산한다. 무효 동행의 후기 기여는 제외한다. 전체 유효 기여를 합한 뒤 표시만 0~100 정수로 제한하며 원 기여를 남겨 정정한다. 임시 후기 숨김은 반영 당도를 유지하고 최종 무효 때 제외한다. 정책 확정과 실제 점수 저장·계산기 연결은 별개다.

## 공개 요약과 탈퇴

한마디가 있는 적격 공개 후기 3개부터 전체 적격 텍스트를 요약한다. 비공개·텍스트 없는 평가는 요약에서 제외한다. 근거가 비공개로 바뀌면 기존 요약은 즉시 숨기고 남은 적격 텍스트 3개 이상이면 다음 정기 주기에 재생성, 미만이면 대기다. 요약은 최대 300자이고 표시·다시 펼칠 때 현재 조건을 조회하며 별도 공개 결과 캐시는 두지 않는다. 실패·대기에도 공개 가능한 원문·칭찬은 유지한다.

탈퇴 후 상대는 남은 기한에 작성할 수 있고 기존 공개 후기는 익명으로 유지한다. 탈퇴한 본인은 신규 작성할 수 없으며 한쪽 공개는 원래 기한 종료를 따른다. 재가입은 새 당도 15·완료 0으로 시작하고 과거 받은 후기·당도를 복구하지 않는다.

## 기존 연결과 변경 필요

`GET /appointments/:id/reviews`의 `appointment_completed`, `can_write`, `deadline_at`, `released`와 `peer_review`는 [후기 DB 계약](review-automation-db.md)을 따른다. 선제 제출과 기존 공개 predicate가 존재하더라도 현재의 한쪽 작성 기한 종료 공개·검토 중 이미 공개된 후기 유지·당도 산식·탈퇴 처리까지 구현됐다는 뜻이 아니다. 관련 SQL·권한·동시성·화면은 후속 대조와 검증이 필요하다. [서비스 API](service-api.md)·[요약 DB](review-summary-db.md)를 함께 확인한다.

## 2026-10-05 최신 공개 정책 SQL 연결

추가 마이그레이션 `20261005001429_current_completion_consent_policy.sql`은 신규 공개를 양쪽 제출 즉시 또는 현재 `review_deadline_at` 종료 조건으로 판정한다. 최초 마감은 실제 완료+7일이며 분쟁 인정 후 재개·연장된 마감도 사용한다. 기존 완료+24시간 공개를 사용하지 않는다.

이미 공개 표시가 있는 유효 후기는 검토 접수만으로 숨기지 않는다. 정리 작업 전 동적으로 공개된 정책 후기 역시 검토 진입 전에 공개 상태를 보존한다. 운영 `override=false`는 계속 숨기며 노쇼·실제 완료 없는 비정상 자료는 제외한다. 공개 후기·상대 열람·칭찬·AI 근거는 공통 적격성을 사용한다. 신규 공개와 작성은 검토 중 보류하며 기존 인정 처리의 남은 기간 최소24시간 재개를 유지한다.

`tests/database/minkyu/current_completion_consent_policy.sql`은 격리 로컬 DB의 합성 자료로 7일 마감·양쪽 즉시·기존 공개 보존·운영 숨김·분쟁 재개·노쇼·권한을 검사하고 rollback한다. 파일 작성만으로 실제 실행이나 운영 적용 완료를 주장하지 않는다.

## 현재 당도 원장과 회차 연결

신규 `20261005013901_current_sweetness_ledger.sql`은 한마디 없는 평가도 반응/별점으로 합산한다. 처음 적격 시점의 기여를 물질화하고 현재 적격 미기록 평가를 중복 없이 포함하므로 maintenance 지연에도 조회 점수가 일치한다. 공개 뒤 임시 숨김은 점수를 유지하고 최종 무효/노쇼 판정은 제외하며 오판 정정은 원 기여를 복원한다. 동일 사건의 운영 감점은 회원 회차별 최대 하나다. 원장·판정 helper는 DB owner만 사용할 수 있으며 운영 담당 권한을 새로 부여하지 않았다.

기존 약속 참가 회차는 고정하고 현재 회차의 당도·완료 횟수·받은 후기·칭찬·AI 근거만 반환한다. 실제 탈퇴/재가입·외부삭제·보관 이행은 별도이며 새 회차를 수동 생성한 합성 검증을 실제 재가입 완료로 설명하지 않는다. 단독 SQL·기존9개 SQL·실제2세션4그룹 및 초기 공개 자료 이식 회귀가 격리 DB에서 통과했다. 상세는 [당도 연결 계약](../../docs/collaboration/requests/minkyu/2026-10-05-sweetness-ledger-contract.md)을 따른다.
