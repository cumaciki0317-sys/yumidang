# 평가·공개 후기 계약

## 개인 완료·후기 제출과 실제 완료의 경계

예상 종료 후 본인 완료 확인을 마친 당사자는 상대방 완료를 기다리지 않고 후기를 제출할 수 있다. 한 명만 확인한 상태는 동행 전체 완료가 아니며 해당 후기는 비공개다. 두 사람 확인 또는 예상 종료+24시간 자동 처리(취소·불발·분쟁 제외)로 실제 완료한다. 지연 처리면 실제 성공 시각을 완료 시각으로 기록한다. 실제 완료부터 작성 마감 7일·한쪽 후기 공개 24시간을 계산하며 양쪽 제출은 완료 조건 충족 후 즉시 공개한다. 완료 횟수는 실제 완료 즉시, 당도는 상대 후기 열람 가능 시 반영한다.

`20261002110000_completion_review_policy.sql`에서 개인 확인 후 선제 제출을 구현했다. `GET /appointments/:id/reviews`는 미완료 상태에서 `can_write=true`, `appointment_completed=false`, 작성 마감 `null`을 반환할 수 있다. 실제 완료 전 상대 후기 본문은 반환하지 않는다. 실DB 검증 결과는 [순차 작업 인계](../../docs/collaboration/requests/minkyu/2026-10-02-ordered-backend-handoff.md)에 기록한다.

현재 적용할 서비스 정책은 [정책.md](../../정책.md)를 따른다. 한쪽 후기 공개는 **실제 동행 완료 시각 +24시간**, 양쪽 제출은 실제 완료 후 즉시다. 완료 횟수는 후기와 관계없이 실제 완료 이력에서 계산한다. 당도 반영 시점은 상대 후기 열람 가능 시점이나, 산식은 민규·팀 검토가 남아 있어 점수 계산은 구현하지 않았다. 공개 적격성은 향후 당도 입력에도 재사용할 수 있다. 브라우저 화면·실제 AI 생성·운영 배포 검증은 별도다.

서비스 정책은 위 통합 문서의 최신 기준을 따른다. 기존 SQL과 과거 인계는 보존한다. [2026-09-29 인계](../../docs/collaboration/requests/jonghyun/2026-09-29-review-policy-handoff.md)의 담당 경계 예외·실행 결과는 해당 작업 당시 범위에 한정된다.

## 제출과 공개

양쪽 후기를 제출하면 완료 후 24시간 전이어도 즉시 공개한다. 한쪽만 제출하면 실제 동행 완료 시각 +24시간부터 공개하고, 그 이후 작성 기한 안에 제출한 후기는 즉시 열람할 수 있다. 미완료·실제 분쟁·불발/노쇼는 제외하며 수동 완료는 양측 완료 확인을 요구한다. 일반 후기 작성 기간은 실제 완료 시각부터 7일이다. 분쟁 중 작성·기한·공개 보류, 동행 인정 후 남은 기간 재개·최소 24시간 보장의 기존 예외는 유지한다.

예상 종료 후 본인 완료 확인을 한 당사자부터 제출할 수 있고, 실제 완료 후에는 7일 작성 기한을 적용한다. 제출 성공 후 수정은 금지하고 동일 요청 재시도는 같은 결과로 처리한다. 분쟁 중 작성·기한·공개를 보류하고 동행 인정 후 남은 기간 재개·최소 24시간 보장 규칙을 유지한다. 상세 입력·오류와 HTTP 경로는 [서비스 API](service-api.md), DB 호출·칭찬·공개 페이지 응답은 [후기 자동화 DB](review-automation-db.md)를 따른다.

양쪽 제출/7일 경과를 기다리던 이전 gate는 폐기한다. 기존 policy 대기 후보에도 새 조건을 적용한다. 명시적 override 숨김과 공개 후보가 없는 과거 후기는 자동 공개하지 않는다. 상대 열람과 제3자 공개의 권한 경계는 유지하고 공개 시점 조건은 일치시킨다. 공개 조건은 제출·조회에 적용하므로 물질화 정리나 하루 한 번 AI 작업까지 기다리지 않는다.

## 평가 입력과 칭찬

좋아요·보통이에요·별로예요 중 하나와 별점 1~5가 필수이고 한마디는 선택이다. 좋아요에서만 칭찬 최대 3개를 선택하며 다른 평가로 바꾸면 칭찬은 제출하지 않는다. 칭찬 목록은 “시간을 잘 지켜요 / 약속한 내용을 지켜요 / 소통이 원활해요 / 배려심이 있어요 / 대화가 즐거워요 / 함께하니 편안해요” 6개다. 공개 칭찬의 상위 5개·실제 횟수를 표시한다. 본인과 다른 회원 모두 현재 당도만 표시하고 변경 내역은 고객지원 문의로 확인한다. 당도 산식·지원 세부 절차는 팀 검토다.

## 공개 원문과 요약

공개 프로필·칭찬 집계·AI 입력은 동일한 현재 공개 적격성을 확인한다. 한마디 없는 공개 평가는 칭찬 집계에는 포함하고 AI 입력에서는 제외한다. 공개 한마디 3개 이상일 때만 요약 후보가 된다. 원문 변경·숨김·분쟁으로 revision을 증가시키고 오래된 요약 게시·열람을 차단한다. 로그·작업 payload에 후기 원문을 넣지 않는다.

공개 정리 RPC는 모델 설정 없이 실행한다. AI 요약 등록은 별도 RPC와 하루 한 번 주기를 사용하며 모델 생성·실제 품질·운영 일일 스케줄러 배포는 이번 변경의 성공으로 간주하지 않는다. 당도는 상대 후기를 열람할 수 있게 될 때 동시에 반영하고, 완료 횟수는 후기와 관계없이 동행 완료 즉시 반영한다. 당도 산식은 민규·팀 검토 필요다.

## 검증·화면 인계

양쪽 후기의 24시간 전 공개, 한쪽의 24시간 직전/경계/직후, 이후 제출의 즉시 열람, 실제 완료+7일 작성 종료, 분쟁·불발/노쇼·미완료 제외, policy 후보·override 보존과 공개/요약 적격성 일치를 확인한다. API 성공을 브라우저 UI 연결로 보고하지 않는다. 화면 담당은 유미·성호이며 이번 화면 연결은 미실행이다.
