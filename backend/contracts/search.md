# 공개 검색·장소·행사 조회 연결 계약 초안

상태: **종현 내부 계약·독립 코어 구현**. 검색·행사·장소 어댑터는 합성 입력으로 검증하며, 민규의 DB/RPC·공통 오류 계약 및 실제 외부 연결은 미완료다. 기준은 `PLAN.md` 3-3·3-6장, `PLAN_상세설계.md` 5.2·6.3·8·11.3장, `AGENTS.md`다. 공고 작성·수정과 위치 공개 권한의 원천 계약은 민규 소유 [posts-search.md](posts-search.md)에 둔다.

## 1. 호출자와 입력

아래는 서비스 내부 논리 입력이다. HTTP 경로·메서드, 실제 RPC명, 숫자 한도는 실제 연결 전에 확정한다. 아래 정렬은 사용자 확정 기준이다.

| 작업 | 호출자 | 입력 제안 | 검증·권한 |
|---|---|---|---|
| `searchPublicPosts` | 일반 탐색: 비로그인·회원 / AI 도구: 인증 회원 | `query?`, `category?`, `cost?`, `startsBefore?`, `endsAfter?`, `authorAge?`, `availability?`, `cursor?` | 필터 값·기간·커서를 검증한다. availability의 논리값은 all/recruiting이며 기본값은 all이다. 비로그인과 회원 모두 서버가 관계를 판단한다. AI는 일반 탐색과 같은 검색 범위·상태 필터를 사용한다. |
| `searchPublicEvents` | 일반 목록·AI·공고 작성 선택 | `query?`, `area?`, `period?`, `kind?`, `mode`, `cursor?` | `mode`는 `new_this_week`, `overlapping`, `post_selection`의 논리값 제안. `new_this_week`는 이번 주 시작 행사. 한국 시간 월요일 00:00부터 다음 월요일 00:00 직전까지를 이번 주로 사용한다. 일반 목록은 overlapping, ongoingOnly 기본 false이며 과거·현재·예정을 포함한다. |
| `lookupPlace` / `lookupPostalAddress` | 인증된 공고 작성자 | `query`, `source`, `cursor?` | 카카오 장소 검색 또는 우편번호 주소 선택의 입력용 결과. 등록 공고 조회·검색 권한과 별개다. 제공사 응답의 원문 전체를 반환하지 않는다. |

공고 목록은 기본적으로 확정·마감·만료 상태도 표시하고, 모집 중만 필터에서는 제외한다(2026-09-23 사용자 확인). 모집 중이 아닌 공고에는 새 신청을 허용하지 않는다. 삭제·비공개 공고의 처리와 상태별 DB 조회는 민규 계약과 연결한다.

공고 검색어는 세 항목 중 한 곳에 연속 부분 문자열로 포함되면 일치하며, 영문 대소문자와 연속 공백 차이는 무시한다(2026-09-23 사용자 확인). 공고의 키워드 일치 대상은 **제목·등록 장소명·등록 주소**뿐이다. 소개·리뷰·상세 만남 지점·기존 혼합 필드 `exact_location`은 검색하지 않는다. 주변·좌표·반경·거리순 검색은 지원하지 않는다. 빈 키워드는 다른 선택 필터에 맞는 목록 요청으로 처리한다(USER_FLOW 5-2). 기간은 시작 포함·끝 제외이며 겹치는 시간이 있는 공고를 포함한다. 기간 안에 시작하는 공고 그룹을 이전에 시작해 겹치는 그룹보다 먼저 표시한다. 각 그룹은 모집 중을 먼저 두고, 모집 중은 시작 시각순·나머지는 최근 등록순이다. 기간이 없으면 모집 중 우선과 같은 하위 정렬을 적용한다. 모집 중만 필터는 다른 상태를 제거한 뒤 같은 일정 순서를 사용한다. 동률은 ID로 고정한다. 검색 코어의 나이·커서 필터는 아직 미지원이며 입력하면 명시 오류를 반환한다. 실제 DB·페이지 계약 확정 후 연결한다.

## 2. 반환 계약과 공개 경계

검색 저장소가 일치 여부를 판단한 다음 **권한이 적용된 카드만** 서비스와 AI에 전달한다. 양쪽 확정 전 카드의 공개 지역은 **시·군·구까지만** 표시한다(2026-09-23 사용자 확인). 주소가 검색어와 일치해도 정확한 주소나 동·읍·면 수준의 저장값을 카드에 넣지 않는다. 상세 만남 지점은 검색 저장소의 일치 대상과 카드 모두에서 제외한다. 이 초안은 검색 카드 자체를 공개 필드로 제한하고, 작성자 본인·양쪽 확정 당사자의 정확한 장소는 별도 권한 조회 경로에서 받는 방식을 제안한다. 해당 별도 경로와 실제 반환 타입은 민규와 합의해야 한다.

```json
{
  "status": "results",
  "posts": [{"id":"post-01","title":"전시 같이 보기","authorDisplayName":"<마스킹 이름>","publicArea":"서울특별시 종로구","startsAt":"2026-10-03T14:00:00+09:00","endsAt":"2026-10-03T17:00:00+09:00","cost":{"kind":"free"},"state":"recruiting","canApply":true}],
  "events": [],
  "nextCursor": null
}
```

| 관계 | 이름·위치 | 가능한 행동 |
|---|---|---|
| 비로그인 | 시스템 별칭·시·군·구 공개 지역 | 목록 확인. 신청·프로필 상세·채팅·AI는 로그인 안내. |
| 일반 회원·최종 동의 대기 | 마스킹 이름·시·군·구 공개 지역 | 현재 공고 상태에 따라 신청 가능 여부 판단. 정확한 주소·상세 지점 제외. |
| 작성자 본인 | 자신의 입력 정보는 별도 관리 조회 | 검색 카드에 자신의 비공개 필드를 섞지 않음. |
| 양쪽 확정 당사자 | 서로의 전체 실명·정확한 주소·상세 지점은 별도 권한 조회 | 상대 선택만으로 권한을 얻지 않음. |
| 확정 공고의 제3자 | 비공개 정보 없이 확정·마감 상태 확인 | 새 신청 불가. 기본 목록에 상태와 함께 표시, 모집 중만 필터에서는 제외. 별도 상세 조회 경로는 민규 계약에서 정함. |

`posts`와 `events`는 카드 종류를 혼동하지 않는다. 행사 카드에는 출처·공식 링크·행사 입장료의 알려진 상태를 표시하고, 동행 비용은 공고 카드에만 표시한다. 공고 없는 행사는 신청 가능한 동행으로 표현하지 않는다. 기존 `exact_location`에는 주소·상세 안내가 섞여 있을 수 있으므로 자동 분해·공개하지 않고, 분리된 등록 정보가 없는 기존 공고는 시·군·구 공개 지역까지만 제공한다. 검색 일치 자체가 장소 추정 단서가 될 수 있고 작성자가 제목에 정확한 위치를 쓸 수도 있다. 작성 화면에서 제목에 정확한 주소·상세 만남 지점을 쓰지 않도록 안내하고, 발견하면 입력을 보존하고 수정 요청하며 수정 전에는 등록을 막는다(2026-09-23 사용자 확인). 자동 탐지의 누락·오탐은 후속 검증 대상이다. 이 절차만으로 모든 위치 노출을 막는다고 보장하지 않는다. 이름 마스킹 형식은 미정이며 위 응답의 이름은 자리표시자다.

## 3. 행사 모드·장소 입력

| 모드 | 포함·정렬 기준 |
|---|---|
| `overlapping` | 일반 목록 기본. 정규화된 region/category 값을 정확히 일치시켜 지역·종류를 좁힌다. 기간 미선택이면 과거·진행 중·예정 전체, 기간 선택 시 겹치는 행사. `ongoingOnly=false`가 기본이고 ON이면 조회 시점에 진행 중인 행사와 선택 기간의 교집합 |
| `new_this_week` | 이번 한국 주간에 시작하며 조회 시점에 미종료인 행사. 첫 수집 주간을 사용하지 않음 |
| `post_selection` | 진행 중·예정만 선택 가능. 기간 미선택이면 전체, 기간 선택 시 겹치는 행사. 작성 입력·일정을 자동 변경하지 않음 |

정렬: 진행 중(최근 시작순) → 예정(빠른 시작순) → 종료(최근 종료순), 동률 ID. 날짜만 있는 자료는 한국 달력 날짜이고 종료 날짜 포함, 시각이 있는 자료는 명시 offset이 필요하며 종료 시각부터 제외한다. 취소는 새 조회·선택에서 숨긴다. 과거 조회와 진행 중 필터가 함께 선택되어 0건이 되어도 조건을 자동 초기화하지 않는다. 원천 상태·날짜를 알 수 없으면 정상으로 추정하지 않고 정규화 오류를 구분한다.

날짜 전용 `selectDateOnlyEvents`는 호환용 계산 helper이며 실조회는 원천 상태를 검사하는 `selectEvents`를 사용한다. 실제 행사 공급사 변환·DB 페이지 연결 전에는 완전한 외부 행사 목록을 제공한다고 설명하지 않는다.

카카오 장소 후보는 `source/sourceId/placeName/address/roadAddress`로 제한한다. 전화번호·좌표·거리·제공사 부가정보는 반환하지 않는다. API 키·페이지 크기·제한 시간은 명시 설정이며 인증된 작성자만 사용한다. 키워드 API의 실제 호출은 아직 검증하지 않았다. [공식 규격](https://developers.kakao.com/docs/ko/local/dev-guide#search-by-keyword).

우편번호 공급사는 **Kakao 우편번호 서비스로 확정**했다(2026-09-23 사용자 답변). 실제 선택창 연결은 사용자 지시로 대기하며 현재 코드는 미설정 오류를 반환한다. 별도 키 없이 사용할 수 있는 주소 선택 서비스이며 장소 검색 API와 구분한다. [공식 안내](https://postcode.map.kakao.com/guide). 장소 후보의 전체 주소는 공고 작성용이며 공고가 등록된 뒤의 공개 주소가 아니다. 선택한 행사도 공고 일정을 자동 변경하지 않는다. 행사 입장료가 불명확하면 무료로 추정하지 않는다. 최초 과거 수집 범위는 **제공처의 지원 범위 확인 후 팀에서 결정**한다. 수집 주기는 팀 검토용 미정 운영 항목이다. Kakao 장소 검색과 KOPIS·서울 열린데이터광장·TourAPI의 이용 신청·키 준비 상태는 **미정·팀원 확인**으로 남겼다(2026-09-23 사용자 답변).

## 4. 정상·0건·오류

`results`는 카드와 불투명한 `nextCursor`를, `no_results`는 빈 카드와 선택했던 조건을 반환한다. 검색 오류는 `unavailable`로 구분하고 조건을 조용히 넓히지 않는다. 아래 코드는 **논리 오류 제안**이며 HTTP 상태·공통 오류 구조는 민규 계약에서 확정한다.

| 코드 제안 | 발생 조건 | 처리 |
|---|---|---|
| `INVALID_FILTER` / `INVALID_CURSOR` | 값·기간·커서 형식 불일치 | 유효한 조건으로 다시 입력. 원본 입력 보존. |
| `UNSUPPORTED_PROXIMITY` | 주변·반경·거리순 요청 | 미지원 안내와 장소명·주소 검색 제안. |
| `UNAUTHENTICATED` / `FORBIDDEN` | 작성용 장소/주소 또는 AI 접근 권한 없음 | 로그인·권한 안내. 검색 결과로 우회하지 않음. |
| `SOURCE_UNAVAILABLE` | 행사·장소 제공사 장애 | 재시도 가능 여부를 구분하고 공고 검색 결과를 행사 결과로 대체하지 않음. |

가상 입력·기대 결과는 [계약 사례](../../tests/fixtures/jonghyun/contract-cases.json)에 둔다. 확인 기준은 주소 일치 후 비노출, 관계별 카드, 레거시 위치 제외, 0건·오류 구분, 행사 세 모드와 기간 겹침이다. 현재 이 사례는 실제 DB·제공사 테스트가 아니다.

## 5. 현재 코드 연결과 한계

- 검색 `searchPublicPosts(repository,input)` / `listProjectedPublicPosts(rows,input)`: 검색 조건·정렬·공개 필드 투영. 입력 저장소는 `createdAt`·명시 비용 유형(free/paid_request/paid_offer)·서버가 계산한 표시 이름/지역/신청 자격을 제공해야 한다. 유료 요청은 작성자→신청자, 유료 제공은 신청자→작성자다.
- 행사 `selectEvents(events,query)` / `queryStoredEvents(repository,query)` / `syncEventPage(provider,repository,request)`: 날짜·상태·정렬·한 페이지 수집/저장 경계. 실제 DB의 제공처+원천 ID 유일 제약은 별도 검증 대상이다.
- 서버 인증·나이 필터·커서·HTTP·RLS·제공사별 행사 변환은 연결 전이다. 가상 저장소는 실제 권한 증거가 아니다.

행사 `query`는 **행사명·장소명·공개 주소** 중 한 필드에 연속 부분 일치하면 찾는다. 영문 대소문자·연속 공백 차이는 무시하고, 빈/공백 검색어는 다른 필터만 적용한다(2026-09-23 사용자 확정 검색 범위 및 기존 빈 검색 계약). 필드를 이어 붙여 일치시키거나 설명·비공개 만남 지점을 검색하지 않는다. 키워드는 지역·종류·기간·진행 중 필터와 교집합으로 적용하며 기존 정렬을 유지한다.
