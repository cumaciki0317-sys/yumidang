# 공개 검색·장소·행사 조회 연결 계약

## 현재 정책과 구현·연결 상태

현재 기준은 [정책.md](../../정책.md)다. 공고 검색 코어·RPC 어댑터는 아래 현재 계약을 구현한다. 민규 소유 HTTP·SQL·공통 RPC 허용 목록은 후속 연결이 필요하다. 실제 DB·외부 호출·배포 검증은 수행하지 않았다.

공고 검색은 제목·등록 장소명·등록 주소·연결 행사명, 작성자 만 나이 19~99 숫자 범위(전체는 상한 없음)다. 소개·후기·상세 지점은 제외한다. 등록일 최신순 기본/시작일 빠른순 선택, 모집 상태 전체 기본/모집 중 선택이다. 비로그인은 일정·나이 필터 모두 전체만 사용하며 작성자 박스는 개인정보 없는 모자이크 로그인 가드다.

공고·행사는 처음과 추가 조회 모두 10개씩, 후기는 5개씩이다. AI는 후보 10개씩 최대 3쪽·표시 최대 5개이며 별도 AI 호출 한도는 [AI 계약](ai-chat.md)을 따른다. 현재 무료만 신청할 수 있다. 과거 유료·비용 미확인 자료는 구분해 표시하되 신청 가능성을 만들지 않는다. 내부 limit 기술 범위는 1~50, 기본은 10이며 화면·AI 호출은 10을 사용한다.

일반 행사 기본은 이번 주 신규 중 미종료, 진행 중 포함은 이전 주부터 아직 진행 중인 행사도 포함한다. 과거 기간 조회를 유지한다. 한국 주간은 월요일00:00~다음월요일00:00 미만이다. 월별 주차는 목요일 귀속 달의 첫 목요일 포함 주부터 세며 월 경계에서 범위를 자르지 않는다. 이는 유미당 표시 규칙이다.

정렬은 진행 중(최근 시작)→예정(빠른 시작)→종료(최근 종료)이며 제공처 실제 지역·유형을 사용한다. 공연은 콘서트·뮤지컬·연극 필터다. 작성용 행사는 진행 중·예정이며 작성 일정과 겹쳐야 하고 행사 선택으로 일정을 자동 변경하지 않는다.

KOPIS Top10은 전국 전체 공연 기본/뮤지컬 선택, 어제까지 최근 7일·매일 갱신·출처/기간/갱신시각 표시다. 미수신 순위를 지어내지 않는다. KOPIS·TourAPI·서울 열린데이터는 실제 출시 연결 목표이며 공급사별 조건·실제 응답은 별도 검증이다. 최근 과거 1개월·미래 오늘부터31일과 오래 진행 중인 자료를 갱신한다. 한도 도달 시 위치를 보존하고 이어 수집한다.

코어는 숫자 나이·16개 카테고리·17개 시도·익명 일정 제한·작성자 null·기본 페이지10을 검증한다. 연결 행사명 검색은 가상 저장소의 순수 일치 규칙에도 반영했다. 실제 HTTP·SQL·AI·화면의 연결 상태는 별도 검증한다.

## 1. 현재 코어 입력과 HTTP 연결 요구

민규 HTTP 진입점은 `GET /functions/v1/service-api/posts`이며 동일 경로의 공고 생성 POST는 회원 인증을 유지한다. HTTP의 숫자 나이·region 변환은 민규 담당이며 아직 최신 필터 연결 완료가 아니다. 종현 내부 입력의 `caller`는 검증된 인증 문맥에서만 만든다.

| HTTP 입력 | 목표 HTTP 변환·현재 코어 계약 |
|---|---|
| query | 선택, 최대 300자. 빈 값은 목록, 영문 소문자·앞뒤/연속 공백 정규화 |
| category | 지금이당·전시·축제·팝업·공연·영화·맛집·카페·쇼핑·여행·운동·산책·게임·반려동물·스터디·기타; 전체 생략 |
| region | 17개 정식 시도명, 전체 생략. 프론트 서울/경기 등 짧은 표시 이름은 명시 매핑하며 부분 문자열 비교하지 않음 |
| cost / availability | all/free/paid, all/recruiting. 기본 all |
| periodStart / periodEnd | 둘 다 생략하거나 시간대 포함 ISO, 시작 포함·끝 제외. 내부 period.startsAt/endsAt로 변환 |
| authorAge / ageMin / ageMax | 전체는 생략 또는 authorAge=all. 숫자 범위는 ageMin·ageMax를 모두 받아 코어 `{min,max}`로 변환. 19~99 정수·양끝 포함·min≤max. 전체에는 99세 상한 미적용. 혼합·중복·단일 경계·구연령대 거절. DB 한국 날짜 기준 만 나이이며 생년월일 반환 금지 |
| sort | created_desc 기본(등록일 최신순), starts_asc 선택(시작일 빠른순) |
| cursor / limit | 이전 응답 커서. 기본 10, 내부 기술 한도 1~50. 제품 클라이언트는 첫/추가 조회 모두 10 |

인증 헤더가 없으면 익명, 있으면 반드시 검증한다. 만료·위조 토큰을 익명으로 바꾸지 않는다. 익명 기간 지정과 all 이외 숫자 나이는 코어가 저장소 호출 전에 AUTH_REQUIRED로 거절한다. DB에서도 JWT 역할로 재검사해야 한다. 익명의 all 이외 나이 조건은 코어 `AUTH_REQUIRED`, DB SQLSTATE `28000`이며 HTTP에서는 `401 AUTH_REQUIRED`로 연결한다. userId/caller 등 권한 주장·알 수 없는 필터·중복 인자·잘못된 커서는 `400 INVALID_REQUEST`다. 종현 코어의 입력 오류를 이 HTTP 오류로 연결하는 책임은 민규에게 있다.

키워드는 제목·등록 장소명·등록 주소·연결 행사명 각각의 연속 부분 문자열을 검색한다. 필드들을 이어 붙여 일치시키지 않는다. 소개·리뷰·상세 만남 지점·혼합 exact_location은 제외한다. 좌표·반경·거리순은 추가하지 않는다. 기간과 양의 겹침이 있는 공고를 포함한다.

정렬은 `created_desc`일 때 등록 시각 내림차순, `starts_asc`일 때 시작 시각 오름차순이며 둘 다 동률 ID 오름차순이다. 기간은 겹침 필터일 뿐이며 모집 여부·기간 안 시작 그룹을 사용자가 선택한 정렬보다 우선하지 않는다. 필터·권한·정렬·페이지는 DB에서 끝내며 서비스는 받은 페이지를 다시 정렬하거나 걸러내지 않는다.

## 2. 반환과 공개 경계

```ts
{ data: { status: "results" | "no_results", posts: PublicPostCard[], nextCursor: string | null }, requestId: string }
```

카드는 id/title/authorDisplayName/publicArea/startsAt/endsAt/cost/state/canApply만 포함한다. authorDisplayName은 `string|null`이다. 회원 목록은 이름 마스킹을 사용하고 익명 RPC는 반드시 null을 반환한다. 비회원 응답은 이름·별칭·사진 없이 작성자 로그인 가드를 표시한다. RPC가 익명에게 문자열이나 여분의 개인정보 필드를 보내면 INVALID_SEARCH_RESPONSE로 실패한다. 예: 변종→변*, 변종현→변*현. 익명 응답에 회원 마스킹을 함께 넣지 않는다.

비용은 free, paid_request(작성자→신청자), paid_offer(신청자→작성자), unknown이다. **unknown은 ‘비용 미확인’, 항상 신청 불가**, 금액·방향 없음이다. 확인된 과거 비용 NULL만 변환하고 잘못된 유형·금액은 오류로 드러낸다. 전체 목록에는 포함하되 무료·유료 필터에서는 제외한다. 현재 유료 유형도 canApply=false이며 신청은 확인된 무료·모집 중·회원·DB 가능 판정에 한한다.

공개 지역은 **동까지** 유지한다. 시도·시군구·선택 구·마지막 동/읍/면/가, 최대 60자를 검사하고 원문을 그대로 반환한다. 시군구가 없는 세종특별자치시는 시도·동/읍/면/가 형식도 허용하며 DB 공개 지역 제약과 맞춰야 한다. 숫자가 있는 종로1가도 허용한다. 앞뒤 공백·상세 주소를 수정해 정상 지역으로 만들지 않으며 정확한 주소를 임의 분해하지 않는다. 행정구역 실존을 확인하는 검사는 아니다. 정확한 주소·상세 지점·원본 실명은 카드와 AI 입력에서 제외한다. 본인 관리·양쪽 확정 당사자의 권한 조회는 민규의 별도 경로다. 제목 자체의 위치 노출은 작성 단계 수정 요청 정책을 유지하며 자동 탐지의 완전성을 주장하지 않는다.

DB 공개 상태 우선순위는 삭제 제외 → 현재 확정 약속 confirmed → 완료/취소/분쟁/불발 closed(마감) → 모집 기한 또는 시작 시각 경과 expired → recruiting이다. 상세 마감 사유는 카드에 넣지 않는다. DB는 현재 신청 규칙으로 canApply를 계산하고 실제 신청 때 재검사한다. 비회원·미확인 비용·모집 종료는 항상 false다.

## 3. 행사 모드·장소 입력

일반 목록의 제품 기본값은 **이번 주 새로 시작한 미종료 행사**, 선택은 **진행 중 포함**이다. 진행 중 포함은 선택 기간과 겹치는 장기 행사를 함께 보여주는 뜻이다. 아래 기존 API의 `ongoingOnly`는 조회 시점에 진행 중인 행사만 고르는 기술 조건이므로 화면의 포함 옵션과 동일하게 연결하지 않는다. 화면 기본값·기간·조회 모드의 실제 연결 검증은 후속 작업이다.

| 모드 | 포함·정렬 기준 |
|---|---|
| `overlapping` | 기간 겹침 조회용이며 일반 목록의 기본값이 아님. 정규화된 region/category 값을 정확히 일치시켜 지역·종류를 좁힌다. 기간 미선택이면 과거·진행 중·예정 전체, 기간 선택 시 겹치는 행사. `ongoingOnly=false`가 기본이고 ON이면 조회 시점에 진행 중인 행사와 선택 기간의 교집합 |
| `new_this_week` | 기존 API는 이번 한국 주간에 시작하며 조회 시점에 미종료인 행사만 반환. 첫 수집 주간을 사용하지 않음. 현재 기본의 의미와 일치하며 실제 화면·월별 주차·조회 연결은 별도 점검 |
| `post_selection` | 진행 중·예정만 선택 가능. 기간 미선택이면 전체, 기간 선택 시 겹치는 행사. 작성 입력·일정을 자동 변경하지 않음 |

정렬: 진행 중(최근 시작순) → 예정(빠른 시작순) → 종료(최근 종료순), 동률 ID. 날짜만 있는 자료는 한국 달력 날짜이고 종료 날짜 포함, 시각이 있는 자료는 명시 offset이 필요하며 종료 시각부터 제외한다. 취소는 새 조회·선택에서 숨긴다. 과거 조회와 진행 중 필터가 함께 선택되어 0건이 되어도 조건을 자동 초기화하지 않는다. 원천 상태·날짜를 알 수 없으면 정상으로 추정하지 않고 정규화 오류를 구분한다.

날짜 전용 `selectDateOnlyEvents`는 호환용 계산 helper이며 실조회는 원천 상태를 검사하는 `selectEvents`를 사용한다. 실제 행사 공급사 변환·DB 페이지 연결 전에는 완전한 외부 행사 목록을 제공한다고 설명하지 않는다.

카카오 장소 후보는 `source/sourceId/placeName/address/roadAddress`로 제한한다. 전화번호·좌표·거리·제공사 부가정보는 반환하지 않는다. API 키·페이지 크기·제한 시간은 명시 설정이며 인증된 작성자만 사용한다. 키워드 API의 실제 호출은 아직 검증하지 않았다. [공식 규격](https://developers.kakao.com/docs/ko/local/dev-guide#search-by-keyword).

우편번호는 Kakao 우편번호 서비스를 사용하며 장소 API와 구분한다. 작성용 주소 후보와 공개 동 지역 표시를 혼동하지 않는다. 실제 선택창 연결·Kakao 키/응답·공급사별 HTTPS·데이터 정규화는 별도 검증한다. 장소는 10개/쪽, 행사 요청은 31일·100건/쪽·최대5쪽·쪽당15초이며 매일00:01 등록한다. 수집 HTTP `POST /functions/v1/event-sync {provider,period:{start,end},page}`, 장소 `GET /functions/v1/places?query&page`의 기존 인터페이스와 내부/회원 권한을 유지한다. 행사 저장은 [행사 DB](event-storage.md)를 따른다.

## 4. RPC·커서와 오류

`createRpcPublicPostSearchRepository(db)`는 공통 `RpcClient`를 주입받아 다음 계약만 호출한다. 클라이언트는 서버가 검증한 회원 JWT 또는 익명 권한으로 구성하며 caller/userId를 SQL 권한 인자로 넘기지 않는다.

```ts
search_public_posts_v2({
  p_contract_version: "2026-10-05",
  p_region: PostRegion | null,
  p_filters: { query, category: string | null, cost, availability,
    periodStart: string | null, periodEnd: string | null, authorAge, sort },
  p_cursor: { sortAt: string, id: string } | null,
  p_limit: number
})
// DB 반환: { items: PublicPostCard[], nextCursor: position | null }
```

DB wire 비용의 예외는 확인된 과거 비용 `cost:null`이다. 어댑터가 이를 `{kind:"unknown"}`으로 바꾼다. DB에서 unknown 객체·누락 필드·잘못된 비용을 보내면 거절한다. 카드 UUID·필드 목록·지역·시각·비용·중복 ID·페이지 크기·마지막 커서 일치를 검사한다. 원본 주소나 추가 필드가 섞인 응답은 빈 결과로 숨기지 않는다.

외부 커서는 `{v:3,filters:{caller,region,query,category,cost,availability,period,authorAge,sort},position:{sortAt,id}}` JSON의 UTF-8 base64url(패딩 없음, 최대4096자)이다. 정규화한 전체 필터·정렬의 구조적 일치를 검사한다. 구형 v1/v2·다른 호출자/지역/숫자나이/필터/정렬·4필드 구형 위치는 `INVALID_CURSOR`로 거절한다. limit는 페이지 크기이므로 지문에 포함하지 않는다. 화면은 조건 변경 시 커서를 버리고 첫 페이지를 요청하며 서버가 잘못된 커서를 첫 페이지 성공으로 바꾸지 않는다. sortAt는 created_desc에서 등록 시각, starts_asc에서 시작 시각이며 PostgreSQL 마이크로초 문자열을 그대로 보존한다. 다음 커서 ID는 마지막 카드 ID와 같아야 한다. starts_asc만 마지막 startsAt과 시각을 비교하고 created_desc는 카드에 없는 등록 시각을 startsAt으로 대신 검사하지 않는다. 입력 커서가 있으면 bigint 마이크로초·소문자 UUID로 정렬 방향에 따른 엄격한 진행을 검사한다. 같은 시각에는 ID가 커져야 하며 동일 순간의 다른 offset 표현도 동률이다. 커서는 인증 수단이나 데이터 snapshot이 아니며 DB는 매번 권한과 필터를 재검사한다. 정적 데이터의 페이지 검증과 조회 중 데이터 변경 고정은 구분한다.

repository `wireCard`는 DB 카드의 날짜·공개 지역·상태 투영 검증 실패를 `INVALID_SEARCH_RESPONSE`로 바꿔 던진다. 따라서 잘못된 DB 카드 날짜는 원문 없는 `500 INTERNAL_ERROR`이고, 잘못된 사용자 기간·커서는 DB 호출 전 `400 INVALID_REQUEST`를 유지한다. 입력 정규화·커서 해석·`db.rpc`의 공통 HttpError(401/403/503)는 넓은 catch로 감싸지 않는다. 회귀: `tests/functions/jonghyun/search-response-errors.test.mjs`(가상 RpcClient + 민규 service-api handler, 실제 DB/Edge 아님). [재현 요청](../../docs/collaboration/requests/minkyu/2026-09-29-search-connect-review.md)

정상 빈 페이지는 no_results/posts:[]/nextCursor:null이다. RPC/응답 검증 실패를 0건 또는 구형 RPC/가상 데이터로 대체하지 않는다. HTTP에서는 입력·커서 오류를 INVALID_REQUEST, 인증 필요를 AUTH_REQUIRED, 내부/RPC 실패를 안전한 공통 오류로 매핑하며 원문을 노출하지 않는다. 행사·장소 장애와 공고 검색 결과는 구분한다.


### 민규 연결 필수 조건

- 동일 v2 이름에 필수 `p_contract_version text`·`p_region text`를 받는 새 시그니처를 제공하고 버전은 정확히 `2026-10-05`만 수락한다. 어댑터는 새 인수를 항상 보내므로 구 SQL은 성공으로 사용되지 않는다. 구 시그니처·구 검색 RPC의 공개 grant/호출 경로를 정리해 우회를 막는다.
- DB에서 최신 16분류·시도·숫자나이·익명 기간/나이 제한을 검증한다. 등록 주소/행사명은 일치 판단 전용이고 공개 카드에는 싣지 않는다. 시도는 구조화된 지역 값으로 비교한다.
- 삭제 공고·탈퇴/비활성 작성자·회원 사이 양방향 차단을 **페이지 절단 전** 제외한다. 익명에게 실제 작성자 식별값·별칭·사진을 투영하지 않고 `authorDisplayName:null`로 반환한다.
- HTTP는 위 ageMin/ageMax·region 변환과 동일 분류를 사용하며 기존 authorAge enum 파서를 교체한다. 공통 RPC 허용 목록과 메서드 계약을 새 시그니처에 연결한다. 인증 헤더 검증 실패를 익명으로 낮추지 않는다.
- 구 SQL/새 SQL의 부재·DB 권한 오류를 0건·구 RPC 재호출로 감추지 않는다. 현재 어댑터는 RPC 오류를 보존한다. 미설치/버전 불일치는 민규 공통 전송 계층에서 원문 없는 서비스 미준비 오류로 처리해야 한다.
- 합성 RpcClient/HTTP 회귀는 운영 연결 성공 근거가 아니다. 마이그레이션 적용 후 익명·서로 차단한 두 회원·탈퇴 작성자·19/99/100세·시도 교집합·10개 페이지를 실제 DB에서 검증한다.

## 구현·연결 확인

`searchPublicPosts`는 DB 페이지의 순서를 유지하고 카드를 검증한다. 입력 오류·인증 오류·DB 응답 오류를 구분하고 실패를 빈 결과나 가상 데이터로 대체하지 않는다. 숫자 필터·카테고리·익명 제한·작성자 가드·페이지 크기의 HTTP/코어/AI/DB 통합을 검증해야 한다. 전체행 가상 저장소는 내부 authorAge·region을 가진 합성 근거로 숫자 나이·지역 일치를 검증하며 커서는 명시 미지원이다. 실제 DB 권한·생년월일 계산 검증을 대신하지 않는다.

`search_public_posts`·`list_posts`·직접 table 등 기존 호출 경로가 최신 검색 범위·권한을 우회하지 않는지 점검한다. 행사 selectEvents/queryStoredEvents/syncEventPage와 공개 DB repository를 재사용하며 중복 검색 구현을 만들지 않는다.

행사 query는 행사명·장소명·공개 주소 중 한 필드의 연속 부분 일치다. 대소문자·연속 공백을 정규화하고 빈 검색은 나머지 필터만 적용한다. 설명·비공개 만남 지점은 검색하지 않는다. 키워드는 지역·유형·기간·진행 필터와 교집합이며 정렬을 유지한다.
