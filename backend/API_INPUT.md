# 수집한 API 입력 안내

## 2026-10-20 현행 기준과 이 문서의 적용 범위

이 문서는 현재 요구와 구현 계약을 구분한다. 아래 기술 시그니처·기존 SQL·검증 기록은 실제 구현 근거이며 새 정책 요구가 자동 구현됐다는 뜻이 아니다.

- 담당은 현재 민규=BE·AI·검색·행사·서버 운영, 종현=FE·UX/UI·앱 API/세션 소비·빌드, 유미=UT·출시/지원 책임이다. 아래 옛 종현 BE·성호 UI 배정은 당시 기록이며 현재 실행 권한으로 사용하지 않는다. 구체 파일은 현행 소유권 정책을 따른다.

- 포텐스닷 문의 회신은 사용자가 공유했다. 공급사는 교육·프로토타입 범위, 일일/기간 제한·기능 축소·보안 우려로 공개 서비스에는 다른 API를 권고했다. 보관·학습·삭제·공동 사용의 구체 조건은 여전히 미확인이다. 포텐스닷 제품 활성화를 기다리는 계획으로 읽지 않는다. Gemini는 종현 테스트 전용 프로젝트에 결제 연결·월50,000원 사용중단 예산을 준비했으나 최종 청구가 지연 없이 반드시 5만원 이하라는 보장은 아니다. 합성 테스트와 대표 유미 계정 전환·제품 adapter·실회원 전송은 별도다. 대표 계정 전환은 회의/브랜치 통합 때 진행한다. Potens 기술 토큰 원장과 Gemini 원화 지출 원장은 분리한다.

- AI 탐색 동의는 첫 사용 시 받고 거절하면 일반 검색을 유지한다. 후기 요약은 가입 시 열람·내 프로필 생성/노출·작성 후기 활용을 기본 미선택인 별도 선택 세 항목으로 받는다. 전체 동의와 개별 자세히 보기를 유지하고 미동의 가입/일반 동행을 허용한다. 세 동의의 철회는 독립적이다. 현재 서버의 summary_allowed 하나·review_summary 일괄 철회가 이 세분화 요구를 구현했다고 해석하지 않는다. 테스트 계정 동의 간주는 실제 동의 증거·DB 값 변경·회원 원문 전송 승인이 아니다.

- KOPIS는 전체 공연·연극·뮤지컬·클래식·국악·대중음악·무용·대중무용·서커스/마술·복합·아동·대학로·내한·축제 14항목, 어제까지 최근7일·매일 갱신이다. basedate 누락만으로 영구 공개 보류하지 않고 공식 사이트의 실제 기간·조건·공연ID/순위/순서를 대조한 분류만 공개하는 A안을 적용한다. 요청 날짜로 기간을 확정하거나 일일순위를 합산하지 않는다. 확인 기간·시각·출처를 표시하고 실패 때 마지막 검증 기간을 유지한다. 아래 all/musical·basedate 필수 parser·not_enabled는 현재 구현/당시 검증의 기술적 한계이며 최신 제품 정책이 아니다. 일반 공연 수집·칼럼 매핑은 순위 대조와 병행한다.

- 직접 입력 행사는 해당 공고에만 저장/표시하며 공용 목록·별도 행사 상세·검수 후 공용화는 만들지 않는다. 행사명 필수, 공개 행사장 장소/주소 선택이며 개인 주소를 금지한다. 새 연결은 예정/진행 중만 허용하고 종료·공식취소·연기일정미정은 제한한다. 단순 검색 누락은 취소/비표출이 아니다. 제공기관 비표출 원천의 정보와 상세 진입만 숨기고 공고/독립 만남 장소·다른 유효 공개 원천은 유지한다. 공식 동일 개최 식별근거만 통합에 사용하고 원천ID·공고관계·필드출처·가역 이력을 보존한다. 현재 eventId UUID 저장을 직접 입력·통합·비표출 구현 완료로 표시하지 않는다.

- 서울은 키/응답의 평문 HTTP 수집을 활성화하지 않는다. 검토된 HTTPS 자동 수집 경로·실제 최신 응답 envelope·페이지 재개·진행 중 갱신 확인까지 보류한다. 홈페이지 HTTPS 성공이나 HTTP 앞에 s를 붙인 주소는 API 전송 보안 검증이 아니다. 이 보류는 다른 공급사·공통 칼럼/화면 준비의 중단을 뜻하지 않는다.

최신 기준: [정책.md](../정책.md). 구현과 남은 조건: [서버·DB 대조 원장](../docs/collaboration/requests/jonghyun/2026-10-20-policy-implementation-audit/server-audit.json).


## 2026-10-20 행사 UX 확정과 서버 구현 경계

기준은 [최종 행사 UX 확정](../docs/collaboration/requests/jonghyun/2026-10-20-event-ux-approved-spec.md)이다. 사용자 명시 전체 문서 동기화 승인으로 반영하며 제품 설계 확정과 실제 코드·DB·배포 완료를 구분한다.

행사 검색은 서버가 실제 조회 가능한 전체 기간에서 하며 동행 일정으로 자동 축소하지 않는다. 행사 기간과 동행 일정의 겹침을 강제하지 않는다. TourAPI는 실제 수신된 관광타입15 전체(축제6·공연10·행사4)를 대상으로 하되 시설타입14로 확대하지 않는다.

키 입력·이전 호출 성공은 최신 행사 UX 지원의 증거가 아니다. 취소/연기/표출 플래그의 의미·원천별 공개 조건·이미지 이용조건·공식 동일 개최 식별근거를 민규가 확인해 연결해야 한다. 등록 때 외부 API를 매번 직접 호출하지 않고 우리 서버의 최신 연결 가능 상태를 확인하는 목표다. 직접 입력·동일 행사 통합·새 알림/변경계약은 이 설정 파일로 활성화되지 않는다.


## 현재 사용 범위

카카오 키는 장소 검색용이며 카카오 로그인을 켜는 근거가 아니다. 로그인은 네이버만, 현재 동행은 무료만이다. KOPIS·TourAPI·서울 열린데이터는 출시 시 실제 연동 목표이며 HTTPS·키·지원범위·응답·요금의 실제 확인 전 성공으로 표시하지 않는다. 포텐스닷 실제 회원 정보 전송은 보관 조건 답변을 팀이 검토하고 사용자가 확인하기 전까지 보류하며 합성 입력만 사용한다.

**현재 개발자가 사용하는 저장소 최상위 `.env`가 로컬 입력 파일이다.** 다른 작업자의 절대 경로나 worktree 내부 `backend/.env` 사본을 최신 입력으로 단정하지 않는다. `KEY=""`의 따옴표 안에 발급받은 값을 넣고 저장한다. 기존 공용 양식인 루트 `.env.example`과 프런트 설정은 변경하지 않는다.

사용자가 수집했다고 확인한 항목은 **Kakao 장소검색·KOPIS 공연·서울 열린데이터광장·TourAPI·포텐스닷 API**다. 먼저 아래 다섯 서비스의 입력란을 채운다. 네이버 로그인 연결은 별도 인증 설정 계약으로 확인한다. 계좌·기관이메일 인증은 현재 제외하며 기존 양식의 제외 기능 필드를 발급 대상으로 삼지 않는다.

기존 포텐스닷 프로토타입 설정은 **LLM 전용**, 요청 모델은 **Sonnet 5**다. 공개 서비스의 현재 공급사 승인이나 Gemini 제품 설정으로 재사용하지 않는다. `POTENS_REQUESTED_MODEL`은 사람이 선택한 이름이며 실제 호출 ID인 `POTENS_MODEL`과 다르다. 공급사 문서로 정확한 ID와 호출 주소를 확인하기 전에는 임의 ID로 호출하거나 다른 모델로 대체하지 않는다.

| 수집한 항목 | 입력란 | 연결 담당 |
|---|---|---|
| 카카오 장소 검색 | `KAKAO_REST_API_KEY` | 민규 |
| KOPIS 공연 정보 | `KOPIS_API_KEY` | 민규 |
| 서울 열린데이터 | `SEOUL_OPEN_DATA_API_KEY` | 민규 |
| TourAPI | `TOUR_API_SERVICE_KEY`, `TOUR_API_KEY_FORMAT` | 민규 |
| 포텐스닷 API | `POTENS_API_KEY`, `POTENS_API_BASE_URL`, `POTENS_MODEL`, `POTENS_API_DOCS_URL` | 민규 |
| AI 공급사·모델·키 | `AI_PROVIDER`, `AI_MODEL`, `AI_API_KEY` 또는 `GEMINI_API_KEY` | 민규 |
| 네이버 로그인 | 실제 서버 설정명·세션 연결은 인증 담당 계약 확인 | 민규 |
| 그 밖의 API | `OTHER_API_1_…`의 이름·용도·주소·문서·키 | 해당 기능 담당 |

기존 포텐스닷 어댑터는 https://ai.potens.ai 의 POST /api/chat과 Bearer 서버 키·{prompt,model}을 사용한다. 선택 모델 ID는 claude-5-sonnet이며 다른 프록시 모델 ID로 바꾸지 않는다. 현재 계정 지원·사용량 단위·입출력 상한의 전달/강제·비용은 별도 확인한다. 실제 키나 키 포함 URL을 공유하지 않는다.

발급받지 않은 항목은 빈칸으로 둔다. 공급사마다 필요한 인증 필드가 다르므로 모든 칸을 채울 필요는 없다. TourAPI 키는 받은 원문을 그대로 넣는다. 사용자가 형식을 확인할 수 없다고 알려왔으므로 `TOUR_API_KEY_FORMAT`은 비워 두거나 `unknown`으로 둔다. 추측으로 인코딩/디코딩하거나 두 형태를 자동 재시도하지 않는다. 추가 API는 `OTHER_API_2_…`처럼 번호를 늘려 기록할 수 있다. 문서 URL에는 키가 붙은 요청 예시 URL을 넣지 않는다.

## 저장과 공유

- `.env`은 기존 `.gitignore` 규칙으로 Git에서 제외되고 최초 파일 권한은 소유자 읽기/쓰기(0600)다. 키를 채팅·공유 문서·`.env.example`에 복사하지 않는다.
- 공유하는 [빈 양식](.env.example)에는 실제 키를 넣지 않는다. 민규는 자기 작업 폴더에서 이 양식을 저장소 최상위 `.env`로 복사하여 사용한다. 기존 로컬 파일이 있으면 덮어쓰지 않는다.
- 서버 키를 `VITE_` 변수나 프런트 코드에 넣지 않는다. 이 파일은 키 입력·인계 장소이며 프런트에서 읽지 않는다.

## 입력 이후

설정 모듈은 `supabase/functions/_shared/config/providers.ts`다. `EnvReader`를 주입받아 기능별로 읽으며, 파일을 자동으로 탐색하거나 import 시 네트워크를 호출하지 않는다. 민규가 각 함수의 런타임에서 `Deno.env.get` 등 서버 환경 조회를 연결해야 실제 기능이 실행된다. 공통 service-api가 모든 외부 키를 필수로 요구하도록 바꾸지 않는다.

현재 작업 폴더의 입력 파일을 다음 오프라인 명령으로 점검한다. 키·URL·모델값을 출력하지 않고 입력 상태만 표시한다.

```sh
python3 -B tools/local/check_api_env.py --env-file .env
```

이 검사에 통과해도 키 유효성·공급사 API 성공을 뜻하지 않는다. 함수에 환경을 주입하는 작업, 공급사 어댑터 연결과 실제 호출 검증은 별도다. [이번 설정 연결 인계](../docs/collaboration/requests/minkyu/2026-09-29-provider-config-handoff.md)에 담당별 API·필드·검사 결과를 기록한다.

기존 서비스 API의 Supabase·내부 작업 설정은 [인증 런타임 계약](contracts/auth-runtime.md)을 따른다. 이 수집 파일을 그대로 운영 secret에 일괄 등록하지 않는다. 외부 키가 든 `.env`를 프런트에서 읽거나 공개 API로 내려주지 않는다.

포텐스닷의 채팅용 ID와 다른 공급사·코드 프록시 ID를 혼용하지 않는다.

## AI 사용량·보관 확인

기존 포텐스닷 프로토타입의 기술 토큰 예산은 등록 계정별 한국시간 하루 320만 토큰 상한, 전체는 등록 계정별 상한의 합계로 관리하는 초기 정책이다. 전송 전 예약을 포함해 계정별·전체 상한을 함께 검사하고 계정 예산이 부족하면 다음 등록 계정을 선택한다. 공급사 전송 후 오류·응답 유실을 소진으로 간주해 자동 전환하지 않는다. 전체 예산 소진 시 개인 한도가 남아도 중단하며 추가 결제는 허용하지 않는다. 같은 멤버십의 실제 포함량·계산 단위·초기화 주기와 공급사 공동 사용 조건은 별도 확인하고 설정·원장·런타임 적용을 검증한다. 320만 토큰은 공급사 화면 80%를 보장하는 값이 아니다. 합성 검증 50,000은 기술 원장 단위로 원화·청구 토큰과 같지 않으며 합성 10회의 충분한 예산을 보장하지 않는다.

회원별 초기 한도는 한국시간 하루 20회·자정 초기화이며 분당 횟수 제한은 없다. 동일 회원은 한 번에 요청 하나만 처리하고 응답 뒤 즉시 다음 요청이 가능하다. 모델 없는 조건 버튼·일반 더보기·창 열기·새 대화·호출 전 차단은 차감하지 않는다. 자연어 해석·성향 비교·설명을 위해 모델 처리를 시작한 새 요청은 1회다. 내부 여러 호출과 같은 요청의 자동 재시도는 추가 차감하지 않으며 처리 시작 후 실패도 1회, 사용자가 새로 재시도한 요청은 새 1회다. 공급사 일일 한도·입출력 토큰 비용·요청당 호출 수를 실제 연결 후 확인해 회원 한도와 전체 예산을 재설정한다.

포텐스닷 회신은 공유됐고 공개 서비스에는 다른 API를 권고했다. 구체 보관·로그·캐시·백업·학습·삭제·공동 사용 조건은 여전히 미확인이다. 공개 서비스에 연결할 API의 조건과 회원 전송을 확인하기 전 실회원 원문은 전송하지 않는다. 초기 합성 검증과 실제 계정 운영을 구분한다. 문서·이전 호출 결과는 현재 계정 한도·단가의 증거가 아니다.

## 동의와 담당 연결

AI 탐색은 첫 사용 동의·거절 시 일반 검색 유지다. 후기 요약은 가입 시 열람·내 프로필 생성/노출·작성 후기 활용의 별도 선택 세 동의와 전체 동의, 작성 때 짧은 재안내를 적용하는 제품 의도이며 철회는 각각 독립적으로 처리한다. 원문 활용 철회 시 해당 후기를 근거에서 제외하고 영향 요약을 숨긴 뒤 남은 허용 공개 텍스트 3개 이상과 대상자 생성/노출 동의 등 현재 조건을 충족할 때만 재생성·공개한다. AI용 사본·외부 사본의 필요한 삭제는 실제 확인 전 완료로 표시하지 않는다. 일반 후기·별점·당도·계정·일반 동행은 AI 철회만으로 바꾸지 않는다. 기존 테스트 계정의 동의 완료 간주는 테스트에만 적용한다. 세 항목은 기본 미선택이며 AI 미동의로 가입을 거부하거나 일반 동행·계정을 차단하지 않고 해당 AI 기능만 제한한다.

일반 운영·허용 증거 접근·AI 비용 책임자는 대표 유미(조유미), 기술 서버 운영·공급사 연결은 민규다. 이 역할 배정과 입력 문서 갱신은 서버 권한 설정·동의 저장·운영 활성화 완료를 뜻하지 않으며 회원 채팅 DB 원문 열람 권한을 추가하지 않는다. 최신 선택 동의의 법적 분류·문구 적합성과 공급사·실회원 전송 확인 전 보류는 유지한다.
