# 유미당 USERFLOW — 현재 사용자 흐름

기준일:2026-10-19. [정책](../../../정책.md)·[IA](IA.md)·[PRD](../requirements/PRD.md)를 따른다. S08 없이 S02에서 S11로 진입한다. 본 문서는 현재 요구사항이며 HTML·실제 서버 적용 확인은 별도다. 제품 검증 상태는 NOT_RUN이다.

## 1. 핵심 사용자 흐름

```text
탐색 S00/S01/S09/S09-2
→ 공고 상세 S02
→ 신청 버튼 → 신청자 채팅 화면 S11
→ 첫 메시지 전송 성공 → 신청 성립·작성자 채팅방 생성·채팅 도착
→ 서로 대화·합의
→ 작성자의 확정 요청
→ 신청자의 최종 수락
→ 약속 확정 S16
→ 완료 확인
→ 상호 평가 S17
→ 공개 프로필 S14 반영
```

공고 작성 흐름은 `S03 → S04 → 생성된 S02`, 행사 기반 모집은 `S09-2/S09-3 → S03`, 취소·철회는 `S11/S16 → S18`이다.

## 2. 로그인·가입·복귀

```text
로그인이 필요한 행동
→ S05 네이버 로그인
├─ 로그인 취소/연동 실패 → 오류 안내 → 재시도 또는 이전 화면
├─ 필수 정보 누락/확인 불가 → 가입 보류·네이버 정보 확인 안내 → 재시도
├─ 여성·만 19세 이상 불충족 → 가입 불가 안내
├─ 기존 회원 → 최신 정보 확인 → 원래 목적 화면 또는 홈
└─ 신규 회원 → S06
   → 프로필 사진 필수 등록
   → 관심사·대화 방식·MBTI 선택 입력
   → 후기 AI 세 항목 선택 동의·전체 동의 편의 기능(기본 미선택, 미동의여도 가입 가능)
   → 가입 완료
   ├─ 사진 없음 → 완료 보류·사진 등록 안내
   └─ 성공 → 완료 팝업 → S00 홈
```

네이버 이름·성별·생일·출생연도4종으로 자격을 확인하고 네이버 계정당 유미당 계정1개를 연결한다. 로그인 전 목적 화면은 기존 회원에게만 즉시 복귀한다. 신규 회원은 가입 완료 뒤 홈으로 이동한다. 사진을 선택한 것만으로 가입 완료가 되지 않으며 `가입 완료`를 눌러야 한다. 사진은 JPG·JPEG·PNG·원본10MB 이하이며 형식/용량 오류를 안내한다. 관심사·대화 방식은 기본 선택과 직접 입력으로 각각20개·항목당40자, MBTI는 E/I·S/N·T/F·J/P 네 쌍 선택이며 비워둘 수 있다.

## 3. 홈·둘러보기·카테고리 탐색

### 3-1. 홈 S00

```text
S00 홈
├─ 비로그인: 로그인 / 신규 행사 / 카테고리 / AI·작성 로그인 유도
└─ 회원: 본인 실명 / 알림
   ├─ 신규 행사 배너 → S09-3
   ├─ 전체보기 → S09-2
   ├─ 다가오는 약속 → S16
   ├─ 나의 동행 → S13
   ├─ 카테고리 → S09
   ├─ AI → S20
   └─ + 공고 작성 → S03
```

- 확정 약속이 없으면 빈 상태를 보여준다.
- 행사 조회 실패는 다시 시도와 함께 표시하며 빈 행사로 처리하지 않는다.

### 3-2. 둘러보기 S01

```text
S01 목록
→ 검색어 입력 또는 필터 열기
→ 카테고리·지역·일정·작성자 나이 선택
→ 적용하기
→ 등록일 최신순 또는 시작일 빠른순
→ 전체 상태 또는 모집 중만 보기
├─ 결과 있음 → 카드 본문 S02 / 작성자 S14
├─ 0건 → 조건 변경·초기화
└─ 조회 실패 → 재시도
```

- 필터는 적용 전까지 결과를 바꾸지 않는다.
- 비로그인은 일정·나이 상세 조건 대신 전체 범위만 사용한다. 공고 작성자 나이는 만19~99세 숫자 범위이며 전체 검색에는 이 상한을 적용하지 않는다.
- 검색 대상은 제목·등록 장소명·등록 주소·연결 행사명이다.
- AI는 S20, `+`는 S03으로 이동한다.

### 3-3. 카테고리 S09

```text
S00 카테고리 선택 → S09
├─ 공고 카드 → S02
├─ 작성자 → S14
└─ 선택 카테고리로 모집 → S03
```

목록 0건과 조회 실패를 구분하며 모집 중만 보기의 기본값은 꺼짐이다.

## 4. 공고 작성·등록

```text
S03 작성
→ 카테고리·제목·소개
→ 장소 선택
   ├─ 장소명 검색(Kakao Local)
   └─ 주소 검색(우편번호)
→ 공개 지역·상세 만남 지점
→ 시작·종료 일시
→ 선택 모집 마감
→ 선택 행사 연결 S09-2 또는 직접 입력(일반 작성은 맨 아래)
→ 다음
├─ 필수값/시간 오류 → 인라인 안내·수정
├─ 개인정보 감지 → 차단·수정/오탐 문의
└─ S04 확인
   → 희망 상대 나이·바라는 점·무료 원칙·마감 확인
   → 공고 등록
   ├─ 등록 실패 → 입력 유지·재시도
   └─ 성공 → 생성된 S02 상세
```

### 작성 중 이탈

```text
S03 뒤로가기
→ 이탈 확인
├─ 계속 작성 → S03 유지
└─ 나가기 → 같은 기기 임시저장
   → 재진입 시 복구 안내
   ├─ 복구 → 입력 복원
   └─ 폐기 → 새 작성
```

등록 성공이나 로그아웃 시 임시저장을 삭제한다. 행사 선택은 작성 일정을 자동 변경하지 않는다. 모집 마감 미설정 시 동행 시작이 마감이며 확정 뒤 공고 삭제로 약속 취소를 대신할 수 없다.

## 5. 공고 상세의 역할 분기

```text
S02 공고 상세
├─ 비로그인
│  ├─ 열람 → 공개 정보만
│  └─ 신청 → S05 로그인
├─ 로그인·미신청
│  ├─ 작성자 프로필 → S14
│  └─ 신청 → S11 첫 채팅 전송 전 화면
├─ 이미 신청/대화 중 → 기존 S11
├─ 작성자
│  ├─ 수정 → S03
│  ├─ 수동 마감
│  ├─ 삭제 확인
│  └─ 신청자 대화·선택 → S11 확정 요청
├─ 최종 동의 대기 → S11 수락/거절
├─ 확정 당사자 → 실명·상세 위치·S16
├─ 확정 공고 제3자 → 비공개 정보 제외
└─ 마감/삭제/조건 불일치 → 새 신청 불가 안내
```

수동 마감 후에도 기존 신청자와 대화하고 시작 전 최종 동의를 요청할 수 있다. 핵심 조건 변경 시 기존 요청은 무효화하고 새 조건으로 다시 동의받는다.

## 6. 신청 버튼→첫 채팅 S11

```text
S02 신청하기
├─ 과거 작성자 거절 → 같은 공고 재신청 불가
├─ 본인 철회 후 1분 미경과 → 재신청 불가·남은 시간 안내
└─ S11 신청자 채팅 화면
   → 공고 조건 확인·메시지 작성
   ├─ 첫 전송 없이 이탈 → 미신청·작성자 알림 없음·작성자 채팅방 없음
   ├─ 전송 실패 → 미신청·작성자 알림 없음·재전송
   └─ 첫 전송 성공
      → 신청 성립
      → 작성자 측 1:1 채팅방 생성과 채팅 도착
      → 대화·합의
```

별도 신청 메시지 화면 S08을 제거한다. 본인 철회 후 1분 경과 시 횟수 제한 없이 재신청하며 거절 후에는 불가하다. 재신청은 동일 공고·상대 채팅방과 이력을 재사용하며 새 메시지 전송 성공 시 성립한다. 기존 일정 겹침 경고는 유지하되 별도 신청 화면에서 처리하지 않고 경고 후 신청 진행을 허용한다. 새 확정은 일정 충돌 시 차단한다.

## 7. 채팅·최종 동의·확정 S11

### 7-1. 확정 전

```text
첫 채팅 전송 성공·신청 성립 → S11 대화
├─ 신청자: 메시지 대화·공고/프로필 확인·신청 철회 S18
└─ 작성자: 메시지 대화
   ├─ 신청 거절 → 대화 종료
   └─ 채팅·합의 후 확정 요청(한 번에 1명)
      ├─ 신청자 거절/요청 철회/만료 → 미확정·신청/대화 유지
      └─ 신청자 수락
         → 최신 조건·권한·정원·일정 충돌 재확인
         ├─ 충돌/상태 변경 → 확정 차단·안내
         └─ 통과 → 확정·실명·상세 만남 지점 공개·S16 약속 생성
            → 다른 신청은 모집 종료·채팅 읽기 전용
```

확정 요청은 `요청 후 6시간`과 `동행 시작 시각` 중 빠른 때 만료된다. 만료 시 약속을 생성하지 않고 신청·대화를 유지한다. 요청 상대를 바꾸려면 기존 요청을 철회한다. 다른 신청의 모집 종료는 거절과 구분한다. 만료와 같은 서버 접수 시각의 수락은 거부하며 확정 취소 자체로 모집을 자동 재개하지 않는다.

```text
확정 상대의 취소 → 기존 다른 신청은 모집 종료 상태 유지
→ 작성자가 모집 재개
→ 이전 유효 신청·채팅 자동 복원·상대방 알림
→ 다시 대화·확정 요청(현재 공고 조건·권한·일정 충돌 재확인)
```

거절·본인 철회된 신청은 자동 복원하지 않는다. 제재 중인 사용자는 복원 후에도 새 확정 요청·수락이 제한된다.

### 7-2. 조건 변경

```text
확정 전 공고 핵심 조건 변경
→ 신청자에게 변경 알림
→ 기존 최종 동의 요청 무효화
→ 새 조건으로 작성자 재요청 → 신청자 수락
```

### 7-3. 확정 후 일정·장소 변경

```text
S11 확정 상태 → 양쪽 누구나 일정·장소 변경 제안
→ 새 일정·장소 입력 → 제안 발송
├─ 거절/철회/만료 → 기존 약속 유지
└─ 상대 수락 → 일정 충돌 확인
   ├─ 충돌 → 변경 차단·기존 약속 유지
   └─ 통과 → 변경 반영·양쪽 알림
```

변경 제안은 `제안 후 6시간`, `기존 시작 시각`, `새 시작 시각` 중 가장 빠른 때 만료된다. 미응답이면 기존 약속을 유지한다. 만료와 같은 서버 접수 시각의 변경 수락도 거부한다.

### 7-4. 채팅 예외

- 전송 실패: 실패 메시지 표시→재전송
- 신고: 더보기→신고 안내→문제 구간 캡처 접수
- 종료 대화: 읽기만 가능, 새 메시지 차단
- 대화방 나가기: 본인 목록에서만 숨김, 상대 기록 보존

## 8. 행사 탐색·연결

### 8-1. 일반 행사

```text
S00 전체보기 또는 행사 메뉴 → S09-2
→ 이번 주 신규 중 미종료 행사
→ 선택: 진행 중 포함 / 지역 / 기간 / 유형 / 공연 장르
├─ 결과 없음 → 조건 변경
├─ 조회 실패 → 재시도
└─ 행사 선택 → S09-3
   ├─ 관련 공고 → S02
   ├─ 진행 중·예정 행사로 모집 → S03
   └─ 종료 행사 → 새 모집 차단
```

### 8-2. 공고 작성용 행사 선택

```text
S03 행사 연결 → S09-2 작성용 모드
→ 연결 가능한 진행 중·예정 전체 검색/목록(동행 일정 자동 축소·겹침 강제 없음)
→ 행사 선택
→ S03 복귀·행사 정보 연결
```

### 8-3. 행사 연결의 확정 분기

[행사 UX 동작 미리보기](행사UX_미리보기.html)는 합성 행사·공고로 확정 설계를 확인하는 별도 모형입니다. 실제 API 호출·회원 데이터·서버 저장·상태 검증·알림·동일 행사 통합 완료를 뜻하지 않습니다.

[행사 UX 최종 확정 기준](../../collaboration/requests/jonghyun/2026-10-20-event-ux-approved-spec.md)은 제품 설계이며 실제 서버/앱 연결·UT 완료와 구분한다.

```text
일반 작성 → 맨 아래 행사 연결 영역
행사 상세의 동행 구하기 → 선택 행사 사전 연결 → 맨 위 행사 영역
비로그인 → 로그인/가입 완료 → 원래 행사 연결 S03 복귀·상태 재확인
행사 검색/목록 → 연결 가능 여부 확인 → 선택 → S03 복귀
  ├─ 0건 → 조건 변경 또는 직접 입력
  └─ 조회 실패 → 입력 유지·재시도(행사 없음으로 안내하지 않음)
직접 입력 → 행사명 필수 + 장소명/공개 행사장 주소 선택
  → 주소 검색·공개 확인·개인주소 금지 안내·의심정보 검사
  → 해당 공고에만 저장(공통 목록/별도 상세/공용화 검수 없음)
행사 없이 작성 → 행사 영역 생략
등록 직전 → 우리 서버 최신 상태 확인
  ├─ 확인 실패 → 입력 보존·다시 확인 또는 사용자가 연결 삭제 후 등록
  ├─ 취소/종료/연기 일정 미정/비표출/기관별 핵심 충돌 → 변경·삭제 안내
  └─ 연결 가능 → 기존 공고 필수조건 검증 후 등록
```

- 행사 선택/변경은 동행 일정을 자동 변경하지 않는다. 달력의 행사 날짜 색 강조는 참고이며 날짜 겹침을 강제하지 않는다. `변경`·`삭제`는 해당 공고 연결에만 적용한다. 직접 입력은 별도 행사기간/요금/이미지를 받지 않는다. 공개 행사장 주소와 확정자만 보는 상세 만남 지점은 별도다.
- 예정/진행 중은 연결 가능, 공식 취소는 `취소된 행사예요`, 종료는 새 연결 불가. 연기 일정 확인 후 조건을 충족하면 연결 가능. 취소 여부 미제공은 정상 수집·유효기간 등 검증 뒤 허용하며 공식 정상 개최로 표현하지 않는다. 단순 검색 누락/호출 실패를 취소·비표출/정보 미제공으로 대체하지 않는다.
- 행사 카드 이미지는 없거나 로딩 실패하면 빈 영역 없이 글만, 이름 최대2줄·상세 전체. 카드/상세 정보순서는 IA를 따른다. 연결 공고는 전체 상태·등록 최신순, 모집중 필터,10개 더보기와 기존 공개/차단 권한 적용. 연결 없음은 `아직 이 행사에 등록된 동행 공고가 없어요`.
- 비표출 확인 → 해당 원천 정보 숨김 → 다른 검증된 공개 원천이 있으면 그 원천 유지, 없으면 `연결된 행사 정보를 현재 제공할 수 없어요 / 행사 취소를 의미하지는 않아요`. 공고·약속·내부 관계 유지. 명시 재표출·공개 조건·최신 정보 검증 뒤 자동 복원, 기존 취소/연기/종료 제한 유지. 직접 입력에는 적용하지 않는다.
- 확실한 공식 행사 단위 동일 개최 근거가 있을 때만 대표 상세/공고로 통합한다. 원천 ID·공고 관계·근거·통합/분리 이력을 보존하고 근거 부족은 출처별 유지한다. 먼저 검증된 공개 원천을 대표로 유지하고 빈 항목만 출처를 남겨 보완한다. 핵심 충돌은 안내·새 연결 제한, 기존 약속 유지.
- 작성자 행사 교체/삭제/직접 입력 행사명·장소 실질 변경 → 핵심 조건 변경 → 확정 전 기존 동의 무효화·알림·재요청 / 확정 후 상대 수락 전 기존 약속 유지. 기관 자동 갱신은 별개. 확인된 취소/연기/변경 일정은 관련 작성자·진행중 동행 확정 상대에게 앱 안 알림, 동일 변화 중복 방지, 새 푸시 없음.
- 현재 서버의 UUID 행사 연결·active/cancelled 및 기존 일정 변경 포트만으로 직접입력·비표출·연기·대표 통합·행사 변경 합의·알림을 모두 지원한다고 표시하지 않는다. 서버 민규·화면 종현·UT 유미가 각각 검증한다.

### 8-4. 공식 KOPIS Top 10

```text
S09-2 공식 순위
├─ 전국 전체 공연 Top 10(기본)
└─ 연극 · 뮤지컬 · 클래식 · 국악 · 대중음악 · 무용 · 대중무용
   · 서커스/마술 · 복합 · 아동 · 대학로 · 내한 · 축제 Top 10
→ 선택 분류의 공식 사이트 실제 기간·전국·분류 조건 확인
→ API 공연 ID·순위·표시 순서 Top 10 대조
├─ 일치 → 출처·실제 기간·확인 시각과 함께 공개 → 행사 상세 S09-3
├─ 실패/불일치 + 과거 검증 목록 있음 → 기존 기간 그대로 유지 + 갱신 지연
└─ 최초 미검증 → 순위 대신 공식 순위 사이트 링크
```

전국 전체 공연을 포함해 총14개 선택 항목을 제공하는 목표이며, 각 분류의 공개 여부는 독립 검증한다. 공식 사이트의 실제 기간이 어제까지 최근7일인지 확인하고 전국·분류 조건과 Top 10이 일치해야 공개한다. 동률은 공식 사이트 표시 순서를 따른다. 분류별 매일 갱신은 목표이며 모든 분류 검증·자동 대조·서버 연결 완료를 뜻하지 않는다.

화면 표시명은 원천의 `서양음악(클래식)` → `클래식`, `한국음악(국악)` → `국악`, `무용(서양/한국무용)` → `무용`으로 바꾼다. 원천 명칭과 조회 조건은 보존한다. 아동·대학로·내한·축제를 일반 장르와 같은 코드로 단정하거나 정확한 API 조건을 추정하지 않는다.

공급사 회신 전 일괄 보류 대신 위 공식 사이트 대조를 공개 조건으로 삼는다. `basedate`가 없는 응답의 내부 집계 기간이 증명됐다고 표현하거나 요청 날짜로 대신 확정하지 않는다. 실제 검증된 사이트 표시 기간을 안내한다. 갱신 실패 시에는 마지막 검증 목록의 기간을 바꾸지 않고 `갱신 지연`을 표시하며, 검증 이력이 없으면 공식 링크로 안내한다. 자체 순위로 대체하지 않으며 일반 공연 조회는 계속한다.

서울 평문 HTTP 수집은 활성화하지 않는다. 안전한 HTTPS 자동 수집·페이지 재개·진행 중 행사 갱신을 검증할 때까지 보류한다. HTTPS 자료를 한 번 수신한 것만으로 보류를 해제하지 않으며 미연결/미수집을 행사0건으로 안내하지 않는다. 서버 수집·계약은 민규, 앱 상태 소비는 종현 담당이다.

## 9. AI 동행 탐색 S20

```text

- 사용자 메시지는 오른쪽, AI 메시지는 왼쪽에 표시한다.

- 비공개 상세 주소·거리·개인 식별 정보는 결과에서 제외한다.
- 초기 AI 대화는 기기 메모리만 사용하며 화면 종료·로그아웃 시 삭제한다. 서비스 서버·브라우저 영구 저장소에는 저장하지 않는다.
- AI 탐색은 첫 사용 시 동의 안내를 제공한다. 동의하면 기존 실행 조건 확인 후 탐색을 시작하며, 거절하면 모델 처리 없이 일반 검색으로 돌아간다. 가입·일반 동행·계정은 유지한다. 후기 요약 열람·내 프로필 요약 생성·노출·작성한 후기의 AI 요약 활용은 가입 시 각각 선택 체크 세 항목으로 안내한다. 세 항목에 모두 동의하지 않아도 가입·일반 동행·계정 이용을 허용하며 미동의한 해당 AI 기능·처리만 제한한다. 짧은 문구와 자세히 보기로 구성하며 기본은 미선택이다. 후기 작성 때는 작성 후기 활용에 동의한 경우 상대방 프로필 요약에 활용된다는 짧은 재안내만 제공하고 동의 체크를 반복하지 않는다. 현재 기존 회원은 모두 테스트 계정이므로 테스트 시나리오에서는 AI 동의를 모두 받은 것으로 간주하고 재동의를 생략한다. 실제 회원의 동의 증거 생성·DB 값 변경으로 확대하지 않는다. 후기 AI 미동의로 가입을 차단하지 않으며, 법적 적합성·공급사 조건 확인 전 회원 원문 외부 전송은 보류한다.
- 현재 프로토타입은 카테고리·주요 지역·무료·주말 조건까지를 범위로 한다.

└─ 일시 통신 실패 → S12 공통 상태 안내: 지금 불러오지 못함 → 다시 시도/이전 화면
```

알림 클릭은 읽음 처리와 화면 이동만 수행한다. 동의·확정·평가 제출을 자동 실행하지 않는다. 새 화면 ID를 만들지 않고 S12 진입의 공통 상태 안내를 사용한다. 현재 서버 권한을 확인하기 전에 캐시의 실명·상세 지점을 노출하지 않는다. 403/404 등 응답만으로 차단한 사람이나 삭제 사유를 추측하지 않고 안전하게 확인된 구분만 안내한다. 일시 오류를 대상 삭제로 처리하거나 재시도만으로 약속 상태를 변경하지 않는다.

## 18. 상태별 추가 행동과 예외

### 탐색·작성·미전송 입력

비로그인 작성자 박스는 전체 모자이크 가드와 `동행인은 로그인 후 확인할 수 있어요`로 표시하고 개인정보를 응답·DOM에 넣지 않는다. 공고/행사는10개, 후기는5개씩 추가 조회한다. 검색어는 같은 기기 최근10개·7일이며 삭제/로그아웃으로 정리한다.

초안은 같은 기기 최근1개, 마지막 수정 후7일 만료다. 새 초안 대체 전 안내하고 복원 시 만료를 표시하며 등록 성공/로그아웃에 삭제한다. 제목50자·소개2,000자·상세 지점300자다. S11 첫 미전송 메시지는 화면 메모리만 유지하고 이탈 삭제를 안내한다. 서버 마감 접수는 마감보다 빠른 경우만 허용하며 재신청은 철회 후1분 경과부터 가능하다.

### 차단·신고·공개글 검사

- 확정 전 신청 철회와 확정 후 시작 전 취소를 구분한다.
- 확정 전 철회는 연속 확정 취소 제재에 포함하지 않는다. 재신청은 철회 후 1분 경과 시 횟수 제한 없이 허용하되 작성자 거절 이력이 있으면 차단한다.
- 확정 후 시작 전 취소는 사유를 선택해 처리하고 상대에게 알림을 보낸다.
- 취소 성립 즉시 전체 이름을 다시 마스킹하고 상세 주소를 숨긴다.
- 시작 이후에는 일방 취소 대신 중단·불발 신고로 접수한다.
- 중단·불발 신고에는 상황 설명이 필요하며 운영 검토 후 조치한다.
### 6-1. 차단

- 차단한 두 사람 사이의 신규 메시지·신청·확정 요청·수락을 막는다. 로그인 상태에서 서로의 공고·프로필을 숨기되 기존 약속 관리에 필요한 정보는 유지한다. 비로그인 공개 접근까지 완전히 막는다고 안내하지 않는다.
- 기존 대화는 읽기 전용으로 두고 기록 확인·신고·나가기를 제공한다. 차단은 즉시 처리하며 확정 약속의 취소는 별도 확인과 기존 취소 규칙을 따른다.
- 차단은 언제든 해제할 수 있으나 종료 신청·취소 약속을 자동 복원하지 않는다. 차단 해제는 차단 때문에 생긴 숨김만 해제하며 신고 등에서 별도로 선택한 본인 콘텐츠 숨김은 유지한다. 독립 숨김은 해당 숨김 관리에서 사용자가 명시적으로 해제하고 현재 권한으로 재조회한다. 차단만으로 후기·당도·칭찬은 바뀌지 않는다.

### 6-2. 신고와 처리

- 운영자는 DB의 회원 채팅 원문을 직접 읽지 않는다. 온라인 신고는 상황 설명과 캡처를 필수로 받는다. 대면 위협·노쇼는 설명과 제출 가능한 자료로 접수하며 캡처가 없다는 이유만으로 접수를 막지 않는다. 접수 자체를 사실 인정으로 취급하지 않는다.
- 공고·채팅·AI 결과는 전용 신고 양식, 다른 대상은 대상이 연결된 공통 양식으로 접수한다. 성희롱·협박·금전/개인정보 요구·사칭·스팸·노쇼·기타를 복수 선택하고 설명할 수 있다.
- 실제 목록·상세 숨김 계약 연결 전 본인 숨김 선택 제공은 보류하고 신고 접수만 안내한다. 사용자 승인에 따라 본인 숨김 클라이언트 구현은 진행하되 실제 연결·검증 전 전체 기능 활성화 완료로 처리하지 않는다. 활성화 후 숨김은 탐색·콘텐츠에만 적용하며 확정 일정·취소·신고·판정 안내를 유지한다. 신고 증거가 최종 종결+90일에 삭제돼도 최소 식별 기록만 별도로 본인이 해제할 때까지 유지하고 설명·캡처·증거는 숨김 목적으로 보관하지 않는다. 해제 시 현재 권한으로 재조회한다. 이 범위·유지 기간은 확정 정책이며 구현·활성화 성공과 구분한다. 전체 공개 제한은 운영 검토 후 결정하며 차단·제재·동행 분쟁의 완료·후기 보류와 구분한다.
- 접수·검토 중·추가 자료 요청·처리 완료 및 내 신고 내역을 표시한다. 신고자에게 조치 여부·대표 사유, 제재 당사자에게 본인 위반·제재·이의 절차만 안내한다. 신고자 신원·다른 사건은 공개하지 않는다.
- 일반 신고의 첫 확인 목표는 평일 09~18시 운영 기준 영업일 2일 이내다. 대표 유미가 일반 신고의 실제 처리와 허용된 신고 증거 열람을 담당하며 사건별 완료 시한은 별도 안내한다. 대체 담당자는 별도 지정하지 않은 상태다. 실제 증거 접근권한·감사·파기 연결 완료와 이 책임 배정은 구분한다. 위급 상황은 공식 긴급 도움 경로를 안내하고 위험 신고를 우선 검토한다.
- 불인정·증거 부족만으로 신고자를 제재하지 않는다. 조작·보복 목적이 확인된 반복 신고를 심사한다. 양쪽이 불발을 인정하면 간단히 처리하고 다툼이 있으면 분쟁 심사한다.

### 6-3. 취소 외 위반과 이의

- 경미 위반은 위협·성희롱·개인정보 노출 없는 낮은 위험의 규칙 위반이다. 반복은 안내·경고 후 같은 유형 또는 같은 피해자 대상 위반의 재발이다. 중대 위반은 성희롱·협박·폭력·스토킹·신상 노출·성적 착취 등 안전·권리 침해다. 정당한 비판과 증거 부족 신고 자체는 위반이 아니다.
- 경미한 첫 인정은 경고, 그 뒤 첫 재발은 신규 공고 작성·신청·확정 7일 제한, 두 번째 재발부터는 매번 30일 제한한다. 직전 확정 위반 후 12개월 동안 재발이 없으면 일반 위반 단계는 경고부터 다시 센다. 연속취소의 첫 경고 유지 규칙에는 이 초기화를 적용하지 않는다.
- 중대 위반이 운영 검토에서 확인되면 경고 없이 해당 계정을 즉시 영구 이용 제한한다. 신고 접수만으로 위반이 확정됐다고 보지 않는다. 심사 중 필요한 접촉 제한과 최종 영구 제재를 구분한다. 기존 약속의 안전 관리·본인 자료 열람·이의 절차는 유지한다.
- 취소 외 제재는 판정·사유·이의 방법이 앱에 성공 제공된 서버 시각부터7일 내 이의 신청을 받는다. 최초 열람·푸시/메일 발송은 기산 기준이 아니며 앱 안내 실패 시 시작하지 않는다. 서버가 정한 이의 마감 시각을 표시한다. 심사 중 기존 제한은 원칙상 유지하되 명백한 오류가 확인되면 즉시 해제하고 잘못된 이력·당도 영향을 정정한다. 이의 신청으로 제재 기간을 다시 시작하지 않는다. 취소 이의의 24시간·판정 보류 규칙은 별개다.

### 6-4. 공개글과 채팅 검사

- 성희롱·협박·혐오·인격 모욕·사칭·스팸·허위 모집·금전/민감정보 강요 및 아동 성적 착취·학대 콘텐츠를 금지한다. 사실과 경험에 근거한 부정 평가·비판은 허용한다.
- 공고·공개 프로필·후기는 개인정보와 금지 콘텐츠를 등록 전에 검사한다. 채팅은 정상 약속 안내를 일괄 차단하지 않고 명확한 고위험을 차단한다. 애매한 위험 표현은 전송 전 확인 안내를 하고 수정하거나 그대로 전송할 수 있게 한다.
- 자동 검사와 운영자의 원문 직접 열람은 다르다. 자동 검사 때문에 원문 로그 보관·외부 AI 전송·DB 직접 열람을 추가하지 않는다. 오탐 문의와 신고 경로를 제공한다.

### 후기 검토와 당도·칭찬·요약

### 7-1. 완료

- 예상 종료 전에는 완료 확인을 할 수 없다.
- 종료 후 각 사용자는 본인의 동행 완료를 확인할 수 있다.
- 한쪽만 확인한 상태는 개인 확인 완료일 뿐 동행 실제 완료가 아니다.
- 양쪽이 확인하거나 예상 종료 시각 +24시간이 지나면 동행을 실제 완료 처리한다.
- 취소·노쇼 건은 자동 완료에서 제외하고 신고·분쟁 검토 중에는 자동 완료를 보류한다.
- 정상 동행으로 인정되면 양쪽이 합의한 최신 종료 시각+24시간이 지났을 때 즉시 완료한다. 아직 지나지 않았다면 그 기준을 유지한다. 검토 중 새로 합의한 종료에도 동일하게 적용하며 검토 시간을 추가하지 않는다.
- 불발을 정상으로 정정할 때 한 명이 이미 탈퇴했고 실제 완료 기록이 없으면 탈퇴자를 진행 약속으로 복귀시키지 않고 정정 시 완료한다. 다른 미결 검토가 있으면 보류한다. 최초 실제 완료부터7일이고 탈퇴 본인의 후기 작성은 불가하다.
- 실제 완료 시 완료 횟수를 즉시 반영한다.
- 이의 검토 중 리뷰 작성·기한 진행·공개를 보류한다. 동행 인정 후 남은 리뷰 기간을 재개하되 최소 24시간을 보장한다.
- 실제 완료 전에는 리뷰 작성 기한이 시작되지 않는다. 검토 후 처음 완료되었다면 실제 완료 시점부터 7일을 시작한다. 이미 완료된 동행은 검토 직전의 남은 리뷰 기간을 재개하며 최소 24시간을 보장한다.
- 검토 중에는 양쪽 제출을 포함해 새로운 리뷰 공개를 보류한다. 이미 공개된 후기는 접수·검토 개시만으로 숨기지 않고 운영자가 임시 비공개 필요성을 판단한 때 숨긴다. 검토 종료 후 양쪽 제출이면 공개하고, 한쪽 제출이면 재개·연장된 작성 기한 종료 시 공개한다.

### 7-2. 평가와 공개

- 본인 완료 확인 후 상대 확인 전에도 후기를 미리 제출할 수 있으나 실제 완료 전에는 비공개다.
- 평가 경험은 `좋아요`, `보통이에요`, `별로예요` 중 하나다.
- 별점 1~5점은 필수, 한마디는 선택이다.
- `좋아요`일 때만 공식 칭찬을 최대 3개 선택할 수 있다.
- 공식 칭찬 6종은 `시간을 잘 지켜요`, `약속한 내용을 지켜요`, `소통이 원활해요`, `배려심이 있어요`, `대화가 즐거워요`, `함께하니 편안해요`다.
- 제출 성공 후 수정과 중복 제출은 불가능하다.
- 후기 작성 기한은 실제 완료 시각 +7일이다.
- 실제 완료 후 양쪽이 제출하면 즉시 공개하고, 한쪽만 제출하면 후기 작성 기한 종료 시 공개한다.
- 상대 후기가 열람 가능해지는 시점에 당도를 반영한다.

### 7-3. 공개 프로필과 AI 후기 요약

- 공개 프로필은 사진, 관계에 따른 이름, 만 나이, 선택 성향, 현재 당도, 칭찬 차트, 후기 원문을 보여준다.
- 칭찬은 누적 상위 5개와 횟수를 표시한다.
- 한마디가 있는 공개 후기 3개 이상일 때만 AI 요약을 제공한다.
- 비공개 후기와 텍스트 없는 평가는 AI 요약 근거에서 제외한다.
- 요약 실패·대기 상태에서도 공개 가능한 칭찬과 원문 후기는 유지한다.
- 숨긴 후기의 칭찬은 차트에서 제외하고 유효하게 재공개되면 복원한다. 다른 공개 후기의 칭찬은 유지한다.
- 비공개 후기를 근거로 만든 기존 AI 요약은 즉시 숨긴다. 남은 공개 텍스트 후기 3개 이상이면 정기 주기에 재생성하며, 미만이면 요약 대기를 표시한다.
- 검토 종료 후 현재 조건을 다시 확인해 공개 가능한 후기를 복원한다. 복원 자체의 당사자 알림은 보내지 않는다.
- 후기 AI 열람 미동의 시 본인의 요약 열람만 제한한다. 내 프로필 생성·노출 미동의 시 본인 요약을 생성·갱신·노출하지 않는다. 작성 후기 활용 미동의 시 본인이 쓴 후기를 타인 요약의 AI 재료에 포함하지 않는다. 다른 두 항목의 상태를 자동 변경하지 않으며 원문 후기·별점·당도는 기존 정책을 유지한다.
- 공개 AI 요약은 최대 300자다. 표시하거나 다시 펼칠 때 서버의 현재 공개 조건을 조회하며 별도 공개 결과 캐시는 두지 않는다.

### 7-4. 당도 계산

- 초기값은 15, 표시는 0~100의 정수다. 아직 평가가 없는 초기값임을 안내한다. 완료 횟수와 칭찬은 당도에 가산하지 않는다.
- 후기 반응은 좋아요 +1·보통 0·별로 −2, 별점은 1~2점 −2·3점 0·4~5점 +1로 각각 계산해 합산한다. 미작성 평가는 0이다.
- 확정된 운영 감점은 취소 제재 1회 −2, 노쇼 1건 −3, 중대 위반 1건 −10이다. 같은 사건에 여러 운영 위반이 겹치면 가장 큰 운영 감점 하나만 적용한다. 개별 취소 한 번을 곧바로 취소 제재 1회로 세지 않는다.
- 유효 후기와 운영 감점이 같은 사건에 함께 있으면 둘 다 합산한다. 노쇼 등으로 동행·후기 자격이 무효라면 해당 후기 기여를 제외한다.
- 초기 15에 모든 유효 가감 내역을 합산하고 마지막 표시값만 0~100으로 제한한다. 사건마다 상·하한으로 잘라 누적하지 않는다. 원 평가·가감 내역을 유지해 무효·해제 시 재계산한다.
- 후기 점수는 상대 후기의 열람이 가능해지는 시점에 반영한다. 양쪽 제출은 실제 완료 조건을 충족한 공개 시점, 한쪽 제출은 작성 기한 종료 공개 시점이다. 운영 감점은 해당 위반·제재가 확정된 때 적용한다.
- 임시 후기 숨김 중에는 이미 반영한 당도를 유지하고 최종 무효 판정 때 해당 기여를 제외한다. 공개 복원·운영 오판 정정과 연결해 재계산한다.
- 계산 예: 초기 15에서 좋아요와 별점 5는 17, 별로와 별점 1은 11이다. 후자가 유효한 실제 완료 동행에서 중대 위반 −10도 확정되면 1이다. 이는 산식 예시이며 실제 회원 결과가 아니다.

### 계정·제재의 추가 분기

진행 확정 약속 없이 분쟁만 남으면 탈퇴를 허용하고 분쟁 처리를 별도로 유지한다. 즉시 재가입하되 동일 네이버의 검증 식별값으로 제재·경고·연속 취소를 승계한다. 영구 제한은 종료 없이, 기간제는 원래 종료까지 유지한다. 이름·생일로 다른 계정을 동일인으로 추정하지 않는다. 새 프로필·당도15·횟수0이며 과거 받은 후기·당도를 복원하지 않는다.

취소 결과는 결과 확정 직전 합의 시작→동행 확정 시각→ID 순이다. 겹친 제재는 각각 실제 적용부터7일, 가장 늦은 종료까지이며 합산하지 않는다. 오판은 원래 순서로 재계산해 잘못된 경고/남은 제한을 즉시 해제하고 알린다. 같은 제재가 유지되면 기존 시작을 보존하고 새 제재만 실제 새 적용부터 계산하며 정정으로 기존 기간을 연장하지 않는다.

탈퇴 전 사건의 제재가 탈퇴 후 처음 확정되면 동일 네이버 계정에 적용하고 재가입 시 승계한다. 과거 사건 감점은 새 가입 회차 당도로 이전하지 않는다.

### 행사·AI 세부 흐름

- 홈 배너·기본 행사 목록은 `이번 주 신규 중 미종료` 행사만 제공하고 화면에 이 기준을 안내한다. 이번 주에 시작했어도 이미 끝났으면 기본 목록에서 제외하며 과거 기간 조회에서 찾을 수 있다.
- `진행 중 포함`을 선택하면 이전 주에 시작해 아직 진행 중인 행사도 포함한다.
- 한 주는 한국시간 월요일 00:00부터 다음 월요일 00:00 미만으로 본다.
- 행사 배너·목록의 `○월 ○주차`는 그 주의 목요일이 속한 달에 귀속한다. 해당 월의 날짜가 4일 이상 포함된 주를 그 달의 주차로 세며, 월 경계에서 한 주를 나누지 않는다.
- 해당 월의 첫 번째 목요일이 포함된 주를 1주차로 하고 이후 월요일마다 2주차·3주차로 순서대로 계산한다. 월말의 주도 같은 기준으로 다음 달에 귀속될 수 있으며, 연말·연초에는 귀속 연도도 함께 바뀐다.
- 매월 1일이 월~목요일이면 그날이 속한 주가 해당 월 1주차다. 금~일요일이면 그날이 속한 주는 전월 마지막 주차이며, 다음 월요일부터 해당 월 1주차다.
- 예: 2026년 9월 1일은 화요일이므로 8월 31일~9월 6일은 `9월 1주차`다. 2023년 9월 1일은 금요일이므로 8월 28일~9월 3일은 `8월 5주차`, 9월 4일~10일은 `9월 1주차`다.
- 이번 주 신규 행사는 해당 주의 월요일 00:00부터 다음 월요일 00:00 미만에 시작한 행사로 판단한다. 달이 다른 날짜도 같은 주간 범위에 포함하며, 월별 주차 표기를 위해 범위를 월초·월말에서 자르지 않는다. KOPIS 공식 순위의 `어제까지 최근 7일` 집계는 별도 기준을 유지한다.
- 표준과 서비스 규칙을 구분한다. ISO 8601-1의 주 달력은 연도 기준 주차를 정의하며, 위 월별 주차는 월요일 시작·목요일 귀속 원칙을 유미당의 월별 표시 규칙으로 적용한 것이다. 월별 주차 자체가 ISO의 직접 규정이라고 표기하지 않는다. 참고: [ISO 8601-1:2019 3.1.1.23 주 달력 정의](https://cdn.standards.iteh.ai/samples/70907/5e8d00e639cf4f849462bd63062f4cd8/ISO-8601-1-2019.pdf).
- 행사 유형은 공연·전시·축제·팝업 등 제공처의 실제 분류를 따른다.
- 공연은 콘서트·뮤지컬·연극 하위 장르 필터를 제공한다.
- 종료된 행사는 조회할 수 있으나 새 동행 모집 대상으로 연결하지 않는다.
- 작성용은 연결 가능한 진행 중·예정 전체를 대상으로 한다. 동행 일정으로 검색을 자동 축소하거나 겹침을 강제하지 않고, 선택 행사의 진행 날짜를 달력에 색으로 강조한다.
- 행사 상세는 명칭, 기간, 장소, 입장료, 출처, 운영 안내, 연결 공고를 제공한다. 세 공급사는 기존 공통 행사 계약으로 정규화한 정보를 소비하며 실제 확보한 정보만 표시한다. 미확인 요금을 무료로 안내하지 않고 행사 기간을 동행 일정으로 대신하지 않는다. 필수/선택 표시와 누락값 문구·배치는 별도 UX 설계이며 새 서버 구현 완료를 뜻하지 않는다.
- 행사장을 공고 작성의 장소 후보로 전달할 수 있다.
- 공식 Top 10은 KOPIS 전국 전체 공연 기본 및13개 분류 전환을 목표로 한다. 분류별 공식 사이트 대조 후 공개, 기존 검증 목록의 기간 보존·갱신 지연, 최초 미검증의 공식 링크 안내는8-3을 따른다.
- 집계 목표는 어제까지 최근7일·매일 갱신이며 검증 후 공개 시 출처·집계기간·갱신 시각을 표시한다. 요청 날짜로 실제 집계 기간을 대신 확정하지 않는다.
- 공식 순위 미수신 시 자체 추정 순위로 대체하지 않는다.

AI 탐색의 첫 사용 동의·거절 시 일반 검색 유지는 사용자 확정 사항이다. 후기 요약 열람·내 프로필 요약 생성·노출·작성한 후기의 AI 요약 활용은 가입 시 각각 선택 체크 세 항목으로 받도록 사용자 확정했다. 세 항목에 모두 동의하지 않아도 가입·일반 동행·계정 이용을 허용하며 미동의한 해당 AI 기능·처리만 제한한다. 원문 처리 동의는 별도 세 번째 항목으로 명시하고 후기 작성 시 짧게 재안내한다. 후기 요약의 세 동의별 독립 철회와 원문 활용 철회 시 영향받는 요약 선숨김·적격 자료 재생성 원칙도 사용자 확정했다. 기존 법적 검토·공급사 확인·회원 원문 외부 전송 보류는 유지한다.


## 행사 데이터 칼럼·화면 매핑 참고

공급사 원본 칼럼→기존 공통 구조→목록/상세/연결 행사 매핑은 [2026-10-19 데이터 대조표](../../collaboration/requests/jonghyun/2026-10-19-event-data-screen-mapping.md)를 따른다. 원본 필드·현재 구현 비교 자료이며 표시 설계는 최종 확정 명세가 우선한다. 해당 후보는 실제 API·저장·공개 DTO·앱 연결 완료를 뜻하지 않는다. 원천에 없는 값·현재 미지원 필드는 임의로 채우지 않는다.

행사 기간·입장료·장소 정보와 공고의 동행 약속 일정·무료 동행·상세 만남 지점은 분리한다. 관련 공고는 유미당 내부 `eventId` 관계로 조회하며 외부 행사 API가 제공하는 정보가 아니다. 서울 HTTPS 서버 구현은 민규7.9 인계, KOPIS 순위 집계 기간은 대조 결과 후 판단하되 일반 데이터 정리는 병행한다.
