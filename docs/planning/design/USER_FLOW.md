# 유미당 USER FLOW — 현재 사용자 흐름

정책 원본은 [정책.md](../../../정책.md), 제품 목적·범위는 [PRD](../requirements/PRD.md), 화면 ID·정보 구조는 [IA](./IA.md)다. 이 문서는 현재 확정한 행동·예외·복귀를 설명한다. [와이어프레임 HTML](./yumidang-wireframes.html)과 실행 코드는 이번에 변경하지 않았으며, 아래 흐름의 실제 동작은 별도로 검증한다.

## 1. 기준과 읽는 방법

현재는 여성·만19세 이상 대상 무료1:1 동행이며 가입·로그인은 네이버만 사용한다. 네이버 이름·성별·생일·출생연도와 필수 사진으로 가입 완료 조건을 확인한다. 선택 이메일·유료 동행·계좌 인증은 후속 검토다.

신청, 작성자의 상대 선택, 양쪽 최종 확정, 개인 완료 확인, 동행 실제 완료, 후기 제출, 후기 공개는 서로 다른 단계다. 특히 개인 완료 확인 후 후기 선제출은 동행 자체를 완료시키지 않는다. 미정 부분은 이 문서의 실행 흐름으로 임의 채우지 않는다.

## 2. 핵심 흐름

~~~text
신규: S05 네이버 로그인 → 필수 정보·자격 확인 → S06 사진·선택 성향
      → 가입 완료 버튼 → 안내 팝업 → S00 홈
기존: S05 네이버 로그인 → 최신 정보·자격 재확인 → 목적 화면 또는 홈

탐색: S00 / S01 / S09 / S20 → 공고 S02 ↔ 작성자 프로필 S14
      → S08 필수 소개 메시지로 신청 → S11 대화
      → 작성자 한 명 선택·최종 동의 요청 → 신청자 조건 확인·동의
      → 양쪽 확정 → 전체 이름·정확한 장소 → S16 → 실제 동행
      → 예상 종료 후 각자 완료 확인
        ├─ 본인 확인 후 S17 후기 제출 가능 (상대 확인 전이라도 가능)
        └─ 양쪽 확인 또는 예상 종료+24시간 자동 처리 → 동행 실제 완료
      → 완료 횟수 즉시 반영 / 후기 공개 조건 충족 시 당도 반영

모집: + / 카테고리 모집 / 행사 기반 모집 / 나의 새 모집
      → S03 일정·장소·선택 마감·선택 행사 → S04 확인
      → 직접 등록 → 생성한 S02 → 신청·대화·최종 동의
~~~

## 3. 로그인·가입·프로필 입력

| 단계·상황 | 행동과 결과 | 실패·제한·복귀 |
|---|---|---|
| 로그인 진입 | 홈 또는 회원 기능에서 S05 네이버 로그인 | 취소·실패는 원래 안내 화면으로, 재시도 가능 |
| 필수 정보 | 이름·성별·생일·출생연도 수신 확인 | 누락·확인 불가면 가입 완료 보류, 네이버 정보 확인·재시도. 수기 입력으로 우회하지 않음 |
| 자격 | 여성·만19세 이상 확인 | 미충족은 가입 불가 안내. 상세 성별·생년월일을 오류 문구에 노출하지 않음 |
| 계정 연결 | 네이버 계정당 유미당 계정 하나 | 자연인1인1계정 보장으로 표현하지 않음 |
| 기존 회원 | 로그인에서 받은 최신 정보·자격 재확인 → 원래 목적 화면 | 목적 없으면 홈. 정보 누락·자격 미충족은 새 공고·신청·확정 보류 |
| 신규 프로필 | S06 → S15 사진 선택·미리보기·저장 → S06 | 필수 사진 없음·실패 안내, 선택만으로 가입 완료하지 않음 |
| 선택 성향 | 관심사·대화 방식 기본 선택지/직접 추가, MBTI 네 쌍 선택 | 비워도 가입 가능. 각각 최대20개·값당40자 |
| 가입 완료 | 버튼 → 완료 안내 팝업 → 홈 | 기존 신청·AI 목적이 있더라도 신규 가입은 홈. 별도 완료 화면 없음 |
| 계정 접근 불가 | 네이버 계정 복구 안내 | 다른 네이버 계정으로 연결 변경·활동 기록 이전은 현재 미제공 |

기존 미검증 계정은 네이버 확인 전 새 등록·신청·확정을 제한한다. 진행 약속·기존 대화 확인과 취소·지원 요청은 허용하며, 자격 미충족 기존 약속은 운영 검토로 정리한다. 계정을 일괄 삭제하거나 미확인 보관 기간을 정하지 않는다.

MBTI는 네 쌍 중 하나씩 선택해 네 글자로 적용하거나 비워 둔다. 가입 후 S15-2에서도 같은 선택·직접 입력 규칙을 쓴다. 입력 성향의 공개 범위는 프로필 열람 권한을 따른다.

## 4. 계정 상태와 추후 인증

현재 S13→S21에서는 네이버 정보·자격 상태와 복구·이용 제한 안내를 확인한다. 이메일·계좌 인증을 현재 가입 완료나 무료 공고·신청 조건으로 요구하지 않는다.

### 4-1. 학교·직장 이메일 인증

S07은 추후 검토 화면 ID로 보존하며 현재 진입을 연결하지 않는다. 기관·효력·갱신·코드 정책은 추후 검토이며 제안된 기간을 현재 확정값으로 적용하지 않는다. 인증이 도입되더라도 가입 자격이나 현재 재학·재직·안전의 보증으로 사용하지 않는다.

### 4-2. 1원 계좌 인증

S22 역시 현재 진입이 없다. 추후 유료 신청·제안자는 1원 인증을 받아야 하며, 무효로 확인된 계좌의 인증 배지는 숨긴다. 조회 실패·확인 불가를 무효 또는 정상으로 단정하지 않는다. 명의 대조에 사용할 정보·공급사·불일치·갱신·효력 상실·확정 허용·상대 안내·지급·정산·환불 세부는 팀 검토다. 네이버 이름을 받았다는 사실만으로 은행의 동일인 확인까지 성립했다고 처리하지 않는다.

## 5. 홈·둘러보기·카테고리 탐색

### 5-1. 홈 S00

| 영역 | 흐름 |
|---|---|
| 상단 | 본인 전체 이름 또는 로그인→S05, 종→S12 |
| 신규 행사 배너 | 가로 넘김, 행사→S09-3, 전체보기→S09-2 일반 목록 |
| 다가오는 약속 | 선택→S16, 없으면 없음 안내 |
| 카테고리 | 선택→S09, 해당 카테고리로 새 모집 가능 |
| 행사 조회 실패 | 재조회 제공,0건과 구분 |
| AI / + | 로그인 확인 후 S20 / S03 |

본문은 행사→약속→카테고리 순서다. 본인 이름 영역에 인증 아이콘·나이·당도를 넣지 않는다. 본인 홈에서 이름 전체를 본다고 다른 회원에게 이름이 공개되는 것은 아니다.

### 5-2. 둘러보기 S01

~~~text
제목·등록 장소명·등록 주소·연결된 행사명 검색어 → 검색 버튼/Enter
→ 카테고리·일정·작성자 나이·모집 상태·정렬 적용
→ 실제 공고 카드 → S02 / 작성자 S14
~~~

- 앞뒤 공백을 정리하고 빈 검색어는 나머지 조건에 맞는 목록으로 복귀한다. 소개·후기·상세 만남 지점은 검색 대상이 아니다.
- 일정은 기간 겹침, 작성자 나이는 만19~99세 숫자 최소~최대 범위다. 희망 상대 나이와 별개이며 나이 전체 검색에는 상한을 적용하지 않는다. 비로그인은 나이 전체만 쓰고 세부 선택 시 로그인 안내한다.
- 등록일 최신순 기본·시작일 빠른순 선택, 전체 상태 기본·모집 중만 보기 선택이다. 모집 여부·AI 점수로 정렬을 뒤집지 않는다.
- 현재 공고는 무료다. 유료 선택·금액을 활성 기능처럼 제시하지 않는다. 행사 입장료는 별도 정보다.
- 주소 검색 일치와 주소 표시 권한은 구분한다. 정확한 주소·상세 지점은 확정 당사자만 보며, 주소 검색이 주변·거리순 검색을 뜻하지 않는다.
- 정상0건은 조건 수정, 장애는 재시도, 권한 오류는 해당 접근 안내로 구분한다. 더 보기로 이어 조회하며 표시 개수는 팀 검토다.
- 최근 검색은 같은 기기에서 재사용·개별/전체 삭제하며 로그아웃·확정할 기한 경과 시 삭제, 삭제 후 복구하지 않는다. 상세 만남 지점·인증 정보는 기록 대상에서 제외한다. 개수·기간은 미정이다.

### 5-3. 카테고리 S09

선택한 카테고리의 목록→공고 S02 / 작성자 S14. 모집은 해당 카테고리를 S03에 전달한다. 카테고리 실제 목록·표현은 검토 대상으로 남기고 공고 없음과 조회 실패를 구분한다.

## 6. 공고 작성·장소 지정·등록

### 6-1. 작성과 장소 입력

~~~text
작성 진입 → 로그인·자격 확인 → S03
→ 카테고리·제목·소개·시작/종료 날짜와 시간
→ 장소 지정
   ├─ Kakao Local 장소명 검색 → 명칭·주소 후보 → 선택 → 주소 자동 입력
   └─ Kakao 우편번호 서비스 → 주소 선택 → 주소·우편번호 입력
→ 별도 상세 만남 지점 / 동까지 공개 미리보기
→ 선택 모집 마감 / 선택 행사 연결 → S04
~~~

종료는 시작보다 늦어야 하고 자정을 넘길 수 있다. 모집 마감 미입력 시 시작 시각에 자동 마감하며 시작보다 늦은 마감은 불가하다. 같은 장소명은 주소로 구분하고 고정 합성 장소를 실제 검색 결과처럼 보여주지 않는다. 장소 검색 실패·0건도 구분한다.

제목의 정확한 주소·상세 지점, 본문의 전화번호·계좌·정확한 주소·상세 지점이 탐지되면 입력을 유지하고 수정 전 등록을 막는다. 오탐 문의를 제공하며 탐지·해제 권한·검토 기한은 팀 검토다.

### 6-2. 행사 연결과 등록

| 단계 | 행동·결과 | 예외·복귀 |
|---|---|---|
| 행사 연결 | 이미지·명칭·기간 목록에서 진행 중·예정 행사 선택 | 기간 지정 시 겹치는 행사로 좁힘, 취소·종료는 새 선택 제외 |
| 전체보기 | S09-2 선택 모드→선택→S03 | 기존 입력·일정을 유지. 행사 선택으로 동행 일정을 바꾸지 않음 |
| 행사 기반 새 모집 | S09-3→S03에 행사 연결 | 행사장을 장소 후보로 확인하고 실제 동행 일정·상세 지점은 작성자가 입력 |
| 등록 확인 | S04에서 희망 상대 나이·바라는 점·일정·마감·공개 지역 확인 | 성별 선택·유료 금액·계좌 인증 단계 없음 |
| 등록 | 직접 제출→성공 시 생성한 S02 | 실패 시 입력 유지·재시도, 별도 완료 화면 없음 |
| 이탈/재진입 | 계속 작성 또는 이탈, 같은 기기의 임시저장 복구 안내 | 등록 성공·직접 삭제·로그아웃·확정할 기간 만료 시 삭제. 삭제 후 복구 불가 |

임시저장 개수·기간·구체 보안 고지는 팀 검토다. 예전 시안의 세션 저장 방식이나 제안한1개·7일을 확정값으로 사용하지 않는다.

### 6-3. 공고 관리

| 행동 | 허용·결과 |
|---|---|
| 확정 전 수정 | 허용. 일정·장소·활동 내용 변경 시 신청자에게 알리고 기존 최종 동의 무효화. 신청·대화 유지, 새 조건 재동의 |
| 수동 모집 마감 | 새 신청만 차단. 유효한 기존 신청·대화 유지, 시작 전 최종 동의 신규/재요청 허용 |
| 자동 모집 마감 | 별도 마감 시각 또는 시작 시각에 새 신청 차단. 시작 이후 최종 확정 불가 |
| 확정 전 삭제 | 일반 목록에서 숨기고 미확정 신청·요청 종료·알림, 대화 읽기 전용 보존. 영구 삭제와 구분 |
| 확정 후 삭제 | 약속 종료 전 삭제 차단. 삭제를 약속 취소로 대신하지 않음 |
| 삭제 확인 취소 | 공고 상세로 복귀 |

## 7. 공고 상세의 역할 분기와 신청

| 관계·상태 | 행동·공개 |
|---|---|
| 비로그인 | 시스템 별칭·동까지 지역으로 공고 확인. 신청→로그인, 기존 회원은 신청으로 복귀·신규는 가입 후 홈 |
| 로그인 미확정 | 마스킹 이름·공개 지역·허용된 프로필. 신청 가능 상태에서 S08 |
| 작성자 | 본인 수정·마감·삭제·상대 선택. 선택만으로 확정 불가 |
| 기존 신청/대화 | 중복 신청 대신 기존 S11로 연결 |
| 최종 동의 대기 | S11 조건·기한 확인, 전체 이름·정확한 장소는 아직 숨김 |
| 양쪽 확정 | 당사자는 전체 이름·정확한 장소·S16, 제3자는 비공개 정보 제외 |
| 마감·삭제·조건 불일치 | 새 신청 불가와 이유 안내. 기존 활동은 현재 권한에 따라 연결 |

S08에서 일정·공개 지역·조건과 필수 소개 메시지를 확인해 신청한다. 성공하면 S11로 이동, 실패하면 입력 유지·재시도한다. 신청 단계 일정 겹침은 경고 후 계속할 수 있으나 기존 확정 약속을 자동 취소하지 않는다.

거절당한 신청자는 같은 공고에 다시 신청할 수 없다. 본인이 철회한 경우에는 신청 가능한 공고에 다시 신청할 수 있다. 첫 채팅 전에는 신청이 성립하지 않게 하는 대안은 팀 검토다. 현재는 소개 메시지 제출로 신청하는 흐름을 유지한다.

## 8. 채팅과 양쪽 최종 동의

~~~text
S11 대화 → 작성자: 상대 한 명 선택·최종 동의 요청
→ 신청자: 동일 일정·공개 지역·조건 확인
   ├─ 거절 → 해당 요청 종료, 신청·대화 유지
   └─ 동의 → 권한·조건 버전·정원·일정 충돌 재확인
      → 양쪽 확정 → 전체 이름·정확한 장소 → S16
      → 미선정 신청·요청 종료·알림, 해당 대화 읽기 전용
~~~

S02·S13·S11 어디서 상대를 선택해도 같은 절차다. 한 번에 한 명 제한은 최종 동의 요청에만 적용하며 여러 신청자와 대화하는 것을 막지 않는다. 상대를 바꾸려면 유효한 기존 요청을 먼저 철회한다.

| 상황 | 처리 |
|---|---|
| 요청 유효기간 | 발송 시각+24시간과 동행 시작 시각 중 빠른 때까지. 화면에 실제 만료 시각 표시 |
| 요청자 철회·상대 거절·만료 | 해당 요청만 종료하고 양쪽 알림. 신청·대화 유지, 만료 요청으로 확정 불가 |
| 재요청 | 시작 전 기존 유효 신청자에게 가능. 수동 모집 마감은 새 신청만 막으므로 이 경로 유지 |
| 조건 변경 | 이전 조건의 요청 무효화, 새 조건으로 다시 요청·동의 |
| 확정 일정 충돌 | 확정 차단·이유 안내. 기존 약속 자동 취소 없음 |
| 동시 확정·반복 실행 | 같은 권한·조건·정원·일정 확인, 약속·알림 중복 생성 금지 |
| 메시지 실패 | 입력 유지·재전송 |
| 종료 대화 | 기존 기록 읽기, 새 메시지 제한 |
| 대화방 나가기 | 본인 목록에서 숨김. 상대 기록 삭제 아님 |

### 확정 후 일정 변경

시작 전 새 일정을 제안→상대가 동의→충돌 검사 후 변경한다. 거절 또는 기존 시작 시각까지 미응답이면 기존 일정 유지다. 새 시작이 기존보다 빠르면 새 시작 시각 전에 동의해야 한다. 일정 유지가 어렵다면 별도 취소한다. 한쪽이 대화에서 제안했다는 이유만으로 약속 일정을 변경하지 않는다.

## 9. 행사 탐색과 공고 연결

| 목적 | 포함 기준·행동 |
|---|---|
| 홈/일반 목록 | 이번 주 새로 시작한 행사 기본. 한국시간 월요일00:00~다음 월요일00:00 미만 |
| 진행 중 포함 | 선택 기간과 겹치는 장기 행사까지 포함. 현재 진행 중만 남기는 필터가 아님 |
| 일반 정렬 | 진행 중→예정→종료, 각각 최근 시작순·시작일 빠른순·최근 종료순 |

| 작성용 선택 | 진행 중·예정, 지정 기간이 있으면 겹치는 행사. 일반 목록의 이번 주 신규를 강제하지 않음 |
| 상세 | 장소·기간·입장료·출처·운영 안내→연결 공고 또는 행사 기반 모집 |
| 취소 행사 | 새 조회·작성용 선택에서 숨김 |
| 결과 없음/실패 | 조건을 임의 초기화하지 않음.0건은 조건 변경, 실패는 재조회 |

지역·유형은 제공처 원문·실제 목록을 사용하고 공급사 분류가 섞이면 검토한 대응표를 추가한다. 제공처·원천ID로 중복을 구분하며 일부 페이지 누락만으로 삭제하거나 비슷한 제목만으로 다른 공급사 행사를 합치지 않는다.

KOPIS·TourAPI는 연결 대상이다. 서울 열린데이터는 HTTPS 등 조건과 연결 여부를 팀이 검토한다. 현재 지원 불가나 실제 연동 성공으로 단정하지 않는다. 공식 링크가 없으면 출처명만 표시한다. 행사 기간만으로 운영일·회차·휴관·잔여석을 보장하지 않으며 공식 정보를 확인하게 한다.

### 공식 공연·뮤지컬 Top10

일반 목록과 별도 영역에서 전국 전체 공연 Top10을 기본으로 보고 뮤지컬 Top10으로 전환한다. 어제까지의 최근7일 공식 KOPIS 순위를 매일 갱신하며 출처·집계기간·갱신시각을 표시한다. 공급사 순위를 자체 인기 지표로 바꾸거나 미수신을 예시 순위로 대체하지 않는다. 실제 API 연결·집계 범위·누락 처리는 구현 검증 사항이다.

## 10. AI 챗봇의 자연어 공고·행사 탐색

~~~text
S00/S01 AI → 로그인 확인 → S20 첫 이용 고지·확인
→ 자연어 요청 → 해석 조건 확인·수정 / 애매한 조건 되묻기
→ 실제 공고·행사를 권한에 맞게 조회
→ 선택 정렬·공개 권한 준수 → 카드·추천 이유·확인할 점
→ 공고 S02 / 작성자 S14 / 행사 S09-3 / 일반 탐색 S01
~~~

- 실제 회원 입력 전송은 외부 보관 조건·팀 검토·사용자 확인이 끝날 때까지 보류한다. 화면의 고지 확인을 공급사 보관 조건 승인이나 전체 법적 동의 충족으로 대신하지 않는다.
- 첫 이용 직전에 전송 항목·목적·공급사·서버 원문 미저장·확인된 외부 보관 조건·거절 방법을 알리고, 상시 다시 보기·조건 변경 재안내를 제공한다.
- 현재 대화의 명시 조건을 프로필보다 우선한다. 관심사·대화 방식은 등록값의 의미 유사성, MBTI는 정확 일치로 판단한다. 미입력은 확인 필요로 표시해 후보에 남기고 실제 불일치·실패와 구분한다.
- 일반 검색과 같이 제목·등록 장소명·주소·연결 행사명을 검색한다. 근처·주변 요청은 미지원 안내 후 장소명·주소를 확인한다. 정렬을 AI 점수로 바꾸지 않는다.
- 반환 직전 최신 상태 확인과 변경된 카드·설명을 어떻게 처리할지는 팀 검토다. 일반 공개 권한은 항상 준수한다.
- 일부만 확인한 카드의 제공 여부, 확인 불가·실패 안내, 재시도·일반 탐색 복귀 세부는 팀 검토로 남긴다. 미확인 상황을 정상 조회 성공으로 꾸미지 않는다.
- AI는 신청·확정·결제·메시지 발송·임의 웹/SQL 조회를 실행하지 않는다. 회원 간 채팅·실명·전화·계좌·비공개 지점은 입력에서 제외한다.
- 개인정보를 전송 전에 발견하면 전송을 멈추고 해당 내용 수정을 안내한다. 출력에서 발견하면 응답을 숨기고 재시도를 안내한다. 공개 장소명·주소와 민감정보를 구분하며 원문을 오류 로그에 남기지 않는다. 탐지 세부·오탐·한도는 팀 검토다.
- 현재 탐색 대화는 종료·새 탐색·로그아웃 시 정리하며 서비스 서버의 이력·오류·사용량 로그에 원문을 저장하지 않는다.

### ‘이번 주말 갈 전시 찾아줘’의 포함 기준

| 전시 기간 | 결과 |
|---|---|
| 지난달 시작·이번 주말까지 진행 | 장기 전시 포함 |

| 이번 주 시작·금요일 종료 | 제외 |
| 이번 주 신규만 요청 | 주말 겹침과 신규 조건을 함께 적용 |

행사와 공고 카드를 구분한다. 연결 공고 없는 행사를 신청 가능한 동행으로 표시하지 않고 행사 기반 모집으로 연결한다. 기간 겹침은 실제 운영·잔여석을 보증하지 않는다.

## 11. 나·사진·공개 프로필·AI 요약 브리핑

| 시작 | 행동·결과 |
|---|---|
| S13 내 동행 | 보낸 신청→S11/S18, 받은 신청→S11, 진행 약속→S16, 평가 가능 동행→S17 |
| 내 공고 | 작성자 상세 S02 / 새 모집 S03 |
| 프로필·후기 | 내 공개 미리보기 S14 / 사진 S15 / 성향 S15-2 / 계정 상태 S21 |
| 사진 교체 | 선택→미리보기→저장→진입 화면. 실패 시 기존 사진 유지, 마지막 사진 삭제 불가 |
| 성향 편집 | 선택지·직접 추가·MBTI·선택 소개→저장. 실패 시 입력 유지 |
| 상대 프로필 | 로그인·관계 권한 확인→허용된 이름·성향·현재 당도·후기→이전 화면 |
| 안전·계정 | 안심 수칙 S19 / 계정 상태·복구·탈퇴 안내 |

받은 후기는 공개 칭찬 상위5개·실제 횟수 차트→AI 요약→원문 순서다. 요약은 한마디 있는 공개 후기3개 이상부터 기준 후기 수·갱신시각과 함께 제공하며 텍스트 없는 평가·비공개 후기를 제외한다. 공개 평가 총수와 요약 사용 텍스트 수를 구분한다.

원문 변경·비공개 전환 시 근거가 낡은 요약 노출을 중단하고 재처리한다. 적격 후기3개 미만이면 요약을 제공하지 않는다. 요약 대기·실패 시 원문과 칭찬은 유지한다. AI 외부 전송 보류와 품질 검토는 여전히 별도 조건이다.

본인·타인에게 현재 당도만 표시하고 변경 내역은 고객지원 문의로 확인한다. 당도 계산식·초기값·운영 지원 세부를 임의로 정하지 않는다.

## 12. 약속 완료·평가·철회·취소

### 12-1. 약속과 완료

| 시점·상태 | 가능한 행동·결과 |
|---|---|
| 예상 종료 전 | 약속·대화 확인. 아직 완료 확인·평가 진입 불가 |
| 예상 종료 후 본인 미확인 | 본인 완료 확인 |
| 본인만 확인 | 동행 자체는 미완료. 상대 확인을 기다리지 않고 S17 후기를 제출할 수 있지만 비공개 유지 |
| 양쪽 확인 | 수동 완료, 실제 완료 시각 기록·완료 횟수 즉시 반영 |
| 예상 종료+24시간 미처리 | 취소·불발·분쟁 제외 자동 완료. 지연 시 실제 성공 시각 기록 |
| 동행 실제 완료 | 후기 일반 작성 마감은 실제 완료+7일. 한쪽 공개 대기는 실제 완료+24시간 |
| 양쪽 후기 제출 | 공개 제외 사유가 없는 완료 동행이면 즉시 공개·당도 반영 |
| 한쪽 후기 제출 | 실제 완료+24시간에 공개·당도 반영. 이미 지난 뒤 기한 내 제출이면 즉시 공개 |
| 실제 이의 검토 | 작성·기한·공개 보류. 동행 인정 후 남은 기간 재개·최소24시간 보장 |

완료 방식·개인별 확인·실제 완료 시각을 구분하고 재실행으로 시계를 초기화하지 않는다. 완료 횟수는 후기와 무관하며 당도 반영은 실제 후기 클릭과 무관하다. 미완료·실제 분쟁·불발/노쇼 후기는 공개하지 않는다. 공개를 일일 작업이나 AI 성공까지 기다리게 하지 않는다.

~~~

제출 전 경험 선택으로 돌아갈 수 있고 좋아요에서 다른 경험으로 바꾸면 칭찬을 제거한다. 선택 키워드는 시간을 잘 지켜요 / 약속한 내용을 지켜요 / 소통이 원활해요 / 배려심이 있어요 / 대화가 즐거워요 / 함께하니 편안해요다.

제출 성공·동행 완료·후기 공개를 같은 성공 상태로 합치지 않는다. 본인 완료 확인 후 선제출을 허용하되 동행 실제 완료 전에는 공개하지 않는다. 수동·자동 완료 이후에는 양쪽 제출 즉시, 한쪽 제출은 실제 완료 시각 +24시간 공개 기준을 적용한다. 신고 접수만으로 공개 후기를 자동 숨기지 않고 운영자 조치 결정을 따른다.

### 12-3. 신청 철회와 확정 동행 취소 S18

| 상황 | 흐름·처리 |
|---|---|
| 확정 전 본인 철회 | S11/S13→사유·유지 또는 철회→결과. 대화 보존·새 메시지 제한, 실패 시 재시도. 이후 신청 가능한 공고에 재신청 가능 |
| 신청 거절 | 결과 안내, 같은 공고 재신청 불가. 최종 동의 요청 거절과 구분 |
| 확정 후 시작 전 취소 | 누구나 사유를 남겨 취소, 양쪽 알림·자동 완료 제외 |
| 시작 이후 | 중단·불발 신고로 접수, 노쇼·책임·제재를 자동 확정하지 않음 |
| 취소 성립 후 정보 | 이름 재마스킹, 정확한 주소·상세 지점 즉시 숨김. 기록은 취소 사실·공개 지역 |
| 취소 유지/실패 | 유지하면 이전 화면, 실패하면 재시도·현재 상태 확인 |

채팅 본문·이미 본 정보까지 지워진다고 안내하지 않는다. 불발·노쇼 인정, 분쟁 증거·종결·이의, 제한 기간·횟수는 팀 검토로 남기고 미확정 수치를 구현하지 않는다.

## 13. 알림·안심 수칙·계정 종료

| 알림·진입 | 도착점·행동 |
|---|---|
| 최종 동의 요청 | S11 조건·만료 시각 확인 후 직접 동의/거절 |
| 요청 만료·철회·거절 | S11 현재 신청·대화 상태 확인 |
| 양쪽 확정 | S16 약속, 미선정자에게 종료 결과 |
| 공고 핵심 조건 변경 | 변경 안내·새 조건 확인·재동의 |
| 완료·평가 | 개인/동행 완료 상태를 확인해 S17 안내 |
| 취소·종료 | 취소 결과·현재 공개 정보·지원 경로 |
| 대상 삭제·접근 불가·실패 | 각각 구분 안내, 실패 재시도 |

알림 클릭만으로 동의·확정·완료를 실행하지 않고 대상·관계·현재 상태를 다시 확인한다. 안심 수칙은 공공장소, 강요 금지, 합의 밖 금전·민감정보 요구 주의, 일정·귀가, 위급 도움을 안내한다. 현재 금지된 유료 거래 모집과 사칭·괴롭힘·차별·성적 강요·사기·개인정보 무단 공개를 금지하되 신고만으로 위반을 확정하지 않는다.

탈퇴 요청은 진행 확정 동행·분쟁 해결 또는 취소 절차를 먼저 안내한다. 탈퇴가 성립하면 이용 중지·프로필 비공개·삭제 가능한 자료 삭제를 적용하고 재가입은 새 계정이며 과거 당도·후기를 복구하지 않는다. 무기한 탈퇴 거부·법정 보관·삭제 기한을 이 흐름으로 새로 정하지 않는다.

대화방 나가기는 본인 목록만 숨긴다. 일반 신고·분쟁에서 운영자는 서버 채팅 원문을 직접 열람하지 않고, 신고자가 필요한 구간을 캡처해 접수하도록 안내한다. 캡처의 처리 근거·접근·보관·삭제는 별도 팀·법률 검토다. 신고·차단·고객지원·운영자 권한·보관 기간의 상세 경로는 팀 검토다.

## 14. 구현·검증 경계와 후속 확인

### 최신 요구와 현재 HTML의 차이

HTML은 변경하지 않았다. 새 네이버 로그인, 무료 전용 작성/신청, 연결 행사명 검색, 숫자 나이 필터, 최종 동의 만료/경쟁·마감·삭제, 개인 완료 후 선제출, 공식 Top10, 개인정보 차단·외부 전송 보류를 실제 화면·서버와 대조해야 한다. 이전 시안의 인증 성공·합성 행사·상태 버튼을 실서비스 결과로 사용하지 않는다.

### 후속 구현의 확인 시나리오

| 확인 범위 | 기대 결과 |
|---|---|
| 가입·복귀 | 네이버 필수 정보 누락 보류·자격 확인·사진 필수·성향 선택. 신규 팝업 후 홈, 기존 목적 화면 복귀 |

| 작성·관리 | 시작/종료·마감·행사 입력 보존·개인정보 차단. 조건 변경 재동의, 수동 마감 후 기존 신청 재요청, 삭제 연계 처리 |

웹 베타→Android 폐쇄 테스트→프로덕션 순서로 준비·검증된 기능을 공개하며 일정은 재산정한다. 베타 대상·기능, Android 제공 방식·실시간 연결, 공식 게시자, AI 보관·품질·운영 한도, 지원·분쟁·보관 세부는 팀 검토다. 이번 문서 최신화를 실제 구현·검증·배포 완료로 보고하지 않는다.
