# 유미당 USER FLOW — PRD 기반 사용자 흐름

현재 확정·미정·검토 필요 정책은 [정책.md](../../../정책.md)에서 확인한다. 이 문서는 계획·화면 설계이며, 정책 문구의 동기화를 코드·DB·화면의 구현 및 검증 완료로 해석하지 않는다.

## 1. 기준과 읽는 방법

- 작성일: 2026-09-22. 이전 USER_FLOW의 내용은 사용하지 않고, 핵심 흐름·기능별 분기·예외·확인 기준으로 나누는 문서 구조만 참고해 새로 작성했다.
- 기본 기준: [PRD.md](../requirements/PRD.md)의 여성 전용 1:1 동행과 인증 → 탐색 → 신청·대화 → 양쪽 확정 → 실제 동행 → 상호 평가.
- 보완 기준: [추가 요구 사항.md](<../requirements/추가 요구 사항.md>)와 [전달.md](../requirements/전달.md)의 **1. 구체적인 수정 요청**. 추가 요구 사항 7-4의 S01 후속 수정 포함.
- 화면·배치 기준: [현재 와이어프레임](./yumidang-wireframes.html). 전체 구조와 화면 목록은 [IA.md](./IA.md)에 정리한다.
- 최신 대화 우선: **이용자는 성인 여성만, 신규 가입은 PASS 휴대폰 본인확인, 기존 회원의 일반 로그인은 문자 일회용 인증번호, 학교·직장 이메일 인증은 선택**이다. AI 챗봇으로 공고 탐색, 받은 칭찬 누적 가로 차트, 리뷰 한마디의 AI 요약 브리핑을 포함한다.
- 공고 장소는 **카카오 지도 API의 장소명 검색 → 장소 선택 → 주소 자동 입력**, 또는 **우편번호 검색 → 주소 선택** 두 경로로 지정한다.
- 공고 탐색의 최신 확정: **공고 제목·공고에 등록된 장소명·주소 검색**만 제공하며, ‘장소 주변 찾기’는 추후 추가 기능으로 옮긴다. 공고 작성의 장소 지정 기능과 탐색의 주변 검색을 구분한다.
- PRD의 목적을 유지하고 이후 확정한 유료·인증·AI·프로필·평가 요구를 반영한다. 전달.md 2장의 미반영 개편안이나 이전 문서에만 있던 기능은 가져오지 않는다.
- PASS 결과의 성명·성별·생년월일·휴대폰번호로 성인 여성 가입 자격을 확인하고 DI로 중복 가입을 막는다. 사진은 필수이며 유료 요청형·제공형의 작성자와 신청자는 각각 등록·신청 전에 계좌 1원 인증을 완료해야 한다.
- 아래 화살표는 서비스 설계다. HTML의 예시 전환과 실제 인증·저장·권한 검사·외부 연동 완료를 동일하게 보지 않는다. 미결정 정책은 따로 표시한다.

## 2. 핵심 흐름

~~~text
가입: S05 PASS 휴대폰 본인확인 → 성인 여성 자격 확인 → S06 사진 등록·선택 성향 입력
     → 가입 완료 버튼 → 완료 안내 팝업 → S00 홈
     [신분증 촬영·제출이나 신원정보 수기 입력 없음 / 학교·직장 이메일은 가입 후 선택 인증]

로그인: 기존 회원 → S05 문자 일회용 인증번호 → 원래 목적 화면, 목적 없으면 S00 홈
        [휴대폰번호 변경·로그인 불가 계정복구·탈퇴 후 재가입은 PASS 재인증]

탐색: S00 홈 / S01 둘러보기 / S09 카테고리 / S20 AI
     → S02 공고 상세 ↔ S14 작성자 신뢰정보
     → S08 신청 [유료는 계좌 인증]
     → 신청 완료 → S11 대화
     → 작성자가 상대 선택·최종 동의 요청
     → 신청자가 같은 일정·지역·금액·지급 방향 확인 후 동의
     → 양쪽 확정 → S16 약속 상세 → 실제 동행
     → 완료 처리 → S17 평가 제출 → 공개 조건 충족
     → S13/S14 칭찬 차트·AI 요약 브리핑·원문 리뷰 → 다음 동행 판단

모집: + / 카테고리 모집 / 행사 기반 모집 / 나의 새 모집
     → S03 일정·장소·비용 작성 → S04 확인 [유료는 계좌 인증]
     → 직접 등록 → 생성한 S02 작성자 상세
     → 신청자와 S11 대화 → 위의 양쪽 최종 동의 흐름
~~~

신청은 참여 요청이고, 상대 선택은 작성자의 최종 동의 요청이다. 어느 단계도 신청자의 최종 동의를 대신하지 않는다. 무료·유료 모두 같은 확정 순서를 사용한다.

## 3. 로그인·가입·프로필 입력

| 단계·상황 | 사용자 행동과 결과 | 실패·제한·복귀 |
|---|---|---|
| S05 진입 | 홈 로그인 또는 회원 기능의 로그인 안내 → 휴대폰번호 입력 | 기존 회원과 신규 회원을 구분해 다음 인증으로 연결 |
| 기존 회원 | 문자 일회용 인증번호 요청·입력·확인 → 로그인 완료 → 원래 목적 화면 | 만료는 재요청, 실패는 코드·번호 확인과 재시도. 목적이 없으면 S00 |
| 신규 회원 | 필수 동의 → PASS 휴대폰 본인확인 → 성명·성별·생년월일·휴대폰번호·DI 확인 | 실패·정보 미확인은 재시도. 성인 여성이 아니면 계정을 만들지 않고 “유미당은 성인 여성만 가입할 수 있어요” 안내 |
| 예외 재인증 | 휴대폰번호 변경·로그인 불가 계정복구·탈퇴 후 재가입 → PASS 재수행 | 성공 후 해당 목적 흐름으로 복귀 |
| 가입 프로필 | PASS 가입 자격 확인 완료 → S06 | PASS 외에 신분증 촬영·제출이나 같은 신원정보 수기 입력 단계를 추가하지 않음 |
| 사진 등록 | S06 중앙 사진 등록 → S15 선택·미리보기 → 이 사진 사용 → S06 복귀 | 사진이 없으면 가입 완료 시 ‘사진 필요’. 사진 선택만으로 가입 완료하지 않음 |
| 선택 성향 | 취향·대화 방식 버튼 또는 직접 추가, MBTI 입력 | 모두 비워 둬도 가입 가능. 취향·대화 방식 최소 1개 조건 없음 |
| 가입 완료 | 사진 등록 후 ‘가입 완료’ → 안내 팝업 → ‘홈으로 이동’ → S00 | 별도 완료 화면·가입 후 필수 성향 단계 없음. 신규 가입은 이전 신청/AI가 아닌 홈으로 이동 |

서비스 이용 대상은 성인 여성이다. PASS에서 확인한 성명·성별·생년월일·휴대폰번호로 가입 자격을 확인하고 DI로 중복 가입을 막는다. 사용자가 인증정보를 직접 입력하거나 수정해 자격 확인을 우회할 수 없다. 자격 불충족 화면에는 상세 성별·생년월일 값을 노출하지 않는다.

MBTI 입력칸을 누르면 화면 중앙에 가로 구분선이 있는 4열×2행 패널이 열린다. 위 E/S/T/J, 아래 I/N/F/P 중 열마다 하나를 선택해 네 글자로 적용하거나 비워 둔다. 가입 후 S15-2에서도 같은 방식을 사용한다.

## 4. 선택 이메일 인증과 유료 계좌 인증

### 4-1. 학교·직장 이메일 인증

~~~text
S13 프로필·후기 또는 안전·계정 → S21 인증 관리
→ S07 학교/직장 선택·기관 이메일 입력 → 인증 메일 발송
→ 코드 입력·확인 → 인증 완료·인증배지 아이콘 표시 → 진입 화면 복귀
~~~

- 가입 뒤 선택적으로 수행한다. 이메일 미인증을 기본 가입 완료의 장애로 두지 않는다.
- 도메인 확인 필요 시 지원 기관 안내와 주소 재입력으로, 만료는 다시 보내기로, 실패는 주소·코드 확인과 재시도로 이어진다.
- 배지는 명칭 대신 계좌 인증배지와 구분되는 아이콘이다. 이메일·도메인은 다른 회원에게 공개하지 않는다. 아이콘 클릭 시 해당 기관 이메일을 사용할 수 있음을 확인한 것이며 현재 재학·재직이나 사용자 안전을 보증하지 않는다고 표시한다. 별도 도움말 화면은 만들지 않는다.
- 검토용 코드 안내는 표시하지 않는다. 지원 기관·코드 유효시간·재시도 제한·갱신 주기는 미정이다.
- 이메일 인증은 여성 전용 이용 정책의 예외 가입 수단이 아니다.

### 4-2. 1원 계좌 인증

| 진입 | 인증과 복귀 | 복귀 후 사용자 행동 |
|---|---|---|
| S21에서 인증 선택 | S22 은행·본인 개인 계좌 입력 → 1원 요청 → 입금 코드 확인 → PASS 성명과 예금주 대조 → 완료 → S21 | 인증 상태 확인 |
| S04 유료 등록 | 유료 요청형·제공형 공고 작성 완료 → 최종 ‘등록하기’ → 미인증이면 등록 차단 → 작성 내용 유지 → S22 인증 → S04 복귀 | 내용을 다시 확인하고 ‘등록하기’를 눌러 직접 등록. 인증 성공만으로 자동 등록하지 않음 |
| S08 유료 신청 | 소개 메시지·조건 작성 완료 → 최종 ‘신청하기’ → 미인증이면 신청 차단 → 입력 유지 → S22 인증 → S08 복귀 | 내용을 다시 확인하고 ‘신청하기’를 눌러 직접 제출. 인증 성공만으로 자동 신청하지 않음 |

개인 계좌는 PASS에서 확인한 성명과 계좌 인증 제공사가 확인한 예금주가 공급사의 명의 대조 기준에 따라 일치할 때만 인증한다. 사용자가 예금주명을 직접 입력하거나 수정해 우회할 수 없다. 초기 출시에서는 PASS 회원 본인의 개인 명의 계좌만 허용하며 개인사업자·법인 계좌는 지원하지 않는다. 명의 불일치 시 “본인 명의의 다른 개인 계좌를 사용해 주세요”라고 안내한다. 만료는 재요청으로, 요청 실패는 입력 유지·재시도로 안내한다.

검토용 코드는 화면에 표시하지 않는다. 무료 동행에는 계좌 인증을 요구하지 않는다. 유료 요청형은 작성자가 신청자에게 지급하고, 유료 제공형은 신청자가 작성자에게 지급한다. 계좌 인증배지는 현재 인증 상태가 유효할 때만 공개 프로필·공고 카드·공고 상세의 작성자 이름 옆에 표시하며 변경·취소·만료·무효 처리 시 숨긴다.

계좌 인증배지 아이콘 클릭 시 “본인 명의 계좌가 확인된 사용자입니다. 계좌 확인은 거래·만남의 안전이나 대금 지급을 보증하지 않습니다.”라고 표시한다. 별도 도움말 화면은 만들지 않으며 인증에 사용한 은행명·계좌번호·예금주명은 다른 사용자에게 공개하지 않는다.

유료 요청형·제공형의 동행 비용은 사용자끼리 직접 주고받는다. 유미당은 결제대행·대금 보관·에스크로·자동 송금·정산·자동 환불·지급 완료 보증을 제공하지 않는다. 지급 방법과 시점은 확정된 두 사용자가 1:1 채팅에서 직접 합의하며, 채팅에서 전달한 계좌를 인증 계좌라고 자동 보증하지 않는다.

## 5. 홈·둘러보기·카테고리 탐색

### 5-1. 홈 S00

| 영역 | 흐름 |
|---|---|
| 상단 | 본인 이름 전체 또는 로그인 버튼을 종 아이콘 왼쪽에 배치. 로그인 → S05, 종 → S12 |
| 행사 배너 | 가로 넘김으로 확인 → 행사 S09-3. 우측 위 전체보기 → S09-2 |
| 다가오는 약속 | 약속 선택 → S16. 약속이 없으면 없음 안내 |
| 어떤 동행을 찾으세요? | 카테고리 선택 → S09의 해당 공고 목록 |
| 행사 실패 | 실패 문구 우측 새로고침 아이콘 → 재조회 |
| AI / + | AI → S20, + → 로그인 확인 후 S03 |

본문 순서는 행사 배너 → 다가오는 약속 → 카테고리다. 본인 이름 영역에서 인증 아이콘·나이·당도는 제거한다. PASS에서 확인한 본인 이름의 전체 표시가 다른 회원에게의 공개 범위를 바꾸지는 않는다.

### 5-2. 둘러보기 S01

~~~text
공고 제목·등록된 장소명·주소를 검색어로 입력 → 검색 버튼/Enter
→ 공고 제목 / 등록된 장소명 / 등록된 주소 중 하나가 일치하는 공고
→ 카드 본문 S02 / 작성자 S14
~~~

- 검색어의 앞뒤 공백을 정리하며, 빈 검색어로 검색하면 다른 선택 조건 내의 목록을 다시 보여준다.
- 검색 대상은 공고 제목·등록된 장소명·주소 세 항목이다. 공개 동네명만으로 제한하지 않으며, 검색 범위를 공고 소개·리뷰 등으로 확대하지 않는다.
- 필터에는 카테고리·동행 비용·일정·작성자 나이를 둔다. 비로그인도 일정 필터를 사용할 수 있고 나이는 전체만 사용한다. 세부 나이 선택 때 로그인 안내를 제공한다.
- ‘장소 주변 찾기’는 현재 흐름에서 제외한다. 기준 장소 선택, 반경 1/5/10 km, 거리 안내·거리순 정렬을 제공하지 않는다. 주변 검색은 나중에 별도로 추가한다.
- 주소 검색은 등록 주소의 일치 여부로 공고를 찾는 기능이며, 해당 주소 근처의 공고까지 찾는 기능이 아니다.
- 등록 주소 검색과 주소 표시 권한은 구분한다. 확정 전 상세 주소 표시 제한은 유지하되, 검색 일치로 장소를 추정할 가능성은 있으므로 검색 응답의 정보 노출 범위를 구현 시 확인한다.
- 결과가 없으면 조건을 바꾸고, 조회 실패는 재시도한다. 현재 일정 필터 등 예시 구현의 한계는 14장에 따로 기록한다.

### 5-3. 카테고리 S09

홈에서 선택한 카테고리의 공고 목록 → S02 공고 또는 S14 작성자. 모집 버튼은 선택 카테고리를 S03에 전달한다. 공고 없음과 조회 실패를 구분한다.

## 6. 공고 작성·장소 지정·등록

### 6-1. 작성과 장소 입력

~~~text
+ / 카테고리 모집 / 행사 상세 / 나의 새 모집
→ 로그인 확인 → S03
→ 카테고리·제목·소개 / 무료·유료 유형·금액
→ 시작 날짜·시간 / 종료 날짜·시간
→ 만남 장소 지정
   ├─ 장소명 검색 [카카오 지도 API의 장소 검색]
   │  → 검색어 입력 → 장소명·주소가 붙은 결과 → 장소 선택
   │  → 선택 장소의 주소 자동 입력
   └─ 주소로 찾기 [우편번호 검색]
      → 도로명·지번 등으로 검색 → 주소 선택
      → 주소·우편번호 자동 입력
→ 상세 만남 지점 입력 / 공개 지역 확인
→ 행사 연결 [선택] → S04 등록 전 확인
~~~

- 장소명 검색은 좌측, 주소로 찾기는 우측에 가로 배치한다. 같은 이름의 장소는 주소로 구분한다.
- ‘삼청 전시관·성수 전시장’ 같은 고정 후보를 처음부터 나열하지 않는다. 최근 검색을 보여주고 재사용·개별 삭제할 수 있게 한다.
- ‘주소 후보를 선택해 주세요’ 문구는 제거한다. 검색 후 결과가 없으면 검색어를 바꾸게 한다.
- 장소명 검색은 카카오 지도 API의 장소 검색 기능을 사용하며, 도로명·지번·우편번호 선택은 우편번호 검색 서비스를 연결한다. 현재 HTML은 실제 API 대신 예시 검색을 사용한다.
- 주소 자동 입력 뒤 ‘3번 출구 앞’ 같은 상세 만남 지점을 작성한다. 공개 미리보기는 시·구·동이며 정확한 주소·상세 지점은 확정 상대에게만 공개한다.
- 시작·종료 날짜와 시간을 각각 입력한다. 종료가 시작보다 늦어야 하며 날짜를 넘기는 일정도 허용한다. 같거나 역전된 일시는 오류 안내한다.
- 유료는 금액과 지급 방향을 확인한다. 동행 비용은 행사 입장료와 별개다.

### 6-2. 행사 연결과 등록

| 단계 | 사용자 행동·결과 | 예외·복귀 |
|---|---|---|
| 행사 연결 | 진행 중·예정 행사의 이미지·이름·기간 세로 목록 → 선택 | 행사장 주소를 후보로 채우고 실제 일정·만남 지점 재확인 |
| 행사 전체보기 | S09-2 선택 모드 → 행사 선택 → 작성 중인 S03 복귀 | 입력 유지. 행사 선택으로 작성 일정을 자동 변경하지 않음 |
| 다음 | 제목·장소·일정·유료 금액 확인 → S04 | 필수 누락·잘못된 일정 안내 |
| 등록 전 확인 | 상대 나이·바라는 점, 일정 범위·공개 지역·비용·지급 방향 확인 | 현재 나이는 선택 칩, 성별 선택 없음 |
| 유료 등록 | 요청형·제공형을 선택해 작성한 뒤 최종 ‘등록하기’ → 미인증이면 차단 → 입력을 유지한 채 S22 → S04 복귀 → 직접 등록 | 인증 성공을 등록 성공으로 처리하지 않음 |
| 등록 | 등록 중 → 성공 시 생성한 S02 작성자 상세로 즉시 이동 | 별도 등록 완료 화면 없음. 실패 시 입력 유지·재시도 |
| 작성 이탈 | 이탈 확인 → 계속 작성 또는 나가기 | HTML은 검토 세션에서 입력 유지. 실제 임시저장 보관 정책은 미정 |

### 6-3. 공고 관리

S02 작성자는 상대 선택, 공고 수정 S03, 모집 마감, 삭제 확인으로 진입한다. 상대 선택은 S11 최종 동의 대기로 연결하며 모집 마감과 동일한 행동이 아니다. 삭제 확인에서 돌아가면 작성자 상세를 유지한다.

수정·마감·삭제의 허용 시점과 확정 이후 조건 변경은 미정이다. 현재 HTML의 관리 버튼과 상태만으로 수정 저장·삭제·관련 신청 처리가 구현됐다고 보지 않는다.

## 7. 공고 상세의 역할 분기와 신청

| 보는 사람·공고 상태 | 가능한 흐름 | 공개·제한 |
|---|---|---|
| 비로그인 | 공개 공고 확인 → 로그인하고 신청 → S05 | 시스템 별칭. 기존 회원은 신청으로 복귀, 신규 가입은 홈으로 이동 |
| 신청 가능한 회원 | S14 신뢰정보 확인 또는 S08 신청 | 마스킹 이름·공개 지역 |
| 작성자 | 신청자 선택·동의 요청, 공고 관리 | 본인 공고 관리 권한과 참여자 열람 권한 분리 |
| 이미 대화 중 | 기존 S11 대화로 이동 | 신청과 최종 확정은 별도 |
| 최종 동의 대기 | S11에서 조건·응답 상태 확인 | 아직 상세 주소·전체 실명 공개 전 |
| 확정 당사자 | 확정 S11 → S16 약속 상세 | 상대 전체 실명 표시·상세 만남 장소 |
| 확정 공고의 제3자·모집 마감·조건 불일치 | 상태 확인 후 탐색 복귀 | 새 신청 불가, 당사자의 비공개 정보 제외 |
| 삭제됨 | 삭제 안내 | 기존 신청·대화 보존 정책은 별도 |

실명 공개 정책은 PASS에서 확인한 전체 이름을 표시할 관계와 시점을 뜻한다. 전체 이름은 양쪽 확정 전까지 기존 공개 범위에 따라 마스킹하며, PASS의 생년월일·휴대폰번호·DI는 공개하지 않는다.

S08에서 일정·공개 지역·동행 비용·지급 방향을 확인하고 소개 메시지를 작성한다. 유료 요청형·제공형에서 최종 ‘신청하기’를 눌렀을 때 미인증이면 신청을 차단하고 S22로 안내한다. 인증 전 입력은 보존하고 성공 후 S08로 복귀하며 자동 제출하지 않는다. 사용자가 다시 ‘신청하기’를 누르면 제출 중 → 신청 완료 → 채팅하기 S11로 진행하고, 실패하면 내용을 유지해 다시 제출한다.

일정 겹침 상태는 안내 후 신청을 계속할 수 있는 화면이며 기존 약속을 자동 취소하지 않는다. 최종 확정 단계의 일정 충돌과 구분한다. 실제 충돌 판정은 후속 구현에서 확인한다.

## 8. 채팅과 양쪽 최종 동의

~~~text
S08 신청 완료 / S10 대화 목록 / S13 내 동행
→ S11 확정 전 대화·공고/프로필 확인
→ 작성자: 상대 선택·최종 동의 요청 [같은 조건에 대한 작성자 의사]
→ 작성자 화면: 신청자의 최종 동의 대기
→ 신청자 화면: 일정·공개 지역·금액·지급 방향 확인
   ├─ 동의하지 않기 → 확정 전 대화 상태
   └─ 이 조건에 동의하고 확정
      → 조건 일치·확정 가능 여부 확인
      → 양쪽 확정 → 전체 실명·상세 장소 공개 → S16 약속
~~~

S02 상대 선택, S13 받은 신청, S11 작성자 버튼은 같은 최종 동의 절차로 연결한다. 작성자의 선택만으로 다른 신청을 종료하거나 해당 약속을 확정하지 않는다. 신청자가 대화 후 생각을 바꿀 수 있도록 마지막 의사 확인을 분리한다.

| 상황 | 제공할 흐름 |
|---|---|
| 최종 동의 요청 전 | 신청자는 대화하고 작성자 선택을 기다림 |
| 조건 변경됨 | 기존 요청의 조건으로 확정하지 않고 새 조건 확인·다시 동의 요청 |
| 확정 일정 겹침 | 확정 불가 안내와 상대 확인. 기존 약속 자동 취소 없음 |
| 메시지 전송 실패 | 입력 내용 확인·재전송 |
| 종료된 대화 | 기존 대화 읽기, 새 메시지 입력 제한 |
| 일정 변경 제안 | 아직 합의되지 않은 제안임을 표시. 확정 후 변경 절차는 미정 |

조건 버전·실제 사용자 권한·동시 확정은 서버에서도 확인해야 한다. HTML의 역할 전환으로 양쪽 화면을 보는 것은 두 계정 간 검증이 아니다.

## 9. 행사 탐색과 공고 연결

| 진입·목적 | 흐름·포함 기준 |
|---|---|
| 홈 배너 전체보기 | S09-2 일반 목록 → 이번 주 새로 시작한 행사 기본 노출 |
| 진행 중 포함 | 선택 기간과 행사 기간이 겹치는 장기 행사까지 포함. 지역·기간·유형으로 좁힘 |
| 일반 목록의 행사 선택 | S09-3 → 기간·장소·입장료·출처·운영 안내 확인 |
| 관련 동행 찾기 | S09-3 연결 공고 → S02 / 작성자 S14 |
| 이 행사로 모집 | 로그인 확인 → 행사 정보를 연결한 S03. 실제 동행 일정·만남 지점은 작성자가 확인 |
| S03에서 행사 전체보기 | 같은 S09-2의 선택 모드. 진행 중·예정 행사 → 선택 → 입력을 유지한 S03 복귀 |
| 선택 모드 취소 | 선택하지 않고 돌아가기 → S03. 일반 탐색의 상세 이동과 구분 |
| 결과 없음·실패 | 조건 변경 / 재조회 |
| 종료된 행사 | 지난 정보·연결 공고 확인. 현재 화면은 새 모집 버튼 대신 종료 안내 |

행사 선택 모드는 기간 적용 전 진행 중·예정 전체를 보여주며, 기간 적용 후에는 해당 기간과 겹치는 행사로 좁힌다. 일반 목록의 ‘이번 주 신규’ 기준을 작성용 선택 모드에 강제하지 않는다.

현재 연결 대상은 공연의 KOPIS와 전국 축제의 TourAPI다. 서울 열린데이터광장은 HTTPS 조건 충족 전 연결하지 않는다. 실제 연동 시 제공된 운영 안내·개별 공식 페이지를 확인하게 한다. 현재 HTML의 출처 사이트·예시 카드는 실제 운영일·회차·잔여석 확인 결과가 아니다.

공연·뮤지컬 Top 10은 현재 와이어프레임의 별도 검토 영역으로 남긴다. 예시 데이터를 실제 순위로 주장하거나 새 순위 정책을 확정하지 않는다.

## 10. AI 챗봇의 자연어 공고·행사 탐색

~~~text
S00 또는 S01의 + 위 AI 버튼 → S20
→ 자연어로 취향·지역·성향·대화 방식·원하는 MBTI 전달
→ AI가 이해한 조건 확인
   ├─ 장소 표현이 모호함 → 검색할 장소명·주소를 되묻기
   └─ 조건 칩 수정·적용
→ 동행 공고 결과 / 행사 결과를 구분해 확인
   ├─ 공고 → S02, 작성자 → S14
   ├─ 행사 → S09-3 → 관련 공고 또는 행사 기반 모집
   └─ 검색어로 둘러보기 → S01
~~~

- 비로그인은 로그인 안내. 기존 회원 로그인 후 S20 복귀, 신규 가입 완료 후 홈으로 이동한다.
- 사용자 메시지는 오른쪽, AI 답변은 왼쪽이다. ‘이번 주말 갈 전시 찾아줘’ 예시도 전송하면 사용자 메시지로 표시한다.
- 현재 대화에서 명시한 조건을 프로필보다 우선한다. 상대 MBTI 미입력만으로 자동 제외하지 않고 확인할 점으로 표시한다.
- 조건에 맞는 공고와 추천 이유·확인할 점을 함께 제공한다. 실제 공고가 없는 행사를 매칭 가능한 공고처럼 표현하지 않는다.
- 공고 결과 없음은 조건 확대 또는 직접 모집 S03으로 연결한다. 한도 도달 시 찾은 카드가 있으면 일부만 확인했다는 안내와 함께 제공하고, 카드가 없으면 확인 불가로 안내한다. 확인 불가를 0건으로 표시하지 않는다. 연결 실패는 재시도 또는 S01 일반 탐색으로 연결하며 한도 수치는 미정이다.
- AI와 일반 탐색의 공고 키워드 검색 대상은 제목·등록된 장소명·주소로 동일하다. 취향·대화 방식 등의 조건은 별도 필터로 조합하며 반경·거리순 검색은 사용하지 않는다.
- ‘근처·주변’을 요청하면 현재 주변 검색은 지원하지 않음을 안내하고 검색할 장소명·주소를 확인한다. 좌표 검색을 수행했거나 가까운 순으로 찾았다고 표현하지 않는다.
- AI 대화는 현재 탐색 중만 유지하고 종료·새 탐색·로그아웃 시 정리한다. 서비스 서버의 이력·오류·사용량 로그에 원문을 저장하지 않는다. 외부 제공사 보관 조건은 별도로 검토한다.

### ‘이번 주말 갈 전시 찾아줘’의 포함 기준

| 전시 기간 | 주말 검색 결과 |
|---|---|
| 지난달 시작, 이번 주말까지 진행 | 포함 — 장기 전시 |
| 이번 주 시작, 이번 주말과 기간이 겹침 | 포함 — ‘이번 주 새로 시작’ 표시 |
| 이번 주 시작했지만 금요일 종료 | 제외 — 주말과 기간이 겹치지 않음 |
| 사용자가 ‘이번 주 새로 시작한 전시만’으로 명시 | 주말 조건과 함께 신규 조건으로 좁힘 |

기간에 포함돼도 실제 운영 여부는 다를 수 있으므로 휴관일·공연 회차는 제공 안내·공식 페이지로 확인한다. 홈의 신규 중심 노출과 AI의 방문 기간 탐색은 목적이 다르다.

## 11. 나·사진·공개 프로필·AI 요약 브리핑

| 시작 | 행동·결과 |
|---|---|
| S13 내 동행 | 보낸 신청 → S11 대화/S18 철회, 받은 신청 → S11 대화·최종 동의 요청, 진행 약속 → S16, 완료 동행 → S17 |
| S13 내 공고 | 작성자 S02 또는 새 모집 S03 |
| S13 프로필·후기 | 받은 후기, S14 내 공개 프로필 미리보기, S15 사진 변경, S15-2 성향 편집, S21 인증 관리 |
| S13 안전·계정 | S21 인증 관리 / S19 안심 수칙 |
| S15 사진 교체 | 선택 → 미리보기 → 저장 → S06 또는 S13 등 진입 화면 복귀. 실패 시 기존 사진 유지, 마지막 사진 삭제 불가 |
| S15-2 성향 편집 | 선택 칩·직접 추가·MBTI·선택 소개 수정 → 저장 → S13. 실패 상태는 입력 유지 |

S13은 현재 ‘나’의 내 동행·내 공고·프로필/후기·안전/계정 구성을 사용한다. 전달.md 2장의 명칭·기본 화면·세로 구조 개편은 선반영하지 않는다.

받은 후기는 S13과 S14에서 다음 순서로 읽는다.

~~~text
받은 칭찬 키워드의 누적 가로 막대 차트
→ 받은 리뷰 한마디를 요약한 AI 요약 브리핑
→ 사용자별 원문 리뷰
~~~

- 칭찬 차트는 좋아요 평가에서 선택한 버튼식 키워드를 사용자별로 누적 집계한다. 상위 5개를 가장 많은 항목 기준의 막대 길이와 실제 횟수로 표시한다.
- AI 요약 브리핑은 한마디 있는 공개 후기 3개 이상부터 기준 후기 수와 함께 제공하고 한마디 없는 평가·비공개 후기를 제외한다. 후기 한마디의 내용을 요약하며 원문에 없는 평가를 만들지 않는다.
- 리뷰 한마디는 선택사항이므로 평가 수와 텍스트 후기 수가 다를 수 있다. 한마디 없는 평가는 요약 기준 개수에 포함하지 않는다. 텍스트가 부족한데도 요약이 있는 것처럼 보여주지 않는다.
- 후기가 없으면 없음 안내, 요약 실패 시 원문은 계속 볼 수 있게 한다. 요약을 원문 리뷰의 대체물로 두지 않는다.

## 12. 약속 완료·평가·철회·취소

### 12-1. 약속과 완료

~~~text
S16 예정 약속 확인 → 실제 동행 → 종료 이후 양쪽 완료 확인 또는 자동 완료
→ 완료 처리·완료 횟수 즉시 반영·평가 작성 가능
→ S17 평가 제출
→ 공개 조건 충족 시 상대 후기 열람 가능·당도 동시 반영
~~~

현재 화면과 추가 요구 사항에서 유지한 완료·평가 기준은 다음과 같다. 실제 시간 경과·자동 작업·분쟁 처리는 HTML에서 검증한 기능이 아니다.

- 예상 종료 시각 이후 두 명 모두 완료 확인해야 수동 완료가 성립한다. 한 명만 확인하면 완료 전 상태를 유지한다. 처리하지 않으면 예상 종료 +24시간에 자동 완료하는 기준이며 취소·불발·분쟁은 제외한다.
- 양쪽 후기를 제출하면 24시간 이전이어도 즉시 공개한다. 한쪽만 제출하면 동행의 실제 완료 시각부터 24시간 후 공개하며, 이 시각 이후 작성 기한 안에 제출한 후기는 즉시 열람할 수 있다. 실제 알림 클릭이나 후기 제출 시각부터 24시간을 새로 계산하지 않는다. 대기 중에도 평가는 작성할 수 있다. 당도는 상대방의 후기를 열람할 수 있게 될 때 동시에 반영하며 실제 열람 여부와는 무관하다. 완료 횟수는 후기 제출·공개와 관계없이 동행 완료 즉시 반영한다.
- 미완료·실제 분쟁·불발/노쇼 상태는 공개에서 제외한다. 작성 기한은 실제 완료 시각부터 7일이며 공개 시점과 구분한다. 제출 성공 뒤 공개 여부는 새 상태를 조회해 표시하며 하루 주기 작업까지 기다리지 않는다.
- 실제 이의 검토 중 작성·기한·공개를 보류한다. 동행 인정 후 남은 작성 기간을 재개하고 최소 24시간을 보장하는 기존 예외를 유지한다. 불발·노쇼 판단·증거·종결 절차는 미정이다.
- 당도 산식은 민규·팀 검토 필요다. 공개 조건 충족을 임의의 별점→당도 자동 환산 규칙으로 해석하지 않는다.

### 12-2. 상호 평가 S17

~~~text
S13 완료한 동행 / S16 평가 / S12 평가 알림
→ 평가 가능한 당사자·기간 확인
→ 가로 버튼: 좋아요 / 보통이에요 / 별로예요
   ├─ 좋아요 → 별점 1~5 필수 + 칭찬 최대 3개 선택 + 한마디 선택
   └─ 보통이에요·별로예요 → 별점 1~5 필수 + 한마디 선택
→ 최종 제출
   ├─ 실패 → 내용 유지·수정·재시도 가능
   └─ 성공 → 제출 완료·수정 불가 → 약속 상세 S16
→ 공개 조건 충족 → S13/S14 후기·칭찬 집계·AI 요약 브리핑
~~~

제출 전에는 경험 선택 단계로 돌아갈 수 있다. 좋아요에서 보통·별로로 바꾸면 이전 칭찬 키워드는 제출하지 않는다. 최종 제출 성공 후에는 재진입해도 수정하지 못한다. 제출 완료와 공개 완료는 다른 상태이며, 완료 전·평가 불가·분쟁 보류 상태를 정상 제출로 처리하지 않는다.

### 12-3. 신청 철회와 확정 동행 취소 S18

| 상황 | 흐름 | 범위 |
|---|---|---|
| 확정 전 신청 철회 | S11 또는 S13 보낸 신청 → 사유 선택·기타 입력 → 유지하기 또는 철회 → 결과 → S10 | 유지하기는 이전 화면. 실패는 재시도. 화면은 사유 안내·기존 대화 보존·새 메시지 제한을 설명 |

S16의 취소됨 화면은 상세 장소를 숨기는 예시다. 취소 후 모든 경로의 이름·주소 접근 정책과 일관된 차단은 별도로 정해야 한다.

## 14. 구현·검증 경계와 후속 확인

### 최신 요구와 현재 HTML의 차이

이번 산출물은 PRD와 확정 요구사항으로 새로 작성한 설계 문서다. 현재 HTML은 인증·AI·검색·행사·후기·시간 상태를 예시로 제공한다. 실제 API·서버 저장·권한·두 사용자 간 처리·배포 검증은 이번 문서 작업에서 실행하지 않는다.

현재 소스에서 확인되는 다음 차이를 최신 설계로 그대로 옮기지 않는다.

- **가입·로그인 분리:** 신규 가입은 PASS에서 성명·성별·생년월일·휴대폰번호·DI를 확인해 성인 여성 자격을 검증하고, 가입 완료 회원의 일반 로그인은 문자 일회용 인증번호를 사용한다. 현재 HTML은 이 분리가 반영되기 전의 예시이며 이번 작업에서 변경하지 않는다.
- **계좌 명의 기준:** PASS에서 확인한 성명과 계좌 인증 제공사가 확인한 예금주가 일치하는 개인 명의 계좌만 허용한다. 개인사업자·법인 계좌는 초기 출시에서 지원하지 않는다.
- **AI 요약 명칭·내용:** 문서는 최신 ‘AI 요약 브리핑’과 받은 리뷰 한마디 요약을 명시한다. 현재 HTML의 ‘AI 리뷰 요약’은 예시 문구다.
- **검색 범위 변경:** 현재 HTML의 제목·공개 지역 검색과 주변 장소·반경 기능은 최신 설계와 다르다. 후속 화면 구현에서 제목·등록 장소명·주소 검색으로 바꾸고 S01·S20의 주변 검색 진입·조건·결과를 제거해야 한다. HTML은 이번 문서 수정에서 변경하지 않는다.
- S01 일정 필터의 선택값은 현재 공고 결과 판정에 사용되지 않는다. 초기화·닫기 동작도 최신 검색 범위에 맞춰 후속 구현에서 정리해야 한다.
- S04 계좌 인증 안내는 실제 유료 유형·인증 상태에 의존한다. 검토 상태 이름만 선택해도 항상 별도 안내가 보이는 구조는 아니다.
- 일부 연결 메타데이터·주석은 실제 버튼과 다르다. S07의 가입 완료 진입 설명은 현재 팝업→홈 흐름과 맞지 않으므로 새 서비스 경로에 넣지 않았다.
- S11 일정 충돌·조건 변경, S16 완료 시계·이의 처리 등은 상태 화면이 있다는 것과 실제 판정·자동 전환이 있다는 것을 구분한다.
- 공고 수정의 기존 값 로딩·저장, 삭제·마감의 관련 데이터 처리, 취소 후 비공개 정보 접근은 실제 구현에서 확인해야 한다.

### 후속 구현의 확인 시나리오

| 확인 범위 | 기대 결과 |
|---|---|
| 가입 | 신규 사용자는 PASS로 성명·성별·생년월일·휴대폰번호·DI를 확인해 성인 여성 자격을 검증한 뒤 사진을 등록. 선택 성향·이메일 미입력 허용. 기존 회원 일반 로그인은 문자 일회용 인증번호 사용 |
| 복귀 | 기존 로그인은 목적 화면, 신규 가입은 팝업 후 홈. 계좌 인증은 입력을 유지한 원래 작업으로 복귀하고 직접 제출 |
| 탐색·공개 | 공고 제목·등록 장소명·주소 각각으로 검색 가능. 주변 검색·반경·거리 정렬 없음. 주소 검색 일치와 주소 표시 권한을 구분하고 확정 전후·제3자의 정보 노출 확인 |
| 장소·작성 | 카카오 장소명 검색·선택 후 주소 자동 입력 또는 우편번호 검색·주소 선택. 시작/종료 검증, 최근 검색, 행사 선택 후 입력 유지, 생성 공고 이동 |
| 유료·매칭 | 요청형·제공형 작성자는 최종 등록 전, 신청자는 최종 신청 전 계좌 인증 필요. 무료 인증 비강제, 인증 전 입력 보존·인증 후 자동 제출 금지, 작성자 선택만으로 확정 불가, 신청자 최종 동의·동일 조건 확인 |
| 행사·AI | 신규 기본/진행 중 포함과 AI 주말 검색 구분. 장기·신규 중 주말 겹침 포함, 금요일 종료 제외, 실제 운영 확인 안내 |
| 평가·후기 | 제출 전 경험 변경·실패 재시도, 성공 후 수정 불가, 칭찬 누적 차트→AI 요약 브리핑→원문, 비공개 리뷰 제외 |
| 실제 연동 | 휴대폰·이메일·계좌 인증, 장소·행사 API, AI 검색·요약, 서버 권한·저장·동시 처리 검증을 예시 UI 확인과 별도로 수행 |

PRD의 회원가입 전환율·신뢰정보 확인율·참여 요청률·채팅 유지율·동행 확정률·실제 완료율·평가 작성률 등은 위 흐름을 평가할 목표 지표다. 목표 수치·산식·분모·실제 수집 완료를 이 문서에서 새로 확정하지 않는다.

확정·미정·검토 필요 정책은 [정책.md](../../../정책.md)에서 관리한다. 당도 반영 시점과 서버의 AI 대화 원문 이력 미저장은 확정이며, 당도 산식·외부 제공사 보관 조건·운영 기록 보관 기준은 별도 검토 대상이다.

‘장소 주변 찾기’는 추후 추가 항목이다. 공고 작성의 카카오 장소 검색·주소 자동 입력·우편번호 검색과 현재의 제목·장소명·주소 검색은 유지한다.
