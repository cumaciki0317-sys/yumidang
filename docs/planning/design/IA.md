# 유미당 IA — 현재 화면 요구사항

기준일:2026-10-19. [정책](../../../정책.md)·[PRD](../requirements/PRD.md)·[USERFLOW](USERFLOW.md)를 따른다. 활성 화면 목표는 S08을 제외한23개다. S07·S08·S22는 현재 화면 ID를 부여하지 않는다. 본 문서는 화면 요구사항이며 실제 서비스 검증 상태는 NOT_RUN이다.

## 1. 전역 내비게이션

하단 탭은 4개다.

| 탭 | 화면 | 역할 |
|---|---|---|
| 홈 | S00 | 신규 행사, 다가오는 약속, 카테고리, AI·작성 진입 |
| U·둘러보기 | S01 | 공고 검색·필터·정렬·상세 진입 |
| 채팅 | S10 | 신청·확정·종료 대화 목록 |
| 나 | S13 | 내 동행·공고·프로필·후기·안전·계정 관리 |

AI 탐색 S20과 공고 작성 S03은 하단 탭이 아니라 홈·둘러보기의 플로팅 버튼에서 진입한다. 알림 S12는 로그인 상태의 상단 종 아이콘에서 진입한다.

## 4. 화면별 정보 구조

### 4-1. 탐색

#### S00 홈

1. 상단: 유미당 로고, 본인 실명 또는 로그인, 알림
2. 이번 주 신규 중 미종료 행사: 가로 배너, 진행 상태, 전체보기
3. 다가오는 약속: 확정 상태·D-day·일정·공개 지역
4. 동행 카테고리: 전시·공연·맛집 등 카테고리 그리드
5. 플로팅 액션: AI 탐색, 공고 작성

#### S01 둘러보기

1. 고정 상단: 검색창, 필터, 정렬, 결과 수
2. 검색 대상: 제목·장소명·주소·연결 행사명
3. 필터: 카테고리·시도 지역·일정·작성자 만 나이19~99세 숫자 범위·모집 중만 보기. 비로그인은 일정·나이 상세 조건 대신 전체 범위만 사용하며 적용하기로 반영한다. 전체 검색에는 공고 나이 상한을 적용하지 않는다
4. 정렬: 등록일 최신순 / 시작일 빠른순
5. 결과 카드: 무료, 모집 상태, 일정, 공개 지역, 작성자, 연결 행사
6. 빈 결과와 조회 실패 상태

#### S09·S09-2·S09-3 행사/카테고리

- S09는 선택한 카테고리의 공고 목록과 작성 진입을 제공한다.
- S09-2는 일반 행사 목록, 공연 하위 장르(콘서트·뮤지컬·연극), 공식 전국 전체 공연 및 13개 분류 Top 10, 작성용 행사 선택을 한 화면에서 상태로 구분한다. 작성용은 연결 가능한 진행 중·예정 전체에서 검색·선택하며 동행 일정으로 자동 축소하거나 날짜 겹침을 강제하지 않는다. 선택 행사의 날짜는 달력에 색으로 강조하고 작성 일정을 자동 변경하지 않는다. 종료 행사는 조회할 수 있지만 새 모집은 제공하지 않는다.
- S09-3은 행사명·기간·장소·입장료·출처·운영 안내·연결 공고와 행사 기반 모집을 제공한다. KOPIS·TourAPI·서울 원천 데이터는 기존 공통 행사 계약으로 정규화해 앱에서 소비하고 실제 확보한 정보만 표시한다. 요금 미확인을 무료로 안내하지 않는다. 행사장은 작성 장소의 후보이며 동행 약속의 일정·상세 만남 지점을 대신하지 않는다. 기본 정보 누락은 안내하고 선택 부가 항목은 없으면 생략한다. 아래 행사 화면 확정 구조를 적용하며 새 서버 계약 구현 완료를 뜻하지 않는다.

### 4-2. 공고와 신청

#### S02 공고 상세

- 공고 제목·카테고리·무료 1:1 표시
- 일정, 공개 지역, 희망 상대, 작성자 요약, 연결 행사
- 신청자: 신청 또는 기존 대화 연결
- 작성자: 수정·마감·삭제·신청자 선택
- 확정 당사자: 전체 이름과 상세 만남 위치
- 확정 제3자: 확정 상태만 표시, 당사자 비공개 정보 제외
- 취소 성립 즉시 S02·S11·S14·S16의 상대 전체 이름을 재마스킹하고 정확한 주소·상세 만남 지점 접근을 회수한다. 공개 지역은 동까지이며 회수된 정보를 클라이언트에 남겨 계속 표시하지 않는다

#### S03→S04 작성

- S03: 기본 정보, 장소명/주소 검색, 상세 지점, 선택 행사 연결, 임시저장. 일반 작성은 행사 영역을 맨 아래, 행사 상세에서 진입하면 맨 위에 둔다. 행사 검색·선택/직접 입력/연결 없음의 세 경로를 제공한다. 모집 마감 미설정 시 동행 시작이 마감이며 행사 선택은 작성 일정을 자동 변경하지 않는다
- S04: 희망 상대 나이, 바라는 점, 일정·마감·공개 지역, 무료 원칙 최종 확인
- 성공: 생성된 S02로 이동
- 실패: 입력 유지, 재시도
- 수동 마감은 새 신청만 차단하고 기존 신청자 대화·시작 전 최종 동의는 유지한다. 핵심 조건 변경 시 기존 최종 동의 요청을 무효화하고 새 조건으로 다시 동의받는다. 확정 후 삭제로 약속 취소를 대신할 수 없다

#### 신청 진입 — S02→S11

- S08의 별도 소개 메시지 입력을 제거하고 S11로 바로 이동한다.
- 첫 메시지 전송 전에는 작성자 알림·채팅 목록·신청 목록에 나타나지 않는다. 미전송 입력은 현재 화면 메모리만 유지하며 이탈 시 삭제 안내 후 삭제한다.
- 일정 겹침은 경고 후 신청 진행을 허용한다. 새 확정은 다른 확정 약속과 일정이 충돌하면 차단한다.
- 첫 전송 성공 시 신청과 작성자 측 1:1 채팅방이 생성된다.
- 본인 철회 후 1분 동안 재신청 불가, 이후 횟수 제한 없이 허용한다. 거절 후에는 재신청 불가다.
- 재신청은 기존 동일 공고·상대 채팅방을 재사용하고 새 메시지 전송 성공 시 성립한다.

### 4-3. 채팅과 확정

#### S10 채팅 목록

- 대기·확정·종료 상태 배지
- 읽지 않은 대화
- 종료 대화 보존
- 대화방 나가기 시 본인 목록 숨김 안내

#### S11 채팅방

- 상대 프로필, 당도, 공고 요약, 무료 상태
- 작성자: 거절 / 대화·합의 후 한 번에 한 명에게 확정 요청 / 요청 철회. 다른 상대에게 요청하려면 기존 요청을 먼저 철회한다
- 신청자: 최종 동의 수락 / 거절; 요청 후 6시간과 시작 시각 중 빠른 때 만료. 만료돼도 신청·대화는 유지하고 약속은 생성하지 않는다. 서버 접수 시각이 만료 시각과 같으면 수락을 거부한다
- 확정 후: 상세 만남 위치, 약속 상세, 시작 전 취소
- 확정 후 양쪽 누구나 일정·장소 변경 제안; 상대 수락·충돌 검사 후 반영
- 변경 만료: 제안 후 6시간·기존 시작·새 시작 중 가장 빠른 때; 거절·미응답이면 기존 약속 유지. 마감과 같은 시각의 수락은 거부한다
- 한 명 확정 후 다른 신청은 모집 종료·읽기 전용; 확정 취소만으로 모집을 자동 재개하지 않으며 작성자가 모집 재개하면 이전 유효 신청·채팅 자동 복원 및 알림
- 신고 안내: 문제 구간 캡처 접수

### 4-6. AI·알림·계정

- S12: 전체/읽지 않음, 모두 읽음, 확정 요청·확정·후기 알림. 진입 시 현재 권한을 재조회하고 공통 상태 영역에서 대상 없음·접근 제한·일시 실패를 구분한다. 확인할 수 없는 사유는 중립 안내와 목록/현재 허용 경로, 일시 통신 실패는 다시 시도·이전 화면을 제공한다. 캐시의 실명·상세 지점을 권한 확인 전에 표시하지 않는다
- S20: 로그인 가드, 간단한 AI 정보 제공 안내, AI/사용자 대화, 빠른 응답, 행사·동행 카드, 새 대화; 설정 지역 사용, 메모리만 유지·화면 종료/로그아웃 시 삭제
- S21: 예정 시작 시각 순 취소 집계·정상 완료 시 0, 첫 3회 경고·이후 연속 3회마다 7일 제한, 경고·제재 시 횟수만 0, 경고 이력 유지; 다른 네이버 계정 변경 메뉴 없음·계정 간 기록 이전 없음, 탈퇴·즉시 재가입·원래 제재 종료까지 기능 제한 유지
- 제한 UI: 신규 작성·신규/재신청·새 확정 요청/수락 차단, 기존 확정 약속 관리·채팅·후기 허용
- 취소 이의 UI: 취소 처리 후 24시간 이내 접수·신청 마감 시각 표시·횟수 우선 반영·기한 종료까지 관련 경고/제재 적용 보류; 미신청이면 기한 종료 후, 신청하면 검토 종료 후 판정; 7일 제한은 실제 적용 시각부터 계산
- S06 가입 약관: AI 탐색 동의는 가입 필수에서 제외하고 첫 사용 시 받는다. 거절하면 일반 검색·일반 동행·계정을 유지한다. 후기 요약 열람·내 프로필 요약 생성·노출·내가 작성한 후기의 AI 요약 활용은 가입 시 각각 선택 체크 세 항목으로 받는다. 세 항목에 모두 동의하지 않아도 가입·일반 동행·계정 이용을 허용하며 미동의한 해당 AI 기능·처리만 제한한다. 짧은 체크 문구와 자세히 보기로 구성하고 기본은 미선택이다. 후기 작성 화면에서는 작성 후기 활용에 동의한 경우 상대방 프로필의 AI 후기 요약에 활용된다는 짧은 안내를 제공하며 동의 체크를 반복하지 않는다. 가입 약관 상단에 `전체 동의`를 제공한다. 선택하면 같은 화면의 모든 개별 동의 항목이 선택되고, 해제하면 모두 해제된다. 개별 항목을 해제하면 전체 동의도 해제 상태가 되며, 모든 개별 항목을 선택하면 전체 동의가 선택된다. 개별 동의와 자세히 보기는 유지하고 기본값은 모두 미선택이다. AI 탐색 첫 사용 동의는 가입 화면의 전체 동의에 포함하지 않는다. 후기 AI 동의 여부를 가입 완료 조건으로 사용하지 않는다. 법적 적합성·공급사 조건의 별도 확인은 필요하다. AI 탐색 철회 시 새 전송을 중단하며, 법적 검토·공급사 조건 확인 전 회원 원문 외부 전송 보류는 유지한다.
- 후기 AI 선택 동의별 상태: 열람 미동의는 본인의 요약 열람만 제한한다. 내 프로필 생성·노출 미동의는 본인 요약의 생성·갱신·노출을 중단한다. 작성 후기 활용 미동의는 본인이 쓴 후기를 타인 요약의 AI 재료에서 제외한다. 다른 두 항목의 상태를 자동 변경하지 않고 일반 후기 원문·별점·당도는 기존 정책을 유지한다.
- 기존 회원 동의 적용: 현재 기존 회원은 모두 테스트 계정이라는 사용자 확인에 따라 테스트 시나리오에서는 AI 관련 동의가 모두 있는 것으로 간주한다. 신규 가입의 기본 미선택·개별/전체 동의 동작은 유지한다. 이 가정으로 실제 회원의 동의 증거를 생성하거나 DB 동의 값을 변경하지 않으며 회원 원문 외부 전송 보류도 해제하지 않는다.
- S17: 실제 완료와 양쪽 후기 제출이 모두 충족되면 즉시 공개, 한쪽만 제출 시 실제 완료부터7일 작성 기한 종료 후 공개. 분쟁 검토 중에는 새 공개를 보류한다
- S14/S17: 탈퇴 회원 표시·기존 공개 후기 익명 유지·상대방 남은 기한 작성 허용. 탈퇴 본인의 신규 작성은 불가하고 한쪽 후기 공개는 원래 기한 종료 기준을 유지한다
- S16/S17: 검토 중 자동 완료·리뷰 작성/기한/공개 보류; 인정 시 양쪽이 합의한 최신 종료+24시간이 지났으면 즉시 완료, 미완료였다면 그때부터 리뷰 7일 시작, 이미 완료였다면 남은 기간 재개·최소 24시간 보장. 검토 중 새로 합의한 종료도 적용하고 검토 시간을 더하지 않는다. 불발을 정상으로 정정할 때 한 명이 이미 탈퇴했고 실제 완료 기록이 없으면 정정 시 완료하되 다른 미결 검토가 있으면 보류한다. 탈퇴자를 진행 약속으로 되돌리지 않으며 최초 실제 완료부터7일·탈퇴자 작성 불가를 적용한다

KOPIS·TourAPI·서울 열린데이터는 모두 출시 시 실제 연동 목표다. 연결 성공은 별도 검증한다. 실제 제공되는 유형·지역·데이터만 화면에 표시한다.

KOPIS Top 10은 전국 전체 공연(기본), 연극, 뮤지컬, 클래식, 국악, 대중음악, 무용, 대중무용, 서커스/마술, 복합, 아동, 대학로, 내한, 축제의 총14개 선택 항목을 제공하는 목표다. 화면에서는 원천 명칭 `서양음악(클래식)`·`한국음악(국악)`·`무용(서양/한국무용)`을 각각 `클래식`·`국악`·`무용`으로 표시한다. 원천 명칭과 조회 조건은 따로 보존하며, 아동·대학로·내한·축제 등을 모두 장르 코드로 단정하거나 API 코드를 추정하지 않는다.

순위 공개는 공급사 회신을 기다리는 일괄 보류 대신 다음 대조 기준을 따른다. 각 선택 항목마다 공식 사이트에 표시된 실제 기간이 어제까지 최근7일인지, 전국·해당 분류 조건이 맞는지 확인하고 API Top 10의 공연 ID·순위·표시 순서를 대조해 일치한 목록만 공개한다. 동률은 공식 사이트 표시 순서를 따른다. 출처·검증한 실제 기간·확인 시각을 표시하며, 이 대조가 API 내부 집계 기간의 증명을 뜻하지는 않는다. `basedate` 누락은 그대로 기록하고 요청 날짜로 응답 기간을 대신 확정하거나 자체 순위로 대체하지 않는다.

분류별로 독립 검증한다. 갱신 실패·대조 불일치 때에는 해당 분류의 마지막 검증 목록을 기존 실제 기간과 `갱신 지연` 안내와 함께 유지하며 기간만 최신으로 바꾸지 않는다. 아직 한 번도 검증되지 않은 분류는 순위를 공개하지 않고 공식 순위 사이트 링크를 제공한다. 매일 갱신은 목표이며 전 분류 검증·자동 대조·서버 연동이 완료됐다는 뜻은 아니다. 일반 공연 조회는 계속한다.

서울 평문 HTTP 수집은 활성화하지 않는다. 안전한 HTTPS 자동 수집·페이지 재개·진행 중 행사 갱신을 검증할 때까지 보류한다. HTTPS 자료를 한 번 수신한 것만으로 보류를 해제하지 않으며 미연결/미수집을 행사0건으로 안내하지 않는다. 서버 수집·계약은 민규, 앱 상태 소비는 종현 담당이다.

## 7. IA에서 제외된 후속 범위

이메일 인증, 계좌 인증, 결제·정산, 친구·초대, 알림 설정, 관리자 행사 등록, 안심 통화·외부 캘린더 연동은 현재 화면과 내비게이션에 없다. 작성용 날짜 선택과 연결 행사 날짜의 색 강조는 현행 행사 UX에 포함되며 외부 캘린더 연동과 구분한다. 구현 시 기존 화면의 숨은 상태로 넣지 말고 정책·진입점·화면 ID를 새로 합의한다.

## 8. 프로토타입 해석 주의

- 화면 상단의 상태·역할 선택은 시나리오 검토 도구다.

## 10. 화면 상태의 세부 조건

- S05/S06: 네이버 이름·성별·생일·출생연도4종으로 여성·만19세 이상을 확인하고 네이버 계정당 유미당 계정1개를 연결한다. 누락/확인 불가면 가입을 보류해 네이버 정보 확인·재시도를 안내한다. 기존 회원은 목적 화면 또는 홈, 신규는 필수 사진과 선택 성향을 입력하고 `가입 완료`를 눌러 완료 안내 팝업을 확인한다. 보존한 목적 화면이 있고 현재 접근 가능하면 그 화면(행사 연결 작성 포함)으로 복귀하고, 그 외에는 홈으로 이동한다. 복귀 때 행사 연결 가능 상태를 다시 확인하며 미완료/취소 로그인에는 작성 권한을 주지 않는다.

- 공개 문서·스토어 검증의 완료 조건은 [PRD 출시 전 필수 검증](../requirements/PRD.md#9-출시-전-필수-검증)에 정리하고 실제 확인 증거는 기존 [배포·복구 체크리스트](../../collaboration/requests/minkyu/2026-10-07-release-recovery-checklist.md)에 연결하는 방식으로 인계한다. IA에는 S13/S21 탈퇴 안내와 공개 개인정보처리방침 삭제 요청 구역의 진입만 둔다. 체크리스트의 과거 상태는 현재 완료 증거로 대신하지 않으며 Google Play/App Store 제출·공개 승인을 뜻하지 않는다.

AI 탐색은 첫 사용 시 동의받고, 거절하면 일반 검색을 유지한다. 동의 확인 전 모델 처리를 시작하거나 질문을 외부로 보내지 않는다. 후기 요약 열람·내 프로필 요약 생성·노출·작성한 후기의 AI 요약 활용은 가입 시 별도 선택 체크 세 항목으로 구분한다. 세 항목에 모두 동의하지 않아도 가입·일반 동행·계정 이용을 허용하며 미동의한 해당 AI 기능·처리만 제한한다. 후기 요약의 세 동의는 독립적으로 철회한다. 열람 철회는 본인의 요약 열람만 중단하고, 내 프로필 생성·노출 철회는 본인 요약을 숨기고 생성·갱신을 중단한다. 원문 활용 철회는 본인이 쓴 기존·향후 후기를 AI 재료에서 제외하고 이를 사용한 기존 요약을 우선 숨긴다. 남은 허용 자료와 기존 공개·처리 조건을 충족한 경우에만 재생성 후 공개하며 불충족·실패 시 숨김을 유지한다. 다른 두 동의는 자동 철회하지 않는다. 계정·일반 동행·일반 후기 원문·별점·당도는 AI 동의 철회만으로 바꾸지 않으며 기존 일반 후기 정책은 별도 적용한다. AI 처리용 복사본·외부 사본·관련 생성물은 필요한 삭제를 추적하고 확인 전 완료로 표시하지 않는다. 기존 법적 검토·공급사 확인·회원 원문 외부 전송 보류를 유지한다. 서버 실행기 작업 한도 등 화면에 직접 노출할 필요가 없는 계약은 정책14장을 참조한다.


## 행사 데이터 칼럼·화면 매핑 참고

공급사 원본 칼럼→기존 공통 구조→목록/상세/연결 행사 매핑은 [2026-10-19 데이터 대조표](../../collaboration/requests/jonghyun/2026-10-19-event-data-screen-mapping.md)를 따른다. 원본 필드·현재 구현 비교 자료이며, 표시 설계는 아래 확정 구조와 최종 명세가 우선한다. 해당 자료의 후보는 실제 API·저장·공개 DTO·앱 연결 완료를 뜻하지 않는다. 원천에 없는 값·현재 미지원 필드는 임의로 채우지 않는다.

행사 기간·입장료·장소 정보와 공고의 동행 약속 일정·무료 동행·상세 만남 지점은 분리한다. 관련 공고는 유미당 내부 `eventId` 관계로 조회하며 외부 행사 API가 제공하는 정보가 아니다. 서울 HTTPS 서버 구현은 민규7.9 인계, KOPIS 순위는 분류별 공식 사이트의 실제 기간·공연 ID·순위·표시 순서 대조 결과로 공개를 판단하고, 일반 행사 데이터 정리와 화면 개발은 병행한다.


## 행사 화면 확정 구조

[행사 UX 동작 미리보기](행사UX_미리보기.html)는 합성 행사·공고로 확정 설계를 확인하는 별도 모형입니다. 실제 API 호출·회원 데이터·서버 저장·상태 검증·알림·동일 행사 통합 완료를 뜻하지 않습니다.

현재 제품 설계의 전체 조건은 [행사 UX 최종 확정 기준](../../collaboration/requests/jonghyun/2026-10-20-event-ux-approved-spec.md)을 따른다. 문서 동기화는 구현·실제 공급사 연결·운영 검증 완료가 아니다.

- **S09-2 목록/작성용 선택:** 이미지(있을 때)→분류·상태→행사명→기간→지역·행사장→요금. 이름 최대2줄·말줄임, 상세 전체 표시. 이미지는 전체가 보이게 표시하고 미제공/로딩 실패는 영역 없이 글만 표시한다. 날짜는 하루/동일 연도 기간/연도 경계를 구분한다. 요금은 명시 무료·단일 금액·요금 상세 확인·요금 정보 없음으로 구분한다. 분류는 명확한 대응만 통일하고 클래식·국악·무용을 사용한다. TourAPI 실제 수신 관광타입15 전체를 포함하되 시설14로 확대하지 않는다. 일반 목록의 주간 기본은 유지하고 검색은 실제 조회 가능한 전체 기간에서 찾는다. 10개씩 더보기, 0건/실패 구분, 0건은 조건 변경·직접 입력 안내.
- **S09-3 상세:** 이름·분류·상태→이미지→기간·시간·장소·공개 주소·요금→소개→제공된 관람 안내→유효 공식/예매 링크→연결 공고. 연결 공고는 전체 상태·등록 최신순 기본, 모집 중 필터와10개씩 더보기. 삭제·차단·본인 숨김·비로그인 정보보호는 기존 공고 규칙 유지. 0건은 `아직 이 행사에 등록된 동행 공고가 없어요`. 비로그인 동행 구하기는 로그인/가입 완료 후 같은 행사가 연결된 S03으로 복귀하고 상태 재확인.
- **S03/S04:** `변경`·`삭제`는 공고의 연결만 수정한다. 직접 입력은 행사명 필수, 장소명·공개 행사장 주소 선택이며 기존 장소/주소 검색·공개 확인·개인주소 금지 안내·의심정보 검사 사용. 검색 불가 주소는 생략 가능하다. 공고의 필수 약속 장소와 분리한다. 직접 입력은 공고 전용이고 공통 목록·독립 상세·공용화 검수 없음. 별도 행사 기간·이미지·요금 입력 없음. 등록 직전 서버 최신 상태를 확인하며 실패 시 입력 보존·다시 확인/사용자 연결 삭제 후 등록. 행사 자동 삭제·매 등록 외부 API 직접 호출 없음.
- **S02 연결 행사:** 종류·이름·기간·행사장·이미지(있을 때)와 행사 정보 보기. 직접 입력은 별도 상세 이동 없음, 연결 없으면 영역 생략. 공개 행사장 주소와 확정 당사자만 보는 상세 만남 지점을 분리한다.
- **상태:** 예정/진행 중은 새 연결 가능, 종료/공식취소는 불가(`취소된 행사예요`), 연기 일정 미정은 불가, 변경 일정 확인 뒤 조건 충족 시 가능. 취소 여부 미제공은 정상 수집·유효 기간 등 기본 검증 뒤 별도로 보존하고 연결 허용하며 정상 개최 확인으로 표시하지 않는다. 오류를 미제공으로 바꾸지 않는다. 취소·연기·갱신은 동행 자동 취소/변경을 뜻하지 않는다. 단순 검색 누락은 취소/비표출 증거가 아니다.
- **비표출/복원:** 해당 원천의 이름·사진·설명·주소·상세 이동을 숨긴다. 다른 검증된 공개 원천이 없으면 `연결된 행사 정보를 현재 제공할 수 없어요 / 행사 취소를 의미하지는 않아요` 안내 카드. 공고·약속·내부 연결 유지, 직접 입력 제외. 명시 재표출·공개 조건·최신 정보를 확인하면 자동 복원하며 종료/취소/연기 제한은 유지한다.
- **동일 행사:** 행사 단위 공식 공통 ID·정확한 공식 상세 링크 등 확실한 동일 개최 근거가 있는 항목만 대표 카드/상세/공고 통합. 제목·기관 홈페이지·날짜·장소 유사성만으로 통합하지 않고 근거 부족은 출처별 유지한다. 먼저 검증된 공개 원천을 대표로 유지, 빈 필드만 검증된 공개 원천으로 보완하고 출처 표시. 비표출 원천값은 재사용하지 않는다. 핵심 충돌은 `기관별 정보가 달라 확인이 필요해요` 안내·새 연결 제한·기존 약속 유지. 원천 ID/공고/통합근거/분리 이력 보존, 상시 수동 검수 없음.
- **변경·알림:** 작성자의 행사 교체·삭제·직접 입력 행사명/장소 실질 변경은 핵심조건 변경. 확정 전 알림·동의 무효화/재요청, 확정 후 상대 수락 전 기존 약속 유지. 원천 자동 갱신과 구분한다. 확인된 취소·연기·변경 일정은 작성자와 진행 중 동행 확정 상대에게 앱 안 알림, 동일 변화 중복 방지. 새 푸시 도입 없음.
- **담당/구현:** 종현은 화면/클라이언트, 민규는 직접입력 저장·확장 상태 DTO·동일 행사 연결표·등록 검사 변경·핵심조건 변경·알림, 유미는 UT. 현재 기존 클라이언트/서버가 모든 확정 상태를 지원한다고 간주하지 않는다.


## 2026-10-20 현재 구현과 요구사항의 구분

이 IA의 화면 구조는 확정 요구사항이다. 화면에 필요한 상태가 적혀 있다는 이유로 실제 클라이언트·서버·DB·운영까지 구현됐다고 판정하지 않는다. [정책·구현 대조 원장](../../collaboration/requests/jonghyun/2026-10-20-policy-implementation-audit/client-audit.json)의 소스 근거와 담당별 검증을 함께 확인한다.

| 화면 | 확정 요구와 실제 구현 사이에 남은 연결 |
|---|---|
| S06 가입 | 후기 AI 선택 동의 세 항목·각 자세히 보기·전체 동의는 확정 요구다. 현재 프리뷰/서비스 가입 폼에는 이 체크와 저장 연결이 없으므로 구현 후 검증한다. 서비스 MBTI는 현재 텍스트 입력이며 네 쌍 선택 UI와 다르다. |
| S20 AI 탐색 | 첫 사용 동의 전 새 모델 처리·외부 전송을 막는 동의 UI·현재 동의 조회/저장 연결이 필요하다. 서버의 동의 필요 응답만으로 첫 사용 동의 흐름을 완료했다고 보지 않는다. |
| S21 AI 관리 | 후기 요약의 열람·본인 생성/노출·작성 후기 활용은 독립 철회한다. 현재 두 기능 단위 철회 포트만으로 세 항목 독립 철회가 완료된 것은 아니다. |
| S03/S04 공고 작성 | 행사 검색·API 연결·공고 전용 직접 입력 UI와 입력 보존은 구현됐으나 직접 입력의 실제 서버 저장은 대기다. 서비스 초안은 현재 세션 메모리만 보관해 정책의 기기 7일 보관과 차이가 있으며 등록 성공 뒤 삭제도 확인·수정한다. 달력의 행사 진행일 색 강조는 후속 작업이다. |
| S09-2/S09-3 행사 | 목록의 이미지 생략·날짜·요금 표시를 구현했다. KOPIS는 현재 두 선택·보류 응답 소비 수준이며 14분류별 검증 결과·실제 기간·갱신 지연·공식 링크 계약을 연결해야 한다. 행사 상세의 연결 공고·확장 안내·비표출/통합 상태도 별도 미완료다. |
| S17 후기 | 프리뷰의 좋아요일 때 칭찬 최대 세 개와 달리 서비스 폼은 칭찬 제한·정확한 평가 문구·AI 활용 짧은 안내가 부족해 보완한다. |
| S12/S13/S21 | 서비스 알림의 읽지 않음 필터, 서비스 공개 운영·외부 삭제·보관 세 묶음 안내를 연결한다. 프리뷰 표시를 서비스 완료 근거로 쓰지 않는다. |

AI 한도·동의 필요 등 중단 응답 뒤 보내기는 사용자 확정 A안에 따라 서버 기준을 유지한다. 안내·입력을 보존하고 자동 재전송하지 않는다. 민규와 이용 가능 상태 확인 수단을 먼저 맞춘 뒤 종현이 버튼 제어를 연결한다. 자체 횟수·자정 타이머·화면 재진입으로 이용 가능을 확정하지 않는다.

포텐스닷은 교육·프로토타입용이며 공급사 회신의 보안·안정성 우려를 실제 서비스 조건 승인으로 해석하지 않는다. Gemini는 종현의 테스트 전용 프로젝트에서 기존 My Billing Account와 월50,000원 사용중단 예산을 연결한 상태다. 선충전이 아니며 최종 청구액의 절대 상한 보장은 아니다. 합성 세 건 검증은 앱 어댑터·실회원 검증이 아니다. 유미 계정 전환은 회의/브랜치 통합 때 계정·프로젝트·결제·키를 확인한 뒤 진행하고 총예산을 늘리지 않는다. 공급사 조건·법적 적합성 확인 전 실회원 원문 외부 전송 보류를 유지한다.
