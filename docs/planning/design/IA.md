# 유미당 IA — PRD 기반 정보 구조

현재 확정·미정·검토 필요 정책은 [정책.md](../../../정책.md)에서 확인한다. 이 문서는 계획·화면 설계이며, 정책 문구의 동기화를 코드·DB·화면의 구현 및 검증 완료로 해석하지 않는다.

## 1. 기준과 범위

- 작성일: 2026-09-22. 기존 IA는 내용의 근거로 사용하지 않고 트리·화면별 표·정책 구분이라는 문서 구조만 참고해 새로 작성했다.
- 기본 기준: [PRD.md](../requirements/PRD.md)의 여성 전용 1:1 동행, 인증, 상대 탐색·신뢰정보 확인, 신청·대화·양쪽 확정, 동행 완료·상호 평가.
- 확정된 보완 기준: [추가 요구 사항.md](<../requirements/추가 요구 사항.md>)와 [전달.md](../requirements/전달.md)의 **1. 구체적인 수정 요청**. 추가 요구 사항 7-4의 후속 S01 검색·필터 수정도 포함한다.
- 화면 기준: [현재 와이어프레임](./yumidang-wireframes.html). 행동 순서와 예외는 [USER_FLOW.md](./USER_FLOW.md)에 정리한다.
- 최신 대화 반영: **서비스 이용자는 성인 여성만, 신규 가입은 PASS 휴대폰 본인확인, 기존 회원의 일반 로그인은 문자 일회용 인증번호, 학교·직장 이메일 인증은 선택**이다. PASS 외에 신분증 촬영·제출이나 신원정보 수기 입력 단계를 추가하지 않는다. ‘AI 요약 브리핑’은 받은 리뷰 한마디를 요약하는 기능이다.
- 검색의 최신 확정: **공고 제목·공고에 등록된 장소명·주소**를 검색한다. ‘장소 주변 찾기’는 현재 범위에서 제외하고 추후 추가한다. 이전 요구사항의 공개 지역만 검색·주변 반경 검색 설명보다 이 결정을 우선한다.
- 기준이 충돌하면 최신 확정 지시를 적용한다. PRD의 목적은 유지하면서 유료 공고·계좌 인증·AI 등을 추가하고, 과거의 가입 인증 설명은 최신 PASS 가입·문자 로그인 방식으로 대체한다. PRD 원문 자체는 변경하지 않는다.
- PASS 결과의 성명·성별·생년월일·휴대폰번호로 성인 여성 가입 자격을 확인하고 DI로 중복 가입을 막는다. 사진은 필수이며 유료 요청형·제공형의 작성자와 신청자는 각각 등록·신청 전에 1원 계좌 인증을 완료해야 한다.
- 제외: 전달.md 2장의 미반영 개편안, 이전 IA에만 있던 기능, 미채택 제안. S13은 현재 화면의 ‘나’와 내부 구성을 사용한다.
- 문서의 인증·AI·외부 데이터 기능은 실제 연동할 설계 범위다. 현재 HTML의 예시 데이터·상태 전환을 실서비스 구현 완료로 보지는 않는다.

S06의 가입 완료는 팝업이고 S04의 성공은 생성한 공고 상세로 이동한다. MBTI 패널과 행사 선택 모드는 별도 화면 ID가 아니다. HTML 검토 도구의 상태·역할 선택 버튼도 서비스 메뉴에 포함하지 않는다.

### 3-1. 가입·선택 인증

- 신규 가입은 PASS 휴대폰 본인확인을 한 번 수행한다. PASS 결과로 성명·성별·생년월일·휴대폰번호·DI를 확인해 성인 여성 가입 자격과 중복 가입 여부를 검증한다. 자격을 충족하지 않으면 계정을 만들지 않고 “유미당은 성인 여성만 가입할 수 있어요”라고 안내하며 상세 성별·생년월일 값은 노출하지 않는다.
- 가입을 완료한 회원의 일반 로그인은 등록된 휴대폰번호로 발송한 문자 일회용 인증번호를 사용한다. 휴대폰번호 변경·로그인 불가 계정복구·탈퇴 후 재가입에서는 PASS 본인확인을 다시 수행한다.
- 사용자가 PASS 결과의 성명·성별·생년월일을 직접 입력하거나 수정해 가입 자격을 우회할 수 없다. PASS 외에 신분증 촬영·제출이나 같은 신원정보를 다시 입력하는 단계는 두지 않는다.
- 사진은 필수, 취향·대화 방식·MBTI는 선택이다. 취향·대화 방식은 기본 버튼과 직접 추가를 함께 제공한다.
- MBTI는 중앙 4열×2행 패널, 위 E/S/T/J·아래 I/N/F/P, 중간 가로 구분선, 각 열에서 하나 선택 방식이다.
- 학교·직장 이메일은 가입 후 S21에서 선택 인증한다. 인증배지는 명칭 대신 아이콘이며 이메일·도메인은 다른 회원에게 공개하지 않는다. 아이콘 클릭 시 해당 기관 이메일을 사용할 수 있음을 확인한 것이며 현재 재학·재직이나 사용자 안전을 보증하지 않는다고 표시한다.
- 계좌 인증배지는 이메일 인증배지와 다른 아이콘으로 공개 프로필·공고 카드·공고 상세에 표시한다. 아이콘 클릭 시 “본인 명의 계좌가 확인된 사용자입니다. 계좌 확인은 거래·만남의 안전이나 대금 지급을 보증하지 않습니다.”라고 표시한다. 별도 도움말 화면은 만들지 않는다.
- S07/S22의 검토용 코드 안내는 제거한다. PASS 가입 인증, 문자 로그인, 이메일 인증, 계좌 인증은 서로 다른 확인 범위다.

### 3-2. 홈·검색·공고 작성

- 홈 배너는 가로 넘김이며 전체보기는 우측 위 텍스트다. 본문은 행사 → 약속 → 카테고리 순서다. 본인 이름 영역에는 인증 아이콘·나이·당도를 넣지 않는다. 행사 실패 문구 우측에는 새로고침 아이콘을 둔다.
- 공고 카드의 작성자 이름 옆에는 현재 유효한 계좌 인증배지와 학교·직장 이메일 인증배지를 각각 표시한다.
- 둘러보기의 검색 대상은 공고 제목, 공고에 등록된 장소명, 등록된 주소다. 세 항목 중 하나가 검색어와 일치하는 공고를 찾으며, 공개 동네명만으로 검색 대상을 제한하지 않는다.
- 현재 탐색에는 별도 기준 장소 선택·반경 설정·거리 계산·거리순 정렬을 제공하지 않는다. ‘장소 주변 찾기’와 관련 안내는 S01·S20의 현재 흐름에서 제외하고 추후 기능으로 남긴다. 카테고리·비용·일정·나이 필터는 유지한다.
- S03은 시작 날짜/시간과 종료 날짜/시간을 각각 입력한다. 종료가 시작보다 늦으면 날짜를 넘기는 일정도 가능하다.
- 장소명 검색은 좌측, 주소로 찾기는 우측이다. 카카오 지도 API로 장소명을 검색해 장소를 선택하면 주소를 자동 입력한다. 다른 경로로는 우편번호 검색에서 주소를 선택해 주소·우편번호를 입력한다. 이후 상세 만남 지점을 작성한다.
- ‘주소 후보를 선택해 주세요’ 문구와 초기 고정 예시 후보를 없애고 최근 검색·검색 후 결과를 제공한다.
- 행사 연결은 이미지·이름·기간의 세로 목록이다. 전체보기는 S09-2 선택 모드를 사용해 진행 중·예정 행사를 연결하고 작성 내용으로 복귀한다. 행사 선택으로 입력 일정을 자동 변경하지 않는다.
- S04 상대 나이는 현재 선택 칩이며 성별 선택은 없다. 등록 성공 후 별도 완료 화면 없이 S02 작성자 상세로 이동한다.

### 3-3. 행사·AI 탐색

- 홈과 행사 목록은 이번 주 새로 시작한 행사를 기본으로 한다. 목록의 ‘진행 중인 행사도 포함’을 선택하면 선택 기간과 행사 기간이 겹치는 장기 행사까지 포함한다.
- AI 챗봇은 취향·지역·성향·대화 방식·원하는 MBTI를 자연어로 받아 공고를 찾고, 해석한 조건을 수정 가능하게 보여준다.
- AI의 공고 키워드 검색도 제목·등록된 장소명·주소를 대상으로 한다. 취향·대화 방식 등의 조건은 별도 필터로 조합한다. 장소 요청을 좌표·반경 검색으로 바꾸거나 가까운 순으로 추천하지 않는다.
- 현재 대화에서 명시한 조건을 프로필보다 우선한다. 상대 MBTI가 비어 있다는 이유만으로 자동 제외하지 않는다.
- AI의 ‘이번 주말 갈 전시’는 주말과 기간이 겹치는 장기 전시와 이번 주 신규 전시를 함께 검색한다. 금요일에 끝난 전시는 제외한다. 명시적으로 신규만 요청하면 좁힌다.
- 사용자 메시지·전송한 예시는 오른쪽, AI 답변은 왼쪽이다. 행사 카드와 공고 카드를 구분한다.
- 행사 기간은 실제 운영일·회차·잔여석을 보장하지 않는다. 제공된 운영 안내·공식 페이지 확인을 안내하며 행사 입장료와 동행 비용을 구분한다.

### 3-4. 상호 평가·신뢰정보

- S17은 가로 버튼 ‘좋아요 / 보통이에요 / 별로예요’ → 별점 1~5 필수·한마디 선택 순서다. 좋아요에만 버튼식 칭찬 키워드 선택을 제공하며 최대 3개다.
- 제출 전 경험 선택으로 돌아갈 수 있고, 최종 제출 성공 후에는 수정할 수 없다.
- 받은 칭찬 키워드는 사용자별 누적 횟수로 집계해 프로필의 가로 막대 차트로 표시한다. 상위 5개를 보여주며 가장 많은 항목을 기준으로 막대 길이를 비교한다.
- 받은 후기의 순서는 **칭찬 누적 가로 차트 → AI 요약 브리핑 → 사용자 원문 리뷰**다. S13의 받은 후기와 S14의 공개 프로필에 같은 구성을 사용한다.
- AI 요약 브리핑은 받은 리뷰 후기의 한마디를 요약한다. 한마디 있는 공개 후기 3개 이상부터 기준 후기 수를 표시하고 한마디 없는 평가·비공개 후기를 제외한다. 원문이 부족하면 없는 내용을 만들지 않는다.
- 리뷰 없음과 요약 실패를 구분하고, 요약이 실패해도 원문은 볼 수 있다. 한마디 없는 평가는 AI 요약 기준 개수에 포함하지 않는다.

## 4. 접근·공개 범위와 동행 비용

| 대상·관계 | 정보·행동 범위 |
|---|---|
| 비로그인 탐색 | 공고에서 ‘동행 123’ 형태의 시스템 별칭과 공개 지역. 신청·프로필 상세·채팅·나·AI는 로그인 안내 |
| 로그인한 일반 회원 | 마스킹 이름·공개 지역, 공개 프로필·성향·후기. 미확정 상대의 상세 주소 제외 |
| 공고 작성자 | 자신의 공고 입력·관리, 상대 선택·최종 동의 요청. 단독 매칭 확정 불가 |
| 확정된 동행 상대 | 서로의 전체 실명 표시와 상세 만남 장소·약속 확인. 상대의 공고 편집 권한은 없음 |
| 확정 공고의 제3자 | 확정·마감 상태 확인, 새 신청 불가. 당사자의 비공개 정보 제외 |
| 본인의 홈 | 본인 이름 전체 표시. 다른 회원에게의 공개 범위 확대가 아님 |

이름의 마스킹·전체 표시 정책은 유지한다. 가입 시 PASS로 확인한 성명을 사용하며 다른 회원에게 전체 이름을 공개하는 관계와 시점은 기존 표를 따른다. 정확한 주소와 상세 만남 지점은 작성자가 입력하고 최종 확정 상대에게만 제공한다.

| 동행 유형 | 비용 방향 | 계좌 인증 |
|---|---|---|
| 무료 | 동행 대금 없음 | 필수 아님 |
| 유료 요청형 | 작성자가 상대에게 지급 | 등록자·신청자 모두 필수 |
| 유료 제공형 | 상대가 작성자에게 지급 | 등록자·신청자 모두 필수 |

작성자가 유료 요청형·제공형을 선택해 공고를 작성한 뒤 최종 ‘등록하기’를 누를 때, 신청자가 유료 공고에서 최종 ‘신청하기’를 누를 때 계좌 인증 상태를 확인한다. 미인증이면 해당 행동을 차단하고 S22로 안내한다. 인증 전 입력은 보존하고 성공 후 원래 화면으로 복귀하며 자동 제출하지 않는다.

개인 계좌는 PASS에서 확인한 성명과 계좌 인증 제공사가 확인한 예금주가 공급사의 명의 대조 기준에 따라 일치할 때만 인증한다. 사용자가 예금주명을 직접 입력하거나 수정해 우회할 수 없다. 초기 출시에서는 PASS 회원 본인의 개인 명의 계좌만 허용하며 개인사업자·법인 계좌는 지원하지 않는다. 불일치 시 “본인 명의의 다른 개인 계좌를 사용해 주세요”라고 안내한다.

유료 요청형·제공형의 동행 비용은 사용자끼리 직접 주고받는다. 유미당은 결제대행·대금 보관·에스크로·자동 송금·정산·자동 환불·지급 완료 보증을 제공하지 않는다. 인증에 사용한 은행명·계좌번호·예금주명은 상대에게 자동 공개하지 않으며, 지급 방법과 시점은 확정된 두 사용자가 1:1 채팅에서 직접 합의한다.

## 6. 정책·구현 확인이 필요한 부분

- 현재 HTML의 가입·로그인 예시는 최신 PASS 가입·문자 로그인 분리와 다르다. 새 IA는 신규 가입에서 PASS로 성명·성별·생년월일·휴대폰번호·DI를 확인하고, 일반 로그인은 문자 일회용 인증번호를 사용하는 기준을 따른다. 원문 PRD·HTML은 이번 문서 작업에서 수정하지 않는다.
- 인증 코드 만료·재시도 횟수·갱신, 최종 동의 요청의 만료·철회, 동시 확정·미선정 신청 처리, 확정 후 일정·금액 변경은 미정이다.
- 공고 수정·마감·삭제의 허용 시점, 확정 동행 취소의 제공 범위·제재, 불발·노쇼·분쟁 처리, 취소 후 실명·주소 접근은 미정이다.
- 주소를 검색 대상으로 쓰는 것과 검색 결과·상세 화면에 주소를 표시하는 것은 구분한다. 확정 전 상세 주소 표시 제한은 유지하지만, 주소 검색의 일치 결과로 장소를 추정할 수 있으므로 기존과 같은 위치 비공개 효과를 보장한다고 표현하지 않는다. 실제 검색 응답의 정보 노출 범위는 구현 시 확인한다.
- 현재 유료 오퍼는 사용자 간 직접 지급 방식이며 플랫폼 결제·대금 보관·에스크로·자동 송금·정산·자동 환불·지급 완료 보증을 포함하지 않는다.
- 당도 산식은 민규·팀 검토 필요이며 변경 내역·표시 기준은 미정이다. 현재 15당 표시는 초기값이며 별점과 자동 환산하는 규칙은 없다.
- 신고·차단·탈퇴·고객지원·관리자 상세 화면은 현재 완성된 사용자 경로로 추가하지 않는다. 이는 현재 HTML의 별도 검토 범위에 근거한다.
- AI 비용·한도·외부 제공사 보관 조건과 최근 검색의 실제 보관 정책은 미정·검토 대상이다. 서비스 서버의 AI 대화 원문 이력 미저장과 중간 요약 보관 규칙은 [정책.md](../../../정책.md#retention)에 확정되어 있다. HTML의 세션 저장을 운영 정책으로 확정하지 않는다.
- 현재 완료·후기 정책: 양쪽 후기를 제출하면 24시간 이전이어도 즉시 공개한다. 한쪽만 제출하면 동행의 실제 완료 시각부터 24시간 후 공개하며, 이 시각 이후 작성 기한 안에 제출한 후기는 즉시 열람할 수 있다. 실제 알림 클릭이나 후기 제출 시각부터 24시간을 새로 계산하지 않는다. 미완료·실제 분쟁·불발/노쇼 상태는 공개에서 제외한다. 일반 작성 기한은 실제 완료 시각부터 7일이며 공개 시점과 구분한다. 이의 검토 중 기한 보류와 동행 인정 후 남은 기간 재개·최소 24시간 보장 예외는 유지한다. 당도는 상대방의 후기를 열람할 수 있게 될 때 동시에 반영하며 실제 열람 여부와는 무관하다. 완료 횟수는 후기 제출·공개와 관계없이 동행 완료 즉시 반영한다. 화면 연결은 유미·성호 담당이며 이번 문서 작업에서 브라우저 UI 연결·검증은 미실행이다.
- 공연·뮤지컬 Top 10은 현재 화면의 별도 검토 영역으로 보존한다. 예시 카드를 실제 순위로 표현하지 않는다.
- 추후 추가: ‘장소 주변 찾기’. 기준 장소·좌표·반경·거리 표시·거리순 정렬은 이번 설계에서 제외하며 재도입 시 별도로 설계한다. 공고 작성의 카카오 장소명 검색·주소 자동 입력·우편번호 검색은 현재 범위에 그대로 포함한다.
