# 유미당 PRD — 사용자 정책 답변 반영

> 문서 기준일: 2026-10-20
> 사용자 확정 선택을 반영한 문서이며 코드·DB·운영 검증과는 구분한다.
> 관련 문서: [정책](../../../정책.md) · [IA](../design/IA.md) · [USERFLOW](../design/USERFLOW.md)

## 1. 제품 개요

유미당은 여성·만 19세 이상 사용자가 무료 1:1 동행 공고의 첫 채팅으로 신청하고 대화·합의 후 작성자 확정 요청에 신청자가 수락하여 약속을 확정하는 서비스다. 사용자의 최신 확정 정책을 적용한다. 일반 신고·허용 증거 접근·AI 비용 관리 책임자는 대표 유미이며 기술 서버 운영은 민규다. 법적 적합성·공급사 계약·실제 운영 준비 확인은 제품 정책 결정과 별도로 진행한다.

### 제품 목표

- 일정·장소·활동 조건이 맞는 동행 공고를 쉽게 찾고 작성하게 한다.
- 공고 신청과 최종 확정을 분리해 대화 후 결정할 수 있게 한다.
- 마스킹 이름·공개 지역에서 시작해 확정 당사자에게만 실명·상세 장소를 공개한다.
- 행사 탐색에서 관련 동행 공고와 새 모집으로 자연스럽게 연결한다.
- 완료·상호 평가·칭찬·후기로 다음 동행 선택에 필요한 신뢰 정보를 만든다.
- 자연어 AI 탐색을 제공하되 개인정보와 공개 권한을 우선한다.

### 비목표

- 신원·안전·만남 성공을 보증하지 않는다.
- 유료 동행·결제·정산·환불을 제공하지 않는다.
- 이메일·계좌 인증을 현재 가입 또는 신청의 필수 단계로 사용하지 않는다.
- AI가 신청·확정·결제·메시지 전송을 대신 실행하지 않는다.

## 2. 대상 사용자와 역할

### 대상

- 대한민국의 여성·만 19세 이상
- 전시, 공연, 축제, 맛집 등 일상 활동을 함께할 1:1 동행을 찾는 사용자

### 역할

| 역할 | 주요 행동 |
|---|---|
| 비로그인 방문자 | 공개 공고·행사 탐색, 로그인 진입 |
| 회원·신청자 | 프로필 관리, 공고 탐색·작성, 첫 채팅으로 신청, 대화·합의, 최종 동의 수락, 완료·평가 |
| 공고 작성자 | 공고 관리, 신청자 대화·거절·선택, 동행 확정 요청 |
| 확정 당사자 | 실명·상세 위치 확인, 약속 관리, 변경·취소·완료·평가 |
| 운영자 | 개인 운영자 조유미(대표 유미), 등록 사업자 없음. 일반 신고·제재·분쟁 운영, 허용 증거 접근·AI 비용 관리 책임. DB 회원 채팅 원문 직접 열람 금지. 실제 도구·권한 설정은 별도 검증 |

## 3. 제품 범위

현재 요구사항은 S08 없이23개 활성 화면이다. HTML 모의 동작·서버·DB·운영 적용은 별도 검증하며 이 문서에서 현재 제품 검증은 NOT_RUN이다.

| 영역 | 포함 기능 |
|---|---|
| 인증 | 네이버 로그인, 여성·성인 자격 확인, 신규 프로필 가입 |
| 탐색 | 홈, 공고 검색·필터·정렬, 카테고리 탐색 |
| 공고 | 작성, 장소·행사 연결, 확인, 등록, 상태 관리 |
| 매칭 | 신청 버튼→채팅, 첫 전송 시 신청 성립, 작성자 확정 요청→신청자 수락, 상호 합의 일정 변경 |
| 약속 | 상세 위치 공개, 시작 전 취소, 완료 확인, 상호 평가 |
| 행사 | 신규·진행 행사, 상세, 관련 공고, KOPIS Top 10 |
| 프로필 | 사진, 성향, 공개 프로필, 칭찬·후기·AI 요약 |
| AI | 자연어 공고·행사 탐색, 가입 약관 및 화면 안내, 현재 화면 메모리만 사용, 설정 지역 추천 |
| 계정·안전 | 알림, 안심 수칙, 계정 상태·제재·탈퇴 |

## 4. 핵심 사용자 시나리오

1. 방문자는 홈·둘러보기·행사에서 공개 정보를 탐색한다.
2. 신청·작성·프로필·AI 이용 시 네이버로 로그인한다.
3. 신규 회원은 필수 사진과 선택 성향을 등록하고 가입을 완료한다.
4. 회원은 공고를 검색하거나 행사에서 관련 공고를 찾는다.
5. 신청 버튼으로 S11에 이동하고 첫 채팅 전송 성공 시 신청과 작성자 측 채팅방이 성립한다. 미전송 이탈은 미신청이다.
6. 서로 채팅·합의한 뒤 작성자가 확정 요청을 보내고 신청자가 수락하면 확정한다.
7. 확정 당사자는 실명과 상세 만남 위치를 확인한다. 변경은 양쪽 누구나 제안하고 상대 수락·충돌 확인 후 반영한다.
8. 종료 후 완료를 확인하고 평가를 제출한다.
9. 공개 가능한 후기와 칭찬이 프로필에 반영된다.

## 5. 기능 요구사항

### FR-1. 로그인·가입

- FR-1.1 네이버 로그인을 유일한 현재 로그인 수단으로 제공한다.
- FR-1.2 이름·성별·생일·출생연도로 여성·만 19세 이상 자격을 확인한다.
- FR-1.3 필수 정보 누락·확인 불가 시 가입을 보류하고 네이버 정보 확인·재시도를 안내한다. 자격 불충족·연동 실패를 서로 다른 상태로 표시한다.
- FR-1.4 신규 회원은 프로필 사진을 필수로 등록해야 한다.
- FR-1.5 관심사·대화 방식·MBTI는 선택이며 비워둘 수 있다.
- FR-1.6 가입 완료는 명시적 버튼과 완료 팝업 확인으로 끝난다.
- FR-1.7 기존 회원은 로그인 전 목적 화면으로 복귀하고 대상이 없거나 접근할 수 없으면 홈으로 이동한다. 신규 회원도 가입 완료 팝업 확인 후 보존한 목적 화면이 있고 현재 접근 가능하면 복귀한다. 행사 상세에서 시작했으면 해당 행사 연결 작성으로 돌아가 상태를 재확인하고, 목적이 없거나 접근할 수 없으면 홈으로 이동한다.
- FR-1.8 자격 확인은 네이버 인증정보만 사용한다. 소셜 계정당 1개 계정이며 계정 간 기록 이전은 제공하지 않는다.

- FR-1.9 후기 요약 열람·내 프로필 요약 생성/노출·작성한 후기의 AI 활용은 가입 시 세 개의 선택 동의 항목으로 구분한다. 모두 기본 미선택이며 짧은 체크 문구와 자세히 보기를 제공한다. AI 미동의를 이유로 가입을 거부하거나 일반 동행·계정을 차단하지 않고 미동의 항목에 해당하는 AI 기능만 제한한다.
- FR-1.10 가입 화면 상단 `전체 동의` 선택/해제는 같은 화면의 모든 개별 항목에 적용한다. 하나라도 해제하면 전체 동의를 해제 상태로 표시하고 모두 선택하면 전체 동의를 선택 상태로 표시한다. 개별 동의와 자세히 보기는 유지한다. AI 탐색 첫 사용 동의는 포함하지 않는다.
- FR-1.11 기존 계정은 전원 테스트 계정으로 테스트 시나리오에서 모든 동의 완료로 간주하고 재동의를 생략한다. 실제 동의 증거 생성·DB 변경·외부 전송 승인을 뜻하지 않으며 실제 회원에 일반화하지 않는다.

### FR-2. 홈·탐색

- FR-2.1 홈은 신규 행사, 다가오는 약속, 카테고리 순으로 제공한다.
- FR-2.2 공고 검색 대상은 제목·등록 장소명·등록 주소·연결 행사명이다.
- FR-2.3 카테고리, 시도 지역, 일정, 작성자 만 나이 19~99세, 모집 상태 필터를 제공한다.
- FR-2.4 등록일 최신순과 시작일 빠른순 정렬을 제공한다.
- FR-2.5 비로그인은 일정·나이 상세 필터가 아닌 전체 범위를 사용한다.
- FR-2.6 결과 없음, 조회 실패, 권한 제한을 구분한다.
- FR-2.7 기본 목록은 모든 모집 상태를 노출하고 모집 중 필터 활성화 시 모집 중 공고만 노출한다. 삭제 공고는 비노출이다.

### FR-3. 공고 작성·등록

- FR-3.1 카테고리, 제목, 소개, 장소, 시작·종료 일시를 필수로 받는다.
- FR-3.2 모집 마감과 행사 연결은 선택으로 제공한다.
- FR-3.3 장소명 검색과 주소 검색을 분리하고 상세 만남 지점을 별도 입력한다.
- FR-3.4 행사 선택은 작성 일정과 입력값을 임의로 덮어쓰지 않는다.
- FR-3.5 개인정보·상세 위치 노출을 감지하면 등록 전 차단하고 수정·오탐 문의를 제공한다.
- FR-3.6 작성 중 이탈 시 같은 기기 임시저장과 복구를 안내한다.
- FR-3.7 등록 실패 시 입력을 유지하고 재시도한다.
- FR-3.8 성공 시 별도 완료 화면 없이 생성된 공고 상세로 이동한다.
- FR-3.9 모든 공고는 무료 1:1이며 금액·결제 입력을 제공하지 않는다.

### FR-4. 공고 상세·관리

- FR-4.1 관계와 상태에 따라 신청, 기존 채팅, 작성자 관리, 약속 상세 행동을 분기한다.
- FR-4.2 수동 마감은 새 신청만 차단하고 기존 신청·채팅을 보존한다.
- FR-4.3 핵심 조건 변경을 신청자에게 알리고 기존 최종 동의를 무효화하며 새 조건으로 재요청한다.
- FR-4.4 확정 당사자와 제3자의 실명·상세 위치 공개를 구분한다.
- FR-4.5 확정 전 삭제와 확정 후 취소를 별도 절차로 처리한다.

### FR-5. 신청·채팅·확정

- FR-5.1 별도 신청 메시지 화면 S08을 제거하고 신청 버튼 클릭 시 S11로 이동한다.
- FR-5.2 신청 일정 충돌은 경고하되 신청은 허용한다.
- FR-5.3 첫 채팅 전송 성공 시에만 신청을 성립시키고 작성자에게 채팅을 전달하며 작성자 측 1:1 채팅방을 생성한다. 미전송 이탈·전송 실패는 미신청이며 작성자 알림도 없다. 미전송 입력은 현재 화면 메모리에만 보관하고 화면 이탈 시 삭제 안내 후 삭제한다.
- FR-5.4 본인 철회 후 1분간 재신청 불가, 이후 횟수 제한 없이 허용한다. 작성자 거절 후에는 같은 공고 재신청을 차단한다.
- FR-5.5 대화·합의 후 작성자가 확정 요청을 보내고 신청자가 수락하면 확정한다. 한 번에 한 명에게 요청하며 요청 철회 후 다른 상대에게 요청한다.
- FR-5.6 확정 요청은 요청 +6시간과 시작 시각 중 빠른 때 만료된다. 만료 시 신청·채팅은 유지하고 미확정 상태로 돌아간다.
- FR-5.7 최종 확정 직전 권한·공고 조건·정원·일정 충돌을 재확인한다.
- FR-5.8 신청자 수락 후 동행을 확정하고 실명·상세 위치와 약속을 제공한다.
- FR-5.9 메시지 실패 시 재전송하고 종료 대화는 읽기 전용으로 보존한다.
- FR-5.10 대화방 나가기는 본인 목록에서만 숨긴다.
- FR-5.11 재신청은 동일 공고·상대 채팅방을 재사용하고 새 메시지 전송 성공 시 성립한다.
- FR-5.12 한 명 확정 시 다른 신청은 모집 종료·채팅 읽기 전용으로 전환한다. 확정 취소만으로 모집을 자동 재개하지 않는다. 작성자가 명시적으로 모집 재개하면 이전 유효 신청·채팅을 자동 복원하고 알린다. 거절·본인 철회 신청은 복원하지 않는다.

### FR-6. 확정 후 변경·취소

- FR-6.1 양쪽 누구나 확정 후 일정·장소 변경을 제안하고 상대 수락·충돌 확인 후 반영한다.
- FR-6.2 변경 제안은 제안 +6시간·기존 시작·새 시작 시각 중 가장 빠른 때 만료된다. 거절·철회·미응답이면 기존 약속을 유지한다.
- FR-6.3 확정 전 철회, 시작 전 취소, 시작 후 중단·불발 신고를 구분한다.
- FR-6.4 취소 시 상대에게 알리고 실명·상세 위치를 즉시 다시 숨긴다.
- FR-6.5 기존 대화는 읽기 전용으로 보존한다.

### FR-7. 완료·평가

- FR-7.1 예상 종료 후 본인 완료 확인을 제공한다.
- FR-7.2 양쪽 확인 또는 종료 +24시간에 실제 완료 처리한다.
- FR-7.3 취소·노쇼는 자동 완료에서 제외, 신고·분쟁 검토 중에는 보류한다. 정상 동행 인정 시 양쪽이 합의한 최신 종료 +24시간이 지났으면 즉시 완료하고 미경과면 그 최신 종료 기준을 유지한다. 검토 중 새로 합의한 종료도 적용하며 검토 시간을 덧붙이지 않는다.
- FR-7.4 본인 확인 후 상대 확인 전에도 비공개 후기 선제출을 허용한다.
- FR-7.5 경험·별점은 필수, 한마디는 선택으로 받는다.
- FR-7.6 좋아요일 때만 공식 칭찬을 최대 3개 선택한다.
- FR-7.7 제출 성공 후 수정·중복 제출을 막는다.
- FR-7.8 후기 기한은 실제 완료 +7일이다.
- FR-7.9 실제 완료 후 양쪽 제출은 즉시, 한쪽 제출은 7일 작성 기한 종료 시 공개한다.
- FR-7.10 실제 완료 시 완료 횟수, 후기 공개 시점에 후기 당도·칭찬을 반영하고 운영 감점은 위반/제재 확정 때 별도로 반영한다.
- FR-7.11 검토 중 리뷰 작성·기한·공개를 보류한다. 실제 완료 전에는 기한을 시작하지 않으며 검토 후 처음 완료되면 그때부터 7일을 제공한다. 이미 완료였다면 남은 기간 재개·최소 24시간 보장, 양쪽 제출 시 검토 종료 후 공개, 한쪽 제출 시 재개 기한 종료 후 공개다.
- FR-7.12 탈퇴 후 상대방은 남은 기한까지 작성 가능하며 탈퇴 회원 표시와 기존 공개 후기 익명 유지를 제공한다. 탈퇴 본인은 새 후기를 작성할 수 없다. 한쪽 후기 공개는 원래 남은 작성 기한을 따른다.

### FR-8. 행사

[행사 UX 동작 미리보기](../design/행사UX_미리보기.html)는 합성 행사·공고로 확정 설계를 확인하는 별도 모형입니다. 실제 API 호출·회원 데이터·서버 저장·상태 검증·알림·동일 행사 통합 완료를 뜻하지 않습니다.

- FR-8.1 홈과 일반 목록에서 이번 주 신규 중 미종료 행사를 제공한다.
- FR-8.2 진행 중 포함, 기간, 지역, 유형, 공연 하위 장르 탐색을 제공한다.
- FR-8.3 작성용은 연결 가능한 진행 중·예정 전체를 검색·선택한다. 동행 일정으로 검색을 자동 축소하거나 겹침을 강제하지 않는다. 달력에 행사 진행 날짜를 색으로 강조하되 작성 일정을 자동 변경하지 않는다.
- FR-8.4 종료 행사 상세는 볼 수 있으나 새 모집은 차단한다.
- FR-8.5 행사 상세에서 관련 공고 또는 행사 기반 모집으로 연결한다.
- FR-8.6 KOPIS 순위 선택은 전체 공연(기본), 연극, 뮤지컬, 클래식, 국악, 대중음악, 무용, 대중무용, 서커스/마술, 복합, 아동, 대학로, 내한, 축제의 14항목이다. 표시명은 서양음악(클래식)→클래식, 한국음악(국악)→국악, 무용(서양/한국무용)→무용으로 바꾸되 원천 코드·원래 분류는 보존한다. 아동·대학로·내한·축제는 장르와 구분되는 공식 특성·지역 조건을 따른다. 집계는 어제까지 최근7일, 갱신은 매일이다. 분류마다 공식 사이트에 표시된 실제 기간·공식 분류/지역·정렬 기준과 API 공연ID·순위·순서가 일치한 Top10만 공개한다. basedate가 없어도 이 대조를 통과한 목록은 공개할 수 있으나 API 내부 집계 기간을 증명했다고 안내하지 않는다. 요청 날짜만으로 기간을 확정하거나 일간 순위를 합산한 자체 주간 순위를 만들지 않는다. 동률은 공식 표시 순서 그대로 유지하고 10개 미만이면 검증한 개수만 표시한다. 출처·실제 확인 기간·확인 시각을 표시한다. 갱신 실패 시 마지막 검증 목록의 기존 기간을 그대로 유지하고 갱신 지연을 안내하며 최신 날짜로 바꾸지 않는다. 최초 미검증·미지원 분류는 공식 사이트 링크를 제공하고 자체 순위로 채우지 않는다. 분류별 성공·실패를 독립 관리한다. 현재 API 매핑·자동 대조·저장·서버 응답 구현과 운영 검증은 별도이며 이 정책 변경만으로 연동 완료로 표시하지 않는다.
- FR-8.7 최근 7일·매일 갱신·출처·갱신 시각을 표시하고 미수신 시 추정치로 대체하지 않는다.
- FR-8.8 KOPIS·TourAPI·서울 열린데이터 3사 실제 연동 목표를 유지하고 연결 성공을 별도 확인한다. 서울 평문 HTTP 수집은 활성화하지 않으며 HTTPS 자동 수집·페이지 재개·진행 행사 갱신·실패 복구를 검증한다. HTTPS JSON 표본 성공은 운영 수집 완료가 아니다. 미연결·미확인을 행사 0건으로 표시하지 않는다. 실제 확보한 유형·지역의 데이터만 노출한다.

- FR-8.9 행사 카드 순서는 이미지(있을 때)·분류/상태·이름·기간·지역/행사장·요금이다. 이름 목록 최대2줄/말줄임·상세 전체, 이미지 미제공/실패는 영역 없이 글만 표시한다. 기간 날짜 형식·요금4종·분류 통일·상세 정보순서는 [행사 UX 최종 명세](../../collaboration/requests/jonghyun/2026-10-20-event-ux-approved-spec.md)를 따른다. TourAPI 실제 관광타입15 전체 포함, 시설14로 확대하지 않는다.
- FR-8.10 일반 작성 행사 영역은 맨 아래, 행사 상세 진입은 맨 위다. 행사 검색·선택/직접 입력/연결 없음 허용. 버튼은 변경·삭제이며 삭제는 공고 연결만 해제한다. 비로그인은 로그인/가입 완료 뒤 원래 행사 연결 작성으로 복귀·상태 재확인한다.
- FR-8.11 직접 입력은 행사명 필수·장소명/공개 행사장 주소 선택, 주소 검색·공개 확인·개인주소 금지 안내·의심정보 검사. 주소를 못 찾으면 생략 가능하고 필수 약속 장소는 별도다. 공고 전용이며 공통 목록·독립 상세·공용화 검수 없음. 별도 행사 기간·이미지·요금 입력 없음.
- FR-8.12 연결 공고는 전체 상태·등록 최신순, 모집중 필터·10개 더보기와 기존 권한을 적용한다. 0건과 오류를 구분한다. 공고의 연결 API 행사는 상세 이동, 직접 입력은 이동 없음, 연결 없으면 영역 생략.
- FR-8.13 새 연결은 예정/진행중 허용, 종료/공식취소 불가(취소된 행사예요), 연기 일정 미정 불가·확인 후 조건 충족 시 허용, 비표출 제외. 취소 여부 미제공은 정상 수집/유효기간 등 검증 뒤 별도 보존·허용하되 공식 정상 개최라 표현하지 않는다. 오류/손상/해석 실패를 미제공으로 낮추지 않는다.
- FR-8.14 등록 직전 우리 서버 최신 상태 확인. 실패 시 입력 보존·다시 확인/사용자 행사 삭제 후 등록. 외부 API 매 등록 호출·선택 행사 자동삭제 없음. 원천 갱신·취소/연기는 기존 약속 자동 변경/취소 아님, 검색 누락만으로 취소/비표출 판단 금지.
- FR-8.15 확인 비표출 원천의 이름/이미지/설명/주소/상세 이동은 숨긴다. 다른 유효 공개 원천이 없으면 연결된 행사 정보를 현재 제공할 수 없어요 / 행사 취소를 의미하지는 않아요 안내 카드. 공고·약속·내부 관계 유지, 직접 입력 제외. 명시 재표출/공개 조건/최신 자료 검증 뒤 자동 복원, 기존 상태 제한 유지.
- FR-8.16 확실한 행사 단위 공식 공통 식별자/정확한 공식 상세 링크 등 동일 개최 근거만으로 대표 카드·상세·공고 통합. 이름/기관홈페이지/날짜/장소 유사성만으로 통합하지 않는다. 근거 부족은 출처별 유지·상시 수동검수 없음. 원천 ID·공고·근거·통합/분리 이력 보존. 먼저 검증된 공개 원천 대표 유지, 빈 항목만 출처를 남겨 다른 검증 공개 원천으로 보완. 대표 비표출 시 다른 공개 원천 전환, 핵심 충돌은 확인 필요 안내·새 연결 제한·기존 약속 유지.
- FR-8.17 작성자의 행사 교체/삭제/직접입력 행사명·장소 실질 변경은 핵심 조건 변경이다. 확정 전 알림·최종동의 무효화/재요청, 확정 후 상대 수락 전 기존 약속 유지. 원천 자동 갱신과 구분한다. 취소/연기/변경 일정은 관련 작성자·진행중 동행 확정 상대에게 앱 안 알림, 같은 변화 중복방지·새 푸시 없음.
- FR-8.18 위 요구사항은 확정 설계다. 직접입력 저장·확장 상태·동일 행사 통합·등록 검사 변경·행사 변경 합의·알림은 민규 서버 계약/구현 및 종현 FE 소비 검증이 필요하다. 기존 포트 존재나 문서 동기화로 완료 처리하지 않는다.

### FR-9. 프로필·후기

- FR-9.1 관계에 따라 마스킹 이름과 실명을 구분한다.
- FR-9.2 사진, 만 나이, 성향, 현재 당도, 칭찬 차트, 후기 원문을 제공한다.
- FR-9.3 사진 저장 실패 시 기존 사진을 유지한다.
- FR-9.4 사진은 필수이며 JPG·JPEG·PNG 원본 10MB 이하로 받는다. 사진 선택만으로 가입을 완료하지 않는다. 관심사·대화 방식은 각각 최대 20개·항목당 40자, 기본 선택지와 직접 입력을 지원한다. MBTI는 선택이며 E/I·S/N·T/F·J/P 네 쌍으로 입력한다.
- FR-9.5 작성자의 AI 원문 활용 동의가 유효한 한마디 포함 공개 후기 3개 이상을 근거로, 프로필 대상자의 생성·노출 동의와 열람자의 열람 동의를 각각 확인한 경우 AI 요약을 제공한다. 세 동의는 서로를 대신하지 않는다.
- FR-9.6 요약 실패가 원문·칭찬 노출을 막지 않게 한다.

### FR-10. AI 탐색

- FR-10.1 로그인 회원만 이용한다.
- FR-10.2 AI 탐색은 첫 사용 안내에서 동의받고 동의 확인 전 모델 처리·외부 전송을 시작하지 않는다. 거절하면 일반 검색·일반 동행·계정을 유지한다. 후기 요약 가입 동의와 분리하며 법적 검토·공급사 조건 확인 전 회원 원문 외부 전송 보류는 유지한다.
- FR-10.3 자연어 요청, 빠른 응답, 새 대화, 행사·동행 카드 결과를 제공한다.
- FR-10.4 GPS 없이 설정 지역을 사용하고 미설정일 때 지역명을 묻는다.
- FR-10.5 비공개 주소·상세 지점·거리와 개인 식별 정보를 결과에서 제외한다.
- FR-10.6 행사와 동행 공고를 구분하고 각각 S09-3과 S02로 연결한다.
- FR-10.7 초기 AI 대화는 기기 메모리에서만 유지하고 화면 종료·로그아웃 시 삭제한다. 서버·브라우저 영구 저장소에 저장하지 않는다.
- FR-10.8 실제 외부 전송 전 공급사 보관·암호화·삭제·비용과 법적 동의를 확인한다. 실제 회원 원문은 공급사 조건 검토와 사용자 확인 전 보내지 않는다.

### FR-11. 알림·계정·안전

- FR-11.1 첫 채팅, 확정 요청, 확정, 조건 변경, 취소, 평가 알림을 제공한다.
- FR-11.2 전체/읽지 않음 필터와 모두 읽음을 제공한다.
- FR-11.3 기존 S12 알림 진입에서 대상의 최신 상태·권한을 확인하고 자동 상태 변경은 하지 않는다. 삭제/접근 불가 등 원인이 미확인일 때 중립 공통 안내와 안전한 이동을 제공하고 일시 실패는 재시도를 제공한다. 403/404만으로 삭제·차단 사유를 단정하거나 민감정보 캐시를 노출하지 않는다.
- FR-11.4 예정 시작 시각 순으로 취소 결과를 집계하며 중간 미정 결과가 있으면 이후 연속 판정을 보류한다. 정상 완료 시 횟수는 0이다. 첫 연속 3회 경고, 이후 연속 3회마다 7일 제한이며 경고·제재 시 횟수만 0, 경고 이력은 유지한다. 신규 작성·신규/재신청·새 확정 요청/수락을 차단하고 기존 확정 약속 관리·채팅·후기는 허용한다.
- FR-11.6 확정 동행이 있으면 탈퇴 차단, 후기 기간만 남으면 탈퇴 허용. 재가입은 즉시 허용하되 원래 제재 종료까지 기능 제한을 유지하고 기간을 연장·초기화하지 않는다. 동일 네이버 계정의 경고·제재·취소 기록을 유지한다.
- FR-11.5 무료 1:1 안심 수칙은 첫 만남 공공장소·강요 금지·금전/민감정보 요구 주의·일정/귀가 공유·위급 시 도움 요청을 포함한다. 신고 시 상황에 맞는 증거 접수를 안내하되 신원·안전·만남 성공을 보증하지 않는다.
- FR-11.8 S21에 네이버 본인·성인 확인 상태, 실명/마스킹 이름, 성별·나이, 가입일, 제재 내역을 모아 표시한다. 정상/경고/이용 정지, 사유·이의 마감·검토 상태·실제 제한 종료를 구분하고 대기/적용/해제 변경을 안내한다.
- FR-11.7 취소 처리 후 24시간 이내 이의 신청을 받는다. 횟수는 우선 반영하되 해당 취소에 근거한 경고·제재는 기한 종료까지 보류한다. 미신청이면 기한 종료 후, 신청하면 검토 종료 후 판정하고 인정 사유는 제외한다. 예정 시작 시각 순 중간 결과 미정에 따른 보류는 유지하며 7일 제한은 실제 적용 시각부터 계산한다.

## 6. 비기능 요구사항

### 개인정보·권한

- 관계·로그인·공고 상태별 공개 범위를 서버에서 재검증해야 한다.
- 목록·검색·AI에서 비공개 상세 장소를 반환하지 않아야 한다.
- 취소 후 실명·상세 위치 접근을 회수해야 한다.
- AI와 로그에 회원 채팅·실명·전화·계좌·비공개 위치 원문을 남기지 않아야 한다.

### 신뢰성

- 최종 동의·완료·후기 공개는 중복 실행되어도 약속·알림·반영값을 중복 생성하지 않아야 한다.

- 외부 API 실패와 결과 0건을 분리해야 한다.
- 등록·신청·메시지·평가 실패 시 사용자의 입력을 가능한 범위에서 유지해야 한다.

### 접근성·사용성

- 모달·바텀시트는 키보드 포커스 이동, Escape 닫기, 포커스 복귀를 지원한다.
- 버튼에는 상태와 목적을 설명하는 접근 가능한 이름을 제공한다.
- 색상만으로 상태를 구분하지 않고 텍스트·배지를 함께 사용한다.

PRD의 각 수용 기준은 [기존 출시·복구 체크리스트](../../collaboration/requests/minkyu/2026-10-07-release-recovery-checklist.md)의 실제 파일·환경·결과·보류 증거와 연결한다. IA·USERFLOW에는 실제 화면 경로만 두며 문서 체크를 제출·출시 승인으로 표시하지 않는다.

- 동의 시점·전체 동의/개별 해제·독립 철회와 영향 요약 숨김/적격 재생성/외부 삭제 미확인 상태를 검증한다.

- 탈퇴 요약/펼침의 실제 기간 일치, 알림 공통 상태/일시 실패/민감정보 비노출을 검증한다.
- Android 예시 모드 내부 APK 빌드·설치·독립 실행 검증은 승인 범위이며 실회원 연결·스토어 배포 완료와 다르다. Apple Developer 계정 생성·유료 가입·서명 필요한 iPhone 내부 배포/TestFlight/스토어 검증은 보류다. 계정 없이 가능한 iOS 설계·공식 요건 확인은 계속할 수 있다.

## 10. 후속 범위

## 11. 확정 정책의 상세 요구사항

아래 요구사항은5장의 기능별 요구사항을 구체화한다. 각 세부 항목은 정책의 해당 장과 함께 적용하며, UI 표시와 서버 강제를 구분해 검증한다.

### FR-12. 관계 권한과 비로그인 응답

| 관계 | 공개 정보 |
|---|---|
| 본인 | 홈과 계정 화면에서 본인 실명, 계정 정보, 현재 당도, 활동 내역 |
| 비로그인 | 공고·행사 공개 정보와 공개 지역. 작성자 정보 박스는 모자이크 형태의 로그인 가드와 `동행인은 로그인 후 확인할 수 있어요` 안내 |
| 로그인·미확정 | 마스킹 이름, 만 나이, 공개 지역, 허용된 성향·후기·현재 당도 |
| 동행 확정 완료 | 상대 전체 이름, 정확한 주소와 상세 만남 지점, 확정 약속 정보 |
| 확정 공고의 제3자 | 확정 상태만 확인하며 상대 실명과 상세 위치는 볼 수 없음 |
| 취소 성립 후 | 전체 이름을 다시 마스킹하고 정확한 주소·상세 지점을 즉시 숨김 |

- 공고 목록에는 동까지의 공개 지역만 표시한다. 비로그인 작성자 가드는 실제 개인정보를 HTML·응답에 넣고 CSS로 가리는 방식으로 만들지 않는다.
- 상세 만남 지점은 작성자 확정 요청에 신청자가 수락하여 확정된 뒤 당사자에게만 공개한다.
- 공고 검색은 제목·등록 장소명·등록 주소·연결 행사명을 대상으로 한다.
- 소개글, 후기, 비공개 상세 지점은 검색 대상이 아니다. 작성자 만 19~99세 상한은 공고 필터에만 적용하고 전체 검색에 복사하지 않는다. 주변·반경·거리순 검색은 제공하지 않는다.
- 프로필 성향은 프로필 열람 권한이 있는 회원에게만 공개한다.

### FR-13. 목록·입력·초안·공고 관리

#### 4-1. 탐색과 필터

- 둘러보기 기본 정렬은 등록일 최신순이며 시작일 빠른순으로 전환할 수 있다.
- 필터는 카테고리, 지역(시·도), 일정, 작성자 만 나이 19~99세 범위를 제공한다.
- 비로그인은 일정과 나이 상세 필터를 사용하지 못하고 전체 범위만 본다.
- 기본 목록은 모집 상태와 관계없이 전부 노출한다. `모집 중` 필터를 활성화하면 모집 중 공고만 노출한다. 삭제된 공고의 기존 비노출 원칙은 유지한다.
- 필터는 `적용하기`를 눌러야 결과에 반영되며 초기화를 제공한다.
- 결과 없음과 조회 실패를 구분하고, 실패를 0건으로 표시하지 않는다.
- 공고·행사는 처음과 추가 조회마다 10개씩, 후기는 5개씩 가져온다. 전체 결과 수와 한 화면의 카드 수를 제한하는 뜻은 아니다.
- 최근 검색어는 같은 기기에 최대 10개를 7일 보관하며 직접 삭제·로그아웃 시 정리한다.
- 공고 카테고리는 지금이당·전시·축제·팝업·공연·영화·맛집·카페·쇼핑·여행·운동·산책·게임·반려동물·스터디·기타 16개다.

#### 4-2. 공고 작성

- 필수 항목은 카테고리, 제목, 소개, 장소, 시작 일시, 종료 일시다.
- 모집 마감은 선택이며 미설정 시 동행 시작 시각에 마감한다.
- 장소는 Kakao Local 기반 장소명 검색 또는 우편번호 기반 주소 검색으로 선택한다.
- 같은 이름의 장소는 주소와 우편번호로 구분한다.
- 공개 지역과 상세 만남 지점을 분리한다.
- 행사 연결은 선택이며, 행사 선택이 작성 중인 동행 일정을 자동 변경하지 않는다.
- 제목·본문에서 연락처·계좌·비공개 상세 위치 등 개인정보가 감지되면 등록을 차단하고 수정 또는 오탐 문의를 안내한다.
- 제목은 50자, 소개는 2,000자, 상세 만남 지점은 300자까지다.
- 작성 초안은 같은 기기 브라우저에 최근 1개만 임시 저장한다. 새 초안으로 대체하기 전에 알리며 마지막 수정부터 7일 뒤 만료한다. 복원 안내에 만료 시각을 표시하고 등록 성공·로그아웃 시 삭제한다.
- 등록 성공 시 별도 완료 화면 없이 생성된 S02 공고 상세로 이동한다.

#### 4-3. 공고 상태와 관리

- 공고 상태는 모집 중, 수동 마감, 최종 동의 대기, 확정, 완료, 삭제 등으로 구분한다.
- 수동 마감은 새 신청만 막고 기존 유효 신청자와의 대화는 보존한다. 기존 와이어프레임의 시작 전 최종 동의 재요청 흐름을 유지한다.
- 확정 전 핵심 조건 변경 시 신청자에게 알리고 기존 최종 동의 요청을 무효화한다. 새 조건으로 다시 요청하고 동의받는다.
- 확정 전 삭제 시 공개 목록에서 숨기고 미확정 요청을 종료하며 기존 대화는 읽기 전용으로 보존한다.
- 확정 후에는 공고 삭제로 약속 취소를 대신하지 않는다. S18의 확정 동행 취소 절차를 사용한다.

### FR-14. 차단·신고·위반·콘텐츠

- 확정 전 신청 철회와 확정 후 시작 전 취소를 구분한다.
- 확정 전 철회는 연속 확정 취소 제재에 포함하지 않는다. 재신청은 철회 후 1분 경과 시 횟수 제한 없이 허용하되 작성자 거절 이력이 있으면 차단한다.
- 확정 후 시작 전 취소는 사유를 선택해 처리하고 상대에게 알림을 보낸다.
- 취소 성립 즉시 전체 이름을 다시 마스킹하고 상세 주소를 숨긴다.
- 시작 이후에는 일방 취소 대신 중단·불발 신고로 접수한다.
- 중단·불발 신고에는 상황 설명이 필요하며 운영 검토 후 조치한다.
#### 6-1. 차단

- 차단한 두 사람 사이의 신규 메시지·신청·확정 요청·수락을 막는다. 로그인 상태에서 서로의 공고·프로필을 숨기되 기존 약속 관리에 필요한 정보는 유지한다. 비로그인 공개 접근까지 완전히 막는다고 안내하지 않는다.
- 기존 대화는 읽기 전용으로 두고 기록 확인·신고·나가기를 제공한다. 차단은 즉시 처리하며 확정 약속의 취소는 별도 확인과 기존 취소 규칙을 따른다.
- 차단 해제는 차단 때문에 생긴 숨김만 해제한다. 신고 등에서 별도로 선택한 본인 콘텐츠 숨김은 명시적 숨김 해제 전까지 유지한다. 해제 후 현재 권한을 다시 조회하며 종료 신청·취소 약속은 자동 복원하지 않는다. 차단만으로 후기·당도·칭찬은 바뀌지 않는다.

#### 6-2. 신고와 처리

- 운영자는 DB의 회원 채팅 원문을 직접 읽지 않는다. 온라인 신고는 상황 설명과 캡처를 필수로 받는다. 대면 위협·노쇼는 설명과 제출 가능한 자료로 접수하며 캡처가 없다는 이유만으로 접수를 막지 않는다. 접수 자체를 사실 인정으로 취급하지 않는다.
- 공고·채팅·AI 결과는 전용 신고 양식, 다른 대상은 대상이 연결된 공통 양식으로 접수한다. 성희롱·협박·금전/개인정보 요구·사칭·스팸·노쇼·기타를 복수 선택하고 설명할 수 있다.
- 일반 신고에서 선택한 본인 콘텐츠 숨김은 탐색·콘텐츠 조회에만 적용하고 확정 일정·취소·신고·판정 안내 등 필수 관리 경로를 유지한다. 신고 증거의 최종 종결+90일 파기와 별도로 최소 식별 기록만 본인 해제까지 유지하고 설명·캡처를 숨김 유지 목적으로 보관하지 않는다. 전체 공개 제한·차단·제재와 구분한다. 클라이언트 연결은 준비됐으나 실제 목록/상세 숨김 계약과 서버 검증 전 전체 기능 활성 완료로 표시하지 않는다. 선택값 저장·신고 실패를 숨김 성공으로 표시하지 않는다.
- 접수·검토 중·추가 자료 요청·처리 완료 및 내 신고 내역을 표시한다. 신고자에게 조치 여부·대표 사유, 제재 당사자에게 본인 위반·제재·이의 절차만 안내한다. 신고자 신원·다른 사건은 공개하지 않는다.
- 일반 신고의 첫 확인 목표는 평일 09~18시 운영 기준 영업일 2일 이내다. 실제 처리 책임자는 대표 유미이며 일반 신고의 부재 시 대체 담당은 종현이다. 실제 도구·권한 설정과 운영 가능 여부를 검증하고 사건별 완료 시한은 별도 안내한다. 위급 상황은 공식 긴급 도움 경로를 안내하고 위험 신고를 우선 검토한다.
- 불인정·증거 부족만으로 신고자를 제재하지 않는다. 조작·보복 목적이 확인된 반복 신고를 심사한다. 양쪽이 불발을 인정하면 간단히 처리하고 다툼이 있으면 분쟁 심사한다.

#### 6-3. 취소 외 위반과 이의

- 경미 위반은 위협·성희롱·개인정보 노출 없는 낮은 위험의 규칙 위반이다. 반복은 안내·경고 후 같은 유형 또는 같은 피해자 대상 위반의 재발이다. 중대 위반은 성희롱·협박·폭력·스토킹·신상 노출·성적 착취 등 안전·권리 침해다. 정당한 비판과 증거 부족 신고 자체는 위반이 아니다.
- 경미한 첫 인정은 경고, 그 뒤 첫 재발은 신규 공고 작성·신청·확정 7일 제한, 두 번째 재발부터는 매번 30일 제한한다. 직전 확정 위반 후 12개월 동안 재발이 없으면 일반 위반 단계는 경고부터 다시 센다. 연속취소의 첫 경고 유지 규칙에는 이 초기화를 적용하지 않는다.
- 중대 위반이 운영 검토에서 확인되면 경고 없이 해당 계정을 즉시 영구 이용 제한한다. 신고 접수만으로 위반이 확정됐다고 보지 않는다. 심사 중 필요한 접촉 제한과 최종 영구 제재를 구분한다. 기존 약속의 안전 관리·본인 자료 열람·이의 절차는 유지한다.
- 취소 외 제재는 판정·사유·이의 방법이 앱에 성공적으로 제공된 서버 시각부터 7일 내 이의 신청을 받는다. 최초 열람이나 푸시/메일 발송 시각이 아니며 제공 실패 시 기산하지 않는다. 안내에 서버의 이의 마감 시각을 표시한다. 심사 중 기존 제한은 원칙상 유지하되 명백한 오류가 확인되면 즉시 해제하고 잘못된 이력·당도 영향을 정정한다. 이의 신청으로 제재 기간을 다시 시작하지 않는다. 취소 이의의 24시간·판정 보류 규칙은 별개다.

#### 6-4. 공개글과 채팅 검사

- 성희롱·협박·혐오·인격 모욕·사칭·스팸·허위 모집·금전/민감정보 강요 및 아동 성적 착취·학대 콘텐츠를 금지한다. 사실과 경험에 근거한 부정 평가·비판은 허용한다.
- 공고·공개 프로필·후기는 개인정보와 금지 콘텐츠를 등록 전에 검사한다. 채팅은 정상 약속 안내를 일괄 차단하지 않고 명확한 고위험을 차단한다. 애매한 위험 표현은 전송 전 확인 안내를 하고 수정하거나 그대로 전송할 수 있게 한다.
- 자동 검사와 운영자의 원문 직접 열람은 다르다. 자동 검사 때문에 원문 로그 보관·외부 AI 전송·DB 직접 열람을 추가하지 않는다. 오탐 문의와 신고 경로를 제공한다.

### FR-15. 후기 검토·당도·요약

#### 7-1. 완료

- 예상 종료 전에는 완료 확인을 할 수 없다.
- 종료 후 각 사용자는 본인의 동행 완료를 확인할 수 있다.
- 한쪽만 확인한 상태는 개인 확인 완료일 뿐 동행 실제 완료가 아니다.
- 양쪽이 확인하거나 예상 종료 시각 +24시간이 지나면 동행을 실제 완료 처리한다.
- 취소·노쇼 건은 자동 완료에서 제외하고 신고·분쟁 검토 중에는 자동 완료를 보류한다.
- 정상 동행으로 인정되면 양쪽이 합의한 최신 종료 시각 +24시간이 지났을 때 즉시 완료한다. 아직 지나지 않았다면 그 최신 종료 +24시간 기준을 유지한다. 검토 중 새로 합의한 종료도 적용하며 검토 시간을 추가하지 않는다.
- 한 명이 탈퇴했고 실제 완료 기록이 없으면 정상 정정 시점에 완료하며 다른 미결 검토가 있으면 보류한다. 최초 실제 완료부터 후기 7일을 적용하고 탈퇴한 본인은 새로 작성할 수 없다. 탈퇴자를 진행 중 약속으로 되돌리지 않는다.
- 실제 완료 시 완료 횟수를 즉시 반영한다.
- 이의 검토 중 리뷰 작성·기한 진행·공개를 보류한다. 동행 인정 후 남은 리뷰 기간을 재개하되 최소 24시간을 보장한다.
- 실제 완료 전에는 리뷰 작성 기한이 시작되지 않는다. 검토 후 처음 완료되었다면 실제 완료 시점부터 7일을 시작한다. 이미 완료된 동행은 검토 직전의 남은 리뷰 기간을 재개하며 최소 24시간을 보장한다.
- 검토 중에는 양쪽 제출을 포함해 새로운 리뷰 공개를 보류한다. 이미 공개된 후기는 접수·검토 개시만으로 숨기지 않고 운영자가 임시 비공개 필요성을 판단한 때 숨긴다. 검토 종료 후 양쪽 제출이면 공개하고, 한쪽 제출이면 재개·연장된 작성 기한 종료 시 공개한다.

#### 7-2. 평가와 공개

- 본인 완료 확인 후 상대 확인 전에도 후기를 미리 제출할 수 있으나 실제 완료 전에는 비공개다.
- 평가 경험은 `좋아요`, `보통이에요`, `별로예요` 중 하나다.
- 별점 1~5점은 필수, 한마디는 선택이다.
- `좋아요`일 때만 공식 칭찬을 최대 3개 선택할 수 있다.
- 공식 칭찬 6종은 `시간을 잘 지켜요`, `약속한 내용을 지켜요`, `소통이 원활해요`, `배려심이 있어요`, `대화가 즐거워요`, `함께하니 편안해요`다.
- 제출 성공 후 수정과 중복 제출은 불가능하다.
- 후기 작성 기한은 실제 완료 시각 +7일이다.
- 실제 완료 후 양쪽이 제출하면 즉시 공개하고, 한쪽만 제출하면 후기 작성 기한 종료 시 공개한다.
- 상대 후기가 열람 가능해지는 시점에 당도를 반영한다.

#### 7-3. 공개 프로필과 AI 후기 요약

- 공개 프로필은 사진, 관계에 따른 이름, 만 나이, 선택 성향, 현재 당도, 칭찬 차트, 후기 원문을 보여준다.
- 칭찬은 누적 상위 5개와 횟수를 표시한다.
- 작성자의 원문 활용 동의가 유효한 한마디 포함 공개 후기 3개 이상과 대상자의 생성·노출 동의를 충족할 때만 AI 요약을 생성·공개한다. 열람자의 열람 동의는 별도로 확인한다.
- 비공개 후기·텍스트 없는 평가·작성자의 원문 활용 동의가 없는 후기는 AI 요약 근거에서 제외한다. 후기 작성 화면에 `작성한 후기는 상대방의 AI 후기 요약에 활용돼요`를 재안내하며 매번 동의 체크를 반복하지 않는다.
- 요약 실패·대기 상태에서도 공개 가능한 칭찬과 원문 후기는 유지한다.
- 숨긴 후기의 칭찬은 차트에서 제외하고 유효하게 재공개되면 복원한다. 다른 공개 후기의 칭찬은 유지한다.
- 비공개 후기를 근거로 만든 기존 AI 요약은 즉시 숨긴다. 남은 허용된 공개 텍스트 후기 3개 이상이며 대상자의 생성·노출 동의와 공급사·전송 조건이 유효하면 정기 주기에 재생성하며, 미만이면 요약 대기를 표시한다.
- 검토 종료 후 현재 조건을 다시 확인해 공개 가능한 후기를 복원한다. 복원 자체의 당사자 알림은 보내지 않는다.
- 공개 AI 요약은 최대 300자다. 표시하거나 다시 펼칠 때 서버의 현재 공개 조건을 조회하며 별도 공개 결과 캐시는 두지 않는다.

#### 7-4. 당도 계산

- 초기값은 15, 표시는 0~100의 정수다. 아직 평가가 없는 초기값임을 안내한다. 완료 횟수와 칭찬은 당도에 가산하지 않는다.
- 후기 반응은 좋아요 +1·보통 0·별로 −2, 별점은 1~2점 −2·3점 0·4~5점 +1로 각각 계산해 합산한다. 미작성 평가는 0이다.
- 확정된 운영 감점은 취소 제재 1회 −2, 노쇼 1건 −3, 중대 위반 1건 −10이다. 같은 사건에 여러 운영 위반이 겹치면 가장 큰 운영 감점 하나만 적용한다. 개별 취소 한 번을 곧바로 취소 제재 1회로 세지 않는다.
- 유효 후기와 운영 감점이 같은 사건에 함께 있으면 둘 다 합산한다. 노쇼 등으로 동행·후기 자격이 무효라면 해당 후기 기여를 제외한다.
- 초기 15에 모든 유효 가감 내역을 합산하고 마지막 표시값만 0~100으로 제한한다. 사건마다 상·하한으로 잘라 누적하지 않는다. 원 평가·가감 내역을 유지해 무효·해제 시 재계산한다.
- 후기 점수는 상대 후기의 열람이 가능해지는 시점에 반영한다. 양쪽 제출은 실제 완료 조건을 충족한 공개 시점, 한쪽 제출은 작성 기한 종료 공개 시점이다. 운영 감점은 해당 위반·제재가 확정된 때 적용한다.
- 임시 후기 숨김 중에는 이미 반영한 당도를 유지하고 최종 무효 판정 때 해당 기여를 제외한다. 공개 복원·운영 오판 정정과 연결해 재계산한다.
- 계산 예: 초기 15에서 좋아요와 별점 5는 17, 별로와 별점 1은 11이다. 후자가 유효한 실제 완료 동행에서 중대 위반 −10도 확정되면 1이다. 이는 산식 예시이며 실제 회원 결과가 아니다.

### FR-16. 행사 주차·수집

- 홈 배너·기본 행사 목록은 `이번 주 신규 중 미종료` 행사만 제공하고 화면에 이 기준을 안내한다. 이번 주에 시작했어도 이미 끝났으면 기본 목록에서 제외하며 과거 기간 조회에서 찾을 수 있다.
- `진행 중 포함`을 선택하면 이전 주에 시작해 아직 진행 중인 행사도 포함한다.
- 한 주는 한국시간 월요일 00:00부터 다음 월요일 00:00 미만으로 본다.
- 행사 배너·목록의 `○월 ○주차`는 그 주의 목요일이 속한 달에 귀속한다. 해당 월의 날짜가 4일 이상 포함된 주를 그 달의 주차로 세며, 월 경계에서 한 주를 나누지 않는다.
- 해당 월의 첫 번째 목요일이 포함된 주를 1주차로 하고 이후 월요일마다 2주차·3주차로 순서대로 계산한다. 월말의 주도 같은 기준으로 다음 달에 귀속될 수 있으며, 연말·연초에는 귀속 연도도 함께 바뀐다.
- 매월 1일이 월~목요일이면 그날이 속한 주가 해당 월 1주차다. 금~일요일이면 그날이 속한 주는 전월 마지막 주차이며, 다음 월요일부터 해당 월 1주차다.
- 예: 2026년 9월 1일은 화요일이므로 8월 31일~9월 6일은 `9월 1주차`다. 2023년 9월 1일은 금요일이므로 8월 28일~9월 3일은 `8월 5주차`, 9월 4일~10일은 `9월 1주차`다.
- 이번 주 신규 행사는 해당 주의 월요일 00:00부터 다음 월요일 00:00 미만에 시작한 행사로 판단한다. 달이 다른 날짜도 같은 주간 범위에 포함하며, 월별 주차 표기를 위해 범위를 월초·월말에서 자르지 않는다. KOPIS 공식 순위의 `어제까지 최근 7일` 집계는 별도 기준을 유지한다.
- 표준과 서비스 규칙을 구분한다. ISO 8601-1의 주 달력은 연도 기준 주차를 정의하며, 위 월별 주차는 월요일 시작·목요일 귀속 원칙을 유미당의 월별 표시 규칙으로 적용한 것이다. 월별 주차 자체가 ISO의 직접 규정이라고 표기하지 않는다. 참고: [ISO 8601-1:2019 3.1.1.23 주 달력 정의](https://cdn.standards.iteh.ai/samples/70907/5e8d00e639cf4f849462bd63062f4cd8/ISO-8601-1-2019.pdf).
- 행사 유형은 공연·전시·축제·팝업 등 제공처의 실제 분류를 따른다.
- 공연은 콘서트·뮤지컬·연극 하위 장르 필터를 제공한다.
- 종료된 행사는 조회할 수 있으나 새 동행 모집 대상으로 연결하지 않는다.
- 작성용은 연결 가능한 진행 중·예정 전체를 검색·선택하며 동행 일정과의 겹침을 강제하거나 자동 기간 축소하지 않는다. 달력에 선택 행사 날짜를 색으로 강조하며 동행 일정은 자동 변경하지 않는다.
- 행사 상세는 명칭·기간·장소·입장료·출처·운영 안내·연결 공고 중 실제 확보한 정보를 제공한다. 공급사 공통 정규화는 기존 SourceEventRecord 계약을 재사용하고 원천 ID·누락값·요금·날짜 정밀도를 보존한다. 요금 미확인을 무료로, 행사 기간을 동행 약속으로 대신하지 않는다.
- 행사장을 공고 작성의 장소 후보로 전달할 수 있다.
- KOPIS 순위 선택은 전체 공연(기본), 연극, 뮤지컬, 클래식, 국악, 대중음악, 무용, 대중무용, 서커스/마술, 복합, 아동, 대학로, 내한, 축제의 14항목이다. 표시명은 서양음악(클래식)→클래식, 한국음악(국악)→국악, 무용(서양/한국무용)→무용으로 바꾸되 원천 코드·원래 분류는 보존한다. 아동·대학로·내한·축제는 장르와 구분되는 공식 특성·지역 조건을 따른다. 집계는 어제까지 최근7일, 갱신은 매일이다. 분류마다 공식 사이트에 표시된 실제 기간·공식 분류/지역·정렬 기준과 API 공연ID·순위·순서가 일치한 Top10만 공개한다. basedate가 없어도 이 대조를 통과한 목록은 공개할 수 있으나 API 내부 집계 기간을 증명했다고 안내하지 않는다. 요청 날짜만으로 기간을 확정하거나 일간 순위를 합산한 자체 주간 순위를 만들지 않는다. 동률은 공식 표시 순서 그대로 유지하고 10개 미만이면 검증한 개수만 표시한다. 출처·실제 확인 기간·확인 시각을 표시한다. 갱신 실패 시 마지막 검증 목록의 기존 기간을 그대로 유지하고 갱신 지연을 안내하며 최신 날짜로 바꾸지 않는다. 최초 미검증·미지원 분류는 공식 사이트 링크를 제공하고 자체 순위로 채우지 않는다. 분류별 성공·실패를 독립 관리한다. 현재 API 매핑·자동 대조·저장·서버 응답 구현과 운영 검증은 별도이며 이 정책 변경만으로 연동 완료로 표시하지 않는다.
- 집계는 어제까지 최근7일, 갱신은 매일이다. 분류마다 공식 사이트에 표시된 실제 기간·공식 분류/지역·정렬 기준과 API 공연ID·순위·순서가 일치한 Top10만 공개한다. basedate가 없어도 이 대조를 통과한 목록은 공개할 수 있으나 API 내부 집계 기간을 증명했다고 안내하지 않는다. 요청 날짜만으로 기간을 확정하거나 일간 순위를 합산한 자체 주간 순위를 만들지 않는다. 동률은 공식 표시 순서 그대로 유지하고 10개 미만이면 검증한 개수만 표시한다.
- 공식 순위 미수신 시 자체 추정 순위로 대체하지 않는다.
- 초기 과거 수집은 최근 1개월, 미래 수집은 오늘부터 31일이며 이미 진행 중인 행사도 별도 갱신한다. 처리 한도에 도달하면 진행 위치를 보존해 다음 실행에 이어 수집하고 미수집 범위를 운영 상태에 표시한다.

### FR-17. AI 한도·실패·동의

- S20 AI 탐색은 로그인 회원만 이용할 수 있다.
- AI 탐색은 첫 사용 동의 후 실행하며 거절하면 일반 검색을 유지한다. 후기 요약은 가입 시 열람·내 프로필 생성/노출·작성 원문 활용을 각각 선택 체크로 받는 제품 의도다. 전체 동의 동작·기본 미선택·상세 안내·테스트 계정의 동의 간주는 FR-1을 따른다. AI 미동의를 이유로 가입을 거부하거나 일반 동행·계정을 차단하지 않고 미동의 항목에 해당하는 AI 기능만 제한한다. 동의의 법적 분류·문구·공급사 조건 확인과 회원 원문 외부 전송 보류를 유지한다.
- 후기 요약 세 동의는 독립적으로 철회한다. 열람 철회는 본인의 열람만, 생성/노출 철회는 본인 프로필의 요약 숨김과 생성/갱신 중단에 적용한다. 원문 활용 철회는 본인이 쓴 기존·향후 후기를 AI 재료에서 제외하고 이를 사용한 기존 요약을 우선 숨긴다. 남은 허용 자료 3개 이상·대상자 동의·기존 공개/처리 조건을 충족한 경우에만 재생성 후 공개한다. 실패·미확인·자료 부족 시 숨김을 유지한다.
- 다른 동의를 자동 철회하지 않으며 계정·일반 동행·일반 후기 원문·별점·당도는 AI 동의 철회만으로 변경하지 않는다. 일반 후기 삭제/숨김/무효 정책은 별도다. 해당 처리의 새 전송을 중단하고 AI 처리용 복사본·외부 사본·관련 생성물의 필요한 삭제를 추적하며 확인 전 삭제 완료로 표시하지 않는다. 공급사의 실제 삭제 지원은 별도 확인한다.
- 실명·전화번호·비공개 상세 주소 등 개인 식별 정보는 추천 입력·결과에서 제외한다.
- GPS는 사용하지 않으며 사용자가 설정한 지역을 추천에 사용한다. 지역을 설정하지 않았으면 지역명을 묻는다.
- 행사 카드와 동행 공고 카드를 명확히 구분하며, 연결 공고가 없는 행사를 신청 가능한 동행처럼 표시하지 않는다.
- 공고 결과에는 비공개 주소·상세 만남 지점·거리(km)를 표시하지 않는다.
- 현재 프로토타입은 카테고리·주요 지역·무료·주말 조건을 다룬다. 세부 운영시간, 실시간 날짜 계산, 미등록 지역 인식은 후속 과제다.
- 초기 AI 대화는 기기 메모리에만 유지하고 화면 종료·로그아웃 시 삭제한다. 서비스 서버나 브라우저 영구 저장소에는 저장하지 않는다.
- 실제 외부 전송, 공급사 보관 조건, 암호화, 법적 동의 문구는 연동 전에 별도 검토·확인이 필요하다.
- 현재 대화는 사용자·AI 메시지 합계 20개, 메시지별 500자, 전체 4,000자로 제한하는 설계다. 초과 전에 알리고 사용자가 확인한 필터로 새 탐색한다. 원문을 몰래 잘라내거나 영구 저장하지 않는다.
- 실제 검색 후보는 10개씩 최대 3쪽(30개) 확인하고 최대 5개를 표시한다. 반환 직전 현재 정보를 재조회한다. 공개 정보만 바뀐 카드는 최신 정보와 함께 낡은 설명을 제거하고, 성향 근거가 바뀌거나 권한을 잃은 카드는 제외한다.
- 확인을 마친 일부 카드만 제공할 때는 일부 확인 결과라고 안내한다. 확인 카드가 0개면 결과 없음이 아닌 확인 미완료로 표시한다. 설명 생성 실패 시 확인된 실제 카드와 정형 안내는 제공한다.
- 공급사 전송 전 미전송이 확인된 일시 오류만 같은 회원 요청 전체에서 자동 1회 재시도한다. 전송 후 오류·응답 유실·전송 여부 불명은 자동 재전송하지 않고 입력을 유지해 직접 재시도·일반 탐색을 안내한다. 입력에서 개인정보를 발견하면 전송을 막고 수정 또는 사용자가 선택한 최소 구간의 오탐 문의를 제공한다. 출력에서 발견하면 답변을 숨기고 사용자 재시도 1회를 제공하며 반복 시 일반 탐색을 안내한다.
- AI `도움이 됐어요` 평가와 `문제 있어요` 신고의 상태를 구분한다. AI 신고는 Storage 소유권·담당자 접근권한·접근 감사·파기 연결 준비 전 비활성화한다. 활성화 시 회원이 확인한 답변 일부 최대 500자 또는 본인 업로드가 완료된 캡처 1개를 제출 전 확인한다. 전체 대화 자동 첨부·서버의 생성 원문 일치 보증은 하지 않는다. 실제 접수와 hideAnswer:true가 확인된 경우에만 본인 답변을 숨긴다. 일반 신고 전체를 비활성화한다는 뜻은 아니다.
- helpful 평가와 중복 접수 기록은 접수 후 90일 또는 탈퇴 중 빠른 때 삭제하며 만료된 AI 요청의 새 평가는 거절한다. AI 신고 증거는 이의 포함 최종 종결+90일 파기다.
- 공급사 예산은 공급사별 계약과 원장을 분리한다. 기존 포텐스닷 프로토타입의 계정별 한국시간 하루320만 토큰·등록 계정 상한 합계는 기술 토큰 예산이며 Gemini의 원화 월 예산으로 환산하지 않는다. 다계정 전환은 공급사 공동 사용 조건 확인·전송 전 계정별/전체 원자 예약·미확인 사용량 보존을 전제로 하며 운영 활성화는 미완료다. 종현 Gemini 테스트는 월50,000원 사용중단 예산을 별도로 적용하고 대표 계정 전환 전 총예산을 늘리지 않는다. 공급사 간 무료 자동 전환과 추가 결제는 자동 승인하지 않는다. 전체 허용 예산이 부족하거나 확인되지 않으면 새 모델 전송을 중단하고 일반 검색·공개 가능한 원문 이용을 유지한다.
- 회원 하루 20회·계정별/전체 토큰 상한과 기존 내부 모델 호출 수 제한을 함께 유지한다. 다계정 전환을 이유로 내부 호출 제한을 늘리거나 우회하지 않는다.
- 회원별 초기 AI 한도는 한국시간 하루 20회이며 자정에 초기화한다. 분당 횟수 제한은 두지 않는다. 같은 회원의 요청은 한 번에 하나만 처리하며 응답 뒤 바로 다음 요청이 가능하다.
- 정해진 조건 버튼·일반 더보기를 모델 없이 처리하면 AI 횟수에서 차감하지 않는다. 자연어 해석·의미 비교·생성 설명을 위해 모델 처리를 시작하는 새 요청은 1회다. 내부의 여러 모델 호출·같은 요청의 자동 재시도는 추가 차감하지 않는다. 창 열기·새 대화·모델 호출 전 차단은 제외한다. 처리 시작 후 실패한 요청도 1회이며 사용자가 다시 보내는 새 요청은 새 1회다.
- 전체 계정 예산이 먼저 소진되면 개인 한도가 남아도 AI 이용을 중단한다. 실제 연결 후 일일 한도량·호출당 토큰 비용과 사용량을 측정해 상단 기준대로 한도를 재설정한다.

### FR-19. 작업 실행·비용 제한

이 절은 개발 연결을 위한 선택값이며 실제 공급사 지원·성능·운영 검증은 별도다.

- 행사 수집과 후기 요약은 매일 한국시간 00:01에 등록한 뒤 분리 실행하고 실패 영역만 재시도한다. 자동 완료·후기 공개는 이 배치를 기다리지 않는다.
- 요약 작업의 실제 실패는 최대 3회, 재시도 간격은 10분부터 늘려 최대 6시간이다. 예산 부족은 실패로 세지 않고 1시간 뒤 확인한다.
- 요약 실행은 최대 10작업·60초, 점유 시간 180초, 입력 12,000자·후기 20개씩, 중간 요약 4개 병합, 단계당 최대 3호출·출력 800토큰이다. 모든 적격 근거를 분할 처리하며 일부만 처리한 것을 전체 요약으로 표시하지 않는다.
- 탐색 해석은 출력 800토큰, 성향 비교는 5후보씩 최대 3호출·호출당 출력 600토큰이다. 합성 검증 예산 50,000은 기술 원장 단위이며 원화나 공급사 포함량으로 환산하지 않는다. 충분하지 않으면 중단하며 합성 10회를 보장하지 않는다.
- 공급사 한도 초기화 주기에 맞춰 비용을 계산하되 미정산 예약을 지우지 않는다. 불일치는 운영 알림과 공급사 기록 대조로 처리하고 자동 환불·한도 초기화를 하지 않는다. 비용 책임자 유미와 기술 운영 담당 민규만 필요한 범위에서 원장을 열람하고 접근·변경을 기록한다.
- 장소는 10개/쪽, 행사 요청은 31일 구간·100건/쪽·최대 5쪽·쪽당 15초다. 일일 요약 실행 호출은 최대 1회·75초, 내부 정리는 20건, 동시 작업 실행기는 1개·점유 자동 연장은 없다. 부족한 작업은 보존해 재개한다.
- 네이버 로그인 요청은 10분, 일반 외부 요청은 15초, 일반 JSON 본문은 64KiB, 자동 완료 재접속은 5초·DB 쿼리는 10초다. 사진 업로드는 일반 JSON 상한과 구분한다.
- 실행기 최대 20은 같은 전역 실행의 고유 큐 작업 ID 20개다. 같은 작업의 재조회·첨부 처리·완료 기록은 추가 차감하지 않는다. 별도 terminal 유지관리 한도·DB/Storage 호출 수 제한과 구분한다. 종류별 배정·재시작은 같은 전역 점유·작업 원장을 사용하고 자동 연장·토큰 재취득으로 우회하지 않는다.
- 모델 출력 상한이 실제 공급사 요청에 전달되어 강제되는지, 계정 한도·호스팅 시간 제한과 위 값이 맞는지는 구현 전에 검증한다. 현재 코드가 이미 이 기준을 만족한다고 보고하지 않는다.

### FR-20. 재가입·집계·정정

- 진행 확정 약속이 없다면 후기/분쟁만 남아도 탈퇴를 허용하고 처리는 별도 유지한다. 동일 네이버 검증 식별값으로 제재·경고·연속기록을 승계한다. 영구 제한은 종료 없이 승계하며 이름·생일로 다른 계정을 자동 연결하지 않는다.
- 재가입은 새 프로필·당도15·횟수0, 과거 받은 후기/당도 미복원이다. 계정 변경 메뉴·계정 간 활동 이전을 제공하지 않는다.
- 취소 집계는 결과 확정 직전 합의 시작→확정 시각→ID 순이다. 제재가 겹치면 각 실제 시작부터7일의 최대 종료를 사용한다. 오판 정정은 순서 재계산·잘못된 경고/제한 즉시 해제·상태 안내를 포함한다.
- 정정 재계산 후 같은 취소 제재가 유지되면 기존 시작 시각을 보존한다. 새로 생긴 제재만 실제 새 적용 시각부터 계산하며 정정만으로 기존 기간을 연장하지 않는다.
- 탈퇴 전 사건의 제재가 탈퇴 후 처음 확정되면 동일 네이버 계정의 경고·기간제/영구 제재를 적용·승계하되 과거 사건 감점을 새 가입 회차의 당도로 이전하지 않는다.
- 탈퇴 시 작성 공고와 진행 중 신청을 취소·정리한다. 진행 중인 확정 동행만 먼저 정리하고 후기 기간·분쟁만으로 탈퇴를 차단하지 않는다.
- 서버 접수 시각이 마감과 같으면 만료다. 철회 후 재신청은1분 경과부터이며 마감 규칙과 구분한다.

### FR-21. 공급사 분리·테스트 월 예산·AI 상태 확인

- **AI 공급사와 실회원 전송 조건:** 포텐스닷은 교육·프로토타입 범위로 구분한다. 사용자가 공유한 공급사 회신은 일일 한도·기간 제한, 기능 축소와 보안 우려로 실제 서비스에는 다른 API를 권고했다. 보관·학습·삭제·공동 사용의 구체 조건이 확인됐다는 뜻은 아니며, 실제 회원 대화·후기 전송은 조건 확인 전 보류한다. 무료 공급사를 이어 붙이는 전환도 공급사별 조건·품질·비용 확인 없이 활성화하지 않는다. [회신 및 공급사 전환 기록](../../collaboration/requests/jonghyun/2026-10-19-gemini-registration-and-fallback.md)을 따른다.
- **Gemini 테스트·지출 상한·대표 계정 전환:** 종현 개인 계정의 테스트 전용 프로젝트에 기존 My Billing Account 결제를 연결하고 월50,000원 사용중단 예산을 설정했다. 선충전·정액 결제가 아니다. 공급사 집계 지연·진행 중 요청·세금 범위 때문에 최종 청구액이 반드시50,000원 이하라고 보장하지 않는다. 앱 서버의 원화 예산 예약·차단은 별도 미구현이며 새로운 하위 한도를 임의 확정하지 않는다. 가상 탐색·후기·지시문 검증3건은 통과했지만 앱 어댑터·실회원·운영 검증을 대신하지 않는다. 대표 유미 계정 전환은 회의·브랜치 통합 때 계정·프로젝트·결제·키를 확인한 뒤 진행하며 자동 실행하지 않는다. 양쪽 계정에 각각5만원으로 총예산을 늘리지 않는다. [월 예산](../../collaboration/requests/jonghyun/2026-10-19-gemini-monthly-budget.md)·[합성 검증과 전환](../../collaboration/requests/jonghyun/2026-10-19-gemini-synthetic-validation.md)을 따른다.
- AI 한도 소진·동의 필요 등 중단 응답 뒤 보내기는 서버 판단을 유지한다. 안내·입력을 보존하며 자동 재전송하지 않는다. 이용 가능 상태 확인 수단을 민규와 먼저 맞춘 뒤 종현이 버튼 제어를 연결한다. 클라이언트 자체 횟수·자정 타이머·재진입만으로 이용 가능을 확정하지 않는다.

## 12. 현재 수용 검사 상태

정책 선택·요구사항 문서화는 실제 제품 수용 검사와 다르다. 비로그인 응답/DOM, 첫 전송 원자성,6시간/7일 경계,검토·공개·당도 분리,즉시 재가입 제재 승계,AI 횟수와 예산,백업 삭제는 실제 환경의 별도 검증이 필요하다. 현재 이 문서의 제품 검사 상태는 NOT_RUN이다. 관련 코드가 있다는 이유나 과거 통과 결과만으로 완료 처리하지 않는다.
