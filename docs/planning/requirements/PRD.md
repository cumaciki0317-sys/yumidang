# 유미당 PRD

정책의 원본은 [정책.md](../../../정책.md)다. 이 문서는 제품 목적·현재 범위·요구사항을 설명하고, 화면 구조는 [IA](../design/IA.md), 행동·예외·복귀는 [USER_FLOW](../design/USER_FLOW.md)에서 구체화한다. 아래 요구사항의 문서 반영은 코드·외부 연동·배포 완료를 뜻하지 않는다.

## 1. 유미당 프로젝트 개요

### 한 줄 정의

여성·만 19세 이상 사용자가 일상 활동의 상대를 찾고, 대화·양쪽 동의를 거쳐 만나는 무료 1:1 동행 서비스.

### 제품 목표

취미·전시·식사·운동·여행 등 함께할 사람이 필요한 사용자가 실제 공고와 상대의 성향·동행 후기 등을 비교하고 직접 동행을 결정하도록 돕는다. 네이버에서 제공받은 가입 정보와 동행 경험을 구분해 보여주며, 로그인이나 프로필이 실제 신원·만남 안전을 보증한다고 표현하지 않는다.

### 사용자 문제와 가설

- 일상 활동을 함께할 상대를 찾고 일정·장소·성향이 맞는지 비교하는 과정이 번거롭다.
- 처음 만나는 상대를 판단할 정보가 부족하다. 선택 성향·대화·완료 이력·후기를 함께 확인하는 것이 판단에 도움이 되는지 검증한다.
- 공고의 조건을 이해했더라도 대화 이후 의사가 바뀔 수 있다. 신청과 양쪽 최종 동의를 분리한다.
- 행사 발견에서 관련 동행 탐색·모집까지 이어지는 경로를 제공한다.

여성 사용자가 느끼는 안전감과 신뢰 향상은 사용자 검증 대상이며 인증·후기만으로 보장하지 않는다.

### 타겟 사용자

전국의 여성·만 19세 이상 사용자다. 일상 동행을 원하는 20~40대를 주요 탐색 대상으로 삼되 가입 자격을 해당 연령대로 제한하지 않는다. 추천 코드·이메일 등으로 가입 자격을 우회하는 경로는 제공하지 않는다.

### 사용자 역할

회원은 공고 작성자 또는 신청자가 될 수 있다. 운영자는 계정·신고·분쟁 등을 담당하되 구체적 권한과 운영 절차는 팀 검토 항목이다. 현재 사업자·법인 회원이나 유료 동행 역할을 활성화하지 않는다.

## 2. 현재 제공 범위

| 기능 | 제품 요구사항 |
|---|---|
| 가입·로그인 | 네이버 로그인만 제공. 이름·성별·생일·출생연도 필수 정보를 받아 여성·만19세 자격 확인. 누락·확인 불가 시 가입 완료 보류 |
| 계정 | 네이버 계정 하나당 유미당 계정 하나. 자연인 1인 1계정 보장을 뜻하지 않음. 다른 네이버 계정으로 기록 이전·연결 변경은 현재 미제공 |

현재 유료 공고·계좌 인증·이메일 배지를 가입·탐색·작성·신청의 필수 단계로 두지 않는다. 유료 거래 모집은 현재 금지 행위에 포함한다. 행사 입장료는 무료 동행 여부와 다른 정보다.

## 3. 핵심 사용자 시나리오

1. 비로그인으로 공고 목록·상세와 행사를 둘러본다. 프로필 상세·신청·채팅·나·AI를 사용하려면 로그인한다.
2. 네이버 로그인에서 필수 정보를 받은 뒤 가입 자격을 확인한다. 신규 회원은 필수 사진과 선택 성향을 입력하고 가입 완료 버튼→안내 팝업→홈으로 간다. 기존 회원은 원래 목적 화면으로 돌아간다.
3. 공고 제목·등록 장소명·주소·연결된 행사명과 필터로 공고를 찾고, 상대의 공개 프로필을 확인한다.
4. 소개 메시지를 필수로 작성해 신청하고 1:1 대화로 연결한다. 작성자가 한 명을 선택해 최종 동의를 요청하고 상대가 같은 조건에 동의하면 확정한다.
5. 양쪽 확정 후에만 상대 전체 이름·정확한 주소·상세 만남 지점을 확인한다. 시작 전 일정 변경은 다시 동의하고, 취소는 사유와 결과를 상대에게 알린다.
6. 예상 종료 후 본인이 완료 확인을 하면 상대 확인을 기다리지 않고 후기를 제출할 수 있다. 동행 자체는 양쪽 완료 확인 또는 자동 처리로 완료된다.
7. 실제 동행 완료 즉시 완료 횟수를 반영한다. 양쪽 후기는 즉시, 한쪽 후기는 실제 완료+24시간에 공개하며 당도도 상대 후기를 볼 수 있을 때 반영한다.

## 4. 탐색·정보 공개 요구사항

- 비로그인 상대 이름은 시스템 별칭, 로그인한 미확정 상대는 마스킹 이름, 확정 당사자는 네이버에서 받은 전체 이름을 본다. 본인 홈의 본인 전체 이름 표시는 다른 사람의 열람 권한을 넓히지 않는다.
- 일반 공개 지역은 동까지다. 정확한 주소와 상세 지점은 확정 당사자에게만 공개한다. 취소가 성립하면 전체 이름을 다시 마스킹하고 정확한 주소·상세 지점을 숨긴다. 이미 본 정보나 채팅 본문을 회수한다는 의미는 아니다.
- 검색 대상은 공고 제목·등록 장소명·등록 주소·연결된 행사명이다. 소개·후기·상세 만남 지점은 제외한다. 검색 일치와 화면 표시 권한을 구분한다.
- 카테고리·일정·작성자 나이·모집 상태로 탐색한다. 일정은 기간 겹침, 나이는 만19~99세의 최소~최대 숫자 범위이며 희망 상대 나이와 구분한다. 전체 검색에는 나이 필터 상한을 적용하지 않는다. 비로그인은 나이 전체만 사용한다.
- 등록일 최신순 기본·시작일 빠른순 선택, 전체 모집 상태 기본·모집 중만 보기 선택이다. 사용자 정렬을 모집 상태·AI 점수로 바꾸지 않는다.
- 주변·반경·거리순 검색은 현재 제공하지 않는다. AI도 장소명·주소를 확인하며 주변 검색을 수행했다고 표현하지 않는다.
- 정상0건·조회 실패·권한 오류를 구분한다. 일반 목록은 더 보기, AI는 추가 요청으로 결과를 이어 보되 정확한 표시 개수는 팀 검토다.

## 5. 공고·신청·확정 요구사항

- 카테고리·제목·소개·장소·시작/종료 날짜와 시간을 필수로 받는다. 종료는 시작보다 늦어야 하고 날짜를 넘길 수 있다. 카테고리 목록·항목별 글자 수는 별도 검토다.
- 모집 마감은 선택 입력이며 없으면 동행 시작 시각이다. 시작보다 늦게 설정할 수 없다. 행사 연결은 선택이며 기존 입력·동행 일정을 자동 변경하지 않는다.
- 제목·본문에서 비공개 상세 위치나 개인정보를 발견하면 입력을 보존하고 수정 전 등록을 막는다. 본문 오탐 문의 경로를 제공하되 탐지 세부·해제 권한은 팀 검토다.
- 등록 성공 시 생성 공고 상세로 이동하고 실패 시 입력을 유지한다. 임시저장은 같은 기기에서 복구를 안내하며 등록 성공·직접 삭제·로그아웃·확정할 기간 만료 시 삭제하고 복구하지 않는다. 저장 개수·기간은 팀 검토다.
- 확정 전 핵심 조건 수정 시 기존 신청자에게 알리고 이전 최종 동의를 무효화한다. 신청·대화는 유지하며 새 조건에 다시 동의한다.
- 수동 마감은 새 신청만 막는다. 기존 유효 신청자는 시작 전까지 최종 동의를 처음 요청하거나 재요청할 수 있다. 삭제는 공고 노출을 종료하고 미확정 신청·동의 요청을 종료, 대화를 읽기 전용으로 보존한다. 확정된 약속 종료 전 삭제는 막는다.
- 신청 소개 메시지는 필수다. 신청 거절 후 같은 공고 재신청은 불가하며 본인 철회 후에는 가능하다. 채팅 첫 메시지로 신청을 성립시키는 대안은 팀 검토이며 현재 흐름으로 바꾸지 않는다.
- 작성자가 한 번에 한 명에게만 최종 동의를 요청한다. 신청·대화 상대 수를 한 명으로 제한한다는 뜻은 아니다. 요청 발송+24시간과 동행 시작 중 빠른 시각에 해당 요청이 만료하며 신청·대화는 유지한다.
- 신청 시 일정 겹침은 경고 후 계속할 수 있지만 최종 확정은 기존 확정 동행과 겹치면 불가하다. 양쪽 확정이 성립하면 미선정 신청·요청을 종료·알리고 대화를 읽기 전용으로 보존한다.
- 시작 전 일정 변경은 상대 동의 후 적용한다. 거절·미응답이면 기존 일정 유지, 변경안의 시작이 더 빠르면 그 시각 전에 동의해야 한다. 시작 전에는 누구나 사유를 남겨 취소하고, 시작 후에는 중단·불발 신고로 접수한다.

## 6. 완료·평가·신뢰정보 요구사항

- 예상 종료 이후 각자 완료 확인을 할 수 있다. 한 사람은 본인 확인 후 미리 후기를 제출할 수 있지만 동행 자체의 완료·공개를 앞당기지 않는다.
- 양쪽 확인이 모이면 수동 완료, 미처리 건은 예상 종료+24시간에 자동 완료한다. 취소·불발·분쟁은 제외한다. 지연되면 실제 처리 성공 시각을 기록하며 소급·재초기화하지 않는다.
- 실제 완료부터7일이 일반 작성 기한이다. 실제 이의 검토 동안 작성·기한·공개를 보류하고 동행 인정 후 남은 기간을 재개하되 최소24시간을 보장한다.
- 경험 선택(좋아요·보통이에요·별로예요)과 별점1~5는 필수, 한마디는 선택이다. 좋아요에는 칭찬 최대3개를 선택할 수 있다. 제출 전 수정·실패 재시도는 허용하고 성공 후 수정·중복 제출은 불가하다.
- 칭찬 목록은 시간을 잘 지켜요 / 약속한 내용을 지켜요 / 소통이 원활해요 / 배려심이 있어요 / 대화가 즐거워요 / 함께하니 편안해요다. 공개 칭찬의 상위5개와 실제 횟수를 누적 표시한다.
- 미완료·실제 분쟁·불발/노쇼 후기는 공개하지 않는다. 공개 가능한 완료 동행은 양쪽 제출 즉시, 한쪽 제출은 실제 완료+24시간부터 공개한다. 그 이후 기한 내 제출도 즉시 공개한다.
- 당도는 상대 후기 열람 가능 시 반영하며 실제 클릭과 무관하다. 완료 횟수는 실제 동행 완료 즉시 반영한다. 본인·타인 모두 현재 당도만 표시하고 변경 내역은 고객지원 문의로 확인한다. 산식·초기값을 임의 확정하지 않는다.
- 프로필은 칭찬 차트→AI 요약→원문 후기 순서다. 한마디 있는 공개 후기3개 이상이 요약 대상이며 실패해도 원문·칭찬은 볼 수 있게 한다. 신고만으로 후기를 숨기지 않고 운영자 조치 결정을 따른다.

## 7. 행사·AI 요구사항

- 홈·일반 행사 목록은 이번 주 새로 시작한 행사 기본, 진행 중 포함을 선택하면 선택 기간과 겹치는 장기 행사도 포함한다. 주 경계는 한국시간 월요일00:00~다음 월요일00:00 미만이다.
- 행사 정렬은 진행 중→예정→종료이며 각각 최근 시작순·시작일 빠른순·최근 종료순이다. 과거 행사 조회는 허용하되 종료 행사를 현재 모집 대상으로 안내하지 않는다.
- 작성용 선택은 진행 중·예정 행사를 대상으로 하고 기간 지정 시 겹치는 행사로 좁힌다. 일반 목록 기본값과 별개다. 취소 행사는 새 조회·선택에서 숨긴다.
- 지역·유형은 제공처 원문·실제 목록을 사용하고 분류가 섞이면 검토한 대응표를 추가한다. 공식 링크가 없으면 출처만 표시하며 링크·회차·휴관·잔여석을 지어내지 않는다.
- Top10은 일반 행사 목록과 별도다. 전국 전체 공연 기본·뮤지컬 전환, 어제까지 최근7일의 공식 순위를 매일 갱신한다. 출처·기준기간·갱신시각을 표시하며 실패·미수신을 가짜 순위로 대체하지 않는다.
- AI는 현재 대화 조건을 프로필보다 우선한다. 관심사·대화 방식은 등록값의 의미 유사성, MBTI는 정확 일치로 판단한다. 미입력은 확인 필요로 남기고 실제 불일치와 구분한다.
- 일반 공개 권한·선택 정렬을 준수하고 실패를 성공으로 꾸미지 않는다. 반환 직전 최신 상태 재확인과 일부 결과·실패 처리의 세부 동작은 팀 검토로 남긴다.
- AI 대화 원문은 현재 탐색 중만 유지하고 서버 이력·오류·사용량 로그에 저장하지 않는다. 회원 간 채팅·실명·계좌·비공개 위치는 AI 입력에서 제외한다.
- AI 첫 이용 전 전송 항목·목적·공급사·서버 미저장·확인된 외부 보관 조건·거절 방법을 안내·확인받고 재열람·조건 변경 재안내를 제공한다. 실제 회원 데이터 전송은 공급사 보관 조건·팀 검토·사용자 확인이 끝날 때까지 보류한다.
- 입력 개인정보 발견 시 외부 전송을 멈추고 수정을 안내한다. 출력에서 발견하면 응답을 숨기고 재시도를 안내하며 원문을 오류 로그에 넣지 않는다. 정상 공개 장소와 민감정보를 구분하고 탐지 완전성을 보장하지 않는다.

## 8. 운영·후속 범위와 출시

- 기존 미검증 계정은 네이버 확인 전 새 등록·신청·확정을 제한하되 진행 약속·기존 대화 확인과 취소·지원 요청 경로를 남긴다. 자격 미충족 기존 약속은 운영 검토로 정리하며 계정을 일괄 삭제하지 않는다.
- 사칭·괴롭힘·차별·성적 강요·사기·개인정보 무단 공개·현재 금지된 유료 거래 모집을 금지한다. 경미한 첫 위반은 경고, 반복·중대한 위반은 제한하되 운영자가 근거·이유·이의 경로를 안내한다. 제재 기간·횟수, 노쇼·분쟁 판단은 팀 검토다.
- 최근 검색은 같은 기기에 저장하며 개별·전체 삭제, 로그아웃 및 확정할 보관 기한 경과 시 삭제, 삭제 후 복구 불가를 적용한다. 상세 만남 지점·인증 정보는 저장하지 않는다. 최대 개수·보관 기간은 팀 검토다.
- 대화방 나가기는 본인 목록만 숨기고 상대 기록을 지우지 않는다. 일반 신고·분쟁에서는 운영자가 서버 채팅 원문을 직접 열람하지 않고 당사자가 필요한 구간의 캡처를 제출하도록 안내한다. 채팅·캡처의 처리 근거·담당 접근·보관·삭제는 팀·법률 검토다.
- 탈퇴 시 진행 확정 동행·분쟁의 해결 또는 취소를 안내하고 성립 후 이용 중지·프로필 비공개·삭제 가능한 자료 삭제를 적용한다. 재가입은 새 계정으로 시작하며 과거 당도·후기를 복구하지 않는다. 자료별 법정 보관·삭제 기한과 무기한 탈퇴 제한 여부는 별도 검토다.
- 선택 학교·직장 이메일 인증, 유료 동행·1원 계좌 인증, 사업자·법인, 수수료·결제·정산·환불, 주변 검색은 추후 검토다. 추후 유료 신청·제안자는 1원 인증이 필요하고 무효로 확인된 계좌의 인증 배지는 숨긴다. 조회 실패·확인 불가를 무효 또는 정상으로 단정하지 않으며 명의 대조·효력·갱신·진행 중 공고와 신청 처리 등은 팀 검토로 남긴다.
- 웹 베타→Android 폐쇄 테스트→프로덕션 순서로 준비·검증된 기능을 공개한다. 고정 출시일은 재산정하고 미완성 기능은 후속 공개로 분리한다. 베타 범위·패키징·실시간 연결·공식 게시자·계정 책임은 팀 검토다.

## 9. 제품 검증과 주요 지표

가입 전환율, 신뢰정보 확인율, 참여 요청률, 채팅 유지율, 동행 확정률, 실제 완료율, 상호 평가 작성률, 긍정 평가 비율, 첫 동행 성사율, 재방문·재매칭률을 관찰 대상으로 둔다. 정의·분모·목표 수치·수집 구현은 별도 설계하며 수치가 개선됐다고 선행 주장하지 않는다. 유료 전환율은 추후 유료 기능이 도입된 뒤 검토한다.

개인정보 노출·사칭·괴롭힘·분쟁·평가 조작, 초기 사용자 부족이 주요 제품 위험이다. 네이버 정보·선택 성향·후기의 한계를 안내하고 실제 사용자 검증으로 판단한다. 화면 시안, 코드 검사, 외부 API 호출, 두 사용자 간 동작, 배포 결과는 서로 다른 검증으로 기록한다.
