이전의 HTML 렌더·일부 클릭 검증은 Expo 기능 동등성 검증이 아니었다. 채팅의 최초 기준을 Stitch S11로 잘못 선택했고, 전체 화면에 대해 Expo 대응 검증 완료 여부를 충분히 구분하지 않았다. 이번 작업은 UI를 바꾸지 않는 소스 감사와 계획 작성이다. Expo 실행·기기 QA·API/DB 검증은 수행하지 않았다. 이전 테스트 숫자나 제작 manifest를 이번 검증 결과로 재사용하지 않는다.

S13 README와 공고 상세 source-manifest에는 Expo 소스 참조 이력이 있다. 기존 산출물 전체가 Stitch만을 바탕으로 만들어졌다고 단정하지 않는다. 제작 시점 참조 이력, 현재 소스 대응, 런타임 검증은 서로 다르다.

## 기준

## 유지할 승인 디자인

폰트·굵기·여백, 카드 소재, 바텀바, 행사 이미지 위치/연결 공고 버튼, S13 안전계정 분리·당도 설명, 채팅 사진·당도 막대·고정 제목 공고 토글·더보기는 보존한다. 알림 끄기는 사용자 승인 시안 추가이며 Expo 대응 없음으로 별도 표시한다. 첨부/이모티콘 제거도 유지한다. 과거 사용자 승인 여부가 불명확한 CTA 제거는 자동 복원하지 않고 근거 대조 후 표시 계약으로 정리한다.

## 재작업 순서와 완료 조건

1. **기준표 확정(다음 첫 작업)**: 각 화면의 버튼/입력/상태/목적 route/전달 id를 Expo 소스와 1:1로 기록. 행사 상세와 인증 세부 대조를 보충. 현재 기록의 완료 표시는 화면 표현/정적 대조/실행 확인으로 분리. 승인된 외관을 변경하지 않는다.
2. **핵심 진입 경로**: 홈→둘러보기→상세→채팅의 목적지 및 id 전달, 뒤로가기 복귀를 먼저 맞춘다. 필터 단일/복수 선택 계약을 Expo에 맞추고 합성 데이터에서 검색·정렬·최근 검색·더보기 결과를 확인. 누락된 홈 CTA는 표시 계약에 따라 복원.
3. **채팅 기본 동작 먼저**: 첫 전송 전/성공/실패/재전송/이탈, 신청 거절/철회/쿨다운/읽기전용부터 구현. 이 단계 통과 전 확정 UI를 더 꾸미지 않는다.
4. **약속 관리 재정렬**: 현재 flow.js를 기준으로 삼지 않고 Expo 입력/역할/실패 모델에 맞춰 수정. 장소 선택, 요청 철회, 만료 동시각 거부, 충돌 차단, 취소와 차단 분리, S16/S18 연결을 비교. 실제 업무 엔진은 복제하지 않고 시안 표시 상태와 이벤트로 표현.
5. **나·행사·인증 후속**: S13 목적지와 후기 상태를 맞추고, 행사 필터/재시도/연결공고 및 가입 복귀를 연결. Preview/Remote 차이를 화면별 명시.
6. **실행 대조(아직 미실시)**: Expo 로컬 예시 모드와 HTML에 동일 fixture/역할/시계를 적용. 각 흐름을 양쪽에서 실행해 결과/disabled/복귀/공개정보/오류를 비교. 320/390/430 폭·긴문구·키보드/터치 표시 검수는 그 후 시행. 실제 서버 동작은 완료 주장 제외.

재작업 완료는 파일 생성이나 기존 테스트 통과가 아니라 대응표의 각 항목에 양쪽 결과와 증거가 채워진 때다. 설치된 Expo 실행 환경이 없는 현 폴더에서는 실행 검증이 남는다. 현재 actor 제한을 바꿔 설치나 공통 설정 수정을 우회하지 않는다.

## 반복 비용 방지

- 이번 턴은 UI/Expo 소스 무수정, 이 감사 문서만 작성.
- 전체 디자인 재생성 금지. 확인된 기능 차이만 작은 단위로 수정.

- 참조 기록/과거 테스트/합성 UI/실제 서버 검증을 같은 완료 표현으로 묶지 않는다.
