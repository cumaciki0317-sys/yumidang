# 화면별 HTML 1차 검토

작성자 sungho · 2026-10-13

## 범위와 확인 방법

사용자가 전달한 ZIP 10개를 보존하고 `apps/mobile/design/sungho/html/extracted/`에 패키지별로 추출했다. 총 552개 파일의 sungho 소유권 검사를 통과했다. 아래 소스 경로는 이 추출 폴더 기준이다. 원본 HTML/CSS/JS는 수정하지 않았다.

기준: [정책](../../../../정책.md), [IA](../../../planning/design/IA.md), [USERFLOW](../../../planning/design/USERFLOW.md). 실제 서비스 소스나 서버의 결함 판정이 아니라 제출된 디자인 시안 검토다.

- 소스 검토: 로그인 S05, 가입 S06, 홈 S00, 둘러보기 S01, 공고 상세 S02, 행사 목록 S09-2, 행사 상세 S09-3, 나 S13, 연결본, 디자인시스템.
- 브라우저 확인: 위 8개 화면의 기본 화면. S01→S02 카드 클릭 연결을 확인했다. S02 비로그인 상태와 S13은 390×844에서도 확인했다.
- 17개 HTML의 정적 src/href 상대 경로에서 누락 파일은 발견하지 않았다. JS가 만드는 이동·자산과 모든 상태를 검증했다는 뜻은 아니다.
- 기존 validation JSON과 테스트 결과는 제작 당시 기록이다. 이번에 해당 테스트를 실행하지 않았다. 전체 모바일 너비·스크린리더·모든 모달/상태 조합 검증은 남아 있다.
- 하네스: 주 작업자는 압축 해제·브라우저 검토·이 문서만 작성. review_auth_events(S05/S06/행사), review_browse_detail(S01/S02/연결본), ux_review(홈/S13/디자인시스템)는 모두 읽기 전용이며 편집 허용 경로가 없다.

## 전체 평가

보라색 강조색, 밝은 카드, 둥근 모서리, 하단 버튼의 시각적 방향은 화면 간 일관된다. 빈 화면·오류·역할별 상태를 선택해 볼 수 있는 구조도 후속 검토에 유용하다. 기존 작업을 새로 만들기보다 현재 화면을 바탕으로 아래 항목부터 정리하는 것이 적절하다.

화면별 HTML은 주로 독립된 디자인 시안이다. 버튼 눌림만 제공하고 실제 인증·저장·검색·다른 화면 이동을 하지 않는다고 명시한 부분은 서비스 장애로 분류하지 않았다. 현재 실제로 연결된 범위는 공고 탐색과 공고 상세이며, 전체 사용자 흐름이 통합된 앱은 아니다.

## 수정 우선순위

### 1. 우선 수정: S02 비로그인 작성자 박스

- 근거: `유미당-공고상세-소스/yumidang-listing-detail/detail.js:18`, `detail.css:62`; 연결본의 `detail/detail.js`에도 동일한 방식.
- 비로그인에서도 사진·마스킹 이름·나이·당도를 DOM에 생성하고 blur로 가린다. 브라우저에서 비로그인 상태의 흐린 사진 박스를 확인했다. 필수 문구 `동행인은 로그인 후 확인할 수 있어요`가 화면에 없다.
- 합성 데이터이므로 실제 고객 정보 유출로 판단하지 않는다. 다만 실제 구현에 그대로 옮기면 안 되는 정책 충돌이다.
- 수정: 비로그인은 중립 자리표시자만 생성하고 필수 안내를 표시한다. CSS 흐림이나 aria-hidden만으로 비공개를 구현하지 않는다. S01의 중립 표시 방식을 재사용하는 것이 좋다.

### 2. S13 완료 카드와 요약 숫자 일치

- 근거: `유미당-나-S13-소스/views.json:3,8,9`.
- 같은 장면에 `동행 완료` 카드와 `완료 0회`, `완료 동행 0`이 함께 있다. 기본 화면에서 시각적으로도 확인했다.
- 수정: 실제 완료 장면이면 횟수를 맞춘다. 본인만 완료 확인한 장면이면 상대 대기 상태로 표현한다. 당도 15 자체는 완료 횟수만으로 오류라고 볼 수 없다.

### 3. S13 확정 상대 이름 표시

- 근거: `유미당-나-S13-소스/views.json:8`의 작성자 장면.
- 받은 신청이 `동행 확정`인데 `김*지 님의 신청`으로 남는다.
- 수정: 확정 당사자에 해당하는 상대만 전체 이름으로 표시하고 미확정·취소 후에는 마스킹한다.

### 4. S09-2 초기화 동작 통일

- 근거: `유미당-S09-2-행사목록-소스/list/events.js:38`.
- 결과 없음 영역의 `조건 초기화`는 진행 중 포함을 true로 바꾸고 지역·입장·장르 조건을 남긴다. 필터 시트 초기화와 결과가 다르다.
- 수정: 같은 기본 조건을 사용한다. 조회 범위를 넓히려는 별도 동작이면 실제 동작에 맞게 버튼 이름을 바꾼다. 기본은 이번 주 신규 중 미종료다.
- 정적 소스 확인이며 브라우저에서 해당 조합 재현은 미실시.

### 5. S09-2 예시 데이터 정렬

- 근거: 같은 패키지 `list/fixtures.js:177,279,293`, `events.js:28`.
- 과거 조회 예시에서 오래전에 시작한 진행 중 행사가 최근 시작한 행사보다 앞서며, 더보기 예시는 예정 행사 뒤에 진행 중 행사를 추가한다.
- 수정: 고정 예시도 진행 중→예정→종료, 각 그룹 최근 시작→빠른 시작→최근 종료 기준에 맞춘다. 실제 조회 엔진을 새로 구현할 필요는 없다.

### 6. S01 카드 정보 보완

- 근거: `유미당-둘러보기-소스/yumidang-browse/browse.js:50`; 연결본 동일.
- 무료 여부와 연결 행사명이 카드에서 빠져 있다. 첫 공고에는 행사 데이터가 있지만 카드에서 표시하지 않는다. IA의 S01 카드 요구사항과 차이가 있다.
- 수정: 무료 1:1 표기와 연결 행사 표시를 과밀하지 않게 추가한다. 행사 입장료와 동행 자체의 무료 여부를 혼동하지 않게 한다.

### 7. S02 활동 제한 상태 안내

- 근거: `유미당-공고상세-소스/yumidang-listing-detail/detail-model.js:4,24`.
- `활동 제한 · 상세 버튼 원본 유지` 장면에 새 신청 버튼이 활성으로 남고 제한 이유를 보여주지 않는다.
- 시안의 의도된 상태라는 점을 구분한다. 인계 전에는 신규 신청 제한 설명과 실제 제한을 안내하는 화면을 포함해야 한다. 차단을 상세에서 할지 다음 화면에서 할지는 기존 서비스 계약과 연결 담당자가 확인한다.

### 8. S06 키보드 포커스 유지

- 근거: `유미당-S06-가입프로필-소스/yumidang-S06/auth.js:15,21,23`.
- 관심사·대화 방식·MBTI 선택 시 innerHTML로 버튼들을 교체하고 포커스를 복원하지 않는다.
- 수정: 기존 버튼의 선택 속성을 갱신하거나 교체 뒤 같은 항목으로 포커스를 복원한다. 사진 선택 후 전체 render도 함께 확인한다.
- 소스에서 확인한 접근성 위험이며 실제 키보드 재현 검증은 남아 있다.

### 9. 디자인시스템의 둘러보기 복사본 동기화

- 근거: `유미당-디자인시스템/유미당-디자인시스템/screens/browse/browse.js:3`과 독립 둘러보기 `browse.js:3`.
- 독립본은 서울→경기→인천, 디자인시스템은 서울→부산→대구→인천이다. 독립본의 10월 12일 지역 표시 순서 변경이 복사본에 없다.
- 정책 결함이 아니라 버전 불일치다. 독립본의 최신 순서를 공통 기준으로 정리하고 원본/배포본 생성 관계를 문서화하는 것을 추천한다. 홈의 동명 최상위 파일에서는 해시 차이가 없었다.

## 화면별 후속 방향

| 화면 | 이번 확인 | 후속 작업 |
|---|---|---|
| S00 홈 | 기본 화면, 단독/디자인시스템 소스 비교 | 빈 약속·행사 실패·로그인 상태의 작은 화면 확인 |
| S01 둘러보기 | 카드·필터 소스, 기본 렌더, 상세 진입 | 무료/행사 정보 보완, 실제 검색 연결은 별도 |
| S02 공고 상세 | 역할별 모델, 기본/비로그인 렌더 | 비로그인 박스 우선 수정, 제한 상태 안내 |
| S05 로그인 | 네이버 단일 로그인, 자격 안내와 기본 렌더 | 실제 인증 연결은 종현/민규 범위 |
| S06 가입 | 필수 사진·선택 성향, 기본 렌더 | 포커스 유지, 법적 검토용 설명은 정식 사용자 본문과 분리 |
| S09-2 행사 목록 | 기본 렌더, fixture/초기화 소스 | 초기화·정렬 수정, KOPIS 합성/보류 표시 유지 |
| S09-3 행사 상세 | 기본 렌더와 상태 소스 | 관련 공고·모집·공식 링크 연결은 별도 |
| S13 나 | 기본 렌더와 장면 데이터 | 완료 숫자·확정 상대 이름 정합성 수정 |

시안의 고정 날짜를 오늘 날짜와 다르다는 이유로 결함 처리하지 않았다. KOPIS의 미연결·합성 예시도 실제 공식 순위 공개로 판단하지 않았다. 행사 입장료 표시는 동행 유료화와 구분한다.

## 적용 순서와 경계

1. 비로그인 S02 → S13 데이터 정합성 → S09-2 초기화·정렬 순으로 수정한다.
2. 카드 정보·접근성·디자인시스템 복사본을 정리한다.
3. 상태별 작은 화면과 키보드 이동을 다시 검토한 뒤 종현에게 표시 컴포넌트/화면 연결 요청을 남긴다.

현재는 검토만 수행했다. 사용자 작업물의 디자인·코드 수정, 실제 서비스 반영, 배포, 커밋·푸시는 하지 않았다. 기존 앱 코드 변경이 없으므로 앱 lint/typecheck는 실행하지 않았다.
