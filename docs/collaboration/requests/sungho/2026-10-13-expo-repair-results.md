사용자가 승인한 글꼴·여백·바텀바·카드 소재·메뉴·공고 접기 디자인은 유지한다. 알림 토글은 사용자 승인된 표시 예시이며 실제 설정을 바꾸지 않는다.

## 검증한 것

- root 브라우저: 신규 회원 로그인→가입, 부분 MBTI 완료 차단→비우기→완료 안내→회원 홈, 빈 약속 CTA 표시 확인.
- root 브라우저: 통합 상세 선택 공고 제목/일정→채팅 동일 값, 첫 전송 성공 표현 확인. 독립 채팅 실패시 입력 유지→재전송 성공 확인.
- root 브라우저: 브런치 검색 4→1건, 검색어 지우기→4건 및 최근 검색어 확인.
- root 브라우저: 행사 목록 e3 선택→같은 제목/기간/입장료 상세 확인.
- 담당 에이전트 실행: 홈 상태 테스트, 둘러보기 조건/입력/페이지 테스트, 상세 32장면 136 검사, 행사 목록 5개 테스트 및 상세 테스트, S13 12장면 테스트 통과.
- root 실행: S05 11개·S06 12개 검사 통과, JS 문법 검사. 연결 테스트는 legacy 복사본이 아닌 canonical 파일을 사용하도록 정정했으며 567+45 검사 통과.
- mock DOM 검사는 브라우저/실기기 실행과 구분한다. 테스트 숫자는 서비스 기능 수가 아니다.

## 남은 경계와 인계

1. S03 공고 편집/작성, S14 공개 프로필, S16 약속 상세, 신고 폼 등 준비되지 않은 HTML 목적지는 route/ID 안내다. 새 화면 제작 완료를 주장하지 않는다. 실제 앱의 해당 경로는 종현이 담당 파일에서 연결한다.
2. 채팅 전송·신청·확정·변경·취소·신고·차단·알림은 화면 예시다. 서버 및 여러 대화방 간 상태 전파·실제 회원 데이터 저장을 구현하지 않았다. 기존 고정 약속 데모는 별도 합성 장면이고 선택 공고 연결 모드에서는 숨긴다.
3. 최근 검색은 페이지 수명 동안만 유지된다. 행사 연결 공고 수에 대응하는 세부 fixture가 없으면 준비 중 안내이며 무관한 공고로 대체하지 않는다.
4. Expo 앱 실행 환경이 없는 상태에서 소스를 대조했다. Expo와 HTML 양쪽 런타임 전체 동등성·기기 QA·실서비스 검증은 미완료다.
5. 실제 적용 요청: 종현은 기존 화면에서 표시 값/상태/이벤트를 연결하고 정책에 따른 실패/공개 조건을 검증한다. 공통 인증/API 변경이 필요하면 민규 담당으로 분리한다. 성호는 해당 소스를 직접 편집하지 않는다.

## 복구 원칙

원본이라는 명칭은 Expo 프로토타입에 사용한다. HTML 합성 시안, 기존 Stitch 자료, 소스 대조, 브라우저 검증, 실제 서비스 완료를 구분한다. UI 검수용 복사본 테스트를 실제 canonical 검증으로 보고하지 않는다. 기존 제공 ZIP은 덮어쓰지 않았다.
