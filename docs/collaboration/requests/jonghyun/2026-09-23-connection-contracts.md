# 종현 → 민규: 1단계 연결 계약 요청 초안

상태: **초기 검토 요청 기록**. 이후 확정 정책과 현재 구현 연결 조건은 [최신 연결 요청](2026-09-23-independent-core-integration.md)을 우선한다. 이 문서는 외부 메시지를 보낸 기록이 아니며 DB·공통 파일을 변경한 결과도 아니다. 종현이 작성한 [공개 검색](../../../../backend/contracts/search.md)·[AI 탐색](../../../../backend/contracts/ai-chat.md)·[리뷰 요약](../../../../backend/contracts/review-summary.md) 논리 계약과 [가상 사례](../../../../tests/fixtures/jonghyun/contract-cases.json)를 실제 권한 경계에 연결하기 위한 요청이다. 실제 RPC명·스키마·HTTP 오류 형식은 민규가 최종 DB와 공통 계약을 대조해 제안해 주기 바란다.

## 확인된 로컬 이력과 최신 정책 차이

| 로컬 SQL에서 확인 | 최신 정책·필요 변경 | 담당 |
|---|---|---|
| `20260916105220_feature03_posts.sql`의 `list_posts`는 제목·소개·공개 지역을 검색하고 `posts` 행을 반환 | 제목·등록 장소명·등록 주소 일치 판단과 반환 권한을 분리. 소개·리뷰·상세 지점은 검색 제외 | 민규 DB/RPC·권한, 종현 검색 서비스 |
| 기존 `post_private_details.exact_location`에는 주소·만남 안내가 섞여 있을 수 있음 | 자동 분해·공개 금지. 새 등록 주소·장소명·상세 지점의 저장/검색/조회 경계 필요 | 민규 |
| `appointment_reviews`는 별점·한마디 중심이고 공개 후기 revision·요약·작업 객체가 없음 | 프로필 공개 근거, 텍스트 후기 3개, 공개 집합 revision, 무효화·조건부 게시·작업 등록 필요. 칭찬/경험 필드도 최신 평가 정책과 대조 | 민규 DB/RPC, 종현 요약 워커 |
| `20260917005621_retry_completion_dispute_review_policy.sql`의 수동 완료 경로는 첫 한 명 확인 때 완료 처리 | 수동 완료는 **양쪽 확인 후** 성립. 한 명만 확인하면 완료 전 유지. 미처리 종료 +24시간 자동 완료와 취소·불발·분쟁 제외 유지 | 민규 RPC, 종현 예약 호출 |
| 기존 후기 `released`는 당사자 간 상대 후기 조회 조건 | 프로필·제3자 공개 근거로 재사용 금지. 별도 공개 원문 조회 경계 필요 | 민규 |

위 항목은 **로컬 SQL 파일 확인 결과**다. 원격 DB에 무엇이 적용됐는지는 이번 작업에서 확인하지 않았다. 과거 이력은 보존하고 후속 변경으로 정리해야 한다.

## 요청할 연결 계약

아래 이름은 **논리 연산명 제안**이다. `targetUserId` 등은 가상 예시이며 최종 식별자·시그니처가 아니다. 공통 오류 형식과 HTTP 매핑도 민규 소유 [conventions.md](../../../../backend/contracts/conventions.md)와 합의해야 한다.

### 1. 공개 공고 검색·관계별 조회

- **대상:** 민규 소유 공고/비공개 상세 스키마, 검색 RPC·RLS, [posts-search.md](../../../../backend/contracts/posts-search.md), `service-api` 연결.
- **입력 제안:** `{query, category?, cost?, interval?, authorAge?, availability?, cursor?, callerContext}`. availability 기본값은 all, 모집 중만 필터는 recruiting. `callerContext`는 서버가 확인하며 클라이언트 제공 권한값은 사용하지 않는다.
- **출력 제안:** 권한 적용된 공고 ID·제목·시·군·구 공개 지역(2026-09-23 사용자 확인)·표시 이름·일정·금액·상태·신청 가능 여부·불투명한 다음 커서. 현재 저장값이 동까지 있어도 확정 전 반환은 시·군·구까지로 제한한다. 검색용 등록 주소·상세 지점·PASS 정보는 반환하지 않는다.
- **오류·권한:** 잘못된 필터/커서, 비공개·삭제, 비로그인·일반·작성자·확정 당사자·제3자를 구분. 정확한 주소와 실명은 별도 권한 조회에서만 제공하는 제안을 검토. 권한 높은 내부 DB 클라이언트가 RLS를 우회할 수 있으므로 호출자 관계를 RPC·반환 데이터에서도 확인.
- **상태별 조회 선택:** 현재 list_posts는 모집 중 공고만 반환한다. 2026-09-23 사용자 확인에 따라 확정·마감·만료 공고도 기본 검색 목록에 상태와 함께 표시하고 모집 중만 필터에서 제외한다. 새 신청 불가와 비공개 필드 제외를 모두 유지한다. 삭제·비공개 상태의 조회 권한은 별도 계약에서 확인한다.
- **완료 확인:** `새문안로`가 등록 주소에 맞더라도 카드에는 시·군·구만 나오고, `exact_location`의 상세 문구는 검색되지 않아야 한다. 일반 검색과 AI 도구의 검색 범위가 같아야 한다. 공고 제목의 정확한 주소·상세 지점 입력을 안내로 예방한다. 등록 전에 발견하면 입력을 보존하고 수정 전 등록을 차단한다(2026-09-23 사용자 확인). 탐지 누락·오탐과 제출 재시도는 검증한다.

### 2. 공개 텍스트 후기·revision 일관 조회

- **대상:** 민규 소유 후기 공개 상태·조회 RPC, [reviews.md](../../../../backend/contracts/reviews.md).
- **입력 제안:** 내부 워커가 `{targetUserId}`로 조회. 일반 사용자에게 원문 묶음과 내부 revision을 직접 노출하지 않는다.
- **출력 제안:** `{targetUserId, sourceRevision, publicTextReviews:[{evidenceId, comment}]}`를 한 시점의 상태로 반환. 공백 한마디·한마디 없음·비공개 제외. 공개 평가 총수는 별도 의미로 구분.
- **오류·권한:** 잘못된 대상·미인증 내부 호출·공개 근거 없음·일시 DB 장애 구분. 공개 조건을 충족한 한마디는 로그인 회원에게 자동 공개(2026-09-23 사용자 확인). 신고 접수만으로 숨기지 않고 운영자가 비공개 조치를 결정할 때 공개 상태를 변경한다(2026-09-23 사용자 확인). 이 변경과 같은 트랜잭션에서 revision 증가·요약 무효화·작업 등록 필요. 기존 `released`를 공개 승인으로 해석하지 않음.
- **완료 확인:** 2개에서는 요약 원문 집합 부족, 3개에서는 적격; 한마디 없는 평가와 비공개 전환은 집합에서 제외. 공개 집합 변경과 같은 트랜잭션에서 revision 증가·기존 요약 무효화·작업 등록을 보장.

### 3. 조건부 요약 게시·안전 조회

- **대상:** 민규 소유 요약 저장 RPC/테이블·권한·공개 조회.
- **입력 제안:** `{targetUserId, sourceRevision, summaryText, sourceReviewIds, sourceReviewCount, promptVersion, modelVersion, jobId}`. 원문 전체는 저장 요청·작업 메시지에 싣지 않음.
- **결과 제안:** `published` / `stale_revision` / `insufficient_reviews` / `not_public` / `invalid_evidence`를 구분. 조회는 로그인 회원에게만 제공하며 요약문·실제 사용 원문 수·갱신 시각·표시 상태만 반환.
- **원자 조건:** 게시 직전 revision·후기 공개 상태·유효 텍스트 3개를 다시 검사. `sourceReviewIds`가 해당 대상의 현재 공개 텍스트 후기이며 중복이 없고 `sourceReviewCount`가 실제 사용 ID 수와 일치하는지도 검사·저장. 모델용 임시 근거 ID와 실제 후기 ID의 대응 방식 합의. 조회 때도 현재 revision·3개 기준 확인. 비공개 전환 뒤 오래된 요약이 새 조회에 나타나지 않아야 한다.
- **완료 확인:** 모델 생성 중 revision 8→9 변경 시 revision 8 결과 게시·노출 모두 거절.

### 4. 작업 원자 등록·점유·완료

- **대상:** 민규 소유 작업 테이블·중복 제약·점유 RPC, 종현 소유 `enqueue`·`lease`·`retry` 연결.
- **입력/출력 제안:** `{kind, targetId, sourceRevisionOrWindow, dueAt}` 등록 → `{jobId, state}`. 점유 → `{jobId, leaseToken, leaseUntil, payloadReference}`. 완료 → `{jobId, leaseToken, result}`.
- **오류·권한:** 내부 실행자만 점유·완료. 동일 중복 키는 새 효과를 만들지 않음. 만료된 점유 토큰과 오래된 revision은 완료 쓰기를 거절. 재시도 가능 오류와 영구 오류를 구분.
- **완료 확인:** 중복 호출·워커 중단·점유 만료 뒤 다른 워커 회수에서 중복 게시·완료·알림이 발생하지 않음. 횟수·간격·실행 수단은 운영 결정 전 미정.

### 5. 수동/자동 완료·후기 공개 시점

- **대상:** 민규 소유 개인별 확인 기록, 완료·평가·이의 RPC, 후속 마이그레이션.
- **입력 제안:** 워커는 `{appointmentId, expectedDueAt, jobId}`로 자동 완료 시점 도래를 알리고 **판정은 RPC가 수행**. 후기 공개 시점도 `{appointmentId, dueAt, jobId}`로 호출하며 서버가 현재 상태·시각을 재검사.
- **결과 제안:** `completed_manual` / `completed_automatic` / `waiting_for_other_confirmation` / `skipped_exception` / `already_completed` 같은 논리 결과. 실제 enum·오류는 합의 대상.
- **완료 확인:** 한 명 확인 때 완료 시각·평가 기한 시작 금지, 양쪽 확인 때 한 번만 수동 완료, 종료 +24시간 미처리 자동 완료, 취소·불발·분쟁 제외, 수동/자동 경쟁 시 중복·시각 재설정 금지. 공개 보류는 실제 클릭이 아닌 **알림 확인 가능 시각부터 24시간**, 작성 기한은 완료부터 7일; 이의 검토 중 보류·재개.
- **미정:** 작업 지연 시 완료 시각·기한을 예정 시각과 실행 시각 중 무엇으로 할지, 취소·분쟁 종결 상세 정책. 결정 전 워커 기본값을 넣지 않음.

### 6. 행사 저장·조회와 공통 인증/오류

- **대상:** 민규 소유 행사 테이블·저장 권한·제공처+원천 ID 유일 제약, 공통 인증·HTTP 오류·로그 규약. 종현은 KOPIS/서울 열린데이터광장/TourAPI 어댑터·표준화·조회 구현.
- **입력/출력 제안:** `{provider, sourceId, title, kind, venueName, publicAddress, startsAtOrDate, endsAtOrDate, timePrecision, admissionCostKnown, sourceUrl, sourceStatus, fetchedAt}` 저장. 조회는 `new_this_week` / `overlapping` / `post_selection`과 기간·커서에 따라 공개 카드 반환.
- **오류·권한:** 내부 수집자만 저장. 잘못된 원천 링크/일정·제공사 장애·중복 저장을 구분. 호출자 인증은 공통 모듈이 확인. 로그·오류에는 AI 대화·후기 본문·상세 만남 지점·인증정보를 남기지 않음.
- **완료 확인:** 같은 제공처·ID 재수집은 중복 행을 만들지 않음. 홈·일반 목록의 신규 기본값은 한국 시간 월요일 00:00부터 다음 월요일 00:00 직전 사이에 **시작**하는 행사(IA 3-3, USER_FLOW 8장, 2026-09-23 사용자 확인); 첫 수집 시각이 기준이 아님. 장기 행사는 겹치는 기간에서 나오고 금요일 종료 행사는 주말 결과에서 빠짐. 작성 선택 모드에는 신규 기준을 강제하지 않으며 행사 입장료와 동행 비용을 혼동하지 않음.

## 종현의 임시 진행 방식과 합의가 필요한 값

민규의 계약이 준비되기 전에는 [가상 사례](../../../../tests/fixtures/jonghyun/contract-cases.json)를 통해 입력·출력 구조와 경계 사례를 검토한다. DB 접근·RPC·외부 제공사 응답을 성공한 것처럼 대체하지 않는다. 민규 계약이 오면 종현 소유 `search.md`·`ai-chat.md`·`review-summary.md` 및 어댑터에서 타입·오류를 맞춘다.

모델/공급사·외부 로그 보관, 예산·요청 한도, 행사 기간 경계와 날짜 정밀도, 작업 실행 수단·재시도 수치·지연 시각, 대량 후기 처리, 공통 오류/인증 형식은 아직 결정 또는 기술 검증이 필요하다. 필요한 선택은 영향과 함께 별도로 제시하고 무응답을 확정으로 취급하지 않는다.
