# 민규 브랜치 통합 시 전달할 행사 UX 인수인계

2026-10-20 / 종현. 사용자가 민규에게 직접 전달하기로 했으며 외부 메시지를 보내지 않았다.

## 전달할 핵심

행사 UX의 사용자 선택12개 및 추가3개가 모두 확정됐다. [최종 명세](2026-10-20-event-ux-approved-spec.md)와 [정책8장](../../../../정책.md#8-행사-탐색과-공식-순위)을 기준으로 한다. 이번에는 사용자 명시 승인으로 정책·PRD·IA·USERFLOW·서버 계약·민규/유미 담당 관련 문서까지 동기화했다. HEAD 소유권 검사는 타 담당 문서를 거절했고 이를 통과로 바꾸지 않았다. 승인 예외는 문서뿐이다. actor·ownership·hook·서버 코드·DB를 바꾸지 않았고 자동 커밋·푸시·배포도 하지 않았다. 기존 미커밋 작업을 보존했다.

## 반드시 서버와 함께 연결할 변경

1. 공고 작성의 행사 기간 겹침 강제를 제거하고 검색 기간 자동 축소도 하지 않는다. 행사 전날 사전 모임도 가능하다. 단 기존 확정 동행끼리 일정 충돌 검사는 유지한다. 명시 기간 검색 API 자체를 제거하는 뜻은 아니다.
2. 직접 입력 행사는 공고 전용 구조로 저장·수정·조회한다. 행사명 필수·장소명/공개 행사장 주소 선택, 기존 장소/주소 검색+공개 확인·개인정보 검사. 소개글에 합쳐 저장하는 우회와 공용 행사/상세 생성은 하지 않는다.
3. 상태는 취소·연기·변경 일정 미정·비표출·명시 재표출·취소 정보 미제공·호출/해석 실패를 구분한다. 미제공을 정상 개최로 표시하지 않고 해석 오류를 미제공으로 바꾸지 않는다.
4. eventId가 있어도 원천 정보를 숨긴 안전 연결 응답이 필요하다. 현재 linkedEvent 필수 파서와 충돌하지 않게 서버·클라이언트를 함께 확장한다. 내부 연결 보존과 원천명/이미지/주소/설명 비노출은 별개다.
5. 동일 행사 통합은 공식 행사 단위 동일 ID/정확한 공식 상세 링크 등 확실한 동일 개최 근거가 있을 때만 한다. 실제 공통 근거는 아직 확인되지 않았고 초기 통합0건도 허용한다. 제목·기간·장소 유사성만으로 통합/상시 수동 검수하지 않는다. 원천ID·공고 관계·근거·통합/분리 복구 기록을 유지한다.
6. 먼저 검증된 공개 원천 대표를 유지하고 빈 필드만 공개 원천으로 보완하며 항목별 출처를 보존한다. 비표출 원천만 숨기고 다른 공개 원천은 유지한다. 핵심값 충돌은 안내/새 연결 제한, 기존 약속 유지다. 공개 원천이 없으면 비표출 안내 카드, 명시 공개 재개 검증 뒤 복원한다.
7. 연결 공고 조회는 대표/원천 관계와 기존 공개 권한을 지켜 전체 상태 최신순·모집중 필터·10개씩 제공한다. 비로그인 개인정보를 더 반환하지 않는다.
8. 행사 교체/연결 삭제/직접입력 행사명·장소 실질 변경은 핵심 조건 변경이며 확정 후 상대 수락이 필요하다. 현재 일정/장소 변경 API가 행사 변경도 이미 지원한다고 간주하지 않는다.
9. 확인된 취소·연기·변경 일정은 연결 공고 작성자와 진행 중 확정 상대에게 앱 안 알림, 동일 변화 중복 방지. 새 푸시 범위는 아님. 등록 직전 우리 서버 최신 상태 검사 실패는 글 보존·재시도/사용자 연결 삭제 후 등록이다.
10. TourAPI addr2는 상세주소이며 행사장명 전용이 아니다. 이미지·안전한 본문·출처·새 분류·공개 DTO 등 기존 매핑 차이도 실제 원천을 확인해 연결한다.

## 종현 측 이번 구현과 검증

- 실제 RemoteEventResults/RemoteEventDetail에 props 기반 공통 행사 표시를 연결했다. 제목2줄/전체·이미지전체/실패시영역제거·기간/요금/분류/장소/출처 표시를 개선했다. 서버 응답/권한/등록 검증을 클라이언트에서 우회하지 않았다.
- [인터랙티브 UX 미리보기](../../../planning/design/행사UX_미리보기.html)는 합성자료·외부요청0인 별도 화면 모형이다. 진입별 행사위치·달력 날짜강조·검색·직접입력·상태·로그인복귀를 확인할 수 있다. 실제 저장/통합/알림을 완료했다고 보지 않는다.
- 사용자 요청으로 clone 자체 node_modules를 설치하고 Expo57 호환 expo-image-manipulator57.0.21을 연결했다. package/lock에서 다른 패키지 버전 변경0.
- 전체 lint·typecheck PASS, 행사 격리회귀12/12 PASS, 합성 HTML UX18동작 PASS, 로컬 웹 export PASS. 실제 회원/공급사/네이버/기기/운영/배포는 NOT_RUN.
- 후속1번에서 검색/선택/직접입력·작성 위치·변경/삭제·로그인 복귀 의도를 클라이언트에 반영했다. 직접입력 실제 저장과 새 상태/대표행사·공고목록 DTO 소비는 서버 계약 연결 대기다. 달력·날짜 UX는 다음 검토로 보류했다. [후속 결과](2026-10-20-event-flow-night-result.md)를 따른다.

## 기존 미완료 경계

서울 HTTPS·일일 수집은 민규 담당이며 이번 작업으로 완료되지 않았다. KOPIS 집계기간 대조는 결과 후 판단하되 일반 데이터·행사 화면 개발은 독립 진행한다. Gemini 운영 계정 전환은 유미 계정 확인 후 회의/통합 때 별도 진행한다. 공급사 조건·회원 원문 외부 전송·실회원 검증·운영 변경 등 기존 경계를 유지한다.
