# 종현 독립 코어 → 민규 연결 요구

현재 정책 기준: [정책.md](../../../../정책.md). 이 문서는 아직 남은 연결 요구를 관리한다. 9월 30일의 코어 구현·로컬 검증·병합 결과는 [통합 인계](2026-09-30-jonghyun-integration-handoff.md)에 보존하며, 완료한 코어를 처음부터 다시 구현하지 않는다. 상세 경로는 [R1~R7](2026-09-29-claude-minkyu-requests.md)을 함께 본다. 이번 문서 동기화는 코드·DB·운영 환경 연결 완료가 아니다.

## 필요한 연결

| 영역 | 현재 연결·수정 요구 | 완료 확인 |
|---|---|---|

| 공고 검색 RPC | 제목·등록 장소명·등록 주소·연결 행사명을 검색한다. 반환 지역은 동까지, 비로그인 별칭·로그인 미확정 이름 마스킹·확정 당사자 전체 이름이다. 현재 무료 공고만 취급한다. | 등록일 최신순 기본/시작일 빠른순 선택, 전체 상태 기본/모집 중 선택, 작성자 만 나이 19~99 직접 범위·전체, 비로그인 나이 전체를 검증한다. 상세 만남 지점은 검색·AI에 보내지 않는다. |
| 행사 저장·목록·순위 | KOPIS·TourAPI를 연결하고 서울은 HTTPS 조건과 연결 여부 모두 팀 검토로 남긴다. 일반 탐색은 이번 주 신규 기본/진행 중 포함 선택, 작성은 진행 중·예정 선택이다. 공식 전국 전체 공연 Top 10/뮤지컬 전환은 별도 영역이다. | 한국 시간 월요일 주간 경계, 과거 조회, 취소 제외, 진행 중→예정→종료 정렬, 중복·날짜 정밀도 보존, 어제까지 최근 7일 공식 순위의 일일 갱신을 확인한다. 공급사 응답 성공은 별도로 증명한다. |
| 공고·매칭 | 선택 모집 마감은 시작 시각 이하이며 미입력 시 시작 시각이다. 신청 소개 메시지는 필수다. 신청 거절은 재신청 불가, 본인 철회는 재신청 가능하다. 최종 동의 거절은 신청 거절과 달리 신청을 유지한다. | 공고당 최종 동의 대기 하나, 요청 후 24시간/시작 중 이른 만료, 수동 모집 마감 후 기존 신청자의 최종 동의 재요청, 양측 동의·일정 변경·시간 겹침을 검증한다. |
| 개인 완료·동행 완료·후기 | 예상 종료 후 본인의 완료 확인으로 먼저 후기 작성 가능. 실제 동행 완료는 양쪽 확인 또는 예상 종료+24시간 자동 처리다. 완료 전 후기는 비공개다. | 취소·불발·분쟁 자동 완료 제외, 실제 completedAt 기록, 완료일부터 7일 작성 기한, 양쪽 후기+완료 시 즉시/한쪽은 actual completedAt+24시간 공개를 확인한다. 알림 클릭·확인 가능 시각을 기준으로 삼지 않는다. |
| 당도·횟수·공개 후기 | 당도는 상대 후기를 열람할 수 있을 때, 완료 횟수는 실제 동행 완료 즉시 반영한다. 신고 접수만으로 후기를 숨기지 않는다. | 계산식은 팀 검토다. 운영자 비공개 결정은 revision 증가·요약 무효화·재작업 등록과 일관되게 처리한다. |
| 요약 원천·원자 게시 | 같은 snapshot의 공개 텍스트 후기 3개 이상·전체 근거를 사용한다. jobId+leaseToken+sourceRevision+근거 ID/count를 재검사한다. | 원문 변경·점유 상실·생성 중 비공개 전환 시 게시 차단, 부분 결과를 전체 요약으로 게시하지 않음을 검증한다. |

| 모델·예산 | 포텐스닷 LLM/Sonnet 5(`claude-5-sonnet`)를 유지한다. 추가 지출 0원 계정 근거 확인 후 합성 10회 평가를 진행할 수 있다. 실제 회원 원문 전송은 공급사 보관 조건 검토·사용자 확인 전 보류다. | 응답·사용량 매핑과 예약/정산·미확인 과금 실패 처리를 검증한다. 대체 모델·운영 예산·원장 보존기간·교체 주기는 팀 검토다. |
| 관측·오류·운영 자료 | 초기 AI 운영 지표는 영구 저장하지 않는다. 대화·후기 원문과 민감 정보는 오류·사용량 로그에 남기지 않는다. 일반 신고 처리는 제출 스크린샷만 사용하며 운영자의 고객 DB 채팅 직접 열람을 만들지 않는다. | 원문 없는 예산 원장과 운영 지표를 분리한다. 대상 가명 ID·오류 수치·보존·삭제 세부 기준은 팀 검토다. |
| 실행·배포 | 행사 갱신·요약 작업 등록은 매일 00:01 Asia/Seoul, 자동 완료는 건별 예약이다. API 허용 목록·함수 등록·환경 주입·gateway CORS를 연결한다. | 로컬 DB/HTTP, 실제 공급사, 브라우저, 원격 DB/배포를 각각 검증한다. 환경값 부재를 가짜 성공·기본값으로 대체하지 않는다. |

## AI 응답과 화면 연결

자연어 조건 해석과 실제 카드, 근거 있는 추천 이유·주의점이 도입 방향이다. 관심사·대화 방식은 등록 성향과의 의미 유사성, MBTI는 정확 일치로 처리하고 미등록은 확인 필요로 남긴다. 공개 권한과 사용자가 선택한 정렬을 준수한다. 반환 직전 재확인·일부 결과·실패 처리 세부 동작과 품질 검사 기준은 팀 검토다. 기존 코어의 가상 검사를 이 세부 정책의 확정이나 실제 사용자 공개 승인으로 읽지 않는다.

입력에서 개인 연락처·계좌·주거 상세정보를 발견하면 외부 전송을 멈추고 수정을 안내한다. 출력에서 발견하면 응답을 숨기고 재시도를 안내한다. 정상 공개 장소·시설 주소와 비공개 만남 안내는 구분한다. 실제 회원 원문 전송 보류 상태에서는 합성 입력만 사용한다.

## 작업-요약 원자성 확인

기존 `createReviewSummaryHandler(deps)`와 `runNextJob`·`runReviewSummaryStep` 연결을 재사용한다. 점유를 잃으면 settle하지 않는다. 요약 게시와 checkpoint 삭제는 원자 처리하고 작업 settle은 별도다. 게시 성공 뒤 settle 전에 중단될 수 있으므로 `(jobId,sourceRevision)` 게시 멱등성으로 시각·알림·내용의 중복 변경을 막아야 한다. 과거 가상 DB 검사를 실제 DB 원자성 증거로 대신하지 않는다.

## 팀·외부 확인으로 남은 사항

과거 행사 최초 수집 범위, 서울 연결 여부, 운영 수치·재시도·원장 한도/교체/보존, 성향·추천/요약 품질 기준, 개인정보 탐지 세부 기준과 외부 원문 보관 조건을 확인한다. 무료만 운영하는 현재 서비스에 유료 결제·계좌 인증 화면을 연결하지 않는다. 추후 유료 신청·제안 시 1원 인증 필수만 확정이며 세부 효력은 별도 검토다. Kakao 우편번호 선택창은 확정된 방식으로 연결하되 장소 API와 구분해 검증한다.
