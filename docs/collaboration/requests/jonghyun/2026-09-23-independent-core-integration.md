## 확정 정책 동기화 요청

행사 키워드는 행사명·장소명·공개 주소의 부분 일치이며 대소문자·연속 공백을 무시한다. 일반 행사 목록 기본은 과거·현재·예정이며 ‘진행 중만’ 기본 OFF다. 홈 ‘이번 주 신규’와 작성 선택 모드는 분리한다. 공고 기간 검색은 기간 안 시작→이전부터 겹침 순으로, 각 그룹 내 모집 중 우선이다. 기간이 없으면 모집 중 우선(시작순), 나머지는 최근 등록순이다. 빈 검색어는 다른 필터에 맞는 목록이다.

프로필 후기는 로그인 회원 공개, 신고만으로 숨기지 않음, 운영자 비공개 시 revision 증가·요약 무효화·재작업 등록을 같은 트랜잭션으로 처리한다. 요약 3개·프로필 세 필드·긴 대화 새 탐색·전체 후기 묶음 처리·임시 checkpoint·Supabase 작업 실행 결정은 최신 사용자 답변을 따른다.

외부 AI 미보관 요구 자체·예외 허용 범위는 **미정·팀 검토**로 전환했다. [팀 검토 문서](2026-09-23-team-ai-retention-review.md)를 기준으로 이전 미보관 필수 기록을 대체한다. 유미당 서버의 대화 이력·원문 로그 미저장은 유지한다.

민규 소유 PLAN·상세설계·backend README·공통 계약에 남은 옛 설명은 위 기준과 연결해야 한다. 화면 연결은 별도 담당 협의가 필요하며, 현재 코어 테스트를 UI 완료로 보지 않는다.

## 실제 실행 전 남은 확인

2026-09-23 사용자 지시로 실제 DB·외부 API 연결은 대기한다. 우편번호 공급사는 Kakao 우편번호 서비스로 확정했으며 공급사 결정은 연결 재개를 뜻하지 않는다.

포텐스닷 기본 호출 안내는 [키를 제외한 요약](2026-09-23-potens-api-reference.md)으로 수령했다. 실제 응답/토큰/오류 상세, 최종 모델/일일 한도/무료 기간/보관 증거, 유료 예산(미정·팀 검토)·대체 모델, 확정한 Kakao 우편번호 선택창 연결, 공급사별 행사 문서/수집범위, 운영 수치·보관기간, 의미 평가 기준 및 실제 검사기. 없는 설정을 가짜 성공이나 숨은 기본값으로 대체하지 않는다.

## 작업-요약 연결 보완

`createReviewSummaryHandler(deps)`가 `runNextJob`과 `runReviewSummaryStep`을 연결한다. 점유를 잃으면 settle하지 않는다. 요약 게시+checkpoint 삭제는 원자 처리하고 작업 settle은 별도다. 게시 성공 뒤 settle 전에 중단될 수 있으므로 DB 게시를 `(jobId,sourceRevision)` 기준으로 멱등하게 하여 재게시 시각·알림·내용을 중복 변경하지 않아야 한다. 현재 검증은 가상 DB 동작이며 실제 원자성 증거가 아니다.

[비용·보관 조건 확인 자료](2026-09-23-ai-cost-and-retention.md)의 미확인 계정 조건과 사용자 답변을 실제 모델 연결 전에 반영한다.

## 준비·결정 상태 후속 답변

- Kakao 우편번호 서비스 사용은 확정. 실제 선택창 연결은 대기.
- Kakao 장소 검색·KOPIS·서울 열린데이터광장·TourAPI 이용 신청·키 준비 상태: 미정, 종현이 팀원에게 확인.
- 과거 행사 최초 수집 범위: 제공처 지원 범위를 확인한 뒤 팀 결정. 과거 조회 허용 정책은 확정.
- AI 개발·검증 예산: 미정·팀 검토. 포텐스닷 기본 호출 안내는 수령했고 실제 성공/사용량/한도 오류 응답과 계정 조건은 추가 확인 필요.
- AI/작업 한도·재시도, 지표/중간 요약 보관기간, 실제 AI 품질 합격 기준·검사 방식: 미정·팀 검토.
- 외부 AI 원문 미보관 요구 자체·예외 범위: 기존 지시대로 미정·팀 검토 유지.
- 실제 DB·외부 API 연결: 사용자 지시로 대기. 공급사 선택이나 자료 수령만으로 재개하지 않음.

확정되지 않은 모델·예산·운영값은 임의 설정하지 않는다. 코드상의 합성 테스트 값은 실제 운영 승인이 아니다.
