# 모바일 회원 화면과 실제 API 연결 결과

작성자 jonghyun, 2026-10-05. 기준 `jonghyun/queue-integration`, 기준 커밋 `9dfca36cfe88f6da658fcbf863d5f4a33c2d0513`. 하네스 mobile-ui의 화면 4개와 이 문서만 수정했다. SDK·세션·Storage·공통 DB/HTTP는 각 담당 결과와 구분한다. 커밋·푸시·배포·실제 회원 데이터 전송은 하지 않았다.

## 연결한 동작

| 화면 흐름 | 현재 코드 |
|---|---|
| 마이페이지·취향·성향 | 실제 `/me`, `/me/traits` 조회, 관심사·대화 방식·MBTI·소개 네 필드 원자 저장, 저장 후 재조회. 실패 입력 유지. 실제 약속/보낸 신청/받은 신청 목록으로 이동한다. |
| 대표 사진·회원 사진 | 실제 사진 선택을 10,000,000바이트 JPG/PNG 원본 검사기에 전달하고 준비된 사진 포트로 재인코딩·업로드·교체한다. 같은 입력 재시도에는 같은 경로를 보존한다. 교체 결과가 불확실하면 새 업로드 대신 실제 현재 사진을 재조회한다. 저장 경로를 이미지 URI로 쓰지 않고 인증된 `display` 포트로 받은 화면용 URI만 표시하며 세션 변경 시 숨긴다. |
| 공고 작성·발행 | 장소/주소/행사 선택 및 기존 작성 화면을 유지한다. 세션에 속한 메모리 초안을 등록 전 확인으로 전달하고 무료 `MemberService.create`를 호출한다. 같은 입력의 재시도는 같은 postId, 입력 변경은 새 postId를 사용한다. 서비스 모드에서 예시 `app.publish`는 호출하지 않는다. |
| 공고 수정·종료·삭제·재개 | 서버 대화 목록의 `my_role=author`와 해당 `post_id`로 작성자임이 확인되는 공고에 한해 관리 진입을 제공한다. 수정은 실제 상세 조회의 `updatedAt`과 필수 장소 값을 보존하고 SDK update를 호출한다. 종료/삭제/재개는 확인 후 서버 성공 응답을 기다린다. |
| S11 첫 메시지·채팅 | 공고 상세에서 대화로 이동하며 첫 메시지 성공 때만 실제 신청 ID로 전환한다. 동일 메시지 재전송은 같은 messageId, 본문 변경은 새 ID를 사용한다. 실제 대화·메시지·이전 메시지·확정 요청을 조회하고, 나가기는 본인 목록 숨김과 확정 취소를 구분한다. |
| 확정 요청 | 서버의 제목·소개·일정·공개 지역·희망 조건·무료 조건 snapshot을 수락 전에 표시한다. 조건/version/기한을 확인할 수 없으면 수락을 막고 최종 판단은 서버가 한다. 작성자 요청/철회와 신청자 수락/거절을 구분한다. |
| 약속·변경·취소·완료 | 실제 약속/변경 상태를 조회한다. 변경 제안은 조회한 updatedAt과 일정/선택한 장소를 보내며 제안 입력에 맞춘 changeId를 재사용한다. 상대 제안에만 수락을 제공한다. 취소 reason에 맞춘 cancellationId, 본인 완료 확인, 후기 상태로 연결한다. 취소 당시 일정 snapshot이 없으면 현재 공고 일정으로 대신 표시하지 않는다. |
| 후기 | 서버 can_write/disputed/released를 기준으로 작성·공개를 표시한다. 경험·별점·선택 한마디·서버 칭찬 목록을 제출한다. 비공개 상대 후기를 임의 표시하지 않으며 제출과 공개 완료를 구분한다. |
| 알림 | 실제 notificationId/kind/requestId/createdAt/readAt을 사용한다. 한국어 정형 문구와 읽음 여부를 표시하고 읽음 처리 후 현재 대화/약속으로 이동한다. 알림 클릭으로 확정·완료를 실행하지 않는다. |
| 차단·신고 | 공개 회원 프로필의 실제 profileId로 차단을 확인하고, 계정 화면에서 차단 해제·다음 목록을 제공한다. 확정 취소와 별개이며 해제로 관계를 복구하지 않는다. 신고 7사유 복수 선택, 온라인 설명+캡처, 대면 설명/선택 자료를 연결한다. 상대가 보낸 실제 chat messageId를 신고 대상으로 사용한다. |
| 계정 | 실제 이용 상태·내 신고 목록/상세, 두 AI의 처리 철회, 준비된 세션 포트의 로그아웃과 선택적 retire를 연결한다. 철회는 계정과 일반 동행을 유지한다. retire 포트가 없으면 탈퇴 버튼을 막고, 포트가 준비되면 명시 확인·응답 검증 뒤 세션을 비운다. |

공통 조회·수정 hook은 세션 epoch, AbortSignal, 화면 focus로 응답을 검사한다. 로그아웃/계정 전환 뒤 늦은 응답으로 회원 정보·사진·성공 안내를 복원하지 않는다. 오류와 정상 0건을 별도로 표시하고 예시 회원·공고를 서버 결과에 섞지 않는다. 내부 UUID/version/원시 JSON은 제품 화면에 표시하지 않는다.

## 확인한 검사와 근거

- 모바일 전체 TypeScript 검사 PASS. 담당 화면 4개 ESLint PASS, 오류·경고 0.
- 소유권 검사 5경로 PASS, 변경 공백 검사 PASS. 새 화면의 다른 언어 혼입 검사 통과.
- root의 합성 세션/HTTP 브라우저 검사는 **15개 의미 검사 PASS, 가상 HTTP 호출 20개**다. 성향 실패 입력 보존·성공 저장/재조회, S11 첫 메시지 실패 재시도 동일 UUID·성공 신청 전환에 더해 공고 발행 실패 시 초안 보존, 동일 UUID·동일 본문 재시도, 무료 조건과 상세 만남 지점의 공개 분리를 확인했다. 전체 화면의 실제 사용자 검증과 구분한다.
- root의 iOS/Android Hermes 코드 export PASS. 실제 기기 실행·네이티브 인증·스토어 심사/출시 성공을 뜻하지 않는다.
- SDK57의 [ImagePicker](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/)와 [Crypto](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/) 공식 문서를 확인해 기존 이미지/UUID API를 사용했다. 실제 기기에서 선택 파일의 MIME/원본 크기를 얻는지는 별도 검증이다.

## 남은 연결과 사용자 결정

사용자는 실제 기능이 없는 신고 숨김 선택을 **보류하고 신고만 연결**하는 A안을 확정했다. UI는 숨김 선택을 제공하지 않고 `hideTarget:false`로 접수한다. 민규의 hideTarget 현재 저장은 신고 메타데이터이며 목록/상세 숨김 실행을 증명하지 않는다. 실제 숨김 계약과 구현이 준비되기 전 성공으로 표시하지 않는다.

신청이 하나도 없는 본인 공고의 목록·소유권 확인은 `ownPosts`나 공개 상세 작성자 식별/owner DTO가 없어 현재 제공하지 않는다. 기존 author 대화로 증명되는 공고 관리는 연결했지만 이를 전체 본인 공고 관리 완료로 확대하지 않는다. 민규에게 별도 회원 공고 목록/owner 계약을 요청한다. 공고→작성자 프로필 이동 ID, 행사 상세→연결 공고 조회와 공개 요약/행사 상세/공식 순위의 미제공 공통 route도 기존 요청대로 남는다.

채팅 읽음 API는 현재 없으므로 새 endpoint를 만들거나 읽음 성공을 꾸미지 않는다. 네이버 native 인증과 앱 밖 탈퇴·개인정보처리방침/고객지원은 포트/공식 공통 연결과 별도 완료 조건이다. 캡처 업로드/취소와 이전 사진 삭제는 실제 SDK/Storage 결과에 의존하며 본 화면 생성만으로 삭제·운영 완료를 주장하지 않는다.

실제 네이버·회원 DB/Storage·일정 경합·공급사·모바일 기기·호스트·배포·스토어·UT는 **NOT_RUN**이다. 합성 브라우저/HTTP·타입/린트 통과와 실제 운영 완료를 구분한다.
