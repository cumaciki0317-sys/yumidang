# Android 작은 화면 검증 — 2026-10-23

출시 대상 앱을 우선한다. 전용 `Yumidang_UX_API35`·공식 Expo Go의 합성 예시 데이터에서 확인했다. 화면을 840×1800px·density420(너비320dp), 시스템 글자200%로 바꿨다. 웹 검사와 출시용 APK/AAB 검증으로 대신하거나 확대하지 않는다.

## 확인 범위

원래 Q13·Q14·Q15와 S11의 대표 경로로 한정한다. 헤더·4탭, 공고 입력·키보드·첫 오류, 행사 검색/직접 입력의 중첩 복귀, 대화 입력/이탈 확인을 본다. 모든 방향·모든 키보드·모든 기기 조합을 이번 완료 조건으로 추가하지 않는다.

## 실제 관찰

- 홈의 4탭 라벨이 줄바꿈되며 표시됐다. 작성 헤더의 제목과 닫기가 겹치지 않았고 닫기 영역은116×116px(약44dp)였다. 예시 모드 상단 디버그 배너의 넘침은 제품 헤더와 구분한다.
- S11 변경 제안의 `상대 응답 대기`와 빨간 배지의 흰 마감 일시가 서로 겹치지 않고 줄바꿈됐다. `compact-deadline-card-final.png/xml`은 키보드 좌표 보정 전 소스에서 관찰한 카드이며, 이후 카드 제품 파일은 변경하지 않았다.
- 행사 검색에 `NoSuchEventCompact`를 입력해 Enter를 누르자 빈 결과 안내와 직접 입력이 표시됐다. 직접 입력에 `CompactManualEvent`를 쓴 뒤 주소 검색을 열고 뒤로가기로 직접 입력→행사 선택 순서로 돌아왔다. 행사 검색어는 보존됐다. 주소 복귀 시 행사명은 화면 위에 있었으므로 그 캡처만으로 값 보존을 판정하지 않는다.
- TalkBack을 켠 상태에서 직접 입력을 열었다 닫자 원래 `직접 입력` 버튼에 녹색 초점 테두리가 표시됐다. 마지막 버튼에서 다음 항목 탐색1회를 수행했을 때 뒤 공고로 초점이 이동하는 현상은 관찰하지 않았다. 전체 탐색 순서나 음성 품질 검증은 아니다. `compact-talkback-modal.png`, `compact-talkback-wrap.png`.

## 발견한 키보드 결함과 원인

초기 작은 화면에서 제목 입력은 키보드 위로 이동했지만 하단 다음 버튼은1044..1211px에 있어 키보드 시작 약1057px와 겹쳤다. 첫 보정 뒤에도929..1096px로 일부가 남았다. `compact-title-keyboard.png`와 `compact-title-fixed.png`는 실패/중간 보정 증거로 보존하며 최종 성공으로 사용하지 않는다.

입력이나 회원 정보 없이 좌표만 임시 진단했다. KAV의 부모 안 y는0, root-relative pageY는82.6667dp, measureInWindow.y는43.8095dp였다. SafeAreaFrame.y는0, 위 inset은38.8571dp였으며 keyboard.screenY는402.6667dp였다. Android의 화면 좌표와 창 좌표를 혼합한 차이가 확인됐다. 임시 로그 두 파일은 원본 해시를 확인한 뒤 원복했고 진단 서버를 종료했다. 최종 보정·재검증 결과는 아래에 별도로 기록한다.

## 적용 경계

실제 회원·네이버·외부 공급사·운영 서버 호출은 하지 않았다. 알려진 서버 계약 후속은 `server-followup.md`를 따른다. 미커밋·미푸시·main 미반영 상태이며, 설정 원복과 최종 소스 해시는 기기 기록에 별도로 남긴다.

## 최종 보정과 재검증

공통 Screen·선택창은 `root frame.y + host.measure.pageY − layout.y`로 키보드와 같은 화면 좌표를 사용한다. 임시 진단 로그는 최종 제품에서 제거했다. 최종 다음 버튼827..994px, 제목584..746px, 하단 입력487..751px가 키보드 시작1057px 위에 표시됐다. 다음을 누르면 첫 카테고리로 이동했다. `compact-title-final`, `compact-lower-final`, `compact-error-final`.

선택창 검색 입력855..1016px와 오른쪽 검색843..1015px, 직접 입력 행사명864..1025px도 키보드 위에 표시됐다. Enter 검색→직접 입력→행사명 입력→닫기→선택→직접 입력 재진입에서 `FinalManualEvent`가 유지됐고, 예시 공고에 연결한 뒤 변경·삭제가 표시됐다. 이는 실제 서버 저장 증거가 아니다. `compact-picker-final`, `compact-manual-final`, `compact-manual-value-final`, `compact-connected-final`.

S11 입력537..779px와 보내기597..718px, 첫 전송 안내799..1051px가 키보드 위에 표시됐다. 시스템 뒤로가기로 키보드와 이탈 확인을 차례로 처리했다. 이탈 안내 제목·설명은 처음 보이고, 아래로 스크롤하면 삭제487..739px·계속 작성776..949px에 접근했다. 계속 작성 후 `CompactUnsentDraft`가 보존됐다. 실제 메시지를 전송하지 않았다. 작은 화면200%에서 제목·설명·두 행동이 한 화면에 동시에 보이는 것은 아니다.

최종 합성 회귀170/170·타입·lint, Android Hermes 번들 생성이 통과했다. 합성 회귀 수를 기기 시나리오 수로 바꾸지 않는다. `compact-restored-settings.json`은 시작 전/원복 후 값이 정확히 일치하며, 전용 에뮬레이터와 Metro8140을 종료했다.
