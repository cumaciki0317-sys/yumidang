# 앱 중심 후속 검증 — 2026-10-23

사용자 최신 지시에 따라 Android 앱의 실제 화면·키보드·뒤로가기·접근성 관찰을 우선한다. 웹은 보조 확인이며, 웹 빌드나 합성 검사 성공을 Android 앱 성공으로 대신하지 않는다. 이번 환경은 전용 API35 에뮬레이터·공식 Expo Go의 예시 데이터다. 출시용 APK/AAB·실제 서버·실회원·독립 UT 검증은 아니다.

## 추가 대조에서 확인한 문제

1. **현재 확정 상태와 확정 이력 혼동(Q05)**: 서버 계약·취소 SQL에서 `matched`는 취소 후에도 남는 이력이다. 현재 약속을 같은 ID로 재조회하고 실제 `confirmed`일 때만 확정 카드를 표시하도록 보완했다. 누락·로딩·실패·모르는 상태는 확인 필요로 표시한다. 예시·서비스 S11/S16/S18에 같은 표시 경계를 적용했다. 과거 `matched`만으로 확정된다는 검사 기대값도 이 근거에 맞춰 고쳤다.
2. **Android 행사 선택→직접 입력 전환 중단(Q15)**: 이전 수정본의 실제 Android에서 선택창이 닫힌 뒤 다음 창이 열리지 않았다. `AppState focus`가 Dialog 닫힘을 항상 통지한다는 가정은 실제 환경에서 성립하지 않았다. [실패 시 화면](android-runtime/audit-manual-open.png)을 보존한다. Android에서는 화면 내부 하단 overlay로 전환하여 Dialog 간 경합을 제거했고, 실제 재검증 결과를 기기 기록에 별도로 남긴다. 웹의 닫힘 콜백 성공을 앱 성공으로 사용하지 않는다.
3. **200% 글자에서 미전송 이탈 안내가 화면 밖에 표시(Q04)**: 시스템 뒤로가기의 이탈은 막혔고 입력도 유지됐지만, 상단 확인 카드가 현재 스크롤 위에 삽입돼 사용자가 보지 못했다. [발견 화면](android-runtime/audit-unsent-leave.png)을 보존한다. 기존 inline 확인 구조를 유지하고 비파괴 행동인 `계속 작성하기`를 실제로 드러내도록 보완한다. 수정 후 관찰은 기기 기록에서 확인한다.

## 이번 실제 Android 관찰

- [가입 사진 순서](android-runtime/audit-signup-photo-order.png): 글자200%에서 사진 항목명·필수 배지, 형식/용량 도움말, 실제 선택 조작, 배경 없는 오류 안내의 순서를 확인했다. 이 사진은 TalkBack 음성 검증 증거가 아니다.
- [약속 상세](android-runtime/audit-appointment-current.png)·[확정 대화](android-runtime/audit-confirmed-chat.png)·[취소 화면](android-runtime/audit-cancel-current.png): 예시의 현재 확정 약속 카드가 표시됐다. 실제 서버의 확정/취소 동시성 검증은 아니다.
- [변경 제안](android-runtime/audit-deadline-card-200.png): 글자200%에서 상대 응답 대기, 빨간 배지의 흰 마감 일시가 줄바꿈돼 표시되고 기존 약속을 유지하는 변경 제안 문구를 확인했다.
- [행사 검색 키보드](android-runtime/audit-event-keyboard.png): 일반 화면 키보드 위에 검색 입력과 오른쪽 검색 버튼이 표시됐다. Enter 실행 후 빈 결과·직접 입력 조작이 표시됐다. 이는 Android 전환 수정 전 관찰이며 수정 후 최종 범위는 results.json을 따른다.

## 남은 경계

후기 AI3종 독립 동의, 행사ID로 연결 공고 조회, 후기 불가 사유, 직접 입력 행사 실제 저장, AI 이용 가능 상태 계약은 [민규 후속](server-followup.md)에 유지한다. 선택 확정·문서 반영·서버 구현·실제 통합 완료를 구분한다. 커밋·푸시·main 병합·배포는 실행하지 않았다.

## 수정 후 판정

기기 기록 N12~N14에서 같은 입력 순서의 오류 해소·A안 복귀·재진입 값 유지·예시 연결, 이탈 안내의 전체 맥락과 실제 TalkBack 초점을 확인했다. 실패 캡처는 이전 수정본 증거로 유지하며 해당 수정본 성공과 구분한다. 당시165건 통합 회귀·타입·lint가 통과했다.

## 작은 화면에서 추가 보완

너비320dp·글자200%에서 입력은 키보드 위로 이동하지만 다음 버튼 하단이 가려지는 결함을 발견했다. Android의 창 좌표와 화면 좌표 차이를 실측으로 확인했고, 부모 화면의 실제 위치를 사용하는 방식으로 고쳤다. 상수 여백이나 글자 크기 제한을 추가하지 않았다. 최종 다음 버튼827..994px는 키보드 시작1057px 위에 표시됐고 실제 조작 후 첫 오류로 이동했다.

행사 검색·직접 입력, 닫은 뒤 행사명 보존·공고 전용 연결, 대화 입력·보내기·계속 작성의 입력 보존도 확인했다. 작은 화면의 긴 이탈 안내는 스크롤로 두 행동에 접근해야 한다. 전체 내용이 한 화면에 동시에 표시된다는 판정은 하지 않는다. 상세 근거와 소스 시점은 [compact-qa.md](compact-qa.md)와 기기 N15~N19를 따른다.

최종170건 통합 회귀·타입·lint·Android 번들 생성이 통과했다. 시험 설정은 원복했고 전용 환경을 종료했다. 실제 서버 계약 연결·최종 디자인·출시용 설치본/실회원 QA는 남아 있다.
