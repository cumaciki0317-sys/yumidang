# 두 검증 도구의 한시 수정과 원복 설계

> 최신 상태: 사용자 후속 한시 재배정 승인에 따른 실제 로컬 연결 검증·새 자원 정리·두 도구 원본 복구·민규 담당 복귀를 마쳤다. [최종 실행 결과](2026-10-14-temporary-validation-result.md)를 따른다. 아래 미실행/대기 표현은 당시 기록이며 전체 진행률은79%(22/28)다.

사용자가 종현 검증 기간에만 두 도구를 임시 수정하고 원복하는 방식을 제안했다. 아래는 검토 가능한 절차이며 아직 한시 소유권 재배정이나 도구 수정은 실행하지 않았다. 현재 전체 진행률은79%(22/28)다.

## 범위와 현재 실행 조건

- 대상은 `tools/local/run_database_tests.py`와 `tests/integration/jonghyun/isolated_ai_contracts.py` 두 파일뿐이다.
- 현재 종현 소유권 검사에서 두 경로가 민규 담당으로 거절된다. AGENTS.md는 거절된 경로의 편집을 제외하고, 재배정이 합의되면 민규가 소유권을 갱신하도록 정한다.
- 실행 도구는 HEAD와 현재 소스 바이트의 일치를 확인한다. 임시 패치도 승인된 수정 경로에서 로컬 커밋으로 고정한 뒤 검증해야 한다.
- 민규 원본 clone을 보존하고 종현 전용 clone에서 수행한다. 작업자·hook을 바꾸거나 검사 조건을 우회하지 않는다.

## 수행 순서

1. 민규가 두 개별 경로에만 종현의 한시 소유권을 등록한다. 같은 기간 민규는 해당 파일을 동시에 편집하지 않는다. 종현이 갱신된 정책과 경로 검사를 확인한다.
2. 실제 시작 시점의 두 파일 원본 바이트·해시·커밋을 보존한다. 기존 자원6개·네트워크1개·볼륨2개의 정확한 관찰 기준과 현재 소스·SQL119개를 다시 확인한다.
3. [지원 설계](2026-10-14-live-validation-guard-conflict.md)의 기존 자원 보존 계약과 OS 임시 폴더 호환만 수정한다. 현재700/600·소켓·소유 대상·원 Auth 증거 검사를 유지하고 관련 회귀를 확인한다. 종현 clone에서 로컬 임시 커밋과 새 소스 핀을 만든다.
4. 이미 승인된 종현 VM·새 합성 대상에서 실제 검증을 수행한다. 요약14는 빈 DB에서 먼저, Auth6 발급 후 행사·피드백·읽음, 탈퇴는 마지막 순서다. 실제 공급사·실회원·운영 적용은 포함하지 않는다.
5. 자식 검증 프로세스 종료, 새 소유 대상 정리, 기존 자원 보존 확인을 마친 뒤 실제 영수증·임시 도구 소스 해시·커밋을 보존한다. 정리나 보존 확인이 미완료이면 먼저 필요한 복구를 끝낸다.
6. 두 파일만 시작 시점의 원본 바이트로 복원하고 해시 일치를 확인해 로컬 복구 커밋을 만든다. 종현의 행사·AI 기능 변경과 다른 작업은 유지한다. 민규가 두 경로의 담당을 다시 민규로 복귀시킨다.

## 검증 결과의 해석

실제 결과에는 임시 도구 버전을 명시한다. 복구된 원본 도구로 같은 검증이 통과했다고 기록하지 않는다. 기능 코드·실제 Auth/DB 연결·모형 공급사·기존 자원 메타데이터 보존·전체 저장 바이트를 구분한다. 원복 후 같은 환경에서 재검증하려면 지원 패치가 다시 필요할 수 있다.

현재 남은 결정은 민규의 직접 도구 구현을 이 한시 재배정 절차로 전환할지다. 결정 전 현재 민규 담당과 소유권을 유지한다. 도구·소유권·운영 자원 변경과 외부 메시지는 실행하지 않았다.
