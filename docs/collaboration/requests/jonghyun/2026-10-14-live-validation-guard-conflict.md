# 종현 실제 검증 준비 조건 충돌과 민규 지원 요청

> 최신 상태: 사용자 후속 한시 재배정 승인에 따른 실제 로컬 연결 검증·새 자원 정리·두 도구 원본 복구·민규 담당 복귀를 마쳤다. [최종 실행 결과](2026-10-14-temporary-validation-result.md)를 따른다. 아래 미실행/대기 표현은 당시 기록이며 전체 진행률은79%(22/28)다.

현재 전체 관리 진행률은 **79%(22/28)**다. 이 기록은 실제 환경 관찰과 준비 조건의 충돌을 정리하며 완료 수를 올리지 않는다. 작업자는 종현이고, 이 문서만 수정했다. 수정 전 종현 소유권 검사를 통과했다. 커밋은 조정자가 담당한다.

## 확인된 사실과 중단 지점

사용자는 정확한 종현 가상 머신의 재시작과 새 소유 합성 검증 대상을 승인했다. 기존 컨테이너·네트워크·볼륨의 변경은 제외했다. 이 승인은 운영 적용·외부 공급사 호출·실회원 검증으로 확대하지 않는다.

실제 실행 담당 조정자는 종현 가상 머신에서 기존 컨테이너 **6개가 실행 중**, 사용자 정의 네트워크 **1개**, 볼륨 **2개**를 관찰했다. 사용 가능한 메모리는 **3,218,924KiB**였다. 이는 해당 읽기 시점의 관찰이며 지속적인 여유나 새 대상 준비 완료를 뜻하지 않는다. 이 문서 작성자는 해당 값을 조정자의 관찰 결과로 인계받았고 실제 호출을 추가하지 않았다.

현재 아래 두 준비 검사 함수는 실행 의도의 `existingContainers`와 `existingNetworks`가 모두 빈 목록이어야 통과한다.

| 담당 파일 | 준비 검사 | 실제 호출 또는 코드 확인 |
|---|---|---|
| `tools/local/run_database_tests.py` | `isolated_prepared_target` | `ISOLATED_INTENT_INVALID`로 거절 |
| `tests/integration/jonghyun/isolated_ai_contracts.py` | `signed_prepared_target` | 실제 호출은 앞선 폴더 검사에서 `SIGNED_PRIVATE_DIRECTORY`로 거절. 기존 목록을 거절하는 `SIGNED_PREPARED_AUTHORITY` 조건도 코드에 존재하지만 이번 호출에서는 도달하지 않음 |

따라서 기존 자원의 실제 목록을 보존하는 실행 의도와 현재 준비 검사는 양립하지 않는다. 메모리 부족이 아니라 **기존 자원이 없는 환경만 허용하는 준비 계약과 비공개 폴더 경계의 불일치**가 실행을 막는다. 두 파일은 민규 예외 12경로에 포함되어 종현 수정 권한 검사가 거절된다.

준비 도구는 정식 SQL 사본을 현재 운영체제의 임시 폴더(`/private/var/folders/.../T`) 아래에만 만든다. 실제700/600 권한으로 준비한 폴더를 인증 검사에 넣으면 `signed_private_read`가 `/private/tmp` 조상 경로만 허용해 `SIGNED_PRIVATE_DIRECTORY`로 거절한다. 임시 폴더 권한을 완화하거나 경로를 가장해 해결하지 않는다. 이번 실제 사전검사 영수증은 `/private/tmp/yumidang-jonghyun-20261014-live-preflight-receipt.json`이며 정식 SQL119개 준비·기존 목록6/1·두 실제 오류·신규 대상 미생성을 기록했다.

VM 시작 뒤 기존6개가 실행 중인 것을 관찰했다. 조정자가 기존 컨테이너에 별도 시작·중지·삭제 명령을 실행한 것은 아니다. 시작 전 VM 내부의 개별 컨테이너 상태는 관측하지 못했으므로 그 이전 상태와의 동일성을 주장하지 않는다. 시작 뒤 두 번째 읽기에서 동일한6개 ID를 확인했고, 기존 자원의 ID·실제 Image ID·설정/호스트 설정/저장소 연결 해시를 비공개 기준 자료에 기록했다. 기존 DB·Storage 바이트에는 접속하지 않았으므로 고객 데이터 전체 보존 검사로 계산하지 않는다.

현재 새 대상 생성·SQL 실행·인증 회원 생성은 **모두 0**이다. 정식 소스·SQL 사본 준비는 실제 환경 준비와 구분한다. 기존 원문·비밀·인증 입력을 이 문서에 넣지 않는다.

## 민규에게 요청하는 두 변경

### 1. 일반 준비 검사의 기존 자원 보존 계약

`tools/local/run_database_tests.py`에 기존 자원이 존재하는 경우의 명시적인 새 계약 버전을 추가한다. 기존 빈 환경 계약과 기본 동작은 유지한다. 알 수 없는 버전, 누락된 증거, 임의의 허용 표시만 있는 입력은 거절한다.

새 계약은 검토된 기존 자원 목록을 변경할 수 없는 기준 자료로 묶는다. 목록은 정렬과 직렬화 방식이 고정되어야 하고, 자료의 해시·관찰 시각·대상 가상 머신·문맥·소켓을 실행 의도에 연결한다. 자료 해시만으로 실제 관찰 성공을 주장하지 않는다.

- 컨테이너: 정확한 식별자·이미지·이름·프로젝트 표식, 설정·호스트 설정·연결 저장소의 해시, 실행 상태와 메모리 부족 종료 여부를 기록한다.
- 사용자 정의 네트워크: 정확한 식별자·이름·표식·설정의 해시와 기존 연결 관계를 기록한다. 새 대상이 붙어 기존 연결 관계를 바꾸지 않도록 별도 새 네트워크를 사용한다.
- 볼륨: 정확한 이름·표식·설정의 해시와 기존 컨테이너 연결 관계를 기록한다. 이 관찰은 저장된 실제 바이트의 백업·복원 검증을 뜻하지 않는다.
- 새 대상: 기존 식별자·이름·프로젝트·네트워크·볼륨과 겹치지 않아야 한다. 새 대상 생성 결과의 원 영수증으로 소유 범위를 확정한다.

순수 준비 검사는 파일 형식·권한·해시·소스 및 SQL 버전·목록 간 겹침만 확인한다. 가상 머신·도커·SQL을 호출하지 않고 실행 허가나 실제 준비 완료를 반환하지 않는다. 실제 실행 경계는 각 자원 변경 호출 전후에 기존 자원의 정확한 식별자와 비교 대상 속성을 읽어 보존을 확인한다. 도커 내부 임시 식별자나 실행 시간처럼 자연히 변하는 값은 보존 판정 항목과 구분한다. 실시간 읽기 실패·속성 차이·소유 대상 미확정이면 다음 변경을 중단하고 실패 또는 미확인으로 기록한다.

기존 자원에 대한 시작·중지·삭제·설정 변경·접속·작업 실행은 추가하지 않는다. 기존 미확정 사용량과 예약은 유지한다. 컨테이너 설정 해시 일치는 고객 데이터 전체 보존 증거로 확대하지 않는다.

### 2. 서명 인증 준비 검사의 같은 계약 사용

`tests/integration/jonghyun/isolated_ai_contracts.py`의 서명 인증 준비 검사도 위 계약 버전을 사용하도록 맞춘다. 서로 다른 기존 자원 허용 규칙을 두 곳에 독립적으로 만들지 않는다. 공통 순수 검증을 재사용할 수 있는지는 민규가 기존 함수 경계를 확인해 결정한다.

같은 파일의 `signed_private_read`에는 정식 준비 도구와 일치하는 비공개 임시 루트 계약이 필요하다. 정규화한 운영체제 임시 루트와 기존 `/private/tmp` 중 검토된 경계만 허용하고, 그 경계 아래 모든 디렉터리700·파일600·소유자·단일 링크·열린 파일 식별자·검사 중 변경 거절을 유지한다. 임의 경로 허용이나 모든 부모 권한 검사 제거로 해결하지 않는다. 기존 비공개 경로 정상/거절 회귀와 OS 임시 루트 정상·symlink/권한·경계 밖 거절을 확인한다.

새 데이터베이스·인증·데이터 조회·게이트웨이 네 대상의 정확한 식별자와 설정 해시를 원 생성 영수증으로 묶는다. 기존 자원 목록과 겹치면 거절한다. 원 인증 토큰·요청·영수증과 현재 소스 핀을 유지하고, 승인 객체나 준비 자료만으로 실제 인증 발급 성공을 만들지 않는다.

실제 호출 전후의 보존 관찰과 새 대상만 정리하는 조건은 일반 검사와 동일하다. 정리 실패나 미확정 생성 응답도 별도 증거로 남긴다. 확인된 새 소유 대상의 정리는 계속할 수 있지만, 이름 추정이나 조회 실패를 이유로 기존 자원을 정리하지 않는다. 고정된 종현 소켓·프로젝트·SQL 계약과 민규 원본 복원 증거의 별도 조건은 유지한다.

## 필요한 회귀 확인

기존 의미 있는 검사에서 변경에 영향받는 경우만 보완한다. 새로운 검증 체계나 전체 재검사를 추가하지 않는다.

| 경우 | 기대 결과 |
|---|---|
| 기존 빈 환경 계약 | 기존 정상·거절 동작 유지 |
| 실제 목록이 있는 새 버전 | 정확한 기준 자료·검토 범위·현재 소스 및 SQL 일치 시 준비 구조만 통과 |
| 실제 목록을 빈 목록으로 바꿈, 항목 누락, 해시 변조 | 거절; 실제 호출 0 |
| 같은 이름으로 컨테이너 재생성, 이미지·설정·소켓 변경 | 거절; 다음 변경 0 |
| 새 대상이 기존 식별자·프로젝트·네트워크·볼륨과 겹침 | 생성 전 거절 |
| 실행 전 또는 실행 후 기존 목록 읽기 실패 | 미확인 기록; 다음 변경 중단 |
| 기존 실행 상태·설정·네트워크 연결·볼륨 연결이 달라짐 | 보존 실패; 성공이나 전체 완료로 집계하지 않음 |
| 생성 응답 유실 또는 일부 생성 | 미확정 유지; 원 영수증과 정확한 조회로 확인된 새 대상만 처리 |
| 새 대상 정리 도중 한 대상 실패 | 실패를 유지하면서 다른 확인된 새 소유 대상 정리; 기존 대상 정리 0 |
| 인증·모델·정산 응답 유실 | 원 요청·예약·미확정 상태 보존; 추가 전송이나 재정산으로 성공 대체 0 |
| 순수 준비 검사 | 도커·인증·SQL 호출 0; 실제 준비 완료·실행 허가 없음 |

## 금지하는 우회와 확정된 담당

실제 기존 목록을 빈 목록으로 기록하지 않는다. 검사 조건을 제거하거나 임시 함수 교체로 우회하지 않는다. 다른 소켓·과거 비공개 입력·기존 데이터로 새 대상을 가장하지 않는다. 기존 컨테이너·네트워크·볼륨의 중지·삭제를 해결책으로 추가하지 않는다. 종현이 작업자·소유권·훅을 변경해 민규 파일을 수정하지 않는다.

사용자는 **① 민규가 두 도구 수정**을 선택했다. 민규가 자기 작업 공간에서 두 도구의 위 계약을 구현·검증하고 종현에게 전달한다. 소유권 재배정은 하지 않는다. 종현은 자기 담당 구현과 이번 원 검증 기록을 보존한다.

현재 두 지원 파일과 소유권은 민규 원본과 종현 clone에서 동일하다. 민규 수정본은 아직 도착하지 않았다. 전달받을 때는 커밋 SHA·정확한 변경 경로·관련 회귀 결과·새 계약 버전을 대조하고, 새 소스 핀과 준비 자료·실제 기존 관찰·새 대상 범위를 다시 묶는다. 이미 받은 VM② 승인 범위에서 실제 연결 검증을 이어간다. 같은 담당 선택이나 VM 승인을 재질문하지 않는다.

이 문서와 아래 복사 문구는 로컬 인계 자료다. 외부 메시지·푸시·운영 적용을 실행한 것은 아니다.
