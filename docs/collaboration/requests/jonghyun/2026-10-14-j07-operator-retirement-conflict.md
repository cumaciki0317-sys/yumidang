# J07 운영 담당 계정 탈퇴와 종결 영수증 보존 충돌 — 2026-10-14

전체 **79%(22/28)** 유지. 정책 선택 전 SQL/권한/탈퇴 조건을 변경하지 않는다. 일반 신고자 탈퇴와 운영 담당자의 탈퇴를 구분한다.

## 현재 소스 근거와 한계

`20261006160000_assigned_report_final_closure.sql`의 `private.assigned_report_final_closures.actor_id`는 NOT NULL·복합 primary key이며 `references auth.users(id)`다. ON DELETE 정책은 생략되어 PostgreSQL 기본 NO ACTION이다. 현재119 migration 파일의 해당 테이블 후속 정의에서 이 관계 제거/변경을 찾지 못했다. 종결 영수증이 남은 운영 담당 Auth 행을 harddelete하면 외래키 제약으로 삭제가 거절될 수 있다. 실제 DB/직원 계정/삭제 명령 재현은0이며 관찰한 운영 장애로 표현하지 않는다.

정책은 일반 회원 탈퇴를 진행 중 확정 동행에서만 막고 신고 자료는 이의 절차 포함 최종 종결+90일에 파기한다. 운영 담당 계정에도 일반 탈퇴를 제공할지, 직원 권한 해제와 Auth 계정 삭제를 별도 관리할지는 현재 정책에서 확정하지 않았다. 영수증 삭제/CASCADE 또는90일 대기를 임의 적용하면 보관·탈퇴 의미가 달라질 수 있다.

기존 직원 Auth 삭제 SQL 시험은 승인/배정/접근 감사 자료의 삭제 경계이며 이 최종 종결 영수증 조건을 포함하지 않는다. 기존 실제 완료/탈퇴 PASS를 이 경우의 증거로 확대하지 않는다. 공개 UUID 영수증을 Git에 가져오거나 실직원 계정을 시험하지 않는다.

## 선택과 추천 설계

추천은 운영 담당 계정도 일반 탈퇴를 허용하되, 직원 권한은 즉시 회수하고 최종 종결 영수증의 최소 담당 식별자·멱등 키·판정 결과를 신고 파기 시점까지 별도로 보존하는 방향이다. Auth FK를 분리할 경우 UUID를 null로 바꾸거나 새 계정과 연결하지 않고 원 영수증/멱등성을 보존해야 한다. 남은 권한·API가 삭제된 Auth ID를 새 접근 권한으로 사용하지 않는지도 함께 검사한다.

대안은 운영 전용 계정을 회원 탈퇴와 별도 관리하는 것이다. 이 경우 별도 계정 종료 절차·책임 담당·안내가 필요하며 단순 FK 오류로 무기한 processing을 남겨서는 안 된다. 어느 안이든 영수증의 원문/식별 범위와90일 파기 정책을 함께 유지한다.

사용자에게 마지막 일괄 질문으로 운영 담당 계정의 탈퇴 허용 여부를 확인한 뒤 상세 migration/경쟁·권한·영수증 보존/파기 설계와 exact 소유권을 확인한다. 민규 검증 도구의 정식 지원·새 native 대상/핀을 갖추기 전 실제 검증은 진행하지 않는다. 이 문서 작성·읽기 검토 외 제품 변경0, 커밋/푸시/외부 메시지0이다.
