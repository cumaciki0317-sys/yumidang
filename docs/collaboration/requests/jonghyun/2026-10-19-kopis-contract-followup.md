# KOPIS 공개 계약 재확인 — 2026-10-19

> 최신 사용자 선택은 [A안·14분류·최근7일 유지](2026-10-19-kopis-expanded-ranking-decision.md)다. 아래 조사 당시의 회신 전 공개 보류 결론은 최신 공개 정책으로 재사용하지 않는다. 공식 자료의 명세 차이 관찰은 보존한다.
작업자: 종현(`jonghyun`). 공식 공개 자료만 읽었다. 인증키 호출·공급사 문의·서버/환경 변경·순위 공개 전환은 하지 않았다.

## 결론

전국 전체 공연 Top 10·뮤지컬 전환, 어제까지 최근 7일이라는 제품 목표와 **공식 순위 공개 보류**를 유지한다. 공개 자료에서 설명을 보완할 수는 있지만, `basedate` 누락의 정상 여부와 API 집계 기간을 입증하는 계약은 해결되지 않았다. 일반 공연 조회를 중단할 이유는 아니다.

## 이번에 확인한 공개 자료

| 항목 | 확인한 사실 | 확정할 수 없는 부분 |
|---|---|---|
| 개발가이드 | 현재 공개 PDF는 v5.0·배포일 2026-04-23이다. 9장 예매상황판 응답 명세에 `basedate`(기준일)와 `rnum`(순위)이 여전히 적혀 있다. | 실제 응답에서 기준일이 빠지는 것이 정상 변경인지 설명하지 않는다. |
| 날짜 요청 | `stdate`·`eddate`가 필수이고 최대 31일로 안내된다. `date`도 필수로 적혀 있으나 같은 장의 요청 예제에는 없다. | 세 날짜 인자의 관계·우선순위와 생략 시 동작이 명확하지 않다. 요청한 날짜를 곧 응답의 검증된 기간으로 표시할 수 없다. |
| 장르·지역 | `catecode`·`area` 필터가 명세에 있다. | 전국 전체·뮤지컬 각각의 최종 정렬, 동률, 잘린 순위 경계 처리 계약은 확인되지 않았다. |
| 공개 집계 안내 | 공식 메인은 예매/취소를 전일까지 반영하고 초대권을 제외한 유료 티켓을 기준으로 하며 보정될 수 있다고 안내한다. 이번 조회에는 최종집계일시 `2026.10.19 00:00`이 표시됐다. | 이 화면의 시각이 `/openApi/restful/boxoffice` 응답의 갱신 완료 시각이라는 보장은 없다. |
| 갱신 시간 | 같은 메인의 공연통계·예매통계 영역은 매일 10시·15시 갱신과 보정 가능성을 안내한다. | 이를 예매상황판 API의 고정 갱신 시각으로 확대하지 않는다. 매일 00:00 갱신도 단일 표시만으로 확정하지 않는다. |
| 이용 조건 | API 안내는 KOPIS 기반 서비스임을 명시하도록 요구하며, 키는 1인 1개·양도/공유 불가이고 호출 제한이 있을 수 있다고 안내한다. | 출처 표기만으로 순위 기준·공식성·모든 이미지 등의 별도 권리까지 확인되는 것은 아니다. 대표 계정으로 바꿀 때 키를 공유하지 말고 공급사 절차를 확인한다. |

## 10월 17일 표본과 이번 확인의 구분

[저장된 API/웹 비교 증거](2026-10-17-provider-evidence.json)는 10월 10~16일 전체·뮤지컬, 10월 3~9일 전체의 세 조합에서 각각 공연 ID와 순위 50/50 일치, `basedate` 누락을 기록한다. 이는 **그날 표본의 대응 결과**다. 이번에는 그 자료를 다시 읽고 공식 공개 명세를 조회했으며 새 인증 API 응답이나 현재 순위 50건을 검증하지 않았다. 주간 웹의 최근 7일 동작 역시 과거 관찰이며 API의 장기 계약으로 승격하지 않는다.

공식 웹 조회는 브라우징 도구로 수행했다. 로컬 Python 직접 접속은 환경 DNS 제한으로 실패했으며, 이를 공급사 장애로 해석하지 않는다.

## 민규 통합 인계와 남은 확인

기존 [문의 초안](2026-10-05-real-environment-validation.md#후속-작업과-kopis-문의-초안)의 다섯 질문을 유지한다. 특히 ① 현행 응답 명세와 `basedate` 생략 정상 여부 ② `date`와 기간 인자의 관계·기간 증명 방법 ③ 전체/뮤지컬 정렬·동률 ④ API 갱신·지연 시 검증 가능한 기준일 ⑤ 출처·기간·공식 순위 표기와 이용 조건의 답이 필요하다. 외부 전송은 하지 않았다.

회신 또는 동등한 공식 계약 근거를 확보한 뒤 두 Top 10을 재검증한다. 보류 중에는 요청 기간을 응답 기간으로 확정하거나 자체 순위로 대체하지 않는다. 공개 웹 표시 시각과 앱 수집 시각은 별도 필드로 남기고, 공연 상세 `updatedate`를 순위 갱신 시각으로 사용하지 않는다.
