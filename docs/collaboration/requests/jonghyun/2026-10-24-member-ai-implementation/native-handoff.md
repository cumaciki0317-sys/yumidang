# Native 인증·세션 연결 준비 인계 — 2026-10-24

작업자: 종현(AI 보조). 기준은 통합 main `efdeba1c2e6e65376a43580889a99b1379ee3d17`과 그 기준에서 진행한 회원·AI 클라이언트 작업 사본이다. 이 문서는 이번에 맡긴 **native 연결 준비의 종료 범위**와 민규에게 필요한 입력을 정리한다. 실제 native 인증 연결이나 새 저장 정책을 확정한 문서가 아니다.

## 현재 확인한 연결과 미연결

- [루트 MemberConnection](../../../../../apps/mobile/src/app/_layout.tsx)은 현재 `Platform.OS === "web" && serviceMode`일 때만 웹 연결을 설치한다.
- [웹 세션 포트](../../../../../apps/mobile/src/web-member-session.ts)는 같은 HTTPS Origin의 `/auth-callback`, 브라우저 탭의 state/verifier와 일회용 교환을 전제로 한다. [가입 계약](../../../../../backend/contracts/signup.md)의 허용 Origin·브라우저 귀속을 native에 그대로 적용하거나 앱에서 Origin을 꾸며 보내지 않는다. 이 challenge를 네이버의 PKCE 지원 증거로 해석하지 않는다.
- [로그인·콜백 화면](../../../../../apps/mobile/src/screens/AuthAiScreens.tsx)의 콜백은 현재 `window.location`을 읽는다. native 포트 미설치 시 준비 안내와 로그인 비활성을 유지한다. 실제 native callback·안전한 앱 복귀/교환 계약은 이번 준비에서 확인되지 않았다.
- 현재 세션은 메모리에서 관리한다. native 재시작 후 세션 유지 여부와 저장/폐기 방법은 인계 후 확인할 사항이다. 이 준비를 근거로 SecureStore·영속 토큰 저장·새 callback API를 추가하지 않는다.

과거 앱 기반 인계의 native 대기와 현재 준비를 구분한다. [23일 요구사항 대조의 기존 미연결 기록](../2026-10-23-ux-implementation/final-requirement-audit.md)도 실제 native 계약 확인을 선행 조건으로 남긴다. 이번 문서는 이를 새 로그인 성공으로 바꾸지 않는다.

## 민규에게 필요한 정확한 입력

다음은 새로운 제품 정책 선택 질문이 아니라 실제 연결 전 필요한 기술 인계다. 값은 확인한 환경과 리비전에 귀속하고, 비밀 키·사용자 토큰·실회원 원문은 문서나 채팅에 붙이지 않는다.

|네이버 등록·허용 경로|등록된 서비스/콜백 URL, 서버 `NAVER_REDIRECT_URI`, 실제 허용 Origin 목록과 native에 적용되는 요청 경계|등록·배포 설정과 정확히 일치한다. 앱 scheme만 추가하거나 웹 Origin을 임의 주입하지 않는다.|
|웹에서 앱으로의 안전한 복귀|승인된 앱 귀속/복귀 경로, 최초 실행과 실행 중 복귀의 전달 방식, 앱이 받아도 되는 필드와 거절할 필드|앱 귀속을 확인하며 링크·주소창 이력·분석 로그에 사용자 access/refresh token을 담지 않는다.|

## 이번 준비의 검사와 종료 기준

기존 포트와 세션 경계를 재사용하며 다음 회귀를 유지한다. 관련 코드를 바꾼 통합본에서 검사하고, 이전 기록을 오늘의 새 실행 결과로 복사하지 않는다.

1. [client-auth-connection.test.mjs](../../../../../tests/mobile/client-auth-connection.test.mjs): 포트 교체/폐기, StrictMode 단일 교환, 같은 tick 이탈 시 요청0, 이탈 후 늦은 성공/실패 거절, 초기 null 복원과 진행 중 콜백의 경합, 가입 상태별 이동, native 미설치 안내·버튼 비활성.
2. [mobile-session.test.ts](../../../../../tests/functions/jonghyun/mobile-session.test.ts)·[mobile-web-session.test.ts](../../../../../tests/functions/jonghyun/mobile-web-session.test.ts): 내부 복귀 경로, 검증 세션/가입 DTO, 다른 Origin/콜백/state·만료/재사용 거절, 메모리 세션 수명과 계정 변경 후 늦은 응답 거절.
3. [member-access-retirement.test.mjs](../../../../../tests/mobile/member-access-retirement.test.mjs): 권한 회수 후 늦은 읽음 ACK/관측 무효화, 포트/계정 교체, Guard 밖의 최소 영수증·동일 ID 수동 재확인, 서버 종료 실패와 기기 정리 실패 구분. 이것은 실제 native 로그인 검사가 아니다.

통합 담당이 전달한 실행 결과는 API 관련 합성 회귀53건과 client-auth-connection30건 통과다. 이 문서 작성 lane에는 그 통합 원 실행 로그를 보관하지 않았으므로 **통합 담당의 실행 결과 전달**로만 표기하며, 이 문서의 독립 재실행 결과나 native 인증 성공으로 사용하지 않는다. 최종 통합 검증 기록이 확보되면 그 환경·명령·로그를 직접 연결한다.

이번 native 준비는 **기존 계약/포트·회귀 목록과 인계 입력·미확인 조건을 정리한 상태**에서 끝난다. native 실제 어댑터, callback 수신, 영속 세션 저장 선택·구현, 네이버 실로그인·사진 저장 완주·독립 APK/AAB·운영 활성화는 완료 조건에 포함하지 않는다. WBS3.1·3.2a/b 전체 완료나 BE 연동 대기 해제를 의미하지 않는다.

## 인계 후 실제 연결의 종료 조건

- 민규가 위 입력을 실제 계약·환경·실패 응답 예시와 함께 제공하고 종현이 기존 포트와의 차이를 확인한다. 차이가 없다는 추정만으로 새 native 포트를 설치하지 않는다.
- 종현이 허용된 경로에서 실제 계약 소비를 구현한 뒤 취소·만료·중복/재사용·응답 유실·계정/포트 교체·앱 복귀를 해당 환경에서 검증한다. 세션/저장 정책 선택이 필요한 차이는 구현 전에 사용자에게 묻는다.
- 실제 가입 상태·사진/신고 Storage·읽음·탈퇴 포트를 범위별로 확인하고, 미연결 포트와 합성 통과를 실제 서버 성공으로 표현하지 않는다.
- 실제 네이버·회원 검증은 HOLD의 명시 재개와 대상/환경 확인 이후 별도 수행한다. 독립 설치본과 운영 배포·스토어·추가 지출은 각각 기존 실행 조건을 유지한다.

이 문서 작성으로 서버·공통 정책·기기 설정·계정·등록 URL을 변경하지 않았다. 새 인증 연결·SecureStore 설치·실회원·외부 모델 호출·커밋·푸시·배포는 수행하지 않았다.
