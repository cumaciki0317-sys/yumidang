# 화면 연결 계약 — AI 탐색·장소·행사·후기 요약

현재 요구는 [정책.md](../../../../정책.md), 화면 흐름은 [IA](../../../planning/design/IA.md)·[USER_FLOW](../../../planning/design/USER_FLOW.md)를 따른다. 아래 API 이름·응답 모양은 기존 연결 계약이며 최신 정책에 맞춘 코드 적용·실제 서버·브라우저 검증은 별도다. [9월 30일 통합 인계](2026-09-30-jonghyun-integration-handoff.md)의 로컬 성공을 새 정책 전체의 구현 완료로 확대하지 않는다.

공통 envelope는 `{data, requestId}` / `{error:{code,message,retryable}, requestId}`이고 헤더 `X-Request-Id`와 연결한다. 실제 경로 등록·허용 목록·환경 준비는 [R1~R7](2026-09-29-claude-minkyu-requests.md)을 확인한다.

## 1. AI 탐색 — `POST /functions/v1/ai-chat`

회원 기능이다. 현재 가입·로그인은 네이버만 사용한다. 실제 회원 원문 외부 전송은 보관 조건 검토·사용자 확인 전 보류하며 합성 데이터만 평가한다. 기능 비활성·미준비를 검색 0건으로 표현하지 않는다.

기존 요청 본문 계약은 세 필드다. 서버의 허용 필드·제한값은 연결 시 확인한다.

```json
{ "clientRequestId": "화면에서 만든 1~128자", "messages": [{"role":"user","content":"이번 주말 조용하게 전시 볼 사람"}],
  "currentFilters": {"target":"posts"} }
```

- 현재 탐색의 `messages`만 화면 메모리에 유지하고 탐색 종료·새 탐색·로그아웃 시 정리한다. 서버 이력·원문 로그로 보내지 않는다.
- 자연어 조건, 실제 카드, 근거 있는 추천 이유·주의점을 제공하는 방향이다. 기존 `explanations: []` 구현 상태를 최종 화면 정책으로 굳히지 않는다. 설명 품질과 실제 공개 조건 검토가 먼저다.
- 입력 개인정보 발견 시 전송을 멈추고 수정 안내, 출력 발견 시 숨김·재시도 안내를 제공한다. 정상 공개 장소·시설 주소와 개인의 비공개 만남 정보를 구분한다.
- 첫 AI 이용 직전 전송 항목·목적·공급사·서버 미저장·확인된 외부 보관 조건·거절 방법을 안내하고 확인받는다. 이후 재열람·조건 변경 재안내를 제공한다.
- 401은 로그인 안내, 기존 본문 초과 413·입력 오류 400은 입력 유지와 함께 처리한다. 실제 응답과 브라우저 연결은 별도 확인한다.

| 기존 status | 연결 시 지킬 의미 |
|---|---|
| `results` | 실제 카드만 표시하고 공고 등록일 최신순 기본/시작일 빠른순 선택을 유지한다. |
| `no_results` | 실제 검색 결과 0건일 때만 사용하고 적용 조건·조건 변경 안내를 제공한다. |
| `needs_clarification` | 조건의 결합·대상 등이 모호할 때 확인 질문을 표시한다. |
| `results` + `partial:true` | 기존 구현의 부분 결과 형식이다. 반환 직전 최신 상태 재확인·부분 결과·실패 처리 세부 동작은 팀 검토이므로 이 형식을 최신 확정 정책으로 간주하지 않는다. |
| `unavailable` | 미준비·실패·보류를 성공 또는 0건으로 바꾸지 않는다. 재시도·일반 탐색 복귀의 세부 동작은 팀 검토 결과와 연결한다. |

`interpretedFilters`는 사용자가 확인·수정할 조건이다. `authorAge`는 작성자 **만 19~99세 최소·최대 직접 입력**이며 전체는 상한을 제한하지 않는다. 비로그인의 나이 필터는 전체만 사용한다. 관심사·대화 방식 형식은 `{values:[{text,polarity:"include"|"exclude"}], combine?:"any"|"all"}`이며 등록값 의미 유사성으로 판단한다. MBTI는 정확 일치, 미등록은 `needs_check`/‘확인 필요’다. 실패나 불일치를 미등록으로 바꾸지 않는다.

카드 기본 필드는 `kind, id, title, locationLabel, startsAtOrDate, endsAtOrDate, costLabel, state, canApply`다. 공고 공개 지역은 동까지이며 현재 동행은 무료만이다. 비로그인은 별칭, 로그인 미확정 상대는 마스킹, 확정 당사자만 전체 이름·정확한 주소를 본다. 유사도 점수·추정 성격·비공개 정보를 만들지 않는다.

행사는 `kind:"event"`, 제공처 `sourceName`과 확인된 공식 `sourceUrl`을 사용한다. 공식 링크가 없으면 `null`로 링크 없이 출처만 표시한다. 행사는 공고가 아니므로 `canApply:false`이며 입장료 미확인을 무료로 표시하지 않는다.

## 2. 가입·성향 편집(S06·S15-2)

사진은 필수, 관심사·대화 방식·MBTI는 선택이다. 관심사·대화 방식은 각각 최대 20개·값 40자이며 중복을 막고 저장 실패 시 입력을 유지한다. 공개 프로필 S14 응답의 권한 있는 회원에게만 성향을 추가한다. 네이버 이름·성별·생일·출생연도 필수와 가입 자격 확인은 별도 서버 계약이다. 이전 PASS·문자 가입이나 현재 이메일 인증 배지를 화면에 추가하지 않는다.

기존 `set_my_profile_traits` 제안 SQL과 HTTP 저장 경로의 채택·연결 여부를 확인하고 실제 저장·재조회·접근 권한을 검증한다. 문서 갱신만으로 연결 완료를 표시하지 않는다.

## 3. 장소 검색 — `GET /functions/v1/places?query=…&page=1`

회원용 Kakao 장소 검색과 프론트의 Kakao 우편번호 선택창은 별도다. 기존 응답은 `{status:"results"|"no_results", places:[{source:"kakao", sourceId, placeName, address|null, roadAddress|null}], nextPage:number|null}`다. 주변·반경·거리순은 제공하지 않는다. 입력 400·인증 401·공급사 503을 처리하고 작성 입력을 보존한다. 함수 등록·`PLACES_PAGE_SIZE` 설정·실제 호출은 각각 확인한다.

## 4. 행사 목록과 공식 Top 10

공개 `GET /events` 경로의 실제 등록을 확인한다. 기존 `mode=overlapping|new_this_week|post_selection`, 날짜 범위·키워드·지역·유형·커서·limit 계약은 아래 정책에 맞게 연결한다. 기존 이름 `ongoingOnly`를 ‘지금 진행 중만’ 필터로 화면에 그대로 노출하지 않는다.

- 기본은 이번 주 새로 시작한 행사, 선택하면 기간과 겹치는 진행 중 장기 행사도 포함한다. 주간 경계는 한국 시간 월요일 00:00~다음 월요일 00:00 미만이다.
- 작성용 선택은 진행 중·예정 행사이며 기존 입력·동행 일정을 유지한다. 과거 행사는 조회 가능하지만 새 동행 모집 대상으로 안내하지 않는다. 취소는 새 조회·선택에서 숨긴다.
- 진행 중→예정→종료 순이고 각 그룹은 최근 시작/빠른 시작/최근 종료순이다. 필터 0건이라고 입력 조건을 초기화하지 않는다.
- KOPIS·TourAPI를 연결하고 서울은 연결 조건·연결 여부 모두 팀 검토다. 지역·유형은 제공처 원문값을 사용한다. 날짜/시각 정확도와 입장료·동행 비용을 구분한다.
- **전국 전체 공연 공식 Top 10 기본/뮤지컬 전환**, **어제까지 최근 7일·매일 갱신** 영역을 일반 목록과 별도로 제공한다. 출처·집계 기간·갱신 시각을 표시한다. 실제 KOPIS 순위 API 연결·지표·기간·장르 응답을 검증하며 가상 순위를 넣지 않는다. 순위 내 종료·취소 항목 표시·선택 세부는 후속 확인이다.

## 5. 개인 완료·후기·요약

예상 종료 후 본인의 완료 확인으로 먼저 후기를 작성할 수 있다. 실제 동행 완료는 양쪽 확인 또는 예상 종료+24시간 자동 완료이며 취소·불발·분쟁은 자동 완료에서 제외한다. 완료 전 먼저 쓴 후기는 비공개다. 실제 완료일부터 7일 작성 기한, 양쪽 후기+실제 완료 시 즉시 공개, 한쪽은 실제 완료+24시간 공개다. 당도는 상대 후기 열람 가능 시점, 완료 횟수는 실제 완료 즉시 반영한다. 계산식은 팀 검토다.

경험 3단계·별점 1~5 필수, 한마디 선택, 긍정 평가의 칭찬 최대 3개, 제출 후 수정 불가를 연결한다. 제출 후 재조회·시간 경과 공개·기존 화면 갱신은 별도 검증한다. 신고 접수만으로 숨기지 않으며 운영자 비공개 조치는 AI 요약 갱신과 함께 처리한다.

AI 요약은 한마디 있는 공개 후기 3개 이상이며 원문 텍스트 수·갱신 시각을 표시한다. 원문 변경·비공개 시 요약을 숨기고 다시 처리한다. 생성 대기·실패에도 원문 후기와 칭찬 차트를 제공한다. 실제 회원 원문 전송과 생성 요약 공개는 보관·품질 기준 검토 전 승인되지 않았다.

## 6. 연결 확인

새 정책 적용 코드와 DB를 확인한 뒤 네이버 인증·접근 권한, AI 보류/입출력 개인정보 처리, 성향 확인 필요, 대화 정리, 행사 세 모드·순위, 개인 완료와 실제 완료 구분, 후기 시각·프로필 반영을 브라우저에서 검증한다. gateway CORS·운영 함수 등록과 실제 공급사 결과는 별도 증거를 남긴다. 이번 문서 수정에서 런타임·브라우저 검증은 수행하지 않았다.
