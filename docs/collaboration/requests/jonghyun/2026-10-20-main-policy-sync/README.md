## 확정 내용과 이번 변경

- 일반 신고 책임자는 대표 조유미, 대표 부재 시 대체 담당은 종현이다. 대체 범위는 일반 신고 처리와 해당 신고의 허용된 제출 증거 확인이다. 다른 운영 업무의 대체 지정이나 실제 DB·Storage 권한 부여로 확대하지 않는다. 역할별 최소 권한·접근 감사·파기 및 운영 검증은 별도다.
- 일반 신고의 본인 숨김은 범위·수명·해제 정책과 클라이언트 구현이 승인됐다. 정책 HOLD·제공 여부 재결정 문구를 제거했다. 서버 처리 성공 확인 후 표시/이동/갱신, 필수 약속 관리 접근과 실제 통합·운영 검증은 후속이다. 이번 문서 수정이 화면·서버 구현 또는 운영 검증을 실행한 것은 아니다.
- KOPIS는 이미 확정한 A안·14분류·어제까지 최근7일·분류별 공식 사이트 대조 조건을 현재 담당 대응표에 보완한다. 원 WBS 인용과 과거 API·파서 관찰은 바꾸지 않는다.
- 후기 AI 가입 선택3종·전체 동의·기본 미선택·독립 철회와 AI 탐색 첫 사용 동의·거절 시 일반 검색 유지를 QA 표에 연결한다. 새 정책 선택을 요청한 것이 아니라 이미 확정한 내용의 대응표 누락을 고친다.

## 이전 PASS가 뜻하는 것

예전 검사 PASS는 그때의 종현 브랜치와 검사 범위에서 원장 참조, 문서 SHA, 사용자 작성본 보존, 새 문서 링크 등이 맞았다는 뜻이다. 제품 전체 기능이나 실제 회원·운영·기기 PASS를 뜻하지 않았다.

예를 들어 그때 `event-storage.md`의 내용이 A였고 원장도 A의 SHA를 저장했다면 검사 PASS는 적절하다. main 통합에서 민규의 페이지 재개 문단 B가 추가되면 현재 문서는 A+B가 된다. 오래된 SHA와 다르다는 이유만으로 B가 잘못됐다고 할 수 없고, 예전 PASS로 A+B를 검사했다고 할 수도 없다.

또한 그 검사는 ‘이번 작업은 문서만 변경한다’는 제한을 검사한다. main에는 별도로 승인된 민규 제품 코드도 통합돼 있으므로 이 옛 검사를 main 전체에 그대로 실행하면 제품 소스 변경을 거절한다. 그것은 이 검사의 적용 범위가 다르다는 뜻이며, 해당 코드가 기능 검사에 실패했다는 판정이 아니다.

이번에는 옛 원장·선택 원본·영수증과 `validation.json`의 PASS를 그대로 보존하고, 옛 README와 HTML에 통합 전 기록임을 표시했다. 현재 문서와 역할 결정은 정책.md와 이 별도 main 문서 검증을 따른다. 과거 실제/합성 PASS와 실패·NOT_RUN은 당시 대상·커밋 범위로만 인정한다.

## 이번 검증의 범위

[문서별 변경·해시](document-manifest.json)와 [검증 결과](validation.json)는 현재 main 기준 커밋에 적용한 문서 변경을 검사한다. 판정 대상은 문서의 최신 역할·정책 연결, 수정 경로·정상 소유권 검사, JSON/HTML 데이터, 사용자 원본 및 과거 영수증 보존, 변경된 Markdown 링크다.

이 검증 PASS도 제품 코드·DB·서버 통합·실회원·기기·공급사 호출·운영·배포·출시 PASS를 뜻하지 않는다. 이번에는 이 실행들을 하지 않았다. 기존 통합 검증 기록은 그 기록의 커밋·환경 범위로 보존한다.

공유 main clone의 actor·hook·소유권 정책은 변경하지 않았다. 원래 owner별 독립 clone에서 검사·수정한 문서 패치만 현재 폴더에 반영한다. 이는 실제 팀원 사람이 작업했다는 기록이 아니다. 문서 검증은 커밋·푸시 전 작업 사본에서 수행했다. 이후 사용자가 main 커밋·푸시를 명시 승인했다. 원래 owner별 정상 검사·hook으로 만든 문서 커밋을 main에 통합하며, 실제 반영 결과는 Git 이력과 원격 main의 커밋 일치로 확인한다.
