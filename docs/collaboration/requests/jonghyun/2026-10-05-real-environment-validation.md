검증 시작2026-10-05·최신 소진 측정2026-10-06 한국시간. 작업자 `jonghyun`, 별도 clone의 `jonghyun/queue-integration`.

최신 소진 결과는 문서 마지막 절을 따른다. 아래 초기 준비·중단 기록은 당시 상태이며 현재의 미실행 상태를 뜻하지 않는다.

## 초기 실제 AI 호출 — 대표 계정2회

사용자가 무료·기존 이용량 사용 가능을 확인한 뒤, 기존 공급사 어댑터와 고정 합성 사례 `pm-synonym`, `rs-basic`만 사용했다. 회원 원문과 회원 DB를 사용하지 않았다.

- 성향 비교: 실제 응답 약 2.9초, JSON 형식과 조건 충족 판단 검사 통과.
- 후기 요약: 실제 응답 약 3.6초, 주장 3개·근거 ID·길이 조건 검사 통과.
- 공급사는 두 응답 모두 사용량을 반환하지 않았다. 기술 예약 3,647단위는 유지했으며 실제 토큰·청구금액으로 표시하지 않는다.
- 설정 모델은 `potens.claude-5-sonnet`이지만 실제 사용 모델을 응답에서 독립 확인하지 못했다. 요청 출력800은 공급사에서 강제되는 상한으로 검증되지 않았다.

최초 제한 환경의 DNS ENOTFOUND와 실제 네트워크 허용 실행의 성공을 구분한다. 자동 재시도나 실제 회원 원문 전송, 운영 활성화는 하지 않았다. 공급사 보관·삭제·로그 조건과 회원 전송 보류는 유지한다.

## 공개 행사·장소 공급사

실제 공식 HTTPS GET은 총11회(Kakao1·KOPIS6·TourAPI4)다. 별도 제한 환경 DNS 실패4시도에는 HTTP 응답이 없었다. 키·요청 URL·외부 원문은 로그에 출력하지 않았으며 DB 쓰기는 없었다.

- Kakao: 장소 검색 HTTP200과 공개 후보 정규화 통과.
- KOPIS: 공연 목록·목록에서 받은 실제 ID의 상세 HTTP200과 정규화 통과.
- TourAPI: 행사 목록·실제 ID의 common/intro 상세 HTTP200과 정규화 통과.
- KOPIS 순위: 순위50개를 실제 수신했다. 순위 번호·공연 ID·공연 기간 형식·필수 항목은 정상이지만 집계 기간 `basedate`는 없다. 태그 공백·속성·CDATA·BOM 등의 변형까지 확인했다. 빈 순위나 자체 추정 결과로 해석하지 않는다.

[공식 KOPIS 개발가이드](https://kopis.or.kr/upload/openApi/%EA%B3%B5%EC%97%B0%EC%98%88%EC%88%A0%ED%86%B5%ED%95%A9%EC%A0%84%EC%82%B0%EB%A7%9DOpenAPI%EA%B0%9C%EB%B0%9C%EA%B0%80%EC%9D%B4%EB%93%9C.pdf) v5는 `basedate`를 응답 항목으로 명시한다. 실제 응답과 달라 최근7일 기간 검증이 실패했다. 사용자는 **순위 보류·공급사 확인 과제로 남김**을 확정했다. 요청 기간을 검증된 응답 기간으로 바꾸지 않았다. 뮤지컬 순위는 미실행이다.

재실행 도구: `tests/integration/jonghyun/public-providers-live.ts`. 명시 실행 옵션과 키 JSON stdin을 요구하며 기본 실행은 외부 호출하지 않는다. 진단 원문은 메모리에서만 분석하고 종료 시 해제했다. 서울 평문 HTTP 수집 보류는 유지한다.

## Android 실제 실행과 수정

기존 `CarePlus_API35` AVD를 초기화하지 않고 부팅했다. 공식 Expo Go57.0.9를 새로 설치했으며 기존 별도 유미당 앱을 실행하거나 삭제하지 않았다.

독립 9개 검사는 **Expo Go 종료 → Go Launcher 시작 → 프로젝트 열기 → 종료 후 다시 열기**의 경로다. 화면 표시, 비로그인 안내·정보 보호, 사진 없는 예시 가입 차단과 해당 검사 프로세스의 JS·Android 치명 오류 여부를 확인했다. 단일 주소로 Expo Go를 완전히 종료한 상태에서 직접 여는 경로는 실패로 남긴다. 이를 제품 standalone 앱의 콜드 실행 통과로 표현하지 않는다.

상단 안내 배너가 상태 표시줄과 겹치는 결함을 발견했다. `_layout.tsx`에서 배너만 top SafeAreaView로 감쌌다. 실제 상태 표시줄 하단74px·배너 글자 상단154px와 수정 화면으로 해결을 확인했다.

실제 사진 변환에서는 Hermes의 `AbortSignal.throwIfAborted` 미지원 오류를 발견했다. `api.ts`의 기본 취소 확인·컨트롤러/리스너/타이머 해제 도구를 공유해 회원 API·사진·웹 세션의 직접 호출을 교체했다. 전역 polyfill은 추가하지 않았다. 관련59개 검사와 앱 전체 타입·린트 통과.

실제 Hermes에서 TextEncoder·URL 제공을 확인했다. MemberService.preferences → ServiceApiClient의 한국어 POST·합성 JWT·네필드 본문·DTO 복귀와 취소 후 늦은 응답 CANCELLED 거절을 확인했다. 응답은 메모리 fetch이며 원격 회원 API 호출0이다. 증거는 `/private/tmp/yumidang-android-api-result.xml`과 PNG다.

수정 후 실제 Android에서 고정 합성 PNG149바이트·64×48 → JPEG780바이트 변환, MIME·JPEG magic·EXIF 없음, Expo native decoder 재디코딩64×48과 제품과 같은 React Native Image의 data URI 표시(onLoad·빨간 사각형)를 확인했다. 최초 시험의 고정 선택 좌표·임시 라우트 import·시험 코드의 바이트 배열 전개·Image.getSize 검사 실패는 각각 시험 준비 오류로 구분했다. 합성 파일을 식별하지 못한 사진 선택 시도는 성공 증거에서 제외했으며 이후 고정 합성 data URI만 사용했다. 외부·서버 이미지 전송과 원문 증거 저장은 하지 않았다. 선택 파일을 확인하지 못한 초기 시도에서 SDK가 기기 임시 캐시를 생성했을 가능성은 배제하지 않으며, 미저장으로 단정하지 않는다.

증거: `/private/tmp/yumidang-android-runtime/result.json`, 같은 폴더의 화면 PNG/XML, `/private/tmp/yumidang-android-codec-result.xml`과 PNG. 검사 도구는 `tests/integration/jonghyun/android-runtime-validation.mjs`다. 테스트 라우트는 임시 복제본에만 있고 제품에 포함하지 않는다.

Expo Go native TaskManager 계층의 `ExpoHeadlessAppLoader` 생성자 예외는 별도 관찰했다. foreground 검사 성공을 background 기능 검증으로 확대하지 않는다. SDK 자체 수정이나 기존 앱 데이터 초기화로 숨기지 않았다.

## iPhone 실기기 직접 관찰

사용자가 Mac·iPhone의 같은 Expo 계정 로그인과 QR 진입을 완료했다. [공식 Expo Go57 안내](https://expo.dev/changelog/expo-go-57-login)의 동일 계정 조건을 확인했다. root는 접근성 권한을 확인하고 미러링 창 ID로 해당 창만 캡처했다. 초기 좌표/입력이 반영되지 않은 시도는 제외했으며 현재 창 좌표와 실제 마우스 입력을 사용해 다음 흐름을 직접 확인했다.

- 홈·둘러보기·채팅·마이페이지 이동. 채팅·마이페이지의 비로그인 안내.
- 공고 카드 → 상세 → 뒤로 이동. 중립 작성자 자리표시자, 공개 지역은 동까지, 정확한 주소·상세 만남 지점 비노출.
- 필터 열기 → 전시 선택 → 적용2건 → 결과2건·조건 표시. 검사 후 초기화·홈 복귀.
- 상태 표시줄 아래 안내 배너 표시. 상단 영역이 겹치지 않음.

증거: `/private/tmp/yumidang-iphone-home.png`, `yumidang-iphone-explore.png`, `yumidang-iphone-chat-after.png`, `yumidang-iphone-me.png`, `yumidang-iphone-post.png`, `yumidang-iphone-filters.png`, `yumidang-iphone-filter-selected.png`, `yumidang-iphone-filter-applied.png`.

실제 iPhone·Expo Go의 **예시 모드 화면 관찰**이다. 회원 Auth/DB/Storage, native 로그·배포 앱·스토어 검증은 아니다. 사진 인코더는 별도 합성 자료로 실제 기기 검사했다. iPhone의 기존 사진·회원 정보를 시험 자료로 사용하지 않았다.

iPhone 사진 검사용 임시8083 프로젝트의 최초 ExpoAsset 초기화 오류는 임시 의존성을 실제 복사본으로 바꾸고 캐시를 비운 뒤 앱을 새로 열어 해결했다. 제품 의존성·공통 설정은 변경하지 않았다. 실제 iOS26.6.2 Hermes에서 회원 SDK 한국어 요청·DTO 복귀·취소 후 늦은 응답 거절 PASS, 원격 호출0을 확인했다(`/private/tmp/yumidang-iphone-sdk-result.png`).

실제 iOS 사진 변환은 합성 PNG149바이트·64×48에서 JPEG901바이트를 만들었으나 APP1(length140)·APP13(length56)이 남아 기존 안전 검사가 INVALID_PHOTO로 거절했다. `/private/tmp/yumidang-iphone-codec-diagnostic.png`에 구조만 기록했다. Expo 재인코딩 출력의 구조를 검사한 뒤 APP1·APP13·주석만 제거하도록 수정했다. JPEG 화소·색상 구간은 유지하며 불완전한 JPEG는 거절한다. 작은 이미지를 재시도 때 확대하던 동작도 제거했다. 새 회귀 검사 포함61개와 타입·린트 통과. 실제 iPhone에서 JPEG701바이트·image/jpeg·64×48·메타데이터 검사 통과와 data URI Image 표시 PASS를 확인했다(`/private/tmp/yumidang-iphone-codec-fixed.png`). 동일 수정 후 Android35에서도 JPEG780바이트·64×48·메타데이터 검사와 실제 Image 표시 PASS를 확인했다(`/private/tmp/yumidang-android-codec-final.xml`과 PNG).

## 후속 작업과 KOPIS 문의 초안

사용자 최신 답변: KOPIS 아직 문의하지 않음·문의문 준비 승인. AI 문의는 개인정보 처리 조건만 보냈으며 답변 대기. 사용량·비용·출력 제한의 실제 호출 추정 가능 여부를 질문했고 아직 비용 정책 변경을 확정하지 않았다. Android 내부 설치 APK 검증 승인, Apple Developer 계정 생성은 추후 보류.
