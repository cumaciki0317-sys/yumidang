1. 이번 설계의 결론

첫 구현 단위는 공개 검색 정책·v2 연결 동기화다. 그다음 장소·행사 → AI 탐색 → 후기 요약·예약 처리 → 실제 통합 검증으로 이어간다. 이미 있는 순수 코어와 가상 검사를 활용하고, 새 계약과 맞지 않는 부분 및 실제 연결 경계만 보완한다.

현재 요청으로 수행한 것은 읽기 검토와 이 설계·질문 HTML 작성이다. 코드·DB·환경·Git 이력은 변경하지 않는다. 마지막 질문의 답변은 설계 선택 기록이며, 구현·유료 호출·원격 변경·배포 지시를 대신하지 않는다. 미응답은 미확정으로 남긴다.

5. 첫 작업 단위: 공개 검색 v2 상세 설계

입력과 공개 카드

PostSort 타입과 sort 입력을 추가하고 기본은 created_desc로 정규화한다. 익명 제한은 authorAge가 all이 아닌 경우에만 적용한다. 잘못된 기간·타입·알 수 없는 필터·limit 거절은 유지한다. SQL의 nullable 선택 필드와 내부 생략 값은 어댑터에서 일관되게 변환한다.

DB publicArea를 잘라내지 않는다. 동을 막는 시군구 전용 검사를 교체하고 동·읍·면·종로1가 등 저장된 정상 공개 지역도 검증한다. 정확한 주소를 공개 지역으로 자동 분해하는 기능은 추가하지 않는다. 필드 허용 목록·실명 원본/주소/상세 지점 부가 필드 거절은 유지한다.

정렬과 두 저장소 경로

실제 RPC 페이지 경로는 DB 순서를 그대로 보존한다. 가상 전체행 경로는 기간을 겹침 필터로만 사용하고, created_desc는 등록 시각 내림차순·starts_asc는 시작 시각 오름차순, 동률은 둘 다 ID 오름차순으로 맞춘다. 기간 안 시작·모집 여부를 선택 정렬보다 먼저 적용하던 규칙은 제거한다.

기존 가상 전체행 저장소의 나이 필터·커서 미지원은 그대로 명시한다. 여러 페이지 검사는 페이지 주입 저장소와 RPC 어댑터에서 수행하며, 전체행 helper 결과로 실제 DB 페이지가 검증됐다고 쓰지 않는다.

커서와 RPC

RPC 이름은 이미 search_public_posts_v2다. p_filters.sort를 전달하고 SQL 커서는 정확히 {sortAt,id}로 바꾼다. 외부 커서는 기술 제안으로 버전 2를 사용하며 정규화한 전체 필터와 sort를 함께 묶는다. 이전 버전·필터/정렬 불일치에는 INVALID_CURSOR를 반환한다. 화면은 조건 변경 시 커서를 버리고 첫 페이지를 요청하며, 서버가 임의로 오류를 1페이지 성공으로 바꾸지 않는다.

시각은 PostgreSQL 마이크로초를 유지한다. starts_asc는 마지막 카드 startsAt과 커서 시각을 비교할 수 있다. created_desc의 등록 시각은 공개 카드에 없으므로 마지막 startsAt과 비교하지 않는다. 마지막 ID·시각 형식/정밀도·커서 진행 여부를 검사하고 실제 등록일 정렬은 DB 통합 검사로 검증한다. 이 검사를 위해 공개 카드에 createdAt을 새로 넣지 않는다.

커서는 권한 증거나 조회 시점 고정 장치가 아니다. 페이지마다 인증·필터를 재검사하며, 정적 자료의 중복·누락 없음과 조회 중 데이터 변경을 고정하는 보장은 구분한다. RPC 실패는 빈 결과·가상 응답·구형 RPC로 대체하지 않는다.

검색 연결 계약

민규 GET 진입점 → requireOptionalPrincipal → createPublicClient 또는 검증 JWT의 createUserClient → 종현 searchPublicPosts / RPC repository → 공통 HTTP 응답 순서다. 헤더가 없는 경우만 익명이며 잘못된 인증은 거절한다. caller/userId를 외부 입력으로 신뢰하거나 service-role로 일반 검색을 대신하지 않는다.

입력·커서 오류는 INVALID_REQUEST, 익명 상세 나이 요청은 AUTH_REQUIRED, DB/응답 오류는 안전한 공통 오류로 연결한다. RPC 원문 오류·검색어·주소·대화 본문을 로그에 남기지 않는다. 공고 생성 POST의 기존 회원 인증은 유지한다. 종현은 새 GET이나 중복 검색 코어를 만들지 않고 민규에게 계약을 넘긴다.

모두 actor=jonghyun이다. 총괄이 먼저 입력·커서 변경 계약을 고정한 뒤 A/B/C가 각 파일만 편집한다. C는 확정 정책을 기준으로 검사를 작성하고 A/B의 구현을 그대로 복제하지 않는다. 의존 타입이 바뀌기 전 B는 변환 설계, C는 사례 정리를 할 수 있다. 범위 추가가 필요하면 겹침·소유권을 확인해 새 작업 단위로 기록한다.

편집 전 check_ownership.py --actor jonghyun --paths로 담당을 검사한다. 총괄은 baseline 대비 변경·미추적 파일을 정확한 허용 목록과 비교하고 담당 중복 0 및 민규 파일 보존을 확인한다. 기존 check_harness.py는 민규만 허용하므로 종현 하네스 검증 도구라고 안내하지 않는다. 커밋을 요청받은 경우에만 --staged 검사 후 종현 브랜치 범위로 처리한다.

Q3에서 AI 자연어 필터를 첫 단위에 함께 넣기로 하면 contracts/ai.ts, chatbot/intent.ts·prompts.ts·tools.ts, 관련 AI 검사와 문서의 영향을 먼저 확인하고 별도 확장 하네스를 만든다. 질문 응답 없이 위 기본 검색 목록을 넓히지 않는다. SQL·인증·공통 DB·GET·최상위 문서는 민규 소유다.
