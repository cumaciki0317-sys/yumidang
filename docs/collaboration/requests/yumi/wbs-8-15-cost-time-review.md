실제 사람이 작업한 시간을 측정하지 않았다. Codex 응답/도구 실행 시간을 유미의 제작 공수로 바꾸지 않는다. 이번 문서의 회의 시간 제안도 제작 시간 실측이 아니다.

3. 수정 이유·재출력·완료/보류를 남긴다. 중단 시간을 공수로 채우거나 총 경과시간을 유미 작업시간으로 바꾸지 않는다.

## 4. 계산·승인·중단의 검토 기준

- 확인된 비용은 같은 통화·세금/기간·포함/초과 조건으로 맞춘 경우에만 합산한다. 미확인이 있으면 알려진 부분합과 빠진 항목을 구분하고 총예산은 산출 불가로 둔다.
- 사용량 비용은 실제 과금 단위와 확인된 요율·포함/초과 조건을 대조한다. 호출/토큰/초/장을 섞거나 가격표를 실제 청구액으로 표현하지 않는다.
- 제작량은 작업 가능 시간·단계별 실측·반려/대기·권리 확인을 확보한 뒤 검토한다. 지금 주당 제작 수·소요시간 범위·비용 상한을 새로 정하지 않는다.
- 기존 추가 결제 금지와 별도 지출 승인 경계를 유지한다. 필요한 지출이 생기면 목적·대체안·금액/통화·주기/갱신·허용 범위·권리/개인정보 조건을 먼저 제시한다.
- 지출 처리는 기존 8.27에서 추적할 후보이며 새 원장 담당·구매 승인권자·갱신 일정을 문서가 자동 지정하지 않는다. 실제 금액·범위와 승인 기록이 있어야 집행을 검토한다.
- 권리 불명·필요 개인정보 처리 근거 불명·요금/초과 조건 미확인·승인 범위 초과면 해당 구매/생성/공개를 보류한다. ‘무료’ 대안도 사용 조건을 확인한다.

## 5. 지금의 운영 준비안과 협의

이번 주말에는 이미 승인한 문서·글·대본·검수표를 먼저 준비한다. 새 서비스 구매·호출·회원 자료 전송 없이 진행하되 현재 도구 이용 비용을 0원으로 표시하지 않는다. 미디어 제작량·제작 도구·월 운영 예산은 자료가 확보된 뒤 유미가 판단한다.

주말 이후 확인할 후보: 유미는 보유 도구·개인 작업 가능 시간, 종현은 템플릿/앱·빌드 준비에서 확인 가능한 작업 단계, 민규는 서버/공급사 청구·사용량/한도 근거다. 이번에 연락·주당 시간 약속·회계 실무 담당 지정을 하지 않는다. 지원 자료는 필요한 집계만 공유하고 카드번호·청구 원본의 불필요한 개인정보를 Git/공개 Notion에 붙이지 않는다.
