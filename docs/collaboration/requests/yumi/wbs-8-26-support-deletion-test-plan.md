## 목적·완료 기준

공개 안내에서 메일 접수·본인 확인·기술 담당 이관·결과 회신까지 실제로 이어지는지 검증할 준비를 한다. TASK 전체 완료에는 시험 수신/처리 근거·응답 안내·미정 담당 구분과 증빙 링크가 필요하다. 이 문서는 시험 계획이며 접수함 설정·메일 발송·회원 삭제를 실행하지 않았다.

## 실제 시험 전 준비

- 유미가 시험 범위·발신/수신 계정·합성 자료·수신자·발송을 승인한다. 승인 전 외부 메시지는 보내지 않는다.
- 민규·종현이 맡은 공개 페이지·앱·서버의 검증 대상 버전과 전용 시험 환경을 확인한다. 실회원 HOLD를 해제하지 않는다.
- 본인 확인에 어떤 최소 자료·보안 전달 경로를 사용할지 실제 담당이 확인한다. 여기서는 신분증·네이버 비밀번호·OTP·토큰 제출을 요구하거나 확인 방법을 확정하지 않는다.
- 시험은 비밀·실회원 자료 없는 코드(예: CASE-DEL-01)를 사용한다. 받은 편지함 원문·실제 주소·증거 캡처를 공개 Git에 올리지 않는다.

## 검토용 답변 뼈대 — 미발송

접수 안내: “유미당입니다. 요청을 확인했습니다. 처리 전 필요한 최소 확인 방법과 예상 일정을 안내드리겠습니다.” 실제 수신 후에만 사용한다.

결과 안내에는 요청 코드, 확인한 처리 범위, 완료/처리 중/확인 필요, 조건부 보관 자료와 종료 조건, 후속 문의 방법을 구분한다. 실제 처리 근거가 없으면 ‘삭제 완료’라는 문장을 사용하지 않는다. 구체적인 본인 확인 문구는 방법 합의 후 작성한다.

## 공식 기준·인수인계

2026-10-22 읽은 [Google Play 계정 삭제 안내](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)는 앱 안의 삭제 경로와 외부 요청 웹 경로를 요구한다. 외부 웹의 눈에 띄는 삭제 구역에서 고객지원 이메일로 요청을 받는 방식도 설명한다. 메일 주소 하나나 로컬 HTML 존재만으로 공개 경로·실제 처리 검증을 대체하지 않는다.

- 수행: 확정 운영 정보 승계, 실제 시험 전 조건·11사례·결과 양식·회신 뼈대 준비.
- 문서 검증: 정책 값·일반 신고 대체 범위·외부 미실행·근거 링크 대조. 실행 검증 0건.
- 미완료: 공개 URL·수신/회신·최소 본인 확인 방법·삭제/보관/백업·권한·부재 대응의 실제 근거.
- 다음 행동: 유미가 공개 경로·접수 준비와 시험 범위를 검토하고, 기술 근거는 민규·종현 기존 TASK와 연결. 연락은 이번에 하지 않음.
- 상태 제안: 유미 문서 준비 반영 승인 시 `작업 중`, P0 유지. Notion은 아직 변경하지 않음.
- Git·변경 범위·공통 검증: [Batch 인수인계](batch-release-readiness-handoff.md).
