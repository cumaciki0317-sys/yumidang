# WBS 8.4 — 콘텐츠 필러·오가닉 테스트 설계

작성일: 2026-10-17 KST · 승인 반영: 2026-10-18 KST · 담당: 유미 · 기존 P1 유지 · 설계 방향 유미 승인 완료

## 1. 목적·근거·실행 경계

[Notion 8.4](https://app.notion.com/p/85a44227a435822d94e1011a18210e46)의 완료 범위는 주제·가설·게시 문구·CTA·측정 방법의 설계다. 실제 영상·글 제작은 8.7·8.8, 승인 게시는 8.12, 게시 후 반응은 8.18에서 다룬다.

공통 입력은 [8.2 R-01~05와 메시지](wbs-8-2-brand-positioning.md), [8.3 단계·KPI](wbs-8-3-funnel-kpi.md)다. 원문이 참조하는 과거 WBS 인수인계 파일은 로컬 검색에서 찾지 못했으므로 현재 Notion 원문·최신 사용자 승인·8.1 근거를 기준으로 설계하고 그 문서를 읽었다고 주장하지 않는다.

고객 가설 P-A, S-P 계획형/S-N 즉흥형, PP-1·PP-2 핵심/PP-3 보완을 그대로 사용한다. 2026-10-18 KST 유미가 첫 콘텐츠 주제로 **‘가고 싶은데 함께 갈 사람이 없었던 순간’(F-01)**을 선택했다. 두 상황을 포괄하며 문화활동·식사 중 하나의 수요 우위를 확정하지 않는다. 주제 선택은 실제 제작·게시나 EXP-01 비교 실행 승인이 아니다. 새 고객 반응은 [8.1 후속](https://app.notion.com/p/3fc44227a43581fe8f1ef2b8700fe064)의 미완료 검증이다.

이번에 콘텐츠를 제작·업로드하거나 계정을 변경하지 않았다. 실제 회원 사진·채팅·후기·낯선 사람의 개인정보를 소재로 사용하지 않는다. 권리 확인된 공개 자료·합성 예시·설명 화면만 후속 제작 후보로 두며 새 AI 도구 구매·추가 결제를 승인하지 않는다.

## 2. 필러 목록과 가설 연결

| 필러 | 주제·상황 | 근거·메시지 | 확인할 가설·반대 결과 | CTA 후보·지표 |
|---|---|---|---|---|
| F-01 함께하고 싶은 활동 | 지인과 시간이 안 맞는 상황. 계획형·즉흥형 둘 다 설명 | PP-1, M-1, E-01~03은 과거 기록. 즉흥 행동은 미확인 | 공감되는 상황이 소개를 이해하게 돕는가. 공감돼도 서비스 필요가 없다는 반응도 보존 | C-SAVE 저장 제안. 제공되는 같은 채널 저장 건수/정의 확인된 노출 지표(K-CH) |
| F-02 상대를 고르는 과정 | 프로필 정보·필요한 대화로 결정하는 상황 | PP-2·PP-3, M-2·M-3. 제품 의도와 효과를 구분 | 판단 과정을 설명하면 기대가 명확해지는가. 정보가 있어도 동행하지 않겠다는 반응 포함 | C-INFO 승인된 소개 보기. 링크가 실제 존재할 때 V, 이후 K-X는 연결 가능 시만 |
| F-03 계획과 지금의 두 장면 | 미리 일정 잡기·지금 함께할 활동 찾기 | S-P·S-N, B-05·B-06. 유미 제품 방향이며 양쪽 수요 검증 아님 | 두 상황을 이해하고 필요한 장면을 구별하는가. 한쪽만 필요·둘 다 불필요도 결과 | C-SAVE 또는 승인된 소개 목적지 하나. 한 게시물에는 CTA 하나만 선택 |
| F-04 준비중 서비스 이용 흐름 | 성인 여성·무료 1:1·탐색→대화→결정의 의도 설명 | B-01~03, R-02. 실제 설치·화면 동작은 미검증 | 무엇을 제공하려는 서비스인지 이해하는가. 가입 자격·공개 상태 혼동 기록 | C-INFO. 설치 가능 확인 전 설치 CTA 금지 |

CTA는 실행 전 채널이 실제 지원하고 집계 가능한지 확인한다. C-SAVE가 지원·제공되지 않으면 같은 실험의 임의 대체 지표로 바꾸지 않고 해당 실험을 보류하거나 재설계한다. 사용자 댓글·DM 수집을 이번 설계가 자동 승인하지 않는다.

## 4. 첫 실험 후보 EXP-01 — 고민 표현 비교

**질문:** 같은 소개에서 첫 상황 문장을 PP-1과 PP-2로 달리하면 관찰 가능한 콘텐츠 반응의 차이가 있는가?

이 설계는 오가닉 게시의 탐색적 비교다. 무작위 배정·동일 노출을 보장하지 못하므로 메시지의 인과 효과나 고객 수요를 확증하지 않는다. 조회가 많다는 이유만으로 주 페르소나나 제품 정책을 바꾸지 않는다.

| 항목 | A안 | B안 |
|---|---|---|
| 주요 변경 변수 | PP-1 활동 기회: 가고 싶은 활동은 있는데, 함께할 사람과 시간이 안 맞나요? | PP-2 상대 판단: 함께할 활동은 같은데, 어떤 사람인지 더 살펴보고 싶나요? |
| 공통 본문 | 같이 하고 싶은 순간, 유미당. 취향과 일정이 맞는 여성 동행을 찾아보세요. 성인 여성을 위한 무료 1:1 동행 서비스를 준비중입니다. | A와 동일. U-03 조합 반영, 게시 전 준비 상태 확인 |
| 공통 CTA 후보 | C-SAVE 한 개 | A와 동일 |
| 비교 단위 | 같은 채널·형식·가능한 유사한 게시 조건의 각 게시물 | A와 동일 |
| 주 지표 후보 | K-CH: 같은 채널·같은 정의의 저장 건수와 노출 분모 | A와 동일 |
| 보조 기록 | 제공되는 조회·도달·링크 이동 각각의 단위와 누락 사유 | A와 동일 |
| 현재 결과 | 미실행 | 미실행 |

계획형/즉흥형 예시까지 동시에 바꾸면 무엇의 영향인지 알기 어려우므로 EXP-01에서는 같은 맥락을 유지한다. 상황별 비교는 후속 별도 실험 후보로 남기며 이번에 시간·횟수·표본을 확정하지 않는다.

### 실행 전에 채울 항목 — 비어 있으면 게시·판정하지 않음

- 유미가 고른 실제 채널·원고 버전·권리 근거·게시 승인 기록
- 지원되는 CTA와 원천 지표·노출/도달/사람 단위의 정확한 정의
- 관찰 시작·종료·관찰창·시간대·표본 충분성 기준, 누락 기록 방식
- 형식·길이·이미지·본문·CTA 유지 및 게시 시각·노출 차이 같은 통제 불가 요인 기록
- 설치나 링크 유도라면 실제 목적지·접근 가능 범위 확인. 공개 계정·링크를 임의로 만들지 않음

같은 채널에서 분모·CTA·집계 범위를 맞출 수 없으면 수치 우열 판정은 보류한다. 표본이 기준에 못 미치거나 관찰창이 끝나지 않으면 미결정으로 기록한다. 구체적인 최소 수·기간·목표율은 새로 정하지 않았다.

## 5. 측정·판정 표

[8.3](wbs-8-3-funnel-kpi.md)의 K-CH·K-X·Q-LINK 정의를 따른다. 플랫폼 조회수와 앱 회원 수를 직접 나눠 전환 성과라고 표시하지 않는다. 댓글 같은 의견이 실제로 수집되더라도 의향·경험·확정 행동을 구분하고 이용 허용 범위 확인 전 원문을 저장소로 복사하지 않는다.

|---|---|---|---|---|---|---|

## 6. 후속 제작·게시 인계와 개별 완료 판정

- 8.5: 필러·실험 후보와 준비중/베타/공개 단계별 실행 조건을 활용한다.
- 8.7·8.8: 유미가 선택한 F-01 ‘가고 싶은데 함께 갈 사람이 없었던 순간’을 첫 소재로 준비할 입력으로 넘긴다. M-1·M-1a 조합을 사용하되 실제 원고·영상 제작과 최종 게시 문구 승인은 후속 범위다.
- 8.9: 공개·합성 입력, 사람 검수·권리·중단 기준을 연결한다.
- 8.12·8.18: 실행 전 조건 승인 후 게시·측정한다. 이번 Batch 승인은 게시·실험 실행 승인이 아니다.

실제 수행은 필러 4개·실험 후보 1개·채널별 설계 예시·측정/보류 조건·후속 전달안 작성이다. R-01의 고객 가설을 성과 사실로 바꾸지 않았고 CTA는 실제 지원·집계 확인 전 실행하지 않도록 구분했다.

2026-10-18 KST 유미가 ‘설계 방향은 승인하고, 제작·게시·측정 실행은 각각 준비 후 검토하기’ 1번을 선택했다. 필러 4개·첫 주제 F-01·채널별 구성·비교 실험 후보·측정 및 보류 원칙의 설계 방향 승인을 기록한다. EXP-01은 실행 후보이며 실제 채널·기간·충분성·권리·게시 조건은 여전히 미확정이다.

문서 작성·구조 검증과 설계 방향 승인은 완료다. 이후 유미의 별도 승인으로 Notion은 설계 범위 `최종 완료`로 반영·재조회했다. B02 시작 시 2026-10-18 재조회에서도 완료 상태를 확인했다. 이번 B02에서는 그 결과를 로컬 안내에 동기화했으며 Notion을 추가 변경하지 않았다. 실제 제작·게시·반응 검증의 완료로 확대하지 않는다. 8.2/8.3은 팀 검토·구현 대조 대기이며 입력이 바뀌면 연결된 설계를 다시 확인한다.

### 팀 협의 추적 — 담당 수락·연락 미실행

- 종현 확인 필요: 실제 콘텐츠 제작 전에 사용할 화면·2.11 디자인 템플릿·준비 상태·진입 경로 확인. 확인 근거는 사용할 버전과 검토 결론이다. 화면이 필요 없는 원고 준비와 구분한다.
- 종현·민규 확인 필요: 앱 가입·신청 전환 측정 전에 실제 계측 가능 범위와 자료 취급 조건 확인. 기존 8.3의 3.10 협의 항목에서 추적하며 중복 TASK를 만들지 않는다.
- Codex: 후속 작업 중 필요한 협의를 먼저 식별하고 대상·질문·막히는 범위·진행 가능한 범위를 유미에게 보고한다. 독립 추적이 필요해지면 기존 TASK와 중복을 확인한 뒤 협의용 TASK로 분리한다. 팀원에게 연락·일정 확정·업무 배정을 자동 실행하지 않는다.

Git·검증 결과·TASK별 인수인계 종합은 [B01 인수인계](batch-brand-strategy-handoff.md)를 따른다.
