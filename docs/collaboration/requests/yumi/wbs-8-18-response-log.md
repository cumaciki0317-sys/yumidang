## 1. 목표·현재 상태·원문 완료 기준

[Notion 원문](https://app.notion.com/p/af544227a4358334ba2201bfc39d714e)은 제공되는 반응/이동 지표만 기록하고 관찰·추정을 나누어 다음 실험 한 가지를 정하는 TASK다. 완료 기준은 측정 가능/미제공 기록·다음 실험과 결과물/검증 증빙 링크이며 사용자 수 확보를 보장하지 않는다.

현재 유미 답변상 Threads·Instagram·TikTok 계정이 없고, 본 Batch에서는 계정 개설·게시·실제 반응 수집을 하지 않는다. 아래는 **빈 기록 양식과 판단 절차 준비**다. 실제 성과와 다음 소재의 최종 결정은 미완료이며 TASK 최종 완료를 제안하지 않는다.

## 3. 간단한 기록 절차

1. 8.12에서 승인·게시된 최종 문구/소재 버전과 실제 URL·게시 시각을 확인한다. 아직 게시하지 않았으면 여기서 `미게시`로 멈춘다.
2. 해당 계정 화면이 실제 제공하는 지표명·도움말 정의·단위·관측 기간·누적/기간값·추출 시점과 시간대를 확인한다. 아래 후보 지표가 제공된다고 미리 단정하지 않는다.
3. 계정 관리 권한 내에서 필요한 집계만 기록한다. 원천의 정의/지원 안내로 해당 항목을 제공하지 않음을 확인한 경우만 `미제공`으로 쓴다. 화면에서 찾지 못했으면 `미확인`, 권한 때문에 접근할 수 없으면 `접근 불가`, 아직 수집하지 않았으면 `미수집`으로 나눈다.
4. 같은 게시물·기간·단위의 값인지 확인한다. 댓글 수처럼 집계 숫자와 개인별 내용은 구분하고 댓글/DM 원문은 복사하지 않는다.
5. 관찰한 사실 한 줄과 가능한 해석·한계 한 줄을 따로 쓴다. 유입이 연결되지 않으면 가입/신청 성과로 바꾸지 않는다.
6. 근거가 확보됐을 때 다음 콘텐츠에서 바꿀 요소 한 가지를 제안한다. 실제 채택·제작·게시에는 해당 단계 승인과 기존 TASK를 연결한다.

관찰 기간·비교 시점은 실제 게시 계획에 맞춰 유미가 정하며 지금 날짜·주간 목표·주당 게시 수를 임의 고정하지 않는다. 기록 준비만으로 계정 분석 기능이 활성화된 것으로 처리하지 않는다.

| 프로필 방문·링크 클릭 | 서로 다른 사건·기능 지원·집계 범위 | 미확인·목적지 미확인 | 프로필 방문을 외부 이동/설치와 같게 보지 않음 |

첫 신청은 S11 첫 메시지 전송 성공으로 신청 생성이 확인된 경우다. 확정과 실제 완료는 별도 사건이며 예상 종료가 지난 것만으로 실제 완료로 세지 않는다. 이 문서에서 회원 식별자나 원문 수집을 승인하지 않는다.

## 5. 바로 쓸 빈 기록표

### A. 게시물과 관찰 조건

| 콘텐츠/문구 버전 | 채널·실제 게시 URL | 게시 시각·시간대 | 관찰 시작/끝·추출 시각 | 기간값/누적·관찰 종료 | 근거 위치·접근 범위 |

### B. 지표 하나당 한 행

| 원천 지표명·단위 | 제공/접근 상태 | 값 | 기간·콘텐츠 일치 | 정의/근거 | 누락·해석 한계 |
|---|---|---|---|---|---|
| 미확인 | 계정/게시 준비 전·미수집 | 미수집 | 미실행 | 미확인 | 실제 반응 없음이라는 판정도 할 수 없음 |

### C. 관찰과 다음 행동

| 확인된 사실 | 해석·가설 | 반대 근거·빠진 정보 | 다음에 바꿀 요소 하나 | 채택/제작/게시 승인 | 연결 TASK |
|---|---|---|---|---|---|
| 실제 관찰 없음 | 판단 보류 | 계정·게시·지표 미확인 | 미결정 | 미승인 | 8.18·후속 제작은 기존 8.11 등 범위 대조 |

미수집을 `0`으로 바꾸지 않는다. `0`은 해당 집계가 실제 0이라고 원천에서 확인했을 때만 쓴다. `미제공`과 `접근 불가`도 서로 다르며, `N/A`는 정의/연결/분모가 성립하지 않아 계산하지 않는 경우다.

## 6. 비교·판단의 기준

- 같은 채널·동일 정의/단위·비슷한 관찰 경과·관찰 종료 상태를 확인한 뒤 비교한다. 플랫폼마다 다른 조회 정의를 하나의 순위로 만들지 않는다.
- 분모가 실제로 확인되고 분자와 같은 범위일 때만 비율을 계산한다. 분모 0·누락·기간 불일치·개인 연결 불가는 N/A다. 수식 검산을 실제 고객 성과로 쓰지 않는다.
- 같은 게시물의 누적값을 여러 번 저장해도 합산하지 않는다. 중복 확인이 안 되는 서로 다른 지표를 합쳐 ‘총 관심자’로 표시하지 않는다. 감소/수정된 수치도 숨기지 않고 원천 확인 시점을 기록한다.
- 사례가 적거나 노출 조건이 다르면 ‘어떤 표현이 더 좋다’고 확정하지 않는다. 소재·첫 문장·형식 등 한 요소 변경을 검토할 수 있으나 인과나 통계적 우위를 보장하지 않는다.
- 아무 반응이 보이지 않으면 먼저 실제 공개 여부·관찰 기간·지표 제공/권한·누락을 점검한다. 바로 수요 없음으로 결론 내리지 않는다.
- 조회와 클릭이 있어도 설치·가입 연결이 없으면 그 구간은 미상으로 남긴다. 채널 이름만으로 가입 출처를 추측하지 않는다.

### 양식 오사용 방지 확인 사례 — 실제 자료가 아님

| 가정한 경우 | 기록/판단 기대값 |
|---|---|
| 아직 계정·게시가 없음 | 미게시·미수집. 조회 0건으로 기록하지 않음 |
| 화면에서 지표 자체를 지원하지 않음 | 미제공. 성과 0으로 기록하지 않음 |
| 조회는 제공되지만 링크 클릭은 접근 불가 | 두 상태를 따로 기록. 클릭률 계산 보류 |
| 같은 게시물 누적 수치를 두 번 확인 | 각각 관찰 시점 기록. 누적끼리 합산 금지 |
| 조회와 가입 집계는 있으나 서로 연결되지 않음 | 개별 집계만 기록. 채널→가입 전환 N/A |
| 계산할 비율의 분모가 실제 0 | 비율 N/A. 0%로 보고하지 않음 |

실제 성과 수치를 넣지 않은 문서 판단 사례다. 앱/플랫폼 기능을 실행한 테스트가 아니다.

## 7. 개인정보·권리·증빙 범위

개별 계정명·댓글/DM 원문·얼굴·연락처·사연·회원 화면을 Git/공개 Notion에 복사하지 않는다. 개인을 추정해 채널과 앱 계정을 연결하지 않는다. 최소 집계와 필요한 정의·버전만으로 기록할 수 있는지 먼저 확인한다. 실제 스크린샷은 권리·접근/공개 범위·노출 정보를 검토한 뒤 승인된 위치에 보관하며 이번에는 만들거나 첨부하지 않는다.

외부 분석 도구·추적 파라미터·설문·DM 수집·SDK 설치·자동 게시·회원 원문 외부 전송은 이번 범위 밖이다. 실제 취급 조건은 기존 5.1·8.3·3.10의 협의/승인과 실회원 HOLD를 따른다.

## 8. 개별 TASK 인수인계

- 목적/완료 기준: 1절 원문 기준. 실제 지표·다음 실험 근거가 있어야 TASK 완료를 검토한다.
- 수행/산출물: 제공 여부 확인표·게시 조건/지표/판단의 빈 기록표·비교/오사용 방지 기준. 새 퍼널 정의는 만들지 않았다.
- 검증: 8.3 정의와 기간·단위·연결 불가·미상 귀속 대조, 미수집/0/N/A 구분과 개인정보 원문 부재 확인. 실제 플랫폼 접근·게시·실측은 미실행.
- 미완료: 계정·최종 콘텐츠/게시 승인·실제 게시·제공 지표와 관찰 조건 확인·반응 기록·다음 소재 결정. 초안이 실제 반응 확인을 대체하지 않음.
- 후속: 유미는 양식 검토, 이후 승인된 게시 결과만 기록. 앱 계측 질문은 종현 3.10, 서버/자료 취급은 민규의 기존 범위와 연결하되 이번에는 연락하지 않는다.
- Notion 제안: `대기 → 작업 중`, 양식 준비·실측 미완료 기록. 최종 완료 보류, 별도 승인 전 미변경.
- 변경 파일/Git/검증/다음 행동: [B04 인수인계](batch-launch-operation-preparation-handoff.md). Commit·Push·PR 미실행.
