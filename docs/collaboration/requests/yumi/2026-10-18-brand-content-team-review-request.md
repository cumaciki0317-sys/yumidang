## 7. Commit·Push 준비안 — 아직 미실행

문서 작업도 실제 영상/팀 협의가 끝날 때까지 Commit을 미룰 필요는 없다. 완료·대기·가설·승인 경계가 명확한 현재 결과를 기록하고 이후 변경은 후속 Commit으로 남길 수 있다. Commit은 로컬 이력 보관이며 Push 후 해당 원격 브랜치에서 확인할 수 있다. 둘 다 팀 검토·PR·Merge·배포를 대신하지 않는다.

### 대상과 구성

- 대상 브랜치: `yumi/batch-brand-strategy`, 현재 HEAD `f4623a642cd48c6a0d207f5cca47335b59a2253d`.
- 추천 Commit 1개: `docs: record brand strategy and content preparation`.
- 범위: 아래 12개 Markdown만. 공통 정책·PRD·팀원 파일·코드·설정·Hook·기존 저장소 변경 없음.

| 묶음 | 포함 파일 | 개수 |
|---|---|---|
| B01 | `wbs-8-1-persona.md`, `wbs-8-1-handoff.md`, `wbs-8-2-brand-positioning.md`, `wbs-8-3-funnel-kpi.md`, `wbs-8-4-content-pillars.md`, `batch-brand-strategy-handoff.md` | 6 |
| B02 | `wbs-8-5-content-stage-plan.md`, `wbs-8-8-first-posts.md`, `wbs-8-9-ai-content-workflow.md`, `wbs-8-7-video-brief.md`, `batch-content-preparation-handoff.md` | 5 |
| 협의 요청 | 본 문서 `2026-10-18-brand-content-team-review-request.md` | 1 |

모든 경로는 `docs/collaboration/requests/yumi/` 아래다. 원고·대본은 최종 승인/실제 제작을 기다리는 검토본임을 유지한다. B01/B02의 검증·Notion 반영 경과와 작성 당시 과거 기록도 함께 보관한다. 12개를 하나로 기록하면 기존 문서의 연결 대상과 최신 인수인계를 같은 Commit에서 찾을 수 있다.

### 승인 후 실행 순서

1. Commit 승인 후 브랜치·HEAD·작업 트리·12개 파일과 내용·소유권을 다시 확인한다. 추가 변경이 있으면 자동 포함하지 않는다.
2. 승인한 파일만 명시적으로 stage하고 staged 목록·diff·소유권 검사를 수행한다. 현재는 staged 0이며 아직 stage하지 않았다.
3. 실제 pre-commit Hook 전체 실행을 확인하고 승인한 Commit을 만든다. 샌드박스의 sh 오류가 재발하면 원인/정식 실행 환경을 확인하며 Hook·actor·소유권을 바꿔 통과시키지 않는다. `--no-verify` 사용 금지.
4. Commit ID·포함 파일·Hook 결과를 보고한다. Commit 승인만으로 Push하지 않는다.
5. Push 별도 승인 후 `origin`의 URL/대상 브랜치·원격 상태를 확인하고 `yumi/batch-brand-strategy`에 정상 Push한다. 강제 Push·다른 팀원 브랜치 변경·자동 Merge는 하지 않는다.
6. 원격 Commit 일치를 확인하고 실제 Git 링크를 필요한 인수인계/Notion에 추가할 반영안을 제시한다. PR은 별도 승인이다.

현재 로컬 원격 추적 참조에서 확인한 것은 `origin/yumi/wbs-8-1-persona`의 `f4623a6`뿐이다. 이번에 fetch/원격 네트워크 조회를 하지 않았으므로 새로운 대상 브랜치의 실제 원격 존재·최신 상태는 보증하지 않는다. 아직 수행하지 않은 staged 검사·Hook 전체 실행·Commit·Push를 완료라고 기록하지 않는다.

## 8. 검증·다음 행동

문서 작성 전 HEAD 소유권 기준 본 경로가 유미 허용임을 확인했다. 작성 후 Commit 후보 12개 경로 모두 HEAD 정책 actor yumi 소유권 검사를 통과했다. 12개 문서의 UTF-8·최종 줄바꿈·표 열 수·상대 링크·끝 공백·문자 혼입·전화/이메일 단순 패턴 검사와 git diff --check를 통과했다. 후보 목록과 실제 작업 트리 12개가 일치하고 기존 수정 2개·미추적 10개·staged 0, HEAD·브랜치 유지임을 확인했다. 신규 미추적 파일은 별도 내용 검사로 확인했다.

읽기 전용 audit_local 리뷰는 큰 내용 결함·발송/수락/완료 오인을 발견하지 않았고 본 문서의 상대 링크 8개가 존재함을 확인했다. Notion 원문 재조회는 root가 수행했고, 독립 리뷰는 로컬 내용 검토이며 원문·법률 적합성 재검증이 아니다. 단순 패턴 검사는 모든 개인정보의 부재를 자동 보증하지 않는다. 실제 staged 검사·Hook·Commit·Push는 아직 실행하지 않았다.

다음 행동은 유미가 Commit 준비안을 검토하고 Commit 여부를 승인하는 것이다. 팀 요청 전달과 Push·PR은 별도 지시 대상이다. 이번 준비에는 GOAL MODE를 사용하지 않는다. 팀 회신·제작·권리 재검수로 장기화되면 별도 목표/종료 기준을 제시한다. 다음 제작 Batch는 팀 확인과 실행 계획 승인 전 자동 시작하지 않는다.
