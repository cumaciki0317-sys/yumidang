실제 시연이 가능할 때도 현재 승인된 환경·합성 자료와 보존할 기존 검증 범위를 확인한다. 미팅을 이유로 실회원 HOLD·자료 외부 전송·배포·결제·정책 보류를 해제하지 않는다. 1.2는 종현 협의 후 진행 조건을 유지하며 이번 문서에서 정책 정합성 검토를 수행하지 않았다. 출시 판단은 기존 7.5의 실제 근거와 미충족 조건을 따로 확인한다.

### 이번 미팅에서 우선 정리할 세 가지

1. 브랜드 문구: 유미가 선택한 대표·설명과 첫 글·스토어 초안이 실제 제공 상태와 맞는지, 수정할 문구가 무엇인지.
2. 영상 준비: 종현 2.11에서 지금 공유 가능한 편집 원본·사용 예시·권리 근거가 있는지, 없다면 수락 가능한 다음 준비가 무엇인지.
3. 측정/자료 취급: 8.3·3.10에서 가상 자료로 먼저 대조할 범위와 실제 수집 전에 필요한 확인/승인이 무엇인지.

여러 이슈를 다 확정하려고 숫자·담당·기한을 임의로 채우지 않는다. P0 차단 항목은 중요도를 유지하고 증빙이 필요한 내용과 현재 실행 가능한 일을 나눠 남긴다.

### 회의 기록 양식 — 결과 미작성

| 기록 항목 | 작성할 내용 | 현재 상태 |

| 근거·시연 | TASK·파일/Commit/앱 버전·합성/실제 구분·확인 결과 | 회의 전·미작성 |
| 결정 | 질문·채택/수정/보류·이유·근거·승인 범위 | 미결정 |

회의 후 실제 합의 내용이 제공되면 기존 TASK와 중복을 확인해 상태/인수인계 반영안을 묶어 제시한다. 공동 소유권을 같은 파일 공동 편집으로 해석하지 않는다. 사람의 발언·사연·연락처를 불필요하게 기록하지 않고 녹음/AI 전사는 별도 검토 없이 시작하지 않는다.

## 7. Notion·Git·다음 작업

Notion 세 TASK는 이번에 변경하지 않았다. 유미 결과 검토 후 8.6·8.15·8.16을 모두 작업 중으로 기록하고 문서 산출물·미확인·팀 확인·실제 실행 미수행을 구분하는 안을 제시한다. 담당·P값·일정·DB 구조는 유지한다. 외부 공유·팀 알림·댓글·회신이 있었던 것처럼 기록하지 않는다.

현재 신규 문서 4개는 미커밋·미스테이징이다. 결과 검토 후 경로별 소유권·staged 목록·실제 Hook을 확인하고 별도 Commit 승인과 별도 Push 승인 후 진행한다. 기존 64d1a79 Push 완료와 신규 B03 결과를 혼동하지 않는다.

다음 추천은 유미의 원고 검토 결과를 반영하고, 팀 회신/템플릿이 확보되면 실제 영상 제작 계획을 이어가는 것이다. 회신이 없으면 미확인 자료 없는 독립 준비를 다시 선정한다. 8.20 실제 베타 안내는 설치 링크·테스트/지원·모집/QA 조건 확인 전 완성 처리하지 않는다. 2.4/2.5 UT는 앱 핵심 구현·QA 이후를 유지한다.

이번에는 GOAL MODE를 사용하지 않았다. 회의 여러 회차·권리 확인·제작/반려/재검수로 장기화되면 구체 목표·종료 기준을 제시한다. 사용자의 명시 요청 없이 Goal을 생성하지 않으며 별도 승인 경계를 대체하지 않는다.
