## 1. 사용 전 조건 — 내부용

이 문서는 입력 항목을 준비한 Markdown이며 외부 설문·접수 채널을 개설하지 않았다. 제출 목적지·접근자·처리 목적·보관/삭제·필요한 고지/동의와 수집 실행 범위가 확인된 뒤 공개한다. 아래 참여자용 부분을 실제 수집 중인 양식으로 전달하지 않는다.

앱 회원 DB·채팅 원문을 직접 열어 증거를 찾는 방식은 사용하지 않는다. 피드백은 일반 사용성 관찰이며 신고·삭제 요청은 해당 별도 절차로 연결한다. UT2.4·2.5 실행이나 실회원 HOLD 해제의 근거가 아니다.

## 2. 참여자용 양식 — 아직 제출하지 마세요

문제 한 건당 한 양식으로 적어주세요. 기억나지 않는 항목은 ‘모름’, 다시 시도하지 않았다면 ‘미확인’이라고 적어도 됩니다.

### 어떤 환경이었나요?

- 앱 버전: 확인 가능하면 기재 / 모름
- 기기·운영체제: 기종과 OS 버전을 아는 범위만 기재 / 모름
- 설치 경로 구분: 안내받은 경로 / 기타 / 모름 — 개인용 초대 URL·토큰은 붙여넣지 마세요.
- 발생 시점: 대략적인 시각만 필요할 때 기재 / 모름 — 정확한 위치·동선은 적지 마세요.

기기 일련번호·광고ID·회원ID·전화번호·이메일·성별·생년월일·계정 이름은 이 양식에서 요청하지 않습니다. 회신·계정 연결이 꼭 필요한 경우에는 운영자가 승인된 별도 경로에서 최소 확인 방법을 안내해야 합니다.

### 어디에서 어떤 일이 있었나요?

- 하려던 일:
- 문제가 생기기 전 눌렀던 순서: 1. / 2. / 3.
- 기대했던 결과:
- 실제로 보인 결과: 개인 정보 없는 짧은 설명
- 오류 문구: 개인 정보·키가 없다면 직접 입력 / 미기재
- 같은 문제가 다시 생기나요? 다시 생김 / 한 번만 확인 / 재시도하지 않음 / 모름
- 작업을 계속할 수 있었나요? 계속 가능 / 일부 불편 / 진행 불가 / 모름
- 더 하고 싶은 말: 선택

작성 예시 — 실제 관찰이 아닌 합성 예시:

> 하려던 일: 글 목록의 다음 내용을 보기<br>
> 순서: 목록 열기 → 더보기 누르기<br>
> 기대: 글이 추가로 보이기<br>
> 실제: 화면 변화가 보이지 않음<br>
> 반복: 재시도하지 않음 / 진행: 일부 불편

사용자 이름·개인 글·채팅 내용을 넣지 않고 조작 단계만 설명하는 예시입니다. 이 문제가 실제 발생했다는 기록이 아닙니다.

### 첨부자료

기본 첨부는 없습니다. 캡처·영상·음성·파일을 필수로 요구하지 않습니다. 먼저 글로 설명해주세요. 추후 자료가 꼭 필요하다면 승인된 방법·범위·접근 권한과 권리 확인을 안내받은 뒤 별도로 검토합니다.

비밀번호·OTP·토큰·신분증·네이버 계정 정보, 본인/타인의 얼굴·프로필·채팅·연락처·상세 위치, 권리 불명 이미지·영상은 보내지 마세요.

## 3. 접수 준비표 — 내부용·미확인

| 항목 | 현재 상태 | 공개/수집 전 확인 |
|---|---|---|
| 제출 목적지 | 미확정 | 실제 접근 가능한 경로·제출/접수 확인·권한 |
| 처리 목적·범위 | 베타 문제 설명 양식의 제안 | 실제 수집 목적·항목·선택/필수·고지/필요 동의 검토 |
| 접근·회신 담당 | 베타 피드백 실무/부재 대응은 미확정 | 일반 신고 대체 종현을 자동 확대하지 않음 |
| 보관·삭제 | 베타 접수 원자료의 구체 처리 근거 미확인 | 정책13장과 맞춰 검토. 진단30일을 자동 적용하거나 새 기간 지정 금지 |
| 기술 담당 연결 | 파일·기능 소유자 기준 | FE/앱 종현, BE/서버 민규. 필요한 요약만 전달 |
| 계정 확인 | 이 양식은 식별자 수집 안 함 | 익명 접수를 보장하는 선언은 아님. 실제 접수 도구의 계정/로그 수집 확인 |
| 외부 AI/도구 | 신규 사용·업로드 없음 | 실회원 원문 HOLD 유지, 피드백 원문을 AI에 자동 전달하지 않음 |

## 4. 운영자가 채울 검토 기록 — 현재 실제 접수 0건

| 자료 코드 | 접수 확인일 | 발생 환경·버전 | 단계·문제 요약 | 재현 판정 | 영향 | 담당 연결·근거 | 현재 상태·다음 행동 |
|---|---|---|---|---|---|---|---|
| 실제 접수 전 | 미실행 | 미확인 | 없음 | NOT_RUN | 미판정 | 미지정 | 준비 단계 |

코드는 접수 후 내부 자료 추적용으로 부여하며 코드화만으로 익명화를 보장하지 않는다. 실회원 연결표·원문을 공개 저장하지 않는다. 접수 사실과 실제 재현·원인 확정·수정 완료를 구분한다. 사용자 서술만으로 결함·안전 위반을 확정하거나 타인에게 원문을 배포하지 않는다. 제품 코드 결함 수정은 해당 파일 소유자에게 연결한다.

## 5. 검증·남은 일

양식은 제출 전 안내, 식별자 미요청, 오류 재현에 필요한 최소 맥락, 첨부 비필수, 예시의 허구 표시, 미확인 접수 조건을 구분했다. 실제 제출·수신·접근권한·자동 로그·보관·삭제 동작은 NOT_RUN이다. [8.20 인수인계](wbs-8-20-handoff.md)에 검증·후속·Git 정보를 연결한다.
