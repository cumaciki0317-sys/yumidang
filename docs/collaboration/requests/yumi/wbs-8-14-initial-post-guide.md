# WBS 8.14 — 초기 동행 공고 공급·첫 이용 안내 준비

## B04 Notion 반영 완료 — 2026-10-18 KST

유미가 세 TASK의 결과·검증·남은 일 기록과 상태 반영을 승인했다. 8.15는 작업 중을 유지하고 8.14·8.18은 대기에서 작업 중으로 변경했다. 각 상세 페이지 끝에 B04 인수인계를 추가한 뒤 재조회하여 상태·추가 내용·기존 본문과 완료 체크·담당·P1·일정 보존을 확인했다. 최종 완료로 변경하지 않았다. 이번에 팀원 멘션·댓글·메시지·알림 발송 작업은 하지 않았으며 Commit·Push·PR도 미실행이다. 아래의 Notion 미반영/제안 문구는 승인 전 작성 기록으로 보존하며 현재 상태는 이 절을 따른다.

## 1. 목표·완료 기준·현재 판정

[Notion 원문](https://app.notion.com/p/05044227a43583a39fec81de110f895c)의 목표는 출시 타깃 활동/지역에 맞는 실제 참여자·초기 공고 마련 방식과 첫 신청 안내를 준비하는 것이다. 완료 기준은 초기 공급 계획·안내안·실제 공고 검수 조건과 결과물/증빙 링크이며 허위 회원·후기 생성은 금지다.

이번에는 공급 방식 후보·선택 기준·검수표·첫 이용 안내를 문서화한다. 활동·지역·목표 공고 수·모집 날짜·참여자·혜택은 확정하지 않는다. 실제 회원 검증 HOLD와 모집/게시 별도 승인을 유지한다. **문서 준비와 검수 완료를 제안할 수 있지만 TASK 최종 완료는 보류**한다.

## 3. 초기 공급 계획 후보 — 아직 모집하지 않음

목적은 숫자를 채우는 것이 아니라, 실제 사람이 실제로 참여할 의사가 있는 공고를 준비하는 것이다. 예시 문장이나 운영자가 만든 가짜 회원·후기로 공급이 있는 것처럼 보이게 하지 않는다.

| 방식 후보 | 준비할 것 | 실제 실행 전 조건 | 한계·보류 사유 |
|---|---|---|---|
| 실제 참여 의사가 있는 사람의 자발적 작성 | 공고 작성 도움말·사실 검수표 | 8.13의 모집/참여 조건, 앱 준비·HOLD 해제와 해당 실행 승인 | 지금은 연락·참여자 모집·가입·공고 게시 안 함 |
| 승인된 모집에서 확인된 활동을 중심으로 준비 | 참여자가 밝힌 활동·가능 일정의 적절한 취급과 작성 방법 | 자료 수집/이용 조건·실제 의사·자격 확인·모집 승인 | 응답·명단 없음. 친구·커뮤니티 수요를 추정해 채우지 않음 |
| 운영 참여자가 실제 동행 당사자로 작성하는 방안 | 실제 참여 가능 여부와 적절한 표시를 팀과 확인할 항목 | 운영 참여·표시 방식에 대한 협의와 실행 승인 | 신규 정책 선택이므로 이번에는 채택하지 않음. 대리 회원/허위 운영 공고 금지 |

활동·지역 선택표는 `활동 후보 / 선택 근거 / 공개 지역 수준 / 실제 참여 의사 확인 상태 / 일정 가능 상태 / 지원·신고 준비 / 결정·승인`으로 준비한다. 현재 모든 값은 미확정이다. 전시·맛집 등 기존 자료의 예시를 출시 우선 카테고리나 특정 지역 확정으로 바꾸지 않는다. 사용자가 정한 카테고리를 줄이거나 이름을 바꾸지 않는다.

실행 순서 후보: 실제 앱·지원 조건 확인 → 승인된 모집/참여 조건 확인 → 활동/지역 선택과 실제 의사 확인 → 당사자가 공고 작성 → 공고 검수 → 승인된 환경에서 공개·첫 이용 안내 → 상태/실패 근거 기록. 각 단계는 필요한 승인과 HOLD 해제 후에만 진행한다.

## 4. 실제 공고 검수표 — 지금은 전 항목 미실행

아래는 준비용 확인 항목이며 앱 입력 필드·관리자 권한을 새로 정의하지 않는다. 실제 화면·권한·기능은 종현의 제공 버전에서 확인한다. 운영자가 고객 DB 채팅 원문을 직접 읽는 검수 방식은 사용하지 않는다.

| 확인 항목 | 통과 근거로 필요한 것 | 보류 조건 | 지금 |
|---|---|---|---|
| 당사자·참여 의사 | 당사자가 실제 참여할 공고임을 허용된 절차로 확인 | 허위·대리 작성·참여 의사 불명 | 미실행 |
| 가입 가능·현재 서비스 범위 | 승인 환경의 네이버 자격 확인·여성 만 19세 이상·무료 1:1 범위 | 필수 정보 미확인·제품 범위 밖 | 미실행 |
| 활동·카테고리·일정 | 공고 내용과 실제 계획·현재 상태 대조 | 이미 불가능한 일정·실제와 다른 내용 | 미실행 |
| 지역과 상세 지점 | 공개 지역은 동까지, 상세 만남 지점은 확정 당사자에게만 표시되는 실제 화면 | 상세 지점/연락처가 공개 글·사진에 노출 | 미실행 |
| 비용·조건 설명 | 제품의 무료 동행과 실제 활동 비용을 혼동시키지 않는지 검토 | 새 유료 동행·수수료·미확정 비용 정책을 단정 | 미실행 |
| 사진·설명·개인정보 | 사용 자산의 권리 근거와 제3자 개인정보 노출 여부 | 타 SNS 무단 복사·타인 얼굴/연락처·권리 불명 | 미실행 |
| 안내 정확성 | 실제 화면의 첫 메시지 신청·상호 확정 흐름과 대조 | 클릭만으로 신청/확정된다고 표현 | 미실행 |
| 공개 가능·대응 경로 | 7.5 출시/보류 판단·9.1 및 8.26 지원 준비와 해당 실행 승인 | HOLD·지원/신고 대응 경로 미준비·승인 없음 | 미실행 |

주장 검토와 법률 검토는 다르다. 출처만 적었다고 사진·음원·스크린샷의 이용 허락을 확보한 것으로 처리하지 않는다. 실제 자산을 선택할 때 기존 [8.9 권리·개인정보 절차](wbs-8-9-ai-content-workflow.md)를 적용한다.

## 5. 첫 이용 안내 초안 — 실제 화면 대조 전 공개 금지

### 동행을 찾는 사람

> 같이 하고 싶은 순간, 유미당.
>
> 하고 싶은 활동과 가능한 일정을 생각해보세요. 미리 계획한 활동도, 지금 하고 싶은 활동도 괜찮아요.
>
> 관심 있는 동행 글에서 활동·일정·공개된 조건을 살펴보세요. 지금 함께할 사람을 찾는다면 지금이당의 글도 살펴볼 수 있어요.
>
> 신청 버튼을 누르면 작성자와 대화하는 화면으로 이동해요. **첫 메시지를 성공적으로 보내면 동행 신청이 됩니다.** 버튼을 누르거나 전송을 시도한 것만으로 신청되지는 않아요.
>
> 필요한 이야기를 나눈 뒤 작성자가 확정 요청을 보내고, 신청자가 수락하면 동행이 확정돼요. 요청이 만료되었거나 조건을 바꿔야 한다면 실제 화면의 안내에 따라 다시 확인하세요.
>
> 유미당은 만 19세 이상 여성을 위한 무료 1:1 동행 서비스이며 네이버 계정으로 가입해요. 동행 성사나 상대의 신원·안전을 보장하지 않아요.

이는 현재 제품 기준을 설명하는 출시 후보 안내다. 서비스 공개·신청 기능 검증을 마친 안내가 아니다. 가입 시 실제 필수 정보가 확인되지 않으면 가입 완료를 보류하며 다른 가입 수단을 임의 안내하지 않는다.

### 공고를 준비하는 사람

> 실제로 함께하고 싶은 활동과 참여할 수 있는 일정을 적어주세요. 공개 글·이미지에 개인 연락처나 상세 만남 지점을 넣지 마세요. 상세 지점은 동행이 확정된 뒤 당사자에게만 제공돼요.
>
> 신청자와 필요한 조건을 이야기한 뒤 확정 요청을 보내세요. 요청을 보낸 것만으로 확정되는 것은 아니며 신청자의 수락이 필요해요.

신고·차단·지원 안내는 실제 접근 경로가 확인된 뒤 연결한다. 검증하지 않은 버튼 이름·메뉴 위치·지원 이메일·설치 URL은 만들어 넣지 않는다. 이 문서는 8.20의 베타 설치/피드백 가이드나 8.13의 실제 모집을 대체하지 않는다.

## 6. 공급·검수 기록 양식 — 실제 기록 없음

| 기록용 내부 코드 | 자료 유형 | 작성/참여 의사 근거 | 활동·일정 검수 | 공개 범위·권리 검수 | 실행 환경·버전 | 결과·보류·다음 행동 |
|---|---|---|---|---|---|---|
| 미부여 | 미실행 | 미확인 | 미실행 | 미실행 | 미확인 | 실제 대상 없음·미실행 |

공개 저장소에는 회원 ID·이름·얼굴·연락처·상세 지점·대화 원문·비공개 공고 링크를 기록하지 않는다. 코드만 붙여도 재식별될 수 있으므로 실제 회원 연결표를 Git/공개 Notion에 만들지 않는다. 실제 증빙은 접근 권한과 자료 취급 조건이 확인된 위치에서 최소한으로 관리하며 이번에 새 저장소나 수집 체계를 만들지 않는다.

## 7. 개별 TASK 인수인계

- 목적/완료 기준: 1절 원문 기준. 준비와 실제 공급·검증을 분리한다.
- 수행/산출물: 본 문서의 공급 후보·선택표·공고 검수표·양쪽 첫 이용 안내·빈 기록표.
- 검증: 출처·제품 기준·신청/확정 구분·상세 지점 공개 범위·허위 공급/성과 부재를 문서에서 대조한다. 실제 앱·회원·게시 검증은 미실행이다.
- 미완료/협의: 활동·지역·실제 참여자·실제 앱/지원 준비·권리 증빙·공개 실행 승인. 신규 운영 참여 방식은 결정하지 않는다.
- 후속: 유미는 문구 검토와 실행 범위 판단, 종현은 실제 화면 대조가 필요할 때 기존 담당 작업으로 확인, 민규는 서버/자료 취급 조건이 필요한 경우 기존 담당 작업으로 연결. 이번에는 연락·배정·기한 합의 없음.
- Notion 제안: `대기 → 작업 중`, 준비 범위와 미완료 기록. 최종 완료 보류. 상태/상세 페이지는 별도 승인 후 반영.
- 변경 파일/Git/공통 검증/다음 행동: [B04 인수인계](batch-launch-operation-preparation-handoff.md). Commit·Push·PR 미실행.
