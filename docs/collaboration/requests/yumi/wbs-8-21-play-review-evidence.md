# WBS 8.21 — Play 심사 자료·데이터 보안 근거 준비표

작성: 2026-10-22 KST / 유미 초안 / 유미·종현 공동 TASK / P0.
[Notion 원문](https://app.notion.com/p/e5344227a435835e8d0a01aad9ecddcf)

## 목표·범위·판정

Play 양식에 넣을 정보의 근거·미확인·확인 담당을 연결한다. 원문 완료 기준은 양식 답변안·근거·심사 접근 확인이며, 법적 미확정 조건을 확정으로 표시하지 않는다. 이 문서는 유미 준비 범위다. Console 입력·신고서 제출·앱 실행·공급사 호출·법률 적합성 판단을 수행하지 않았다.

공통 근거는 [정책](../../../../정책.md), [개인정보 처리 목록](../minkyu/2026-10-06-privacy-data-inventory.md), [정책/API/RPC 차이표](../minkyu/2026-10-20-policy-api-rpc-gap-map.md), [최신 정책 동기화](../jonghyun/2026-10-20-main-policy-sync/README.md)다. 실제 운영의 전수 조사 결과로 확대하지 않는다.

## 제출 대상 고정 — 현재 미확인

| 항목 | 확인할 내용 | 현재 판정 |
|---|---|---|
| 앱 식별 | package name·versionName/versionCode·AAB 해시·빌드 일시 | 최종 제출 빌드 미확인 |
| 배포 범위 | 내부/비공개/공개 테스트·정식, 언어·국가 | 실제 Console/유미 판단 필요 |
| 계정·실행 주체 | 기존 Play 계정은 민규 소유, 유미 자료 준비·출시 판단, 종현 기술 준비 | 계정 이전·권한 변경 없음 |
| 근거 일치 | 실제 빌드와 SDK/권한/서버/공급사 설정의 동일 버전 | 문서·소스와 배포된 빌드 일치 미확인 |

## 데이터 보안 — 답변 준비 후보이며 Console 확정값 아님

행마다 실제 수집 여부·기기 밖 전송·목적·필수/선택·공유 해당성·일시 처리·삭제·암호화·공급사/SDK를 확인한다. SDK나 공급사 전달을 모두 ‘공유 없음’ 또는 모두 ‘공유 있음’으로 일괄 단정하지 않는다.

| 처리 후보 | 정책·기록에서 확인한 의도 | 실제 제출 전에 받아야 할 근거 | 확인 연결 |
|---|---|---|---|
| 네이버 가입·계정 | 이름·성별·생일·출생연도 필수, 구조화 저장·네이버 응답 원문 미저장 | 실제 OAuth 범위·저장 필드·누락 거절·계정 식별자·세션/로그 | 민규 서버 + 종현 화면 |
| 프로필·사진·선택 성향 | 필수 사진·선택 성향, 공개 범위 제한 | 업로드/메타데이터·공개 DTO·Storage 접근·삭제 검증 | 민규 + 종현 |
| 공고·지역·상세 지점 | 공개 지역은 동까지, 상세 지점은 확정 당사자 | 위치 정보의 실제 입력/전송 방식·지도/장소 공급사·권한·최종 필드 분류 | 민규 + 종현 |
| 채팅·후기·신고 제출 자료 | 서비스 콘텐츠 처리. 운영자 DB 채팅 원문 직접 접근 금지 | 전송·저장·접근·신고 캡처·보관 종료·파기·로그 제외 | 민규 + 종현, 운영 검토 유미 |
| AI 탐색·요약 | 탐색 첫 사용 동의, 후기 선택3종·기본 미선택·독립 철회 | 실제 모델 경로·적격 필드·재료/요약·각 철회·외부 사본 처리 | 민규 + 종현 / 5.1 |
| 진단·보안·사용량·비용 | 원문/비밀 제외 진단30일·보안90일, 비용 원장 별도 | Auth/호스팅/SDK 실제 로그·기기식별자·성능/분석 도구와 삭제 설정 | 민규·종현 / 8.3·3.10·8.15 |
| 문의·삭제 요청 | 공개 메일 접수, 필요한 최소 확인·회신 | 메일 서비스 실제 처리·확인 방법·접근/파기·시험 근거 | 유미·기술 담당 / 8.26 |

위 목록은 Google 양식의 최종 데이터 유형 매핑이 아니다. 생일·성별·지역·계정 식별자 등은 실제 전송값과 현재 Console 정의로 분류해야 한다. 광고 SDK·정밀 위치·종단간 암호화·수집 없음·분석 없음은 확인 전 선언하지 않는다. 서버로 전달해 저장하지 않는다는 이유만으로 일시 처리 예외를 확정하지 않는다.

### 행별 확인 기록 양식

자료 코드 / 실제 필드·데이터 유형 / 출발→도착 / 필수·선택과 거절 영향 / 목적 / 공급사·SDK·버전 / 공유 분류와 근거 / 전송·저장 보안 / 보관·삭제·철회 / 빌드·서버 버전 / 증빙 링크 / 확인자·일시 / 미확인·최종 승인.

비밀번호·토큰·신고 캡처·회원 행을 증빙으로 이 문서나 공개 Git에 복사하지 않는다. 권한이 확인된 증빙 위치와 최소 요지만 연결한다.

## 공개 안내·콘텐츠·심사 접근 준비

위 읽기는 기존 기록·소스의 범위 확인이다. 이번에 앱·DB·서버·모델을 실행하지 않았다. 각 데이터 행을 채울 때 정책값 / 소스 관찰 / 검증 환경 / 미확인 / 확인 담당을 분리한다.

| 항목 | 검토용 답변 방향 | 완료에 필요한 증거·현재 한계 |
|---|---|---|
| 개인정보처리방침 | 앱·실제 개인 운영 주체·실제 처리와 보관을 일치시킴 | 공개 HTTPS URL·앱 내 링크·현행 내용·비로그인 접근 미확인 |
| 계정 삭제 | 앱 내 탈퇴와 외부 공개 삭제 요청 경로를 구분 | [8.26 계획](wbs-8-26-support-deletion-test-plan.md)의 수신·처리 시험 NOT_RUN |
| 연령·대상 | 만19세 이상 여성은 제품 가입 조건 | Play 대상 연령 설정·등급 질문지·각 지역 결과는 별도. 공식 등급 미결정 |
| 사용자 콘텐츠 | 공고·프로필·채팅·후기·신고·차단의 제품 범위 설명 | 실제 공개·상호작용·제한·신고/차단·제재와 6.3 QA 근거 필요 |
| 광고·결제 | 현재 무료1:1, 유료 동행은 추후 | 무료 동행만으로 광고 없음·앱 가격·인앱 구매 없음을 확정하지 않음. 빌드/Console 확인 |
| 심사 접근 | 네이버만 가입·로그인, 자격과 필수정보 누락 제한 | 심사자가 제한 구간을 확인할 실제 승인된 경로·준비 자료·재현 단계·성공 증거 필요 |
| 자산·권리 | 자체 소개·합성 화면을 우선 검토 | 최종 로고/폰트/사진/영상 권리·기능 버전·개인정보 검수는 8.9·2.11 연결 |

네이버 비밀번호·OTP를 문서에 넣거나 심사용 인증 우회·새 로그인 수단을 만들지 않는다. 심사자가 실제로 접근할 방법이 준비되지 않으면 `접근 미확인`으로 남긴다. 계정/자격 조건을 바꿔 해결해야 한다면 새 범위·정책 결정이므로 작업을 멈추고 유미에게 확인한다.

## 공급사·책임의 현재 기준

- 포텐스닷 회신은 수신됐다. 교육·프로토타입 조건과 실서비스 대체 API 권고를 승계하며 ‘회신 없음’으로 되돌리지 않는다.
- Gemini 종현 테스트 프로젝트의 월50,000원 사용중단 예산·합성3건 기록은 최종 청구 상한·운영 연결·회원 전송 검증이 아니다. 대표 유미 계정 전환·예산 증액을 실행하지 않는다.
- 실회원 원문 외부 전송 HOLD 유지. 현재 구성에서 AI가 선택 사항인 점과 실제 제한/철회 동작의 검증을 구분한다.
- 일반 신고 책임 유미·부재 대체 종현의 결정은 실제 ACL·감사·삭제 완료 근거가 아니다. 삭제/일반 지원 대체로 확대하지 않는다.

## 공식 근거 — 2026-10-22 재조회

- [데이터 보안](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en): 외부 라이브러리·SDK를 포함한 실제 처리를 근거로 신고한다. 내부 테스트만 활성인 경우의 예외를 모든 베타/정식에 확대하지 않는다. 현재 트랙은 미확인이다.
- [심사 준비](https://support.google.com/googleplay/android-developer/answer/9859455?hl=en): 개인정보 안내·광고·대상·제한 구간 접근 자료를 준비한다. 현재 계정에서 요구하는 문항은 실제 Console과 최종 빌드로 대조해야 한다.
- [콘텐츠 등급](https://support.google.com/googleplay/android-developer/answer/9859655?hl=en): 실제 콘텐츠에 대한 질문지 결과와 등급기관 판단을 확인한다. 가입 조건을 공식 등급으로 치환하지 않는다.
- 삭제 경로의 공식 요건과 시험 설계는 [8.26 문서](wbs-8-26-support-deletion-test-plan.md)를 재사용한다.

## 검증·개별 인수인계

- 유미 수행: 제출 대상 표, 데이터 처리 후보7묶음, 양식/증거 요청 항목7개, 행별 확인 양식 작성.
- 문서 완료 기준: 각 항목에 기준·근거·미확인·담당이 연결되고, 제품 의도/구현 기록/운영 증거/Console 확정을 혼동하지 않음.
- TASK 미완료: 최종 빌드·SDK/권한 목록·서버/공급사 실제 처리·공개 URL·심사 접근·등급/Console 답변 확정·공동 검토.
- 다음 행동: 유미가 준비표 검토 후 종현의 빌드/화면 자료와 민규의 실제 처리·공급사 근거를 받아 빈칸을 채운다. 이번에 요청 발송하지 않음.
- 상태 제안: 승인 후 `작업 중`, P0·공동 담당 유지. 초안만으로 최종 완료하지 않음.
- 현재 Notion 미변경, Commit·Push 미실행. [Batch 인수인계](batch-release-readiness-handoff.md) 참조.
