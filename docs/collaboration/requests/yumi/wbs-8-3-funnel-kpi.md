# WBS 8.3 — 유입→탐색→동행 퍼널·KPI 설계

작성일: 2026-10-17 KST · 담당: 유미 · 기존 P1 유지 · B01 문서 설계 후보

## 1. 목표·입력·설계 경계

[Notion 8.3](https://app.notion.com/p/94144227a435820fb4d9814d8d7188b3)의 목표는 발견→방문→설치→가입→첫 신청의 단계·전환·측정 표를 정의하고, 종현 3.10에 전달해 합성 집계 일치를 확인하는 것이다. 이 문서는 탐색을 가입과 신청 사이에 명시하고 기존 방문자의 가입 전 탐색도 별도로 구분한다.

입력은 [8.2 R-01~R-05](wbs-8-2-brand-positioning.md), [PRD 핵심 시나리오·성공 지표](../../../planning/requirements/PRD.md)다. 고객의 실제 단계 이동·전환율은 측정하지 않았다. 페르소나·메시지는 제품 선택과 가설이며 검증된 유입 원인으로 바꾸지 않는다.

**이벤트명·표·집계 규칙은 협업 검토용 제안**이다. SDK·분석 서비스·DB·API·식별자·동의·보관 정책을 구현하거나 채택하지 않는다. 실측 기간·전환 관찰창·유입 귀속 방식은 담당 협의 전 미확정으로 둔다. 아래 합성 관찰창만 검산을 위해 별도로 고정한다.

## 2. 단계·성공 사건·단위

| 단계 | 의미·이벤트 후보 | 성공 사건 | 단위·확인할 수단 | 현재 측정 상태 |
|---|---|---|---|---|
| D 발견 | `content_discovered` | 채널에서 콘텐츠가 노출·조회됨 | 플랫폼별 조회수/도달/고유 시청자 구분. 제공 항목·정의 미확인 | 미실측. 조회수는 사람 수로 바꾸지 않음 |
| V 프로필·링크 방문 | `profile_visited`, `outbound_link_clicked` | 프로필 방문 또는 목적지 링크 클릭 각각 기록 | 플랫폼 제공 단위와 고유 여부·반복 클릭 구분 | 미실측. 서로 다른 두 사건을 합쳐 사람 수로 세지 않음 |
| I 설치 | `app_install_observed` | 설치로 인정할 실제 성공 근거 확인 | 스토어 집계/첫 실행/설치의 차이와 재설치 여부를 종현과 확인 | 미연결. 첫 실행을 설치와 같다고 확정하지 않음 |
| G 가입 완료 | `signup_completed` | 신규 회원 가입 완료가 성공으로 확인됨 | 계정 단위의 성공 결과를 권한 내에서 계측할 수 있는지 검토 | 미구현·미실측. 로그인 성공·가입 버튼과 구분 |
| E 탐색 | `post_detail_loaded` | 공고 상세의 허용 정보가 성공적으로 표시됨 | 앱 계측 후보. 단순 홈 진입·로딩 실패와 구분 | 미구현·미실측. 성공적인 탐색 전체를 대표한다는 가설 |
| A 첫 신청 성립 | `application_created` | S11 첫 메시지 전송 성공으로 신청 생성 확인 | 신뢰할 수 있는 성공 응답·도메인 상태와 연결 가능한지 3.10 검토 | 미구현·미실측. 버튼 클릭·메시지 시도·전송 실패 제외 |

가입 전에 공고를 보는 방문자는 `E_guest`로 구분한다. G 이전의 탐색을 G 이후 탐색으로 옮겨 채우지 않는다. 기존 회원·재로그인은 신규 가입 G의 분모에서 제외하고 별도 재방문 흐름으로 관리한다. 공고 작성·모집자는 별도 경로이며 신규 신청자 퍼널에 억지로 넣지 않는다.

PRD의 신청→확정→실제 완료→평가 지표는 향후 확장 경로다. 확정 요청이나 수락 시도는 실제 확정과, 예상 종료 시각은 실제 완료 처리와 구분한다. 이 Batch는 해당 확장 계측을 구현하지 않는다.

## 3. 전환 정의·비교 가능성

### 같은 집단과 같은 관찰 기준

1. 실제 지표에는 유입 집단(코호트), 집계 기간의 시작 포함/끝 제외, 전환 관찰창, 기준 시간대, 관찰 종료 여부를 명시해야 한다. 값은 실측 전 협의 대상으로 남긴다.
2. 본 문서의 계정 퍼널은 신규 가입 G 집단에서 가입 이후 E, 이후 A를 순서대로 충족한 고유 계정 수를 센다. A는 E를 충족한 집합의 부분집합이어야 한다.
3. 사람 전환 수는 같은 계정의 반복 신청을 한 번만 센다. 신청 건수·재신청 건수는 별도 사건 지표이며 사람 전환율과 섞지 않는다.
4. 같은 사건 재시도·중복 전달은 동일 논리 성공 사건으로 한 번만 센다. 실제 중복 제거 키의 구현은 서버·클라이언트 담당 확인 전 확정하지 않는다.
5. 관찰창이 끝나지 않은 사람은 진행중으로 표시한다. 기간말 가입자의 향후 신청이 아직 관찰되지 않았다고 최종 실패로 단정하지 않는다.

| 지표 | 계산 제안 | 사용 조건·N/A 조건 |
|---|---|---|
| K-GE 신규 가입→탐색 | G 뒤 E를 충족한 고유 신규 계정 / G 고유 계정 | 동일 G 집단·관찰 기준 필요. 분모 0은 N/A |
| K-EA 탐색→첫 신청 | G 뒤 E 뒤 A를 충족한 고유 계정 / G 뒤 E 고유 계정 | 앞 단계 건너뛴 A는 별도 이상/다른 경로로 분류 |
| K-GA 가입→첫 신청 | G 뒤 E 뒤 A 고유 계정 / G 고유 계정 | 위 두 지표와 동일 집단·관찰 기준에서만 비교 |
| K-CH 채널별 반응 | 제공되는 반응 건수와 같은 정의의 노출·도달 분모를 명시 | 플랫폼 정의 확인 전 계산 보류. 채널 간 단위 다르면 직접 비교 금지 |
| K-X 채널→설치→가입 | 합법적·승인된 연결과 동일 집단이 확보된 경우만 설계 확정 | 채널 방문·설치·가입 연결 불가면 N/A. 개별 단계의 집계만 보고 |
| Q-LINK 연결 가능 범위 | 연결 가능한 구간/불가 구간·누락 사유를 표로 보고 | 이를 전환 성과로 해석하지 않음. 미상 유입은 임의 채널 귀속 금지 |

고유 사람 수가 아닌 조회·반응 건수 기반 비율은 ‘사람 전환율’이라고 부르지 않는다. 보고 대상 구간의 연결률이 낮다면 연결된 일부의 결과를 전체 유입 성과로 일반화하지 않는다. 귀속 방식을 아직 정하지 않았으므로 마지막 클릭·첫 클릭·여러 채널 중 하나를 임의 선택하지 않는다.

### 실제 기록용 빈 표

| 기간·관찰창 | 대상 집단·구간 | 원천·집계 단위 | 분모 | 분자 | 연결·누락 | 결과 | 관찰 종료 여부 |
|---|---|---|---|---|---|---|---|
| 미확정 | 채널 D→V | 플랫폼 정의 확인 필요 | 미수집 | 미수집 | 미확인 | N/A | 미실행 |
| 미확정 | V→I→G | 채널·스토어·앱 연결 확인 필요 | 미수집 | 미수집 | 연결 불가 가능 | N/A | 미실행 |
| 미확정 | G→E→A | 신규 계정 성공 상태의 계측 검토 필요 | 미수집 | 미수집 | 미구현 | N/A | 미실행 |

빈칸·미수집은 0건이 아니다. 목표 전환율·유입 목표·고객 비율은 산출하지 않았다.

## 4. 합성 사례와 기대 결과 — 실제 회원 아님

계산 규칙만 확인하기 위한 고정 자료다. `syn-*`는 가상의 표식이며 실제 계정과 연결하지 않는다. 합성 관찰창은 2026-10-01 00:00 이상, 2026-10-02 00:00 미만 KST이며, 이 창 안에서 순차 G→E→A를 확인한다. 실서비스의 관찰창·성과 목표를 정한 것이 아니다.

| 사건 ID | 합성 대상 | KST 시각 | 사건 | 처리 |
|---|---|---|---|---|
| t01 | syn-01 | 10-01 09:00 | G | 가입 집단 포함 |
| t02 | syn-01 | 10-01 09:05 | E | 탐색 포함 |
| t02 | syn-01 | 10-01 09:05 | E 중복 전달 | 같은 사건 ID로 1회 처리 |
| t03 | syn-01 | 10-01 09:06 | 신청 버튼 클릭 | A 아님 |
| t04 | syn-01 | 10-01 09:07 | 메시지 전송 실패 | A 아님 |
| t05 | syn-01 | 10-01 09:08 | A 성공 | 첫 신청 포함 |
| t05 | syn-01 | 10-01 09:08 | A 성공 중복 전달 | 같은 사건 ID로 1회 처리 |
| t06 | syn-01 | 10-01 10:00 | 다른 신청 A 성공 | 사건 건수는 별도, 사람 전환은 여전히 1 |
| t07 | syn-02 | 10-01 11:00 | G | 가입 집단 포함 |
| t08 | syn-02 | 10-01 11:10 | E | 탐색 포함 |
| t09 | syn-02 | 10-01 11:11 | 재로그인 | G 추가 아님 |
| t10 | syn-02 | 10-01 11:12 | 메시지 전송 실패 | A 아님 |
| t11 | syn-03 | 10-01 12:00 | G | 가입 집단 포함 |
| t12 | syn-03 | 10-01 12:05 | A 성공·선행 E 없음 | 원천 성공 기록은 보존하되 순차 퍼널 A에서 제외·별도 경로 점검 |

| 검산 항목 | 기대 결과·의미 |
|---|---|
| 중복 제거 | 18행의 전달 기록 → 고유 사건 16개. 같은 ID의 중복 2개 제외 |
| 신규 가입 G | syn-01·02·03 = 3명 |

| 원천 성공 A 사건 수 / 성공 계정 수 | t05·t06·t12 = 3건 / syn-01·03 = 2명. 순차 첫 신청 1명과 구분 |
| 분모 0 사례 | 빈 G 집단 → N/A, 0% 아님 |
| 원천 누락 사례 | E 수집 자체가 불가능한 집단 → K-GE·K-EA는 N/A. 실제 0명과 구분 |
| 유입 미상 사례 | 채널 집계 D=100조회·V=10클릭과 위 G=3명은 개인 연결 없음 → 채널→가입 전환 N/A |
| 관찰 미종료 사례 | 관찰 종료 전 조회라면 진행중. 최종 미전환으로 판정하지 않음 |
| 실제 완료가 아닌 사례 | 예상 종료 시각만 지난 합성 약속은 실제 완료 집계에 포함하지 않음 |

끝 경계·순서 누락을 감추기 위해 사건을 생성하지 않는다. syn-03의 성공 A를 지우거나 앞선 탐색이 있었을 것이라고 추정하지 않는다. 수집 누락인지 실제 다른 경로인지는 별도 점검 대상이다.

## 5. 개인정보 최소화 검토와 협업 요청안

### 이번 문서에서 확정하지 않은 것

- 실회원 식별자·쿠키·기기 ID·광고 ID·IP·SNS 계정 연결, 원문 메시지 수집 및 분석 공급사 전송을 승인하지 않는다.
- 관찰 가능한 도메인 성공 결과와 집계만으로 정의를 검토하되 실제 필드·접근권한·법적 근거·보관기간은 민규/종현/유미 확인 후 결정한다.
- 같은 사람이라는 추측으로 다른 기기·채널·로그인 전후 기록을 붙이지 않는다. 미상은 미상으로 남긴다.
- 아래 이벤트명은 제안이며 서버 응답·정책 변경이나 새 API 계약이 아니다. SDK·추적 코드·운영 DB·실회원 자료는 건드리지 않았다.

### 종현 3.10 전달용 — 미발송

1. D/V/I의 실제 제공 지표와 설치·첫 실행의 구분, 계정 성공 사건 G/E/A에 대한 계측 가능 범위를 확인해 달라는 요청안.
2. 첫 메시지 전송 성공→신청 생성과 재로그인·재시도의 신뢰할 수 있는 판정 지점, 건너뛴 단계의 처리 근거 확인 요청안.
3. 합성 18행을 같은 정의로 계산해 고유 사건 16·G/E/A 3/2/1을 얻는지 대조할 요청안.
4. 실제 관찰창·귀속·동의·필드·보관은 미결정임을 전달하고 필요한 민규 검토 연결을 요청할 안.

외부 메시지는 보내지 않았다. 실제 앱 계측이나 종현 구현과의 집계 일치는 검증하지 않았으므로 해당 완료 조건은 대기다.

## 6. 개별 TASK 인수인계

- 수행: 단계·성공 사건·고유 집단·전환·미상·기간·중복 규칙과 측정 표를 제안하고 합성 검산 자료를 준비했다.
- 문서 검증과 실제 계산 결과: [B01 인수인계](batch-brand-strategy-handoff.md)에 실행 결과를 남긴다. 표의 기대값만으로 검산 실행을 대신하지 않는다.
- 미완료: 종현 3.10 전달·구현과의 대조, 실제 데이터 가용성·관찰창·귀속·개인정보 조건 확정. Notion 제안은 `대기 → 작업 중`이다.
- 8.4 전달: K-CH의 같은 채널·같은 단위 원칙, K-GE/K-EA의 집단·단계 구분, K-X 연결 불가 N/A 규칙. 모든 실제 성과는 미실행으로 유지한다.
