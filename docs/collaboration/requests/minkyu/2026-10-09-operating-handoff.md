## 최종 배포 순서와 판정

1. 최종 API·worker·completion 소스 SHA와 모든 SQL의 순서/해시를 준비한다. 이미 운영 적용한 이력과 미적용 항목을 구분한다. 사본 파일과 검사 전 임의 SQL은 포함하지 않는다. READY가 아니라 PREPARED_NOT_ACTIVATED로 기록한다.
2. 최신 전체 DB·앱 catalog/함수·ACL·역할 실효 권한·Storage 실제 바이트의 일관 백업을 만들고 독립 환경에 복원한다. 원본/복원 SHA·건수와 미확정 기록을 비교한다. 알려진 성공 삭제의 최소 영수증으로만 재파기하고 UNKNOWN은 보존한다. 접근 담당과 실제 보관 만료 기준을 연결한다.
3. API/DB의 각 적용을 하나씩 확인한다. 실패·응답 유실·UNKNOWN이면 다음 변경을 중단하고 같은 원 키를 조회한다. lease 만료·관찰 응답·새 키로 성공을 만들지 않는다.
4. completion 전용 LOGIN과 queue 전용 최소 LOGIN, 운영 CA/호스트 검증·내부 비밀·역할/채널을 검사한다. 테스트 CA·테스트 bootstrap 값은 운영으로 복사하지 않는다. 환경 구문 PASS와 실제 연결/권한/READY를 구분한다.
5. 검토된 기능 조립에서 실행기 READY·영속 예약 조회·누락 복구·두 프로세스 경쟁·LISTEN 유실·재시작을 검증한다. completion은 실제 완료/후기 공개 기한을 처리한다. 종류별 closed guard를 임의 개방하지 않는다.
6. runner READY와 새 실행 증거를 같은 점검 구간에 확인한 뒤 기존 cron 전환표를 적용한다. 이전/이후 예약·중복 전송·빠진 대상이 없는지 확인한다. 순위·서울·회원 AI 등 보류 기능은 계속 보류한다.
7. 실제 두 회원 흐름·주기 처리·복구·지원 담당 인수인계까지 확인한 뒤 운영7/7과 기능 전체표를 판정한다. 사용자가 지금 보류한 실회원 흐름은 합성 JWT로 완료 처리하지 않는다.

## 장애 관측과 중지·복구

| 관측 | 확인할 최소 기록 | 중지·복구 |
|---|---|---|
| queue/예약 처리 지연 | kind·원 requestId·예정/실제 시각·상태·고유 작업 수 | 현재 점유와 영속 예약 조회, 누락만 정해진 처리로 연결 |
| 응답 유실/UNKNOWN | 원 부모/child 키·원 global/job lease·DB 효과/확정 상태 | 새 claim/dispatch/DELETE/ACK 금지, 같은 키 조회·원 ACK 확인 |
| 삭제 ACK 있음 | 원 dispatch/ACK hash·대상 hash·복구 출처·외부 부재 확인 | GET-only 확인 뒤 기존 ACK의 DB 완료 경로만 사용 |
| 삭제 BEGIN만 있음 | external_pending·원 키·미확정 상태 | 삭제 성공으로 단정/ACK 생성/재삭제하지 않음, 원 증거 보존 |
| 예산/정산 불일치 | 원 계정·한국시간 사용일·예약/사용량·최소 receipt | 미확정 예약 유지·자동 계정 전환 금지, 원 계정/날짜 정산 |
| 파기 지연 | 확정 종료/기한·대상 최소 ID·처리 상태 | 확정된 만료만 처리, 정책/TTL을 worker가 임의 결정하지 않음 |
| Auth/공급사 장애 | 원 요청·상태 코드·typed 오류·시각 | 일반 사용자 인증 실패를 서비스 자격으로 우회하지 않음 |

진단에는 AI 대화·공급사 원응답·채팅 원문·회원 이름/주소·비밀을 저장하지 않는다. 진단30일/보안90일 및 비용 원장 공급사 기간 종료+90일은 정책 기준이며 최소 멱등 영수증과 백업의 기간은 별도 미정이다. 운영 지표의 임계값·알림 받는 담당·대체 연결은 실제 담당 확인 뒤 정한다.

## 인수인계 시 남길 증거

최종 source/database manifest, 운영 전/후 이력·catalog·권한/역할 비교, READY/예약/경쟁/복구·주기 처리 영수증, 실회원 검증 결과, 전체 백업/Storage 복원 결과, 실제 접수/본인 확인/결과 안내 검증, 담당/대체/비용/백업 권한과 보관 만료를 연결한다. 접근 제한된 영수증의 경로/hash만 공개 문서에 남기고 원문·실제 환경 비밀은 포함하지 않는다. 부분 PASS·실패·NOT_RUN·보류를 유지하며 검증 도구 존재를 운영 완료로 계산하지 않는다.
