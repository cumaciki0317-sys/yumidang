# 외부 공급사 공식 공개 근거 재검토

2026-10-10, 작업자 minkyu. 전체 관리 75%(21/28), 운영 2/7의 기존 분모를 유지한다. 이번 작업은 공개 공식 문서 읽기와 자기 요청 문서 작성뿐이다. Docker·리소스 조회·DB 질의·키 사용·공급사 API 호출·로그인·회원 원문 전송·결제·외부 메시지·활성화는 0이다. member110 STOP 자동 승인 검토 거절 이후의 독립 준비이며, 거절된 중지나 새 startup window를 우회하지 않는다.

## 이전 확인과 이번 차이

[기존 실행 기록](2026-10-09-backend-execution.md) 4.45와 공급사 읽기 기록, [공급사 계약 검토](2026-09-29-provider-api-review.md), [공식 Top10 계약](2026-10-02-kopis-top10-contract.md)을 먼저 확인했다. 서울 HTTPS와 KOPIS basedate는 이전에도 보류였고 Potens API 개인정보/사용량 조건도 미확인이었다. 이번 재확인에서 이 보류를 해소하는 새 계약이나 실응답 증거는 확보하지 못했다. 문서가 없거나 공급사가 지원하지 않는다고 단정하지 않는다.

## Potens: 공개 안내와 API 계약의 구분

[공식 홈](https://potens.ai/)에서 제품 안내와 Claude Sonnet 4.6 표시를 읽었다. 이는 특정 유미당 API 계정의 모델 ID·버전·하위 처리자 계약이 아니다. 현재 선택 모델을 이 표시로 교체하거나 실제 API 모델을 확인했다고 기록하지 않는다.

공식 홈의 로그인 링크와 [ai.potens.ai](https://ai.potens.ai/)는 이번 web 읽기에서 Internal Error였고, `potens.ai`·`comento.kr`로 제한한 검색에서도 해당 API에 적용되는 계약 본문을 확보하지 못했다. 이는 도구의 접근 실패/검색 범위의 한계이지 약관 부재나 서비스 장애 증거가 아니다. 공식 도메인의 라운지 게시물과 AI 뉴스는 API 개인정보/청구 계약 근거로 채택하지 않았다. 같은 이름을 쓰는 다른 업체의 privacy 문서도 제외했다.

| 확인 대상 | 현재 판정 | 완료에 필요한 계정/API 적용 근거 |
|---|---|---|
| 입력·응답·오류 로그 | 미확인 유지 | 실제 `/api/chat` 원문 저장 여부, 항목, 접근자, 기간과 예외 |
| 캐시·백업 | 미확인 유지 | 원문 캐시/백업 유무, 만료·백업에서의 삭제와 복원 시 처리 |
| 학습·평가·하위 처리자 | 미확인 유지 | 제공사와 실제 모델 업체 각각의 적용 범위, 학습/품질평가 사용 여부 |
| 삭제 | 미확인 유지 | 계정/요청별 삭제 가능 범위, 완료 시점, 로그·캐시·백업·하위 처리자 예외 |
| 공동계정·서비스 제공 | 미확인 유지 | 개발/운영 서버키, 여러 최종 사용자 처리 허용, 계정 사용량 합산·제한 |
| 모델·출력 제한 | 미확인 유지 | 실제 API 모델/버전, 출력 최대값 지원 필드와 서버 강제 상한 |
| 포함량·사용량·초기화 | 미확인 유지 | 계정 포함량/리셋 기준, 토큰·캐시·재시도·실패 청구 단위, 추가 결제 방지 |

학습 미사용을 원문 미보관으로 해석하지 않는다. [이전 종현의 실제 계정 검증](../jonghyun/2026-10-05-real-environment-validation.md)에서 관찰한 token_usage 필드는 과거 해당 응답의 관찰이며 공급사 강제 출력 상한·실제 모델·청구 단위 계약을 대신하지 않는다. 현재 어댑터도 확인되지 않은 출력 제어 필드를 임의 전송하지 않는다. 계약 답변을 받기 전 회원 원문 전송과 공급사 활성화 보류를 유지한다. 기존 문의 초안을 발송하거나 추가 메시지를 만들지 않았다.

## 서울 문화행사 HTTPS

[서울시 문화행사 공식 데이터 페이지](https://data.seoul.go.kr/dataList/OA-15486/S/1/datasetView.do?tab=A)는 `culturalEventInfo`, 시작/끝 인덱스와 문화행사 필드를 안내한다. 페이지의 최신 표시 데이터 갱신일은 2026-10-09, 주기는 하루 1회다. API 예시는 여전히 `http://openapi.seoul.go.kr:8088/`를 사용한다. [공식 활용 안내](https://data.seoul.go.kr/together/guide/useGuide.do)의 코드 예제도 HTTP이며 한 번 요청의 최대 1,000건과 sample 제한을 설명한다.

HTTPS 홈페이지가 열린다는 사실이나 데이터 갱신일이 최신이라는 사실은 문화행사 API의 HTTPS 경로·인증서·redirect·키 전달 안전성·실제 JSON 성공을 입증하지 않는다. HTTPS가 불가능하다고 단정하지도 않는다. 남은 조건은 공급사의 정확한 HTTPS endpoint/지원 근거 및 승인된 공개 행사 요청의 실제 TLS·응답 검증이다. 이번에는 sample/실키 API를 호출하지 않았으며 HTTP fallback·TLS 검증 완화·우회 proxy를 추가하지 않았다. 기존 서울 수집 hold는 유지한다.

## KOPIS 공식 최근 7일 / basedate

[공식 OpenAPI 개발가이드](https://kopis.or.kr/upload/openApi/공연예술통합전산망OpenAPI개발가이드.pdf) 16~17쪽(0 기반 페이지 15~16)의 예매상황판 v5.0, 배포일 2026-04-23을 다시 읽었다. 요청에는 stdate/eddate와 최대 31일, 장르/지역 조건이 있고 응답에는 basedate 기간과 공식 rnum·mt20id가 명시된다. 좌석수·상연횟수는 판매 수량으로 바꾸지 않는다.

한 가지 문서 내 확인 필요사항은 요청 표가 date도 필수로 적지만 기간 조회 URL 예제에는 date가 없다는 점이다. 표/예제만으로 rolling 7일의 실제 집계나 인자 충돌 해결을 추정하지 않는다. 문서의 basedate 샘플은 7일 범위지만 임의 stdate/eddate 요청의 실제 응답이 같은 기준을 반환한다는 실증이 아니다.

유미당 기준인 한국 날짜 어제까지 7일, 전국 전체 Top10/뮤지컬 전환은 그대로 유지한다. [기존 실제 공급사 검증과 보류 기록](2026-10-09-backend-execution.md)의 basedate 누락을 이번 문서 확인으로 성공 승격하지 않는다. 다음 완료 증거는 공급사 규격 확인과 해당 요청의 실응답 기간 대조, 공식 순위의 원 번호/식별자/수집 시각 보존이다. basedate 누락·불일치 때 요청 기간을 공식 집계 기간으로 표시하거나 자체 인기순·가상 카드로 채우지 않는다. 키 호출·순위 갱신·공급사 문의 발송은 하지 않았다.

## 인수인계

이번 추가 공식 공개 근거로 닫힌 운영 조건은 없다. Potens 개인정보/사용량 계약, 서울 실제 HTTPS 수집, KOPIS 실제 최근 7일 집계 확인은 각각 미확인 또는 실검증 미완료로 남는다. 코드·SQL·환경 변경과 공급사 정책 임의 확정 없이 독립 준비 문서만 추가했다.
