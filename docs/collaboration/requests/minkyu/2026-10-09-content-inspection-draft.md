# 일반 콘텐츠 사전검사 연결과 탐지 기준 초안 — 2026-10-09

기준은 [정책6-4](../../../../정책.md#6-4-공개글과-채팅-검사)와 공고4-2다. 금지 범주는 이미 확정되어 있다. 이번 초안은 그 범주를 다른 규칙으로 바꾸지 않으며 자동 분류기의 세부 탐지·오탐·품질 기준은 사용자 검토 전 미확정이다. 외부 AI 전송·원문 로그·운영자 채팅 DB 직접 열람을 추가하지 않는다.

## 확정 정책과 검사 대상

성희롱·협박·혐오·인격 모욕·사칭·스팸·허위 모집·금전/민감정보 강요·아동 성적 착취/학대 콘텐츠는 금지한다. 사실·경험에 근거한 부정 평가·비판은 허용한다. 공개글의 개인정보·금지 콘텐츠는 등록 전에 검사하며, 채팅은 명확 고위험 차단과 애매 위험 확인 후 그대로 전송을 구분한다.

| 저장 경로 | 검사할 자유 입력 | 입력 전체에 대한 DB 결합 |
|---|---|---|
| 공고 생성·수정 | 제목·본문·성향 메모·공개 지역·등록 장소명·태그 | postId·전체 p_input·수정의 expectedUpdatedAt 포함 |
| 공개 프로필·성향 | 소개·관심사·대화 방식 | 전체 배열·MBTI·소개 포함 |
| 가입 완료 | 관심사·대화 방식 | 사진 경로를 포함한 원 가입 입력 전체. 사진 경로는 문장 검사의 대상이 아님 |
| 공개 후기 | 한마디 | 약속·점수·경험·칭찬 코드까지 원 제출 전체 |
| 신청 첫 채팅·일반 채팅 | 실제 메시지 | 작성자·공고/방·원 messageId·정확 본문 |

등록 주소·상세 지점을 제목/본문의 비공개 위치 노출 규칙에 일괄 입력하지 않는다. 정상 주소 입력을 금지 콘텐츠로 판정하면 제품의 정당한 기능을 막는다. 실제 저장 입력 전체를 ticket에 결합하는 것은 분류기에 모든 필드를 전달하는 것과 다르다.

## 판정·오탐 기준의 검토안

아래는 자동 탐지 품질을 검토할 분류 예이며 확정된 분류기 출력이 아니다.

| 경우 | 검토할 처리 |
|---|---|
| 공개 소개/본문의 본인 또는 타인의 실제 연락처·계좌·비공개 상세 위치 | 개인정보 노출 차단·수정/오탐 문의. 공공 장소의 정당한 이름·공지와 구분 |
| 직접적 위해 의사·성적 강요·인증 비밀 강요 등 명확한 고위험 채팅 | 차단. 사용자의 ‘그대로 전송’으로 해제하지 않음 |
| 맥락에 따라 강요인지 정상 대화인지 판단이 어려운 표현 | 확인 안내. 동일 작성자·대상·messageId·정확 본문에 한해 수정/그대로 전송 |
| ‘2번 출구에서 만나자’, 행사/약속 정보 | 정상 전송. 주소나 번호가 있다는 이유만으로 차단하지 않음 |
| ‘약속 시간을 지키지 않아 불편했다’ 등 경험 기반 부정 평가 | 정상 등록. 모욕/협박과 구분 |
| 신고 인용·타인의 위협을 설명하는 문장·오탐 사례 | 인용/대상/의도를 평가. 단어가 존재한다는 이유만으로 본인의 고위험 의사로 간주하지 않음 |
| 검사기 오류·timeout·불명확한 출력·승인된 버전 없음 | 새 저장 승인 ticket 발급 중단. 가짜 allow로 대체하지 않음 |

승인 전에 정상/애매/고위험·공개 개인정보·부정 평가·신고 인용·띄어쓰기/철자 변형 합성 검증 묶음을 만들고 결과를 분리해 검토한다. 검사 통과 수를 정확도 보장으로 표현하지 않는다. 실제 회원 원문을 벤치마크나 오류 로그로 보관하지 않는다. 허용할 오탐/미탐 기준·안내 문구와 문의 처리 담당은 아직 확인이 필요하다.

## 현재 구현·증거와 다음 연결

민규 소유 `_shared/services/content-inspection.ts`는 기존 책임과 겹치는 분류기 폴더를 만들지 않고 일반 콘텐츠 검사 포트를 준비한다. 8개 저장 RPC의 입력과 검사 문장을 분리하고, 승인된 서버 조립값·정책/검사기 버전이 없으면 호출 전에 닫는다. 사용자 헤더/본문으로 승인하지 않는다. 검사 중 원 입력이 변해도 발급에는 검사한 입력만 전달하고 사용자·대상·작업·operation/messageId가 다른 ticket은 거절한다. 공개글에 confirm_required를 허용하지 않고 채팅 high-risk block을 확인으로 승격하지 않는다. 취소를 무시하는 검사기의 늦은 응답은 발급을 시작하지 않는다. 발급 응답 유실 시 자동 재발급/새 요청 키/성공 대체0이다.

현재 포트9·SDK8·HTTP6·factory5개 모형 검증과 Deno 타입 검사는 PASS다. SQL116에 전체 입력 digest·사용자/대상/버전·원 operationId·최소 소비 결과를 구현했고, 실제8개 작성 RPC를 같은 트랜잭션 소비에 연결했다. 가입/preferences 내부 traits는 기존 private validator를 재사용해 이중 소비를 막는다. HTTP 검사·채팅 확인과 원 사용자 JWT의 ticket 조회/저장 adapter도 신뢰된 서버 조립 옵션에 연결했다. 기본은 미설치/SQL disabled이며 정상 검사 강제 기능으로 표시하지 않는다. 계약은 [content-inspection.md](../../../../backend/contracts/content-inspection.md)를 따른다.

변경 전 SQL116의 실제 전체 rollback·두 채팅 세션 동시성 검증은 PASS다. 이어 실제 Auth/PostgREST/제품 HTTP 통합에서 ticket 조회가 회원 상태 공유 잠금을 읽기 전용 트랜잭션에서 사용해 실패한 것을 확인했다. 해당 조회를 POST VOLATILE RPC로 수정하고 새 통합·SQL·동시성 검증 중이다. 이전 PASS는 당시 해시에 한정한다. 실패한 쓰기를 재전송하지 않고 clone·로그·영수증을 보존했다. 직접 RPC gate 구현이 있어도 실제 HTTP PASS·분류기 품질·소비자 확인 화면·운영 활성화는 아직 완료되지 않았다.

검사 ticket의 짧은 실행 유효기간과 최소 멱등 기록의 최종 보관기간은 별개다. 미정 최소키 TTL을 임의 설정/파기하지 않는다. 소비 결과를 시간이 지났다는 이유만으로 새 전송 허가로 바꾸지 않는다. SQL·HTTP·소비자 연결과 실제 격리 검증 후에도 승인된 분류 기준/품질과 운영 적용이 남는다.

합성 판정 검토용24사례를 [content-inspection-cases.json](../../../../tests/fixtures/minkyu/content-inspection-cases.json)에 준비했다. 정상 약속·경험 기반 비판·신고 인용·합성 개인정보·직접 강요·맥락이 애매한 표현을 분리한다. PROPOSED_NOT_APPROVED이고 분류기 품질 PASS/외부 전송 승인이 아니다. 실제 회원 원문·비밀은 포함하지 않는다. 기준 확인 뒤 실제 검토된 분류기의 결과와 비교해야 한다.
