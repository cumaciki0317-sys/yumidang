# 종현 백엔드100 작업 인계

사용자 요청: “푸쉬해서 종현이 풀받고 ‘나 종현이야’ 하면 백엔드 작업을100%까지 진행할 수 있도록”. 이 문서는 이미 승인된 전체 잔여 작업의 재개 지시다. 자기소개 후 계획을 짧게 설명하고 실제 독립 작업을 계속한다. 시작 승인을 반복해서 묻지 않는다.

## 현재 상태와 완료 기준

전체 **79%(22/28)**: 핵심9/10·추가5/6·민규 독립5/5·운영3/7. 최초 계획의 핵심8/10·운영1/7은 과거 출발 수치다. [100% 계획](2026-10-09-backend-100-plan.md), [실행 기록](2026-10-09-backend-execution.md)4.76~4.85와 [정책](../../../../정책.md), [상세 설계](../../../../PLAN_상세설계.md)11장·6~9장을 읽는다. 기능 실제 검증과 운영7/7, 모든 실패·보류·미검증 해소 후에만100%다. 매 보고는 전체 진행률·변경·실제 검증·증거·남은 조건·다음 작업을 포함한다.

## 가져오기와 담당

원격 브랜치는 `minkyu/foundation-harness`다. 기존 작업이 있는 clone은 덮어쓰지 말고 별도 worktree/clone을 만든다. 다음으로 별도 종현 clone과 브랜치를 준비한다. 일반 worktree는 Git 로컬 actor 설정을 공유할 수 있으므로 민규 clone에서 종현 actor로 바꾸지 않는다.

```sh
git clone --branch minkyu/foundation-harness https://github.com/jjackbb/yumidang.git ../yumidang-jonghyun-backend100
cd ../yumidang-jonghyun-backend100
git switch -c jonghyun/backend100
python3 tools/collaboration/setup_actor.py --actor jonghyun
```

기존 종현 전용 작업 브랜치를 갱신할 때는 로컬 변경과 커밋을 먼저 보존하고 `git merge --ff-only origin/minkyu/foundation-harness`의 가능 여부를 확인한다. 실패하면 강제 초기화하지 말고 새 worktree를 사용한다. 다른 브랜치에서 단순 `git pull`만 하면 이 인계를 받지 못할 수 있다. 과거 ZIP·start_jonghyun.py 패키지의 옛 J1 기준으로 시작하지 않는다.

최신 ownership.json을 확인한다. 종현은 백엔드 전체(ownership.json 관리 제외), 인증·DB·마이그레이션·공통 환경·tools/local·기존 민규 및 공통 테스트·모바일 서비스/세션 연결을 이어받는다. 성호의 frontend·모바일 화면/UI/UX 경로는 유지한다. 민규 기록과 정책/hook/지침 관리 파일은 민규 소유다. 후속 기록은 종현 요청 폴더에 작성한다. 수정 전 `check_ownership.py --actor jonghyun --paths ...`, 커밋 전 `--staged`를 실행한다. 복잡한 작업은 별도 worktree의 하네스 팀으로 구현·권한·복구 검토를 분리한다.

## 실제 검증과 아직 없는 증거

- 실제 공개 탈퇴 API→Storage/Auth 삭제→원ACK→SQL115/118 자동 복구→같은 ID/원 JWT 완료 조회 PASS로 운영3단계가 닫혔다. Auth **작업 완료 응답** 유실 검증이며 Auth DELETE 자체 응답 유실 검증으로 확대하지 않는다. 영수증 SHA256 `96d18ee5c88eae455862dc27b977403efb46821b4553ebd781cf06856d20f7c2`.
- 후기 요약14개 배치는0/14. v7 observer 실패·v3 preflight 실패를 보존한다. 마지막 읽기 검증은 제품181테이블·Storage103행·기존320컨테이너 동일, SHA256 `104c0b6090608c810bd2569159928a5f54535d1b31ff5c7e99d7308d6d5343ee`. 성공으로 집계하지 않는다.
- AI22/23 일일·예산 검증 v5 및 후기 요약 preflight v4는 STATIC/모형 검토만 통과했다. 실제 실행은 NOT_RUN. AI24 자정은 실제 한국시간 경계를 기다려야 하며 시계 모형으로 대체하지 않는다.
- native-final 첫 실제 실행은 초기 읽기 쿼리180초 타임아웃 FAIL. 백업/복원 시작 전 실패했고 보호 DB 전체 동일은 미확인이다. 실패 SHA256 `9cf5528952993c68a0ab8a2870c67cf9cf5672ef5596af92551437d74170c322`, 최종 메타 SHA256 `148df202621bc23163b6f8bb19a92e1798bffe1c89afa0db13f0449094723845`. 운영 최종 백업/복원은 미완료이며 기존39개 Storage 실제 바이트 누락도 미해결이다.
- 최근 VM 읽기 관찰은 CPU PSI avg10=99.96%, load90.59로 혼잡했다. 특정 원인은 UNKNOWN이다. 동일 상태에서 재시도하거나 메모리 기준을 낮추지 않는다. 시작 여유1GiB, 실행 중768MiB/3초 기준을 유지한다.

위 원본 영수증·폐쇄 실행 wrapper/graph는 민규 컴퓨터 `/private/tmp`의 비공개 자료이며 Git push에 포함되지 않는다. SHA는 과거 증거 위치의 식별자이지 종현 환경의 PASS 증거가 아니다. JWT·암호·회원 원문·DB 덤프·전체 원본 로그는 전송하지 않는다. 저장소의 기존 Python/TS/SQL 통합 검증 파일과 상세 실행 기록으로 종현 환경에서 새 증거를 생성한다. 민규 임시 환경의 컨테이너 ID·소켓·이미지 digest·경로·그래프 승인·사전 상태를 종현 환경에 재사용하지 않는다.

## 다음 실행 순서

1. 새 clone의 정책·소유권·dirty 상태와 코드, 기존 검증 기록을 대조한다. 실패/미실행과 완료를 별도로 유지한다. 기존 구현을 중복 생성하지 않는다.
2. 종현 환경의 Docker/DB/Storage/이미지/리소스·기존 컨테이너를 읽기로 확인하고 **새 격리 환경만** 구축한다. 로컬 검증 스크립트의 `FOUNDATION = REPO.parent / 'minkyu-foundation'`, 민규 임시 경로·고정 source ID·native proof 의존을 실제 새 경로/입력 계약으로 명시 수정하고 검토한다. 이 인계는 그 스크립트를 그대로 실행해도 된다는 READY 판정이 아니다. 기존 증거 핀을 삭제해 통과시키지 말고 새 기준과 해시를 생성한다. 스크립트 기본 실행에 부작용이 있을 수 있으므로 검토 전 import/실행하지 않는다.
3. 새 graph·사전 snapshot·고유 owned scope·정리 권한·메모리 기준을 검토한 뒤 후기14개 경쟁/철회/숨김/삭제, AI22/23 한도·예산, 실제 자정24를 검증한다. 외부 모델은 합성 어댑터로 유지한다. 공개 탈퇴/5종 실행기 PASS를 보존하며 관련 변경 때만 회귀한다.
4. 실제 SQL119/행사 최신 상세·가격·필터·AI 카드 일치, 메시지 읽음·신고·피드백·주기 파기 소비 연결을 대조한다. 성호 탈퇴 화면은 [요청](2026-10-09-sungho-retirement-consumer.md)을 따른다. `RemoteMemberScreens.tsx`의 민규 worktree 미커밋 화면 수정은 성호 소유라 이번 커밋에서 제외했다. 기존 원격 화면과 소비 계약을 대조하고 성호가 처리하도록 요청 문서로 연결한다.
5. 최종 소스/마이그레이션 해시 고정→운영 읽기 차이 재확인→DB/역할/실제 Storage 바이트 일관 백업·새 격리 복원→삭제 재적용/UNKNOWN/권한 검증→배포·지원·중지/복구 검토 묶음을 준비한다. 준비를 운영 완료로 계산하지 않는다.
6. 실회원은 사용자가 재개할 때 두 네이버 계정으로 팀원이 직접 로그인해 전 과정과 권한을 검증한다. 공급사 보관/학습/삭제/공동계정·서울HTTPS/KOPIS 공식7일·지원/비용/멱등 보관의 미정 조건을 기존 목록에서 확정한다. 조건이 없으면 활성화는 닫되 독립 구현을 계속한다.
7. 구체적인 운영 적용 묶음에 대한 사용자 승인 후 순차 배포하고 운영4~7의 실제 증거를 닫는다. 실회원/공급사/운영 승인이 없으면100% 선언은 불가능하며 남은 조건을 정확히 보고한다.

## 유지할 제한

실회원은 “준비는 됐는데 지금 안함” HOLD 유지. 추가 결제·자동 외부 메시지·정책 임의 확정·회원 원문 외부 전송·운영 DB 쓰기/배포는 승인되지 않았다. member110 정상 중지 승인은 이미 사용됐으며 다른 기존 DB 중지/VM 재시작 권한으로 재사용하지 않는다. Railway Chrome 접근성 조회는 자동 승인 검토가 사적 창 노출 위험으로 거절했고 별도 허용 답변이 없어 보류다. 백엔드 인계가 브라우저 조회 승인으로 확대되지 않는다. 프론트 재설계·스토어 제출·유료 결제 기능을 범위에 추가하지 않는다.

## 이번 인계 묶음 확인

정규 코드·문서194개를 소유권 검사 후 선별했다. 숫자 공백 복제본, 캐시, 옛 ZIP, 성호 소유 화면은 제외하고 원본을 보존했다. 코드와 기록의 비밀 패턴 검토에서 확인된 운영 자격증명은 없었다. 이번 묶음의 추가 회귀는 Node CLI/TLS/공유 큐43개, TypeScript 탈퇴 복구/소비자/큐69개, 운영 준비 Python25개로 총137개 PASS다. Python31파일 AST와 staged diff 공백 검사도 PASS다. 이는 모형·정적·준비 검사이며 미실행 통합/운영 항목을 닫지 않는다. 소유권 이관은 구현 인계 커밋 다음의 정책 단독 커밋으로 적용한다.

구현 인계 커밋은 `30898a9`, 정책 단독 이관 커밋은 `9ae3ce2`다. 이관 정책 행렬은 종현9개 대표 경로 허용·관리/화면8개 거절·성호4개 경로 유지·민규의 이관 경로 편집 거절을 확인했다. 현재 소스에는 후속 `20261010030000_hidden_message_read_receipts.sql`도 포함돼 있으므로, 과거 SQL119 준비 묶음과 현재 파일 개수를 동일하다고 가정하지 않는다. 이 후속 파일의 실제 적용/배포 포함 여부와 검증 증거를 새 최종 묶음에 별도로 대조한다. 과거119개의 실제 증거를 새 마이그레이션 검증으로 확대하지 않는다.
