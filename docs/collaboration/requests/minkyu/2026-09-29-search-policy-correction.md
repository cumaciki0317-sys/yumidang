# 검색 정책 정정과 원문 출처 — 2026-09-29

사용자가 공개지역·이름·정렬·비로그인 필터 기준을 직접 정정하고 검색 조건의 출처 설명을 요청했다. 최초 정정은 민규 현황·AGENTS·이 요청 문서에 기록했다. 이후 코드 수정 요청으로 [5차 하네스](../../minkyu-search-db-harness.json)에 따라 민규 DB/인증 구현을 진행한다. 종현 코드는 직접 수정하지 않는다. 기준 HEAD는 병합한 `bd15429`다.

## 최신 사용자 지시

| 항목 | 적용 기준 |
|---|---|
| 공개 지역 | 동까지 보여준다. 정확한 주소/상세 만남 지점의 별도 관계 권한은 유지한다. |
| 이름 | 공고·대화 중 미확정 상대는 중간 글자 마스킹. 매칭 확정 당사자는 전체 이름. 비로그인은 “동행 1234” 같은 별칭 전체를 표시하며 실명 전체를 공개하는 뜻이 아니다. |
| 정렬 | 추가 답변으로 **등록일 최신순 기본, 시작일 빠른순 선택** 확정. |
| 상태 필터 | 모집 중만 보기 옵션을 제공하되 기본은 전체다. |
| 비로그인 | 공고 탐색 가능. 추가 답변 원문: “비로그인은 나이필터를 전체로밖에 못씀”. 나이만 로그인 상세 선택 제한이며 종전의 날짜 제한까지 유지하지 않는다. |

“공고 매칭 시 전체 이름”은 기존 원문의 확정 당사자 간 공개와 연결해 적용한다. 단순 신청·대화 시작이나 제3자의 공고 열람을 전체 이름 공개로 확대하지 않는다. 별칭 숫자 길이, 2글자/긴 이름 마스킹 경계, 페이지 수를 예시에서 새 정책으로 추론하지 않는다.

## 검색 조건의 실제 출처와 의미

[PLAN.md 3-3](../../../../PLAN.md#3-3-공고장소검색정보-공개)의 115행과 [상세설계 5.2](../../../../PLAN_상세설계.md#52-검색용-주소와-공개-범위)에는 제목·등록 장소명·등록 주소 키워드 검색, 카테고리·비용·일정·작성자 나이 필터가 있다. [IA](../../../planning/design/IA.md) 34·114·157~158행과 [USER_FLOW](../../../planning/design/USER_FLOW.md) 111~118행에서도 확인된다.

| 종류 | 문서에 적힌 의미 | 사용자 화면의 예 |
|---|---|---|
| 키워드 | 공고 제목/등록 장소명/등록 주소 중 일치 항목을 찾음 | “전시”, 특정 장소명 또는 주소 검색. 소개·후기·상세 만남 지점까지 검색하지 않음 |
| 카테고리 | 공고의 활동 분류로 좁힘 | 전시 등 특정 분류만 보기 |
| 비용 | 동행 비용 유형으로 좁힘 | 전체/무료/유료. 행사 입장료와는 구분 |
| 일정 | 공고 일정에 대한 날짜/기간 조건 | 원하는 기간에 진행되는 공고 찾기. 기간 경계·입력 UI는 계약과 따로 설명해야 함 |
| 작성자 나이 | 공고 작성자의 나이로 좁힘 | 나이대 선택. 작성자가 희망하는 동행 상대 나이와 구분 |
| 상태 | 모집 중만 보기 토글 | 기본 전체, 선택 시 모집 중만. 최신 사용자 지시로 명확함 |

기존 답변은 검색어·필터·상태 옵션을 한데 “검색 조건”으로 나열해 각 의미와 출처가 불명확했다. 위 설명은 원문을 풀어 쓴 것이며 새로운 검색 범위를 추가한 것이 아니다.

## 원문 대조에서 확인한 오류

1. [추가 요구 사항](<../../../planning/requirements/추가 요구 사항.md>) 104행과 USER_FLOW 152행에는 **“공개 미리보기는 시·구·동”**이라고 적혀 있다. 종현 search.md의 시군구 제한은 이 원문 및 최신 사용자 지시와 충돌한다. 앞서 원문에 직접 모순이 없다고 설명한 것은 검토 부족이었다.
2. 추가 요구 사항 35~40행은 일반 회원 “김*연”, 비로그인 “동행 123”, 확정 상대 전체 실명을 명시한다. 현재 이름 지시는 이 기본 구조와 일치한다.
3. [구버전 와이어프레임](../../../planning/design/yumidang-wireframes_구버전.html)에는 등록일순↔시작일순 선택 예시가 있지만 당시 검토 중/미동작 표시가 있다. 현재 사용자 지시를 선택 정렬의 최신 기준으로 기록한다.
4. 기간 안 시작→이전부터 겹침 및 모집 여부 우선 복합 정렬은 종현 후속 계약에 적혀 있다. 원기획 Markdown에서는 이 구체적인 정책의 확정 근거를 확인하지 못했다. 다른 대화의 실제 합의 여부를 확인하지 않은 채 사용자 결정이라고 단정하면 안 된다.
5. 기본20/최대50은 기존 SQL/검색 계약의 기술 한도다. 원기획에서 사용자가 정한 페이지 정책이라는 근거는 확인하지 못했다. 이번 답변은 해당 수치를 추가 승인한 것이 아니다.
6. USER_FLOW 118행은 현재 화면의 비로그인 날짜·나이 상세 조건 로그인 안내를 기록한다. 최신 답변은 나이만 전체로 제한하므로 이 이전 화면 설명과 검색 계약의 기간401 정책은 동기화 대상이다.

## 종현담당 수정 요청 — 다음 구현 시

- 대상: `backend/contracts/search.md`, `_shared/contracts/search.ts`, `_shared/services/search-service.ts`, `_shared/db/repositories/search.ts` 및 관련 종현 검색 검사.
- 지역 검사가 동을 거절하지 않도록 계약·공개 카드 검사·가상 자료를 맞춘다. 원본 실명/정확한 주소/상세 지점의 부가 필드 거절은 유지한다.
- 날짜 기간을 비로그인이라는 이유만으로 거절하는 코어 정책을 변경하고, 나이 all만 허용하는 검사는 유지한다.
- 등록일순/시작일순 선택을 입력·RPC·커서에 포함하도록 민규와 맞춘다. 기존 기간/모집 그룹 커서를 그대로 재사용하지 않는다. 기본 전체 상태와 모집 중만 옵션은 유지한다.
- 마스킹/별칭/확정 당사자 공개를 분리한다. 공개 카드가 확정 당사자의 실명을 모든 사용자에게 노출하게 만들지 않는다.

`_shared/`는 `backend/supabase/functions/_shared/`를 뜻한다. 민규는 새 SQL/RPC·공통 인증·HTTP·민규 테스트 및 민규 소유 기획 문서 동기화를 담당한다. UI 문서는 수정 범위 확인 후 함께 최신화한다. 후속 민규 구현·검증과 정확한 연결 계약은 [검색 DB 인계](2026-09-29-search-db-handoff.md)에 기록한다. 상대 파일 직접 수정은 하지 않는다.

## 구현 전에 남은 세부 사항

사용자가 원문 설명을 읽은 뒤 바꾸려는 필터가 있는지 구분한다. 등록일 최신순 기본·시작일 빠른순 선택은 추가 답변으로 확정됐다. 페이지당 수량은 이번 대화에서 새로 확정하지 않았다. 문서의 기존 기술값을 사용자 승인으로 대신하지 않는다. 동 공개·이름 관계·전체 기본·비로그인 나이 전체 제한은 다시 미정으로 되돌리지 않는다.
