# 다계정 연결 시 기존 호출 제한 유지

2026-10-06 사용자 확정: 기존 내부 모델 호출 수 제한도 유지한다. DB/어댑터 연결과 실제 로컬 검증은 완료했으며 외부 공급사 호출·운영 활성화는 별도다.

## 현재 확인된 동작

`AI_BUDGET_LEDGER_ID`가 선택한 원장의 `open_calls + settled_calls`에 매 실제 모델 예약이 한 번씩 반영된다. 원장은 날짜별·계정별이 아니며 정산은 호출 슬롯을 반환하지 않는다. 회원의 한국시간 하루20회는 첫 모델 예약 때 세는 별도 제한이다. 탐색·요약 각각의 모델 호출과 재시도도 호출 원장에 포함된다. 운영 원장ID·call_limit 숫자는 저장소의 합성 테스트 숫자로 대체하지 않는다.

## 민규 DB/어댑터 연결 요구

- 기존 원장ID·call_limit·누적 카운터를 유지한다. 새 날짜·계정을 이유로 원장을 새로 만들거나 카운터를 초기화하지 않는다.
- 한 예약이 기존 호출 원장과 원래 계정·한국시간 일자를 함께 참조한다. 기존 호출 검사와 계정/전체 토큰 예약은 같은 트랜잭션에서 성공하거나 모두 롤백한다.
- 계정 예산 거절은 기존 호출 카운터를 변경하지 않는다. 호출 원장 한도 소진은 `global_budget_denied`로 반환한다.
- 정산은 원래 원장에 `open_calls - 1`, `settled_calls + 1`을 멱등 적용한다. 미확인 사용은 예약을 보존하며 날짜가 바뀌어도 재전송·자동 반환하지 않는다.
- 기존 `unit_limit` 또한 별도 원장 제한이므로 임의 제거하지 않는다. 기존 기술 단위와 공급사 토큰 포함량을 동일하다고 설명하지 않는다.

## 종현 연결 요구

대상은 종현 소유 `ai/providers/account-pool.ts`와 `ai/providers/runtime.ts`다. 민규는 직접 수정하지 않는다. `AccountReservationPort`의 `account_budget_denied`만 호출 전 다음 계정으로 이동하고 `global_budget_denied`에서는 중단한다. 기존 단일계정 budget router와 pool을 겹쳐 예약/회원 횟수를 두 번 차감하지 않는다. 민규 원자 RPC 어댑터는 실제 경쟁·원 계정/일자 지연 정산·미확인 예약 보존 검증을 통과했다. 공급사 승인과 종현 runtime 연결·검증이 끝나기 전 외부 호출은 비활성 상태를 유지한다.

## 완료 검사

마지막 호출 슬롯의 경쟁 예약 한 번만 성공, 계정 변경으로 호출 제한 우회 불가, 계정 거절 후 카운터 보존, 동일 정산 재전송의 중복 없음, 자정 후 원 계정·원 일자 정산, 미확인 예약 보존, 회원20회 중복 차감 없음을 실제 DB/HTTP로 확인한다. 현재 민규 잔여6번은 완료다. 계정 pool→민규 adapter→실제 HTTP/DB 연결도 검증했으며 제공처 모델 호출은 합성 응답으로 구분했다. 실제 자정 경과 대신 원 일자를 고정한 지연 정산 fixture를 사용했다.
