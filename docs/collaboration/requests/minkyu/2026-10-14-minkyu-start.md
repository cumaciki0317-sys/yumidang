# 민규 자기소개 시작 인계

## 2026-10-20 현행 기준과 이 문서의 적용 범위

이 문서는 현재 요구와 구현 계약을 구분한다. 아래 기술 시그니처·기존 SQL·검증 기록은 실제 구현 근거이며 새 정책 요구가 자동 구현됐다는 뜻이 아니다.

- 담당은 현재 민규=BE·AI·검색·행사·서버 운영, 종현=FE·UX/UI·앱 API/세션 소비·빌드, 유미=UT·출시/지원 책임이다. 아래 옛 종현 BE·성호 UI 배정은 당시 기록이며 현재 실행 권한으로 사용하지 않는다. 구체 파일은 현행 소유권 정책을 따른다.

최신 기준: [정책.md](../../../../정책.md). 구현과 남은 조건: [서버·DB 대조 원장](../jonghyun/2026-10-20-policy-implementation-audit/server-audit.json).


“나 민규야” 또는 “민규입니다”를 받으면 actor=`minkyu`로 [공통 자동 시작 절차](../../team-start.md)를 적용한다. 사용자 승인된 본인 담당 업무를 바로 이어가며 별도 시작 승인을 반복 요청하지 않는다. 이 문서는 민규가 관리하는 공통 인계이며 실제 민규 산출물의 소유권을 바꾸지 않는다.

## 담당과 파일

- WBS 업무 책임: BE·AI·Infra·DB/RPC/마이그레이션·검색/행사/장소/jobs·서버 OPS·공통 정책/소유권 관리.
- 편집 후보: `backend/`, `tools/local/`, `tools/collaboration/`, 공통 정책/최상위 문서, 서버 테스트(개별 UI/클라이언트 예외 확인). 정확한 허용 여부는 HEAD 소유권 검사로 확인한다.
- 실제 파일 진입점: [백엔드 실행](2026-10-12-backend100-execution.md)·[Auth 최신 실행](2026-10-13-auth-lifecycle-execution.md)·[최신 합성 검증 인계](../jonghyun/2026-10-14-minkyu-final-handoff.md)·[진행 기록](../../minkyu-progress.md)·[서버 계약](../../../../backend/contracts/service-api.md), `backend/supabase/functions/`, `backend/supabase/migrations/`, `tools/local/`.
- 본인 기록·상대 담당 요청: `docs/collaboration/requests/minkyu/`. 상대 요청/현황 파일은 편집하지 않는다.
- QA는 세 사람 공동 책임이며 결함 수정은 해당 파일 단독 owner가 한다.

## 첫 작업 결정

현재 첫 후보는 **[4.2] 최신 정책·API 계약·DB 구현 차이 검토**다. 카탈로그의 현재 상태·담당·Notion 링크를 확인하며 재개 시점 변경과 선행 조건에 따라 다음 독립 미완료를 선택한다.

[WBS 전체 작업과 담당/상태](2026-10-14-wbs-task-catalog.md)에서 본인 담당을 필터링하고 해당 Notion 페이지 본문·우선순위·선행 작업과 실제 파일 증거를 읽는다. 완료 항목을 시작 목록에 다시 넣지 않는다. 공동 담당 항목은 산출물과 수정 경로를 나눠 같은 파일 동시 편집을 피한다.

최신 실행 기록과 실제 HEAD의 서버 구현/검증 증거를 대조하고 BE/AI/서버 OPS 미완료 중 독립적으로 진행 가능한 첫 항목을 이어간다. 과거 종현 J01~J09 기록의 완료/PASS는 보존하고 새 민규 담당 서버 차이만 구현한다. FE·앱 클라이언트 수정은 종현에게 요청한다. 운영 준비와 실제 운영 적용을 분리하고 실회원 HOLD 및 대상 VM identity/여유 기준을 유지한다.

현재 전체 백엔드 마지막 명시 기준79%(22/28)는 이번 인계 작성으로 늘리지 않는다. 실제 진행 보고에는 선택한 WBS ID·파일·검증·조건·다음 작업을 남긴다. Notion 완료 상태만으로 실제 구현/운영 완료를 판정하지 않는다. 공통 시작 절차의 실회원·공급사·운영·외부 전송·커밋/푸시 경계를 그대로 적용한다.

## 민규 담당100% 재개 — 2026-10-19 사용자 정정

목표는 민규 담당 활성44개 전체다. [전체 담당 대조](2026-10-19-minkyu-full-scope.md)와 [전체 실행 하네스](../../2026-10-19-minkyu-full-scope-harness.json)에서 항목별 미완료를 이어간다. [10/18 완료 기록](2026-10-18-plan-completion.md)은 일부 실행 계획의 완료 증거이며 민규 전체 완료가 아니다. 해당 계획에서 제외했던 업무도 민규 담당에 그대로 남는다. 현재 전체 프로젝트79%(22/28)를 민규 담당 완료율로 보고하지 않는다.

이미 완료한 Auth·합성 AI·준비 도구는 보존하고, 전체 담당의 다음 독립 구현·검증으로 진행한다. 중간 묶음 완료는 진행 보고로 알리고 전체 목표를 완료 처리하지 않는다. 실회원·공급사·운영·원본 확보 조건은 각 항목에 연결하며, 다른 독립 작업을 막는 일괄 조건으로 사용하지 않는다.
