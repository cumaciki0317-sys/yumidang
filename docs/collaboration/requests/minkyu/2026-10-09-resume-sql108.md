## 이번 수정과 검증

민규 소유 테스트 실행기 세 개만 보완했다. 제품 코드·SQL100~108·종현 파일은 이번 재개에서 수정하지 않았다. 편집 전 소유권 검사와 하네스 읽기 전용 검토를 수행했다.

`member_cleanup_ack_recovery_local.py`는 기존 fixture·열린 제어·점유·RPC 권한을 거절하고 변경과 전송 전에 private 단계·식별자를 저장한다. 전역 점유를 잠금·확인한 뒤 테스트 dispatch를 준비하며 정리할 때 타인 token을 보존한다. 테스트 탈퇴에 필요한 pipeline 준비는 같은 트랜잭션 안에서만 열고 원복한다. 세션 식별자는 소유자 문맥에서 읽어 회원 RPC에 전달한다. 재개는 사진이 존재하고 탈퇴 작업이 아직 생성되지 않은 단계가 확인됐을 때만 허용한다.

`member_cleanup_ack_recovery_http.ts`는 실제 제품 공통 processor→HTTPS→PostgREST/TLS DB→Storage를 호출한다. 기존 ACK를 가진 합성 Storage task 한 개에서 GET 2회, **추가 DELETE 0 · dispatch 0 · ACK 기록 0**을 확인했다. 잘못된 전역 token·anon은 거절됐고 `applied` 다음 해당 task 전용 호출은 `idle`이었다. 원 ACK·dispatch 해시 불변과 task 완료, 제어·EXEC·전역 점유 닫힘을 별도로 재조회했다. 합성 회원·사진 및 나머지 정리 task는 테스트 자료로 남아 있으며 전체 회원 정리·Auth 삭제 완료를 뜻하지 않는다.

`product_connection_restore108_local.py`는 원 테스트 DB를 읽기만 한다. 새 격리 DB 두 개에서 전체 dump 복원 → 합성 결과 1건의 상세 파기 → 파기 전 백업으로 다시 복원 → 동일 상세 파기 재적용을 수행했다. 첫 복원 직후 보호 대상 테이블·runtime 결과·SQL108 함수·ACL 비교와 마지막 원본의 같은 검사 대상 불변 비교가 통과했다. 전체 DB 모든 테이블·catalog의 전수 비교를 뜻하지 않는다. SQL108 함수 존재·정의·ACL, 메시지 읽음·회원 task·dispatch·ACK·intent 및 `external_pending` 전체 기록 해시를 대조했다. 최소 fingerprint와 관련 없는 기록이 보존됐으며 신규 복원 DB는 공개 포트·bind mount 없이 cron 실행·host 접속·복구 EXEC·제어를 닫았다.
