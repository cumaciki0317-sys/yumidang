## GitHub로 합치는 순서

각자 기존 별도 clone·본인 브랜치에서 한 묶음씩 완성한다. 공유할 때 대상 파일·RPC/DTO·해시/커밋·실행한 검사·미실행 조건을 남긴다. 상대 브랜치 수신 후 기존 변경을 보존하고 담당 검사·충돌 검토·해당 연결 검증을 거쳐 합친다. AI가 추적하지 못한 로컬 파일을 GitHub에 공유된 것으로 안내하지 않는다. 소유권/hook을 바꾸거나 대량 stage로 우회하지 않는다. 이 분담 자체는 커밋/푸시를 실행하지 않는다.

가장 먼저 민규의85/86·신고/worker port 계약과 종현의 신규 소비자 변경을 공유해2번 실제 통합을 진행한다. 이후 원자 예산/AI→검색·행사→두 회원 전체흐름→운영 전환 순서다. 외부 조건 확인은 코드를 기다리지 않고 준비한다.
