# 행사 DB 연결

## 2026-10-20 현행 기준과 이 문서의 적용 범위

이 문서는 과거 요청·설계·검증 기록이다. 아래 원 관찰·명령·해시·PASS/FAIL은 당시 증거로 보존한다. 재개할 때는 다음 현행 조건을 먼저 적용하며 과거 작업 권한·보류를 현재 지시로 재사용하지 않는다.

- 담당은 현재 민규=BE·AI·검색·행사·서버 운영, 종현=FE·UX/UI·앱 API/세션 소비·빌드, 유미=UT·출시/지원 책임이다. 아래 옛 종현 BE·성호 UI 배정은 당시 기록이며 현재 실행 권한으로 사용하지 않는다. 구체 파일은 현행 소유권 정책을 따른다.

- KOPIS는 전체 공연·연극·뮤지컬·클래식·국악·대중음악·무용·대중무용·서커스/마술·복합·아동·대학로·내한·축제 14항목, 어제까지 최근7일·매일 갱신이다. basedate 누락만으로 영구 공개 보류하지 않고 공식 사이트의 실제 기간·조건·공연ID/순위/순서를 대조한 분류만 공개하는 A안을 적용한다. 요청 날짜로 기간을 확정하거나 일일순위를 합산하지 않는다. 확인 기간·시각·출처를 표시하고 실패 때 마지막 검증 기간을 유지한다. 아래 all/musical·basedate 필수 parser·not_enabled는 현재 구현/당시 검증의 기술적 한계이며 최신 제품 정책이 아니다. 일반 공연 수집·칼럼 매핑은 순위 대조와 병행한다.

- 직접 입력 행사는 해당 공고에만 저장/표시하며 공용 목록·별도 행사 상세·검수 후 공용화는 만들지 않는다. 행사명 필수, 공개 행사장 장소/주소 선택이며 개인 주소를 금지한다. 새 연결은 예정/진행 중만 허용하고 종료·공식취소·연기일정미정은 제한한다. 단순 검색 누락은 취소/비표출이 아니다. 제공기관 비표출 원천의 정보와 상세 진입만 숨기고 공고/독립 만남 장소·다른 유효 공개 원천은 유지한다. 공식 동일 개최 식별근거만 통합에 사용하고 원천ID·공고관계·필드출처·가역 이력을 보존한다. 현재 eventId UUID 저장을 직접 입력·통합·비표출 구현 완료로 표시하지 않는다.

- 서울은 키/응답의 평문 HTTP 수집을 활성화하지 않는다. 검토된 HTTPS 자동 수집 경로·실제 최신 응답 envelope·페이지 재개·진행 중 갱신 확인까지 보류한다. 홈페이지 HTTPS 성공이나 HTTP 앞에 s를 붙인 주소는 API 전송 보안 검증이 아니다. 이 보류는 다른 공급사·공통 칼럼/화면 준비의 중단을 뜻하지 않는다.

## 행사 수집·표시 연결

KOPIS·TourAPI·서울 열린데이터를 출시 연결 대상으로 두고 실제 제공 데이터만 노출한다. 공급사별 HTTPS·계정 권한·형식·실패를 확인하며 연결 의도와 실제 성공을 구분한다. `provider + sourceId`로 식별하고 제목만으로 다른 공급사 행사를 합치지 않는다. 제공처 값·시간 정밀도·비용 unknown·공식 출처를 유지한다.

홈과 기본 목록은 이번 주 신규 중 미종료 행사다. 진행 중 포함을 켜면 이전 주 시작 행사도 포함한다. 한국시간 월요일 00:00~다음 월요일 00:00 미만을 사용하고 월별 주차는 목요일 귀속 규칙으로 표시한다. 과거 행사는 조회 가능하지만 종료 행사를 새 동행 모집 대상으로 연결하지 않는다. 작성용 선택은 일정과 겹치는 진행 중·예정 행사다.

`mode=new_this_week|overlapping|post_selection`과 제공처별 필터를 실제 저장소에 연결한다. `StoredEventRecord`의 `sourceStatus`, `precision`, `admission`, `sourceUrl`, `collectedAt` 의미를 유지하고 불명 입장료를 무료로 만들지 않는다. 등록 행사 선택·공급사 갱신으로 작성 중 동행 일정을 자동 변경하지 않는다.

초기 과거 수집 최근 1개월·미래 오늘부터 31일·이미 진행 중 별도 갱신을 적용한다. 요청은 31일 구간·100건/쪽·최대 5쪽·쪽당 15초이며 공급사의 실제 한도를 확인한다. 처리 한도 이후 진행 위치를 보존하고 미수집 범위를 표시한다. 페이지 손상·인증 오류·수집 중단을 정상 0건으로 저장하지 않는다.

## DB·RPC 연결 점검

기존 서비스·repository·RPC 허용 목록을 대조하고 승인된 담당이 필요한 최소 변경을 한다. 현재 정식 migration과 실제 대상 이력을 비교하여 이미 적용한 제안 SQL을 중복 채택하지 않는다. 파일 존재만으로 배포된 RPC라고 판단하지 않는다.

HTTP 응답은 `{data,requestId}` 또는 `{error:{code,message,retryable},requestId}`다. RPC에는 HTTP envelope를 중복 추가하지 않는다. `22023` 입력오류, `P0002` 대상없음, `28000` 인증필요, `42501` 권한거절, `40001` 충돌을 실제 문맥에 맞게 매핑하고 SQL 원문/detail을 공개하지 않는다.

행사비용 JSON은 `CASE`로 객체 자료형을 먼저 검사하며 조건이 명시적 TRUE일 때만 저장한다. 원자배치 실패를 일부정상자료 저장으로 숨기지 않는다. 요약잠금은 투영상태→작업→중간저장/표식 순서를 맞추고 잠금대기후 점유토큰·만료를 재검사한다.
