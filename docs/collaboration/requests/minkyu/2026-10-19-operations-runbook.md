## 실제 실행 전과 복구 순서

1. 현재 대상 project/배포/daemon identity·source를 다시 확인하고 변경 목록과 기존 자원 baseline을 고정한다. 접근 실패는 과거 자료로 대체하지 않는다.
2. 운영 쓰기·배포·기능 중지/재시작·복원 대상은 구체적으로 검토 가능한 작업 묶음을 준비한 뒤 기존 실행 승인 경계를 따른다. 다른 컨테이너나 공유 환경을 중지하지 않는다.
3. 변경 후 동작·권한·기존 데이터·예산/UNKNOWN·정리 영수증을 남긴다. 일부 실패의 전체 재실행, 추측한 다운 SQL·비밀 포함 로그를 금지한다.
4. 실패 시 신규 전송/기능 guard부터 닫는 계획을 따르고 마지막 성공 source와 데이터 복구 지점을 확인한다. 실제 guard 조작은 대상별 승인 범위에서만 실행한다.
5. 담당 전체 대조표에 원증거와 미완료를 갱신한다. 이 실행표 작성과 합성 회귀만으로 운영 가동·복구·100%를 선언하지 않는다.
