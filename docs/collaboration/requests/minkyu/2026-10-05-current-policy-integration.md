## 종현 담당 후속 연결

1. 모바일 최초 전송은 `POST /posts/:id/requests`에 `{messageId,message}`를 보낸다. messageId는 전송 재시도에서 유지하고 새 전송에서 새UUID를 사용한다. 메시지는1..1000자다. DB가 신청/채팅/알림을 원자 처리한다. 실제 모바일 Auth→HTTP→DB 검증은 아직 필요하다.
2. 기존 분류를 가진 역사 공고는 DB에서 읽기·상태 변경을 보존한다. 모바일의 현재16분류 엄격 decoder가 역사 자료 전체를 실패시키는지 확인하고 역사 표시 정책에 맞춰 처리한다. 새 등록은 현재16개만 허용한다.
3. 동의 철회 화면은 `POST /me/ai-processing/withdraw`, `{kind:"exploration"}` 또는 `{kind:"review_summary"}`에 회원 JWT로 연결한다. 일반 프로필/공개 후기 보존, 관련 요약 숨김을 안내한다. 외부 사본 삭제까지 이API가 끝내는 것으로 안내하지 않는다.
4. 요약6 RPC와 작업6 RPC는 전역 worker token을 함께 전달한다. 요약 계약 버전은2026-10-05 입력이며 임의 반환키를 추가하지 않았다. AI는 새 scope4 RPC만 사용하고 generic 예약/snapshot/publish를 직접 호출하지 않는다.

## 운영 연결 대기

운영 Supabase 접근은 확인했으나 migration20개로 최신 로컬과 차이가 있다. 기존 매분 자동완료cron 활성도 확인했다. 전체 drift·변경 영향·복구 절차 및 cron 전환·중복처리 방지를 준비한 후 운영 적용 범위를 확정한다. Railway는 사용자에 따르면 생성됐으며 팀원에게 프로젝트/서비스 페이지와 배포 담당을 확인 중이다. 관리자 DBURL 대신 전용 실행기LOGIN을 사용한다.
