# 유미당 현재 역할과 파일 단독 수정 규칙

브랜치를 받은 뒤 “나 종현이야”·“나 유미야”·“나 민규야”라고 입력하면 [팀원별 시작 안내](team-start.md)에 따라 Notion 담당 작업을 바로 이어간다.

현재 기준은 [2026-10-14 역할 재배정](requests/minkyu/2026-10-14-role-reassignment.md), [backend/ownership.json](../../backend/ownership.json), [정책.md](../../정책.md), [상세설계11장](../../PLAN_상세설계.md)이다. 최신 사용자 승인이 이전 인계의 담당 지시보다 우선한다.

| 영역 | 업무 책임 | 파일 수정 |
|---|---|---|
| BE·AI·Infra·서버 OPS | 민규 전담 | backend 전체·SQL·검색/행사/jobs/AI·계약·환경·tools/local·서버 테스트 |
| FE·UX/UI·앱 연동·빌드 준비 | 종현 | frontend·모바일 UI/클라이언트 API/세션·디자인·지정 UI 테스트 |
| PM/기획·정책 | 유미 주담당·종현 공동 정리 | 공통 정책/요구사항/관리 문서는 민규; UI 설계는 종현 |
| Brand&Marketing·UT | 유미 | docs/planning/ut/·requests/yumi/ |
| QA | 민규·종현·유미 공통 | 영역별 단독 owner; 여러 사람이 같은 파일을 수정하지 않음 |
| OPS | 서버 기술 민규·앱 배포 기술 종현·출시/지원 체계 유미 | 일반 신고 실무/대체 담당의 기존 미정 상태 유지 |

작업자는 민규 `minkyu`, 종현 `jonghyun`, 유미 `yumi`다. 성호 담당과 신규 시작은 제거한다. 옛 owner/작성자/검증 기록과 `sungho` 이름이 든 자산·공급사 계정 ID는 역사 및 실행 연결 보존을 위해 유지한다. 현재 owner는 폴더명보다 정책의 가장 구체적인 규칙으로 판정한다.

## 작업 절차

1. 자기 별도 clone/worktree와 `작업자/작업명` 브랜치에서 HEAD·기존 미커밋·actor·hook·현재 소유권을 읽는다. 다른 clone의 설정/인덱스를 공유하거나 actor를 바꾸지 않는다.
2. 수정 전에 `python3 tools/collaboration/check_ownership.py --actor 작업자 --paths 대상파일...`을 실행한다. 담당 밖 파일은 읽기·검토만 하고 자기 `requests/작업자/` 폴더에 변경 요청을 작성한다.
3. 여러 에이전트도 같은 actor와 파일별 단독 수정 목록을 사용한다. 전체 포맷·대량 스테이징으로 다른 파일을 변경하지 않는다.
4. 커밋 요청이 실제 있을 때만 대상 브랜치/변경 목록을 확인하고 `--staged` 검사와 hook을 실행한다. 자동 커밋·푸시는 하지 않는다. `--no-verify`, checker 변경, actor 변경으로 거절을 우회하지 않는다.
5. 재배정은 사용자 명시 승인 후 민규가 별도 정책 변경으로 관리한다. 각 clone은 새 정책을 받은 뒤 구현한다. 현재 미커밋 후보 정책 검증과 HEAD hook 적용은 별도다.

## QA·UT와 테스트 경계

QA 공통은 요구사항·재현·판정·출시 차단 후보를 함께 확인하는 역할이다. BE/AI 테스트는 민규, UI·클라이언트 전용 테스트는 종현이 수정하며 UT 시나리오·관찰·개선 자료는 유미가 담당한다. `owner=common`이나 복수 owner는 사용하지 않는다. 유미는 명시 UT/요청 경로 밖 편집을 허용하지 않는다. 실제 코드 결함은 소유자에게 연결한다.

새 presentation 컴포넌트는 props로 값과 이벤트를 받고 서버 정책·민감정보 공개 조건을 복사하거나 바꾸지 않는다. 종현의 앱 인증/세션 소비와 민규의 서버 인증/RPC를 구분한다. domain 공통 정책의 민규 예외는 ownership에서 확인한다.

## 이전 인계와 실행 조건

종현 백엔드100·J01~J09 및 성호 UI 배정은 당시 구현·검증 근거로 보존하며 현재 수정 허가로 사용하지 않는다. 세 사람의 자기소개 자동 시작은 [팀 시작 절차](team-start.md)에 따라 각자 현재 WBS 담당과 파일 소유권 범위로 이어간다. 옛 `start_jonghyun.py`는 읽기 무결성 `--check`만 유지하고 백엔드 작업 패키지 실행/생성을 중단한다.

마지막 명시 전체 진행 기준79%(22/28)는 역할 변경만으로 늘리지 않는다. 상태·완료 증거·기존 PASS·실회원 HOLD·공급사 조건·운영 실행·외부 전송·추가 결제·VM/컨테이너 승인 경계는 유지한다. 실제 기능·운영 동작 검증을 이번 담당 동기화 결과로 계산하지 않는다.

## 검사 연결

자기 clone의 현재 actor 및 기존 hook을 먼저 확인한 뒤 `python3 tools/collaboration/setup_actor.py --actor 작업자`를 실행한다. 기존 다른 actor/custom hook은 덮어쓰지 않는다. HEAD 정책은 신뢰 기준이며 유미/성호의 미배정 파일은 거절한다. AI 지침·hook·CI는 OS 파일 잠금이나 시스템 접근 인증이 아니다.
