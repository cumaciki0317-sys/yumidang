## 적용 경계

화면 기능 기준은 기존 Expo 프로토타입과 현재 정책, 디자인 기준은 [guide.md](guide.md) 및 [source-manifest.json](source-manifest.json)의 현재 entry다. Stitch 파일과 이전 복제본은 기능 근거로 사용하지 않는다. 이번 결과는 디자인 문서/토큰/참조 환경 정리이며 Expo 실제 적용은 미완료다. 성호는 허용된 새 presentation 컴포넌트를 props/events로 작성할 수 있다. 기존 실제 화면 연결은 담당자 소유권 확인 후 수행한다. 인증·API·DB·서비스 상태·정책을 디자인 컴포넌트로 옮기지 않는다.

기존 Expo에 필요한 값이나 이벤트가 없는 경우 디자인상의 이름만 보고 새 기능을 만들지 않는다. 누락된 연결 항목을 기록하고 담당 구현에서 해결한다. 정책과 화면 예시가 충돌하면 예시의 동작을 정책으로 해석하지 않는다.

## 컴포넌트 표시 값과 이벤트

표의 이름은 인계용 의미 명칭이며 현재 앱에 같은 타입이 존재한다는 뜻이 아니다. 기존 타입과 콜백을 확인해 매핑한다. 새 API를 요구하는 명세가 아니다.

| 구성 | 표시 입력 | 이벤트 | 지켜야 할 상태 |
|---|---|---|---|
| 공통 내비게이션 | 현재 탭, 기존 목적지, bottom/side insets | 기존 탭 선택 | 48px/12px, 숨김 화면에는 생성 안 함 |
| 홈 약속 카드 | 로그인 표시, 약속 상태, 제목/일정/상대 표시값, D-day | 기존 약속 열기 | guest/empty/booked/ongoing, 동일 최소높이 |
| 둘러보기 필터·정렬 | 선택 조건, 정렬값, 오류/빈/로딩 표시 | 기존 필터 열기/선택/적용/초기화, 정렬 변경 | 누름 중 화살표, 입력/적용 상태 구별 |
| 동행 카드 | 제목/시간/지역/배지, 공개 가능한 프로필, 당도 | 공고 열기, 프로필 열기 | guest 자리표시자, 긴 글, 없음/실패 값 |
| 공고 상세 시트 | 역할, 공개 범위가 적용된 공고/신청/연결 행사/주소, 가능한 액션 | 기존 닫기/채팅/거절/더보기 등 | 31장면 contract, 상세 공개 여부는 기존 상태가 결정 |
| 행사 카드 | 상태/분류/시도/장소/요금/기간/이미지/연결 건수 | 기존 상세 및 연결 공고 열기 | 0건은 상태 표시, 없는/실패 이미지, 긴 제목 |
| 행사 상세 | 기존 행사 정보/포스터/관련 공고 표시 | 기존 CTA | 목록과 글자 크기가 다름, 임의 통일 금지 |
| 채팅 헤더·공고 패널 | 상대 표시 프로필/당도, 공고, role/scene, 가능한 액션 | 접기/펼치기, 더보기, 요청/거절 확인 후 기존 콜백 | 역할별 메시지 정렬, 요청/거절은 확인 팝업 |
| 채팅 메시지·입력 | sender 식별, body/time/sendState, inputValue, canSend, readOnly | 입력 변경, 전송, 재전송, 빠른 문구 입력 | 실패한 본인 메시지 재시도, 재전송은 실제 콜백에 연결 |
| 나 화면 | 기존 탭/프로필/당도/일정/신청/계정 표시값 | 기존 메뉴 열기, 정보 토글 | 마스킹/완료/후기 상태 정책은 기존 처리 |
| 로그인·가입 | 로딩/오류, 네이버 표시 정보, 사진/선택 성향 | 기존 로그인/사진 선택/입력/가입 콜백 | 사진 필수, 선택 성향; 네이버 브랜드 보존 |

표시 입력은 공개 범위·권한 판정이 끝난 값이다. 비로그인 컴포넌트에 실제 이름·사진을 전달한 뒤 가리지 않는다. 이벤트는 사용자의 의도를 전달하며 성공·실패·만료·공개 범위 변경은 기존 서비스 상태의 다음 props로 받는다. 확인 팝업은 로컬 표시 상태로 열고 취소 시 이벤트를 호출하지 않으며, 확인 시 한 번만 호출한다. 빠른 문구의 입력/전송 방식도 승인된 현재 화면과 기존 이벤트를 대조해 연결한다.

## 최신 화면에서 유지할 구체 항목

- 채팅 탭 아이콘은 둘러보기 기준으로 SVG만 translateY(-1px) 광학 보정한다. 활성·비활성 모두 동일하며 버튼 클릭 영역·다른 아이콘·행 중앙 배치는 유지한다. Expo에서는 아이콘 wrapper에 transform: [{translateY: -1}]을 적용하고 버튼에는 적용하지 않는다.
- S10: 공고 제목(15px/700, 최대 2줄) → 이름·만 나이·당도 → 마지막 메시지(14px) 순서다. 제목과 이름 간격4px, 이름과 메시지 간격10px. 상태 칩은 우측 상단12px, 당도는 보라색 텍스트다. 카드 간격18px, 목록 상단 여백12px다. 안 읽은 개수는 프로필 좌측 상단에 빨간색 #EF4444 배지로 표시한다(카드 기준 left/top23px, translate(-50%,-50%), 높이16px, 글자10px/700, 100개 이상99+, 0개 숨김). 마지막 메시지 우측 시간은11px다. 종 아이콘은18px이며 새 알림이 있으면 보라색과6px 빨간 점을 표시한다. 하단 채팅 탭에도6px 빨간 점을 사용하고 검토 패널에서 표시를 전환한다. 빈 상태 아이콘은 동일 말풍선 형태와 연보라색을 유지한다. 박*연 사진은 생성 프로필 스프라이트의 고정 예시이며 실제 회원 기본값이 아니다.
- S10 메뉴: 대화방 500ms 길게 누르기는 앱 프레임 중앙의 메뉴를 연다. 상대 이름20px/700, 대화방 알림끄기(켜기) → 차단 → 신고 → 나가기 순서이며 강조색·구분선은 없다. 스크롤/10px 초과 이동은 길게 누르기를 취소한다. 확인 대화상자와 닫은 후 포커스 복귀를 유지한다. 메시지 수신·읽음·알림 설정 및 신고/차단/나가기는 Expo 상태와 콜백으로 연결하며 HTML은 표시 예시다.

- 홈·둘러보기·공고 상세의 원본 HTML은 승인된 검토시안2의 floatingWhite 재질로 확정한다. #FAF8FE 배경·흰 표면·투명 경계·blur 없음, Pretendard와 #852CFF 유지. 채팅목록 S10의 목록 UI도 사용자 확정이다. 행사·채팅·나·로그인·가입 확장 화면은 잠정 검토 상태다. Expo에는 아직 적용하지 않았다.
- 홈/둘러보기 내비게이션은 흰 플로팅, 로봇은 흰색, +는 단색 보라다. 배경 페이드와 마지막 카드 하단 여백을 함께 대응하되 safe-bottom은 부모에서 한 번 처리한다.
- 동행 카드 중앙 반원은 표시 장식이다. RN에서는 같은 배경색의 가장자리 장식 또는 마스크로 구현하고 카드가 늘어나도 높이50%에 맞춘다. 그림자는 곡선 주변만, 터치는 통과시킨다. 본문/프로필 좌우24px와 점선 #DCD2EB를 유지한다. 카드 내용에 가로 음영이나 모서리 끼움 효과를 넣지 않는다.
- 생성된 프로필 사진은 고정 시안 자산이다. 실제 회원 기본값으로 배포하거나 역할/공개 상태와 무관하게 표시하지 않는다. 기존 공개 가능한 photo props와 오류/비로그인 placeholder를 사용한다.


- 홈의 상단 프로필 및 약속 카드 상대 사진은 실제 이미지 자산이 로딩되는 상태로 적용한다. 비로그인·약속 없음 카드에 삭제한 로그인/동행 둘러보기 CTA를 다시 만들지 않는다.
- 가입프로필은 `auth.css`의 최종 S06 규칙을 따른다. 섹션은 radius18·투명 경계·흰 표면과 floatingWhite 그림자, 섹션 제목15/22, 칩13/18, 입력 높이44, 사진 선택은 중립 보조 버튼이다. 헤더 제목18/26과 섹션 제목15/22를 혼동하지 않는다. 사진 필수·선택 성향·오류/처리 중 표현은 유지한다.
- 홈과 다른 화면에서 제거한 연결·구현 안내 팝업을 서비스 기능으로 복원하지 않는다. 버튼의 실제 목적지는 기존 Expo 이벤트로 연결하며, 시안에서 동작 설명이 없다는 이유로 서비스 이벤트를 삭제하지 않는다. 신청 거절·확정 요청·나가기 확인과 실제 입력 오류 안내는 별개이며 유지한다.

## Native로 옮길 때

- HTML을 WebView로 복사하거나 CSS를 그대로 import하는 방식의 인계가 아니다. 색·간격·글자·표면과 상태 표현을 기존 React Native 컴포넌트에 대응시킨다.
- rem은 root16 기준 비교값. 텍스트 확대를 끄거나 화면 배율로 전체 글자 크기를 강제하지 않는다. 실제 Pretendard weight 매핑과 줄바꿈을 확인한다.
- CSS px 수치는 웹 기준 시각값이다. React Native에서는 논리 단위로 대응하되 브라우저 화면 배율·devicePixelRatio를 곱해 옮기지 않는다. line-height, padding, border를 함께 대응하고 짧은 글/긴 글 및 텍스트 확대에서 확인한다.
- CSS backdrop-filter/그라데이션/다중 그림자는 플랫폼에서 같은 값으로 동일하게 보인다고 보장하지 않는다. 현재 floatingWhite와 채팅 말풍선·선택/오류 표시의 의미을 구별해 시각적으로 맞춘다.
- 부모 SafeArea/키보드 회피에서 inset을 한 번 적용한다. 하단바/입력바의 디자인 여백과 OS 내비게이션 영역을 구분한다.
- 팝업/시트는 앱 viewport 기준. 취소는 기존 화면 유지, 확인만 기존 이벤트 호출. 확인 전 처리, 자동 신청/확정 등 새로운 상태 전이를 추가하지 않는다.
- 검토 패널, 고정 예시 상태 선택기, HTML의 explain 이벤트, 합성 날짜/개인정보는 서비스 UI로 이식하지 않는다. `preview-panel.css`·`preview-panel.js`와 `.yd-preview-*` 레이아웃은 외부 검토 도구다. 패널 너비·전체 페이지 스크롤·화면과 패널 사이 간격은 앱 레이아웃 토큰이 아니다.
- HTML의 `env(safe-area-inset-bottom)`·DOM 포커스·hover·CSS 선택자·ARIA 속성을 그대로 React Native 스타일에 복사하지 않는다. 앱의 기존 safe area, Pressable 상태, 접근성 props에 대응한다. 아이콘의 시각 크기와 누름 영역 크기를 분리해 유지한다.
- 읽음 표시는 검토 과제이지 이번 확정 기능이 아니다. hostEmpty로 작성자 새 대화 진입을 만들지 않는다.

## 매 화면 확정 시 갱신 절차

1. 사용자 확정 범위와 실제 최종 CSS/마크업/상태를 대조한다.
2. guide.md와 guide.html의 현재 규칙을 교체하고 design-tokens.json의 해당 화면만 갱신한다. 공통 토큰을 바꾸면 관련 화면 영향도 확인한다.
3. 현재 실행 entry와 Expo 참조 파일을 확인한다. 화면별 원본 HTML 및 실제로 연결된 자산을 기준으로 확인하며, 보존된 과거 검증 문서를 실행 소스로 취급하지 않는다.
4. 전체 등록 소스의 문서·토큰 대조를 마친 경우에만 verify-design-system.py --refresh로 해시를 갱신한다. 일부 경로만 정리한 경우 해시를 일괄 갱신하지 않으며 --references-only로 경로 검증을 분리한다. 전체 검증은 옵션 없이 실행한다. 해시는 변경 감지 수단이며 디자인 검토를 대신하지 않는다.
5. check_ui_scope.py를 실행한다. 변경 UI의 필요한 장면만 시각 확인하고 실제 확인 범위를 기록한다.
6. 디자인시스템 동기화와 Expo 구현 완료를 별개로 보고한다.

## 현재 인계 시 주의점

둘러보기와 공고 탐색 연결 시안은 S01 원본으로 통합했다. 공고를 누르면 S02 원본을 상세 시트로 불러오며, 닫으면 목록 위치를 유지한다. 구버전 HTML·이동용 진입점·연결판 복사본과 사용하지 않는 하위 둘러보기·상세 CSS/JS는 제거했다. 현재 화면이 참조하는 자산과 장면 계약 문서는 보존한다. DS screens/home/assets는 행사 목록이 사용하는 이미지 자산만 보존한다. 기존 검증 JSON과 미대조 토큰은 전체 동기화 완료 근거가 아니며, HTML 디자인과 실제 Expo 적용은 구분한다.

## 완료 판정과 미검증 경계

문서 링크·소스 해시·범위 검사 통과는 인계 자료의 정합성 확인이다. 실제 Expo의 기기 렌더링·기능 연결·접근성 완료를 뜻하지 않는다. 현재 HTML 예시만으로 실제 푸시, 메시지 전송/재전송, 읽음, 사진 업로드, 서버 만료, 로그인 성공을 검증했다고 기록하지 않는다.

Expo 담당자는 적용한 화면 단위로 Android 글꼴/줄바꿈, 시스템 내비게이션 inset, 키보드와 입력바, 긴 내용, 기존 역할별 상태와 콜백을 확인한다. 글래스·그림자의 플랫폼 차이는 기기에서 시각 비교 후 조정한다. 이번 디자인 정리 단계에서 이 검증을 수행하기 위한 별도 앱 엔진이나 연결 프로토타입을 만들지 않는다.


## S10·S11·S12 남은 검토 반영

- S10: 모든 메시지 확인 장면은 대화방을 유지하고 개수 배지와 하단 채팅 점만 숨긴다. 비로그인도 채팅 점을 숨긴다. 목록 하단의 나가기 안내는 제거하고 나가기 확인 팝업에서 안내한다.
- S11: 변경 제안자는 작성자/신청자 역할과 별개로 내가 제안/상대가 제안 값을 받는다. 본인 제안은 철회, 상대 제안은 거절/수락을 표시한다. 차단은 입력을 막되 확정 약속의 상세·취소와 시작 후 중단/신고 접근을 유지한다. 첫 메시지 전·첫 전송 성공·신청 거절·모집 종료·철회·재신청·삭제·완료 고정 장면은 마스킹 이름을 사용한다. 차단된 확정 약속의 이름 공개는 기존 확정 상태를 유지한다. 전송 실패 이탈 안내는 신청자의 첫 전송 실패에만 신청 미생성을 설명하며 작성자에게 적용하지 않는다. 작성자가 보는 상대 철회 장면에는 상대의 철회 상태를 표시한다.
- S12: S12 알림은 공고 제목15px/700을 우선 표시하고 상태 배지12px를 같은 행 오른쪽에 둔다. 설명13px/20px는 제목 아래10px, 약속 일정12px/18px는 설명 아래4px, 도착 시각11px/16px는 아래12px·오른쪽 정렬이다. 카드 모서리20px, 패딩18px 16px, 간격12px, 사진40px, 읽지 않은 점6px를 사용한다. 모두 읽음은 높이40px·13px/700·보라 글자/연보라 배경이며 불가능할 때 회색으로 비활성화한다. 버튼 눌림은 .96/100ms이며 reduced motion을 존중한다. 하단 안내문과 바텀바는 없다.
- S12 표시 값: 공개 범위를 적용한 이름/사진, 공고 제목, 알림 종류·내용, 약속 일정, 도착 시각, 읽음 여부·개수, 대상 ID와 접근 상태. 이벤트: 뒤로, 필터 변경, 알림 선택, 모두 읽음, 재시도, 로그인 요청.
- S12 장면: default / unread / read / empty / guest / loading / error / updates / missing / permission / expired / cancelled / read-error
- 전체/읽지 않음 필터, 동행 신청·확정 요청·동행 확정·변경 제안·후기·완료와 취소·조건 변경·변경 완료·모집 재개 예시를 유지한다. 읽지 않은 목록에서 모두 확인했으면 모든 알림을 확인했어요를 표시한다. 비로그인은 로그인 안내와 이벤트만 제공하며 개인 알림을 표시하지 않는다. 조회 불가 상태의 개수는 —이며 실제 빈 목록은 0이다. 누름·모두 읽음·재시도·로그인은 검토 패널에 이벤트만 표시하고 결과는 고정 장면에서 선택한다. 실제 읽음 처리·최신 대상 검증·이동은 기존 Expo 담당 영역이다.
- Expo 연결 근거: apps/mobile/src/screens/CommunityScreens.tsx의 NotificationsScreen과 apps/mobile/src/screens/RemoteMemberScreens.tsx의 RemoteNotificationsScreen. HTML 정리와 실제 Expo 상태·API 연결은 별개다.
